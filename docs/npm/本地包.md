# npm 本地包安装（不发布到npm仓库，本地文件/本地目录引入）

## 三种常用方式

假定你的本地包目录：`./packages/my-local-lib`

## 1. npm install 本地文件夹（最常用）

```bash
npm install ./packages/my-local-lib
```

效果：

1. 复制一份代码到 `node_modules/my-local-lib`
2. package.json 写入依赖：

```json
"dependencies": {
  "my-local-lib": "file:packages/my-local-lib"
}
```

⚠️ 缺点：**不会自动监听源码变更**。改本地包代码，项目里看不到更新，需要重新 install。

## 2. npm link（软链接，开发调试首选）

### 步骤

```bash
# 1. 进入本地包目录，建立全局链接
cd packages/my-local-lib
npm link

# 2. 回到业务项目，链接这个包
cd ../../
npm link my-local-lib
```

原理：创建软链接，业务项目 `node_modules` 指向源码目录。
✅ 优点：修改源码实时生效
❌ 痛点：

- 全局污染；多人协作、CI环境不好用
- Windows 部分环境软链接权限问题

解除链接：

```bash
npm unlink my-local-lib
```

## 3. file: 协议直接写在 package.json（无需手动install）

```json
"dependencies": {
  "my-local-lib": "file:./packages/my-local-lib"
}
```

然后执行：

```bash
npm install
```

行为和方式1一致，复制文件，不是软链接。

## 4. 压缩包方式（file:.tgz）

本地先打包：

```bash
cd packages/my-local-lib
npm pack
# 生成 my-local-lib-1.0.0.tgz
```

业务项目引入：

```json
"my-local-lib": "file:./packages/my-local-lib/my-local-lib-1.0.0.tgz"
```

适合模拟线上安装行为，和正式npm包逻辑一致。

# 关键区别一张表

| 方式                   | 是否软链接 | 修改代码自动生效 | 适合场景             |
| ---------------------- | ---------- | ---------------- | -------------------- |
| `npm install file:xxx` | ❌复制文件 | ❌需要重装       | 简单本地依赖、CI打包 |
| `npm link`             | ✅软链接   | ✅实时生效       | 本地开发调试         |
| `file:.tgz`            | ❌复制包   | ❌需要重新pack   | 模拟生产安装测试     |

# ⚠️ 容易踩坑

1. 本地包必须有合法 `package.json`，包含 name、main/exports
2. 使用 monorepo（pnpm workspaces / npm workspaces）优先用工作区方案，比 npm link 稳定
3. **开源协议相关提醒**
   如果你本地私有包只是自己内部调试没问题；一旦打包发布、交付产品，本地包内部依赖的 licenses 同样要纳入SCA扫描，不能忽略。

## 补充：pnpm 用户

pnpm 的 `file:` 、workspace 协议比npm原生更稳定，推荐：

```json
"my-local-lib": "workspace:^"
```
