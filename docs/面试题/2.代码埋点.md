# 代码埋点（手动埋点）SDK 原理 + Demo
> 代码埋点：业务代码**手动调用埋点SDK方法**上报事件，优点：精准可控；缺点：每个业务点需要人工写代码维护，漏写就没有数据。

## 一、埋点SDK核心原理
埋点SDK本质就是一个**事件采集上报工具库**，核心做几件事：
1. **对外暴露上报API**：比如 `track(eventName, properties)`，业务代码在对应业务位置手动调用。
2. **事件数据组装**：拼接事件名、自定义业务属性、设备信息、用户ID、时间戳、页面信息、环境等公共上下文。
3. **数据缓存**：内存/本地存储缓存事件，避免频繁网络请求；队列管理，防止事件丢失。
4. **批量/异步上报**：
   - 策略1：达到队列阈值批量上报；
   - 策略2：定时器定时上报；
   - 策略3：页面卸载前，把剩余事件补发（`beforeunload` / `sendBeacon`）
5. **网络发送**：优先用 `navigator.sendBeacon`（页面关闭也能发，不阻塞页面）；降级用 `fetch`/`XMLHttpRequest`。
6. **异常保护**：SDK内部try‑catch，**不能因为埋点报错影响业务主流程**。

> 区分：
> - 代码埋点：业务手动调用 `track()`；
> - 全埋点（无埋点）：SDK自动劫持DOM事件，不需要业务写track，但数据噪声大。

## 二、极简浏览器端埋点SDK完整Demo
```javascript
// tracker-sdk.js 极简埋点SDK
class Tracker {
  constructor(options = {}) {
    // 上报后端地址
    this.reportUrl = options.reportUrl || "http://localhost:3000/track";
    // 事件缓存队列
    this.eventQueue = [];
    // 批量上报阈值：攒够多少条上报
    this.batchSize = options.batchSize || 5;
    // 定时上报间隔 ms
    this.timerInterval = options.timerInterval || 3000;
    // 用户id
    this.userId = options.userId || "";

    // 启动定时上报
    this.startTimer();
    // 页面关闭前补发剩余事件
    this.bindUnload();
  }

  // 对外暴露【手动埋点上报方法】——业务代码在这里手动调用！
  track(eventName, customProps = {}) {
    try {
      const event = {
        eventName, // 事件名，如 "pay_success"、"button_click"
        timestamp: Date.now(),
        pageUrl: location.href,
        userAgent: navigator.userAgent,
        userId: this.userId,
        customProps // 业务自定义属性 {goodsId:123, price:99}
      };
      // 推入事件队列
      this.eventQueue.push(event);
      // 判断是否达到批量上报阈值
      if (this.eventQueue.length >= this.batchSize) {
        this.flush();
      }
    } catch (err) {
      // 埋点出错绝不影响业务，只打印日志
      console.warn("[tracker error]", err);
    }
  }

  // 立即上报队列所有数据，清空队列
  flush() {
    if (this.eventQueue.length === 0) return;
    const events = [...this.eventQueue];
    this.eventQueue = [];

    const payload = JSON.stringify(events);
    // sendBeacon：异步，页面关闭也可发送，不阻塞主线程；兼容性好
    if (navigator.sendBeacon) {
      const blob = new Blob([payload], { type: "application/json" });
      navigator.sendBeacon(this.reportUrl, blob);
    } else {
      // 降级 fetch
      fetch(this.reportUrl, {
        method: "POST",
        body: payload,
        keepalive: true,
        headers: { "Content-Type": "application/json" }
      }).catch(e => console.warn("report fail", e));
    }
  }

  // 定时轮询上报
  startTimer() {
    setInterval(() => {
      this.flush();
    }, this.timerInterval);
  }

  // 页面卸载，补发剩余事件
  bindUnload() {
    window.addEventListener("beforeunload", () => {
      this.flush();
    });
  }

  setUserId(uid) {
    this.userId = uid;
  }
}

// ===================== 使用示例（业务代码，代码埋点） =====================
// 1.初始化SDK
const tracker = new Tracker({
  reportUrl: "http://localhost:3000/track",
  batchSize: 3
});

// 2.【代码埋点：业务事件处手动调用track】
// 场景：用户点击支付成功按钮，业务逻辑完成后手动埋点
function handlePaySuccess(goods) {
  // ----- 业务逻辑：支付处理 -----
  console.log("支付成功");

  // ====== 手动埋点，代码埋点核心：业务处手动调用track ======
  tracker.track("pay_success", {
    goodsId: goods.id,
    amount: goods.amount,
    payChannel: "alipay"
  });
}

// 场景：用户注册完成埋点
function handleRegister() {
  tracker.setUserId("u_10086");
  tracker.track("user_register", { registerType: "phone" });
}
```

## 三、Node.js 后端埋点简单示例（服务端代码埋点）
服务端埋点逻辑类似，没有`sendBeacon`，用http，队列+批量上报：
```javascript
// node-tracker.js
class ServerTracker {
  constructor(reportUrl) {
    this.reportUrl = reportUrl;
    this.queue = [];
  }
  track(eventName, props) {
    this.queue.push({ eventName, props, ts: Date.now() });
    if(this.queue.length >=10) this.flush();
  }
  async flush() {
    const list = [...this.queue];
    this.queue = [];
    await fetch(this.reportUrl, {
      method:"POST",
      body:JSON.stringify(list)
    }).catch(()=>{});
  }
}

// 使用：接口内部手动埋点

```

## 四、真实商业埋点SDK（神策/友盟）额外扩展能力
上面是极简demo，生产SDK会增加：
1. **本地持久化**：`localStorage/indexedDB` 存事件队列，页面刷新不丢失未上报事件；
2. **采样率**：比如只上报30%事件，降低流量；
3. **公共属性管理**：统一设置全局属性，每次事件自动带上；
4. **超时、重试策略**：网络失败，延后重试上报；
5. **页面pv、duration采集**；
6. **事件校验**：校验事件名、属性格式；
7. **A/B测试属性、预置属性**；
8. 小程序/app端：原理一致，只是API换成端内网络存储。

## 五、三种埋点对比
|埋点类型|实现方式|特点|
|---|---|---|
|**代码埋点**|业务手动调用 `track()`|精准，需要人工维护代码；就是上面demo模式|
|可视化埋点|后台配置元素选择器，SDK监听dom|不用改业务代码；改版容易失效|
|全埋点（无埋点）|SDK自动捕获所有点击、页面|无需开发；上报大量无用数据，数据不准|

## 六、关键坑点（生产实践）
1. **埋点不能阻塞业务**：所有埋点逻辑必须包try‑catch；
2. **页面关闭丢失数据**：必须使用 `sendBeacon / keepalive`；普通fetch在页面关闭会被直接丢弃；
3. **队列无限膨胀**：网络断连时，要做队列最大上限，防止内存爆掉；
4. **不要同步上报**：不要每次track就立刻发http请求，会造成大量请求，性能差。
