# 统计全站所有静态资源加载耗时

静态资源：js、css、图片、字体、视频等。浏览器 `Performance API` 里的 **PerformanceResourceTiming** 专门用来获取每个资源完整加载指标，不需要埋点，浏览器原生采集。

> 核心对象：`performance.getEntriesByType('resource')`

## 一、关键时间字段（PerformanceResourceTiming）

| 字段                                  | 含义                                                       |
| ------------------------------------- | ---------------------------------------------------------- |
| `name`                                | 资源完整URL                                                |
| `initiatorType`                       | 资源类型：script/css/img/font/fetch/xmlhttprequest等       |
| `startTime`                           | 开始请求时间                                               |
| `domainLookupStart ~ domainLookupEnd` | DNS解析耗时                                                |
| `connectStart ~ connectEnd`           | TCP连接耗时                                                |
| `secureConnectionStart ~ connectEnd`  | TLS SSL握手（https）                                       |
| `requestStart ~ responseStart`        | 请求到第一个字节(TTFB)                                     |
| `responseStart ~ responseEnd`         | 下载响应体耗时                                             |
| `duration`                            | **总耗时：从开始请求到下载完成** `responseEnd - startTime` |

> `duration` 就是该资源完整加载耗时。

## 二、简单代码：打印当前页面全部静态资源耗时

```javascript
// 获取所有资源条目
const resources = performance.getEntriesByType("resource");

const resourceList = resources.map((item) => {
  return {
    url: item.name,
    type: item.initiatorType,
    // DNS耗时
    dns: item.domainLookupEnd - item.domainLookupStart,
    // TCP连接
    tcp: item.connectEnd - item.connectStart,
    // SSL握手 https才有
    ssl: item.secureConnectionStart
      ? item.connectEnd - item.secureConnectionStart
      : 0,
    // TTFB 首字节
    ttfb: item.responseStart - item.requestStart,
    // 下载耗时
    download: item.responseEnd - item.responseStart,
    // 资源总耗时
    total: item.duration,
    size: item.transferSize, // 传输字节大小（压缩后）
  };
});

// 按耗时降序排序，看最慢资源
resourceList.sort((a, b) => b.total - a.total);
console.table(resourceList);
```

### ⚠️重要坑：getEntriesByType 获取不全

页面**动态懒加载资源**（滚动后加载图片、动态import js），在页面onload执行拿不到后面加载的资源。

**解决方案1：监听资源新增，PerformanceObserver（推荐生产环境）**

> PerformanceObserver 可以监听后续所有新产生的resource条目，覆盖懒加载、动态import、接口请求。

```javascript
const allResources = [];

const observer = new PerformanceObserver((list) => {
  const entries = list.getEntries();
  entries.forEach((item) => {
    allResources.push({
      url: item.name,
      type: item.initiatorType,
      total: item.duration,
      transferSize: item.transferSize,
    });
  });
});

// 监听 resource 类型
observer.observe({ entryTypes: ["resource"] });

// 页面卸载时，可以上报 allResources 给后端
window.addEventListener("beforeunload", () => {
  // 上报 allResources，ajax / beacon
  // navigator.sendBeacon('/api/report-performance', JSON.stringify(allResources))
});
```

`navigator.sendBeacon` 适合页面关闭上报，不会阻塞页面卸载。

## 三、区分静态资源 & 接口请求过滤

`initiatorType`

- 静态资源：`script`、`css`、`img`、`font`、`video`
- 接口：`fetch`、`xmlhttprequest`

只统计静态资源，可以做过滤：

```js
const staticTypes = ["script", "css", "img", "font", "video"];
const staticRes = allResources.filter((r) => staticTypes.includes(r.type));
```

## 四、几个常见问题

1. **duration=0？**
   资源来自浏览器内存缓存，没有走网络，浏览器直接读取缓存，网络阶段时间全部为0。transferSize=0代表内存缓存；transferSize>0走网络。
2. **重复url资源会多次记录**：同一个js多次请求，会生成多条resource记录。
3. PerformanceObserver 兼容性：现代浏览器全部支持；IE不支持。
4. 跨域资源：默认**拿不到部分时间字段**（DNS/TCP/TTFB会为0）。

> 需要服务端返回响应头：`Timing-Allow-Origin: *`，否则跨域资源只能拿到 startTime、duration、name。

## 五、完整上报思路（生产实践）

1. 使用 `PerformanceObserver` 持续收集全部 resource，区分静态资源、接口。
2. 过滤掉内网、监控上报自身请求，避免循环上报。
3. `beforeunload` 使用 `sendBeacon` 批量上报给后端接口。
4. 后端聚合：统计页面各静态资源P50/P95耗时，找出慢资源。

## 六、和Chrome DevTools关系

Network面板就是浏览器内部读取 PerformanceResourceTiming 渲染出来的。代码拿到的数据和Network面板时间是同源。
