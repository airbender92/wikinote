# 前端监控完整方案

前端监控核心目标：**发现错误、定位问题、统计性能、还原用户现场、辅助业务分析**。
分为五大模块：**异常监控、性能监控、用户行为监控、资源监控、上报SDK设计**；同时要考虑采样、降噪、防上报风暴、数据存储、告警。

## 一、监控采集哪些数据

### 1. 异常监控（错误）

1. **JS运行时错误**：`window.onerror`，捕获同步代码错误
2. **Promise异步错误**：`window.onunhandledrejection`，捕获未catch的Promise异常（接口报错、async报错）
3. **Vue/React框架错误**：框架自带错误钩子，onErrorCaptured / componentDidCatch；window.onerror拿不到框架内部渲染错误
4. **请求异常**：fetch/axios拦截捕获http错误：状态码、url、请求参数、响应、耗时
5. **资源加载错误**：js/css/img字体加载失败 `error`事件
6. **console.error**（可选）：收集业务打印错误，谨慎开启，数据量大

> 错误带上：错误堆栈stack、message、url、行号列号、用户UA、页面路由、时间戳。

### 2. 性能监控

1. **页面基础指标**

- FP、FCP、LCP（最大内容绘制，核心用户体验指标）
- CLS 布局偏移
- FID / INP 交互响应

> 使用 `PerformanceObserver` 采集，不要自己定时器算。

2. **资源性能**：静态资源js/css/img加载耗时（`performance.getEntriesByType('resource')`）
3. **接口性能**：每个请求耗时、TTFB、请求大小。
4. **窗口信息**：视口宽高、devicePixelRatio。
5. 页面卸载时间 `beforeunload`，用于统计页面停留时长。

### 3. 用户行为监控（埋点）

- 页面PV/UV、路由跳转记录
- 点击行为：点击元素、元素selector、innerText
- 路由变化记录：history模式监听popstate、重写pushState/replaceState
- 用户操作栈：简单回放现场，发生错误时，上报最近N条行为（面包屑 breadcrumb）

> **面包屑非常关键**：报错的时候，看用户之前点了什么、跳了什么路由，还原复现路径。

### 4. 特殊场景采集

1. 白屏监控：判断页面关键节点是否渲染出来
2. 内存监控（可选）：memory使用情况
3. 长任务监控：PerformanceObserver longtask，主线程阻塞>50ms任务，页面卡顿根源
4. 划词、ResizeObserver、AbortController等异常

## 二、SDK核心技术设计（重点工程问题）

### 1. 上报方式

优先使用 **`navigator.sendBeacon()`**

- 异步，不阻塞页面；页面卸载也可以完成上报；
- 不要用axios/fetch上报，页面关闭时请求会被直接丢弃，丢失监控数据。

```js
// 上报示例
function report(data) {
  const blob = new Blob([JSON.stringify(data)], { type: "application/json" });
  navigator.sendBeacon("/api/monitor", blob);
}
```

### 2. 合并上报 + 防抖 + 采样，防止上报风暴

线上全部上报会产生巨量流量，**必须做策略**

1. **采样率 sampleRate**：比如线上只采集 10% 用户，`Math.random() < 0.1` 才开启监控；错误类可以提高采样。
2. **批量合并**：维护上报队列，攒多条数据，达到条数阈值 或者 时间窗口（比如3s）统一一次sendBeacon上报。
3. **限流降噪**：同一个错误短时间大量重复出现（比如死循环报错），做频率限制，不要每条都上报。
4. 忽略本地开发环境、内网测试环境。

### 3. 错误堆栈处理

压缩后的代码，stack是混淆后的，**需要source‑map解析**。

> 前端拿到的是压缩后行号列号，后端根据source‑map还原原始源码位置。
> ⚠️source‑map不要部署到生产CDN，存放在后端服务。

### 4. 面包屑 Breadcrumb（错误现场还原）

维护内存队列，最多保存最近20条行为：路由跳转、点击、请求、警告。
当发生错误的时候，**把面包屑附加到错误上报数据一起提交**。
没有面包屑，很多线上错误根本无法复现。

面包屑示例内容：

```js
[
  { type: "route", message: "跳转 /list", time: 1750000000 },
  { type: "click", message: "点击查询按钮", time: 1750000002 },
  { type: "request", message: "GET /api/list 400", time: 1750000003 },
];
```

### 5. 各个捕获API的坑

1. `window.onerror` 捕获不到跨域JS脚本错误 → JS脚本增加 `crossorigin="anonymous"`，服务端返回CORS头。
2. `unhandledrejection` 捕获Promise错误；但是业务代码写了空catch，就捕获不到。
3. 框架错误：Vue `app.config.errorHandler`；React `ErrorBoundary`，否则框架内部报错window.onerror拿不到完整堆栈。
4. fetch本身不会抛出错误，404/500不会触发onunhandledrejection，**必须自己拦截fetch包装**。
5. 被AbortController取消的请求，不要当做错误上报。

### 6. 不要侵入业务

SDK尽量不修改业务逻辑；重写history、fetch需要做好保存原始方法。

```js
// hook history pushState 监听路由
const originalPush = history.pushState;
history.pushState = function (...args) {
  // 面包屑记录路由变化
  originalPush.apply(this, args);
};
```

## 三、数据流程全链路

1. 浏览器SDK采集异常/性能/行为 → 内存队列
2. 合并、采样、过滤降噪 → sendBeacon上报后端接口
3. 后端接收数据，存储（ES/MySQL）
4. 数据清洗：sourcemap解析错误堆栈、打标签
5. 聚合统计：错误率、PV、LCP均值
6. **告警规则**：错误率突增、关键页面LCP恶化，钉钉/邮件告警
7. 后台平台：查看错误列表、堆栈、用户面包屑、性能大盘

## 四、告警策略（非常重要，避免告警轰炸）

不要一个错误就告警，做聚合：

1. 按错误指纹聚合（message+堆栈hash生成指纹）
2. 阈值：比如同一个错误1分钟内超过20次，触发告警
3. 区分等级：P0页面白屏、接口大面积失败；P1普通JS错误；P2次要警告
4. 过滤测试用户、内网环境。

## 五、自研 vs 开源方案选型

### 开源成熟方案（企业常用）

1. **Sentry**：专注异常监控，sourcemap解析，面包屑，告警；性能能力弱一些。
2. **OpenTelemetry**：完整可观测，前端+后端全链路追踪，比较重。
3. **Fundebug、ArkUI‑Monitor**：商业SaaS。

> 小团队：直接接入Sentry，不用从零写SDK；
> 大团队：基于Sentry二次开发，或者自研SDK，对接内部告警体系。

## 六、关键指标定义，用来衡量页面质量

1. **JS错误率 = JS错误数 / PV**，一般要求控制在 1%以内
2. **接口错误率 = 失败请求 / 总请求**
3. **LCP 指标**：良好 <2.5s，差 >4s
4. **INP交互指标**：衡量页面响应卡顿
5. **白屏率**

## 七、避坑清单

1. ❌用fetch/axios做上报，页面关闭丢失数据 → 使用 sendBeacon
2. ❌全量上报，不采样，流量打爆后端
3. ❌不做面包屑，报错缺少上下文，无法复现
4. ❌生产环境暴露source‑map，源码泄露
5. ❌跨域js没有crossorigin，捕获到Script error.拿不到堆栈
6. ❌把开发环境、测试环境错误混入生产大盘
7. ❌重复上报同一个循环触发的错误，没有限流降噪
8. ❌忽略Promise未捕获异常，只依赖window.onerror

## 极简SDK架构伪代码

```
采集层
├─ 错误捕获：onerror、unhandledrejection、vue errorHandler
├─ 请求捕获：hook fetch/axios
├─ 性能采集：PerformanceObserver LCP、INP、longtask
└─ 行为采集：click、hook history，维护面包屑队列

处理层
├─ 采样判断 sampleRate
├─ 过滤忽略错误
├─ 错误去重限流
└─ 组装面包屑、设备信息

上报层
├─ 本地队列缓存
├─ 合并攒批
└─ sendBeacon 上报后端
```
