# 结论：**这个说法是错误的❌**

> 前提：带宽固定、网络完全稳定、上传全程不中断。
> 虽然需要传输的**文件有效载荷总字节是一样**，但是切片上传会引入额外开销，**切片上传耗时会略大于整体上传**，并不是差不多。

## 1、为什么总字节相同，时间却不一样？

整体上传：**1次HTTP请求**，一次发送全部文件二进制数据，仅1套HTTP请求头、响应头、TLS握手、RTT往返开销。

切片上传：把文件拆成N片，发起**N个独立HTTP请求**，带来多份额外开销：

1. **协议开销**：每一个分片都带有HTTP请求头/响应头（cookie、鉴权、各种header）；HTTPS场景每个请求带来TLS握手、RTT往返时延。分片切得越小、分片数量越多，这部分开销累积越大。
2. **客户端开销**：客户端做文件切割、Blob处理、分片hash校验计算，消耗CPU时间。
3. **服务端开销**：接收每一片、暂存分片、全部上传完成后执行文件合并磁盘IO，消耗服务端时间。
4. 即使是HTTP2多路复用，消除了多TCP连接开销，但每个分片依然保留HTTP头部的协议开销，无法完全消除。

> 带宽是物理链路上限，带宽决定**文件本体数据传输耗时**，但是上面这些**协议、IO、RTT开销不占用带宽，但是要消耗时间**。

## 2、那切片上传的价值是什么？

切片上传**不是用来提速（稳定网络下），核心价值是稳定性，不是速度**：

1. **断点续传**：网络中断，只重传失败分片，不用全部重传；网络不稳定时，切片上传总耗时会远优于整体上传。
2. **规避网关/服务器单请求body大小限制**，支持超大文件上传。
3. 内存友好，客户端、服务端不用一次性加载完整大文件到内存。
4. 可以展示更细粒度上传进度。

| 场景     | 带宽固定，网络稳定无丢包 | 网络不稳定，会中断失败       |
| -------- | ------------------------ | ---------------------------- |
| 整体上传 | 耗时更短                 | 一旦中断，全部重传，耗时爆炸 |
| 切片上传 | 耗时略长（额外请求开销） | 只重传失败分片，整体耗时更优 |

## 3、常见误区：切片并发就能变快？

浏览器同一域名有最大并发请求限制（HTTP1.1约6个），就算写代码同时发出几十个分片请求，多余请求会排队等待，**并不能突破物理带宽上限**，反而排队增加等待时延。

> 带宽已经跑满时，再多并发也不能让本体数据传得更快，只会叠加更多请求开销。

## 4、补充面试答题精简版

> “带宽一定情况下，切片上传和整体上传耗时差不多，该说法错误。
> 在网络稳定、不会发生中断的理想条件，二者待传输的文件有效数据大小相同，但是切片上传会产生多次HTTP头部、TLS握手、客户端切片计算、服务端分片合并等额外开销，耗时会比整体上传更长。
> 分片上传的优势不在于稳定网络下缩短上传时间，而在于网络波动中断时，支持断点续传，仅重传失败分片；同时解决大文件内存超限、服务器单请求大小限制的问题。”

# 前端文件切片核心原理

利用 `File.prototype.slice()`（File继承Blob）对文件二进制做切割，得到多个 Blob 分片，逐个上传分片，最后通知后端合并。

> 注意：不是数组slice，是二进制Blob的 `.slice(startByte, endByte)`，单位字节。

## 关键API

- `File`：用户选择的文件对象，继承 `Blob`
- `file.slice(start, end)`：截取二进制片段，返回 Blob
- `FileReader`：可选，读取分片做md5/hash校验
- `FormData`：携带分片二进制、分片序号、总片数、文件唯一标识

## 完整基础示例

```
<input type="file" id="fileInput" />
<script>
const fileInput = document.getElementById('fileInput')

// 单个分片大小 5MB
const CHUNK_SIZE = 5 * 1024 * 1024

fileInput.onchange = async (e) => {
  const file = e.target.files[0]
  if (!file) return

  const totalSize = file.size
  // 计算分片总数：向上取整
  const totalChunks = Math.ceil(totalSize / CHUNK_SIZE)

  console.log('文件大小', totalSize, '分片数量', totalChunks)

  // 循环切割每一片
  for (let chunkIndex = 0; chunkIndex < totalChunks; chunkIndex++) {
    const start = chunkIndex * CHUNK_SIZE
    const end = Math.min(start + CHUNK_SIZE, totalSize)

    // ✅ 核心切片：二进制切割
    const chunkBlob = file.slice(start, end)

    const formData = new FormData()
    formData.append('file', chunkBlob)
    formData.append('chunkIndex', chunkIndex) // 当前分片序号
    formData.append('totalChunks', totalChunks) // 总分片
    formData.append('filename', file.name)
    // 文件唯一标识，后端用来区分哪一组分片，可用文件hash
    formData.append('fileKey', 'xxx-unique-file-id')

    // 上传分片，串行上传；也可以改成并发（注意浏览器并发限制）
    await uploadChunk(formData)
  }

  // 全部分片上传完成，通知后端合并文件
  await mergeRequest({ filename: file.name, fileKey: 'xxx-unique-file-id', totalChunks })
}

// 上传分片
async function uploadChunk(formData) {
  const res = await fetch('/api/upload/chunk', {
    method: 'POST',
    body: formData
  })
  return res.json()
}

// 请求后端合并分片
async function mergeRequest(params) {
  await fetch('/api/upload/merge', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(params)
  })
}
</script>
```

## 重点细节

### 1. slice 参数单位

`file.slice(start字节, end字节)`，**左闭右开区间 `[start, end)`**

```
start = index * CHUNK_SIZE
end = start + CHUNK_SIZE
// 最后一片不能超过文件总大小：Math.min(end, file.size)
```

### 2. 串行 vs 并发上传分片

- **串行（示例代码）**：一片传完再传下一片，简单稳定，不容易触发浏览器并发限制，弱网友好；速度慢一点。
- **并发**：同时发出多个分片请求，HTTP1.1浏览器同域最大并发6个；不要开太大并发，容易超时、429。>

> 带宽跑满之后，并发不会提升速度，只会增加请求开销。

### 3. fileKey 文件唯一标识（断点续传核心）

同一个文件的所有分片必须携带同一个 `fileKey`，后端靠这个key把分片归为同一组。

> 最佳实践：前端计算整个文件的md5作为fileKey；不用文件名，文件名可重复。

### 4. 断点续传配套逻辑

1. 选择文件，计算文件md5得到fileKey
2. 请求后端接口：查询该fileKey哪些分片已经上传成功
3. 前端切片循环时，**跳过已经上传成功的分片，只传缺失分片**
4. 全部传完调用合并接口

### 5. 常见坑

1. ❌ 不要用数组slice切割文件，那是切割数组，不是二进制
2. ❌ 分片大小不要太小：比如几十KB，分片数量爆炸，HTTP头部开销巨大；一般 2‑10MB 之间选。
3. ❌ 不要把File转成base64再切片：base64体积膨胀1/3，性能差。**直接操作Blob.slice**。
4. 大文件计算md5会阻塞主线程，要用 `SparkMD5` 配合 WebWorker，避免页面卡顿。

## Vue3简易封装版本

```
<script setup>
import { ref } from 'vue'
const CHUNK_SIZE = 5 * 1024 * 1024
const progress = ref(0)

async function handleFileChange(e) {
  const file = e.target.files[0]
  if (!file) return
  const totalSize = file.size
  const totalChunks = Math.ceil(totalSize / CHUNK_SIZE)

  for (let i = 0; i < totalChunks; i++) {
    const start = i * CHUNK_SIZE
    const end = Math.min(start + CHUNK_SIZE, totalSize)
    const chunk = file.slice(start, end)

    const fd = new FormData()
    fd.append('chunk', chunk)
    fd.append('index', i)
    fd.append('total', totalChunks)

    await fetch('/api/upload/chunk', { method:'POST', body:fd })
    progress.value = Math.round(((i+1)/totalChunks)*100)
  }
  // 调用合并接口
}
</script>
<template>
  <input type="file" @change="handleFileChange"/>
  <div>上传进度：{{ progress }}%</div>
</template>
```
