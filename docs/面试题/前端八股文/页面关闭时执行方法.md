# 页面关闭/刷新时执行 JS 方法

常见场景：**保存草稿、上报埋点、取消请求、提示用户未保存数据、清理切片上传状态**。

> 重点坑：页面关闭是**不可阻塞**，不能做耗时操作、不能异步await，ajax/fetch默认会被浏览器直接中断。

## 1. 主要事件

### ① `beforeunload`：关闭/刷新/跳转**前触发**

> 作用：可以弹出浏览器确认提示，**但不能异步执行业务逻辑**，只能同步代码。
> 用户可以选择「留在页面」或「离开页面」。

```js
window.addEventListener("beforeunload", (e) => {
  // 自定义提示文本现在浏览器已经忽略，只会显示浏览器默认提示
  // 只要给 returnValue 赋值，就会弹出确认框
  e.returnValue = "";
  // 同步逻辑可以跑，不能写await、fetch异步
  console.log("页面即将关闭/刷新/跳转");
});
```

⚠️限制：

1. 不能执行异步（接口请求、定时器、Promise），页面销毁直接中断。
2. 返回提示文案**浏览器不支持自定义**，统一显示系统提示。
3. 用户交互要求：部分浏览器要求页面发生过用户点击交互，才会弹出确认框。

### ② `unload`：页面正在卸载，马上销毁

> 触发时机：确认离开之后执行，**大部分异步直接作废**

```js
window.addEventListener("unload", () => {
  console.log("页面正在卸载");
  // 这里普通 fetch/axios 极大概率被浏览器丢弃，发不出去
});
```

> ❌不要在 unload 里面发普通 ajax。

## 2. 页面关闭想要上报接口（最重要：`navigator.sendBeacon`）

**专门为页面卸载上报设计的API，异步、后台执行，浏览器保证尽量发送，不会阻塞页面关闭**
适合：埋点上报、通知服务端“客户端断开、终止切片上传任务”。

```js
window.addEventListener("beforeunload", () => {
  // sendBeacon：POST请求，只能传少量数据，适合上报
  const data = JSON.stringify({ fileId: "xxx", status: "abort" });
  navigator.sendBeacon("/api/upload/abort", data);
});
```

### sendBeacon 特点

✅ 浏览器后台排队发送，页面关闭也尽量完成请求
✅ 不会阻塞页面关闭，不会卡住用户
❌ **不支持获取响应结果**，不知道成功失败；
❌ 数据大小有限制，一般 64KB；适合上报，不适合大请求；
❌ 只支持简单POST，不能自定义复杂请求头（部分环境有限制）。

> 切片上传场景使用：页面关闭，调用 `sendBeacon` 通知后端：该文件上传任务终止，可以清理临时切片。

## 3. 现代替代：`visibilitychange`（标签页隐藏，不一定关闭）

> 用户切tab、最小化、回到后台触发；**不等于页面关闭**，很多移动端场景优先用这个。

```js
document.addEventListener("visibilitychange", () => {
  if (document.hidden) {
    // 页面被隐藏（切后台、切标签）
    console.log("页面隐藏");
    navigator.sendBeacon(
      "/api/upload/abort",
      JSON.stringify({ fileId: "xxx" }),
    );
  } else {
    // 页面重新可见
  }
});
```

> 区分：`visibilitychange` 只是隐藏；`beforeunload/unload` 才是真正关闭/刷新。
> 移动端浏览器有时候关闭标签不一定可靠触发 unload，会优先触发 visibilitychange hidden。

## 4. 各个方案对比总结

| 方案                 | 触发时机                 | 能否异步请求                     | 适用场景                           |
| -------------------- | ------------------------ | -------------------------------- | ---------------------------------- |
| beforeunload         | 即将关闭，可以弹出确认框 | ❌普通异步失效；✅sendBeacon可用 | 提示未保存、执行sendBeacon上报     |
| unload               | 页面销毁瞬间             | ❌几乎所有异步失效               | 只跑极短同步逻辑                   |
| navigator.sendBeacon | 配合beforeunload使用     | ✅浏览器后台保证发送             | 上报、通知后端终止任务（切片上传） |
| visibilitychange     | 页面切后台/切tab         | ✅sendBeacon可用                 | 移动端兜底，页面不可见时清理任务   |

## 5. 切片上传业务最佳实践示例

> 需求：用户关闭页面，通知后端终止本次切片上传，清理碎片

```js
function bindPageCloseUploadAbort(fileId) {
  const handler = () => {
    const payload = JSON.stringify({ fileId });
    // sendBeacon 通知服务端终止上传任务
    navigator.sendBeacon("/api/upload/abort", payload);
  };
  window.addEventListener("beforeunload", handler);

  // 组件销毁时解绑，防止内存泄漏
  return () => {
    window.removeEventListener("beforeunload", handler);
  };
}

// 使用
const unbind = bindPageCloseUploadAbort("upload_123456");
// vue组件卸载：unbind()
```

## 6. 常见坑

1. ❌ 在 unload / beforeunload 写 axios/fetch，期望拿到返回结果：**请求大概率丢失，收不到响应**，必须用 sendBeacon。
2. ❌ 期望 await 异步操作：页面进程直接销毁，Promise不会执行完成。
3. ❌ 自定义 beforeunload 提示文字，现代浏览器全部忽略，只会显示浏览器自带提示。
4. ❌ 以为 visibilitychange hidden = 页面关闭：只是切后台，切换回来页面还在。
5. sendBeacon跨域问题：后端需要正确配置 CORS，`Access‑Control‑Allow‑Origin`。

## 7. Vue/React 注意点

- 在组件挂载时 addEventListener，组件销毁时 `removeEventListener`，避免重复绑定，内存泄漏。
- 不要用匿名函数直接绑定，否则无法移除事件。
