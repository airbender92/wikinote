# 前端防止重复请求方案

重复请求常见场景：

1. 按钮连续多次点击（保存、提交、查询）
2. 路由快速切换，上一个接口还没返回
3. 防抖节流不适合异步请求（节流只控制调用频率，不能取消正在进行的旧请求）
4. 重复触发 useEffect / watch，组件频繁渲染发起请求

> 核心手段：**loading锁、AbortController取消请求、请求缓存、请求去重Map**

## 1、按钮点击：loading 状态锁（最简单，UI层拦截）

适用：提交类、按钮触发请求；缺点：页面跳转/组件销毁，锁不会自动释放。

```
let loading = false

async function submit() {
  if(loading) return // 请求中直接拦截
  loading = true
  try {
    await fetch('/api/submit')
  } finally {
    loading = false // 无论成功失败都释放锁
  }
}
```

Vue示例

```
<template>
  <button @click="submit" :disabled="loading">提交</button>
</template>
<script setup>
import {ref} from 'vue'
const loading = ref(false)
const submit = async ()=>{
  if(loading.value) return
  loading.value = true
  try{
    await api.submit()
  }finally{
    loading.value = false
  }
}
</script>
```

## 2、AbortController ✨重点：取消正在进行的请求（fetch / axios）

场景：快速切换tab、路由跳转，旧请求回来会污染数据，**不仅阻止新请求，还能把旧请求直接取消**。

### fetch 原生

```
let controller = null

async function queryData() {
  // 如果上一次请求还在，直接取消
  if(controller) controller.abort()

  controller = new AbortController()
  const signal = controller.signal

  try {
    const res = await fetch('/api/list', { signal })
    return await res.json()
  } catch(e) {
    // abort抛出异常，区分是手动取消还是真实错误
    if(e.name === 'AbortError') {
      console.log('请求被取消')
    }else{
      console.error('真实错误', e)
    }
  }
}
```

### Axios 版本（Axios 内部封装 AbortController）

axios v0.22+ 原生支持 signal

```
import axios from 'axios'

let abortController = null

async function getList() {
  if(abortController) abortController.abort()
  abortController = new AbortController()

  try {
    const res = await axios.get('/api/list', {
      signal: abortController.signal
    })
    return res.data
  } catch(err) {
    if(axios.isCancel(err)){
      console.log('请求取消')
    }
  }
}
```

> 组件销毁时一定要取消请求，防止组件卸载后还执行setState/赋值，内存泄漏

```
// Vue3
onUnmounted(()=>{
  if(abortController) abortController.abort()
})
```

## 3、全局请求去重Map：相同接口同时只允许一个进行

适用：多处调用同一个接口，短时间并发触发；用Map保存`key -> abortController`
key可以由 `url + method + 参数` 拼接生成。

```
// 全局请求控制器Map
const requestMap = new Map()

// 生成请求唯一key
function getRequestKey(config) {
  const {url, method, params, data} = config
  return [method, url, JSON.stringify(params||{}), JSON.stringify(data||{})].join('|')
}

async function requestWrap(config) {
  const key = getRequestKey(config)
  // 如果存在相同请求，取消上一个
  if(requestMap.has(key)){
    const oldController = requestMap.get(key)
    oldController.abort()
  }

  const controller = new AbortController()
  config.signal = controller.signal
  requestMap.set(key, controller)

  try {
    return await axios(config)
  } finally {
    // 请求完成删除记录
    if(requestMap.get(key) === controller){
      requestMap.delete(key)
    }
  }
}
```

> 注意：查询接口适合；**提交POST接口不能取消！** 取消提交请求可能后端已经执行，前端断连而已，会造成数据错乱，提交接口只用loading锁，不要abort。

## 4、请求缓存：短时间内相同查询直接返回缓存，不发网络

适合查询类接口，短时间重复查询同样参数，缓存结果。不适合实时数据、提交接口。

```
const cache = new Map()

async function query(params) {
  const key = JSON.stringify(params)
  // 命中缓存直接返回
  if(cache.has(key)){
    return cache.get(key)
  }
  const res = await axios.get('/api/query', {params})
  cache.set(key, res.data)
  // 可选：设置缓存过期时间
  setTimeout(()=>cache.delete(key), 3000)
  return res.data
}
```

## 5、防抖 debounce

适合输入框搜索，输入过程不发请求，停止输入N毫秒后再请求。

> ⚠️防抖：**延迟发起请求，不会取消已经发出的请求**，一般配合AbortController一起用。

```
import {debounce} from 'lodash'
const search = debounce(async (kw)=>{
  await api.search(kw)
}, 300)
```

# 📌不同场景最佳实践总结

| 场景                       | 方案                                       |
| -------------------------- | ------------------------------------------ |
| 按钮提交、保存（POST）     | **loading锁，禁止abort**，不能取消提交请求 |
| Tab切换、筛选查询GET       | AbortController，新请求取消旧请求          |
| 输入框搜索                 | debounce + AbortController                 |
| 多处并发调用同一个查询接口 | 全局requestMap去重                         |
| 非实时查询数据             | 内存缓存                                   |

## 避坑重点

1. **POST提交千万不要Abort取消**：HTTP abort只是客户端断开，后端可能已经完成业务逻辑，会造成前端以为失败，实际后台数据已变更。提交类只用loading锁。
2. useEffect / watch 触发重复请求：一定要在清理函数中调用abort()
3. loading锁：异常场景必须写`finally`释放锁，否则页面永久卡死loading
4. 去重key：params、body参数要参与key生成，不同参数不能当成同一个请求。

# 请求去重：不使用 AbortController

> 前提：**不取消正在跑的旧请求**。
> 逻辑：同一个请求（url+method+参数）并发期间，**只允许发起一次**；后续重复调用全部排队/直接丢弃，等待第一个请求完成后，再放行后续调用。

适用场景：

- 不想中断后端已经在执行的请求（尤其部分POST）
- 老项目浏览器不支持AbortController
- 不想处理abort异常分支

实现思路：维护一个**进行中请求Map**

- key：`method|url|params|data` 唯一标识请求
- value：Promise实例
- 调用时：如果key已存在，直接返回现存Promise，不发起新请求；
- 请求结束（成功/失败），删除Map中的key，释放。

## 核心封装代码

```js
/**
 * 请求去重，不取消请求，并发相同请求复用同一个Promise
 */
const pendingRequest = new Map();

// 生成请求唯一key
function genRequestKey(config) {
  const { method, url, params, data } = config;
  return [
    (method || "get").toUpperCase(),
    url,
    JSON.stringify(params ?? {}),
    JSON.stringify(data ?? {}),
  ].join("|");
}

/**
 * 请求包装函数
 * @param {Function} requestFn 真正发请求的函数，返回Promise
 * @param {Object} config {method,url,params,data}
 * @returns Promise
 */
function requestDeduplicate(requestFn, config) {
  const key = genRequestKey(config);

  // 如果该请求正在进行，直接复用已有Promise，不发起新网络请求
  if (pendingRequest.has(key)) {
    return pendingRequest.get(key);
  }

  // 发起真实请求
  const promise = requestFn()
    .then((res) => {
      return res;
    })
    .catch((err) => {
      throw err;
    })
    .finally(() => {
      // 无论成功失败，都清除，允许下一次发起
      pendingRequest.delete(key);
    });

  pendingRequest.set(key, promise);
  return promise;
}
```

### 使用示例（axios）

```js
import axios from "axios";

// 真实请求函数
function httpGetList(params) {
  return requestDeduplicate(() => axios.get("/api/list", { params }), {
    method: "get",
    url: "/api/list",
    params,
  });
}

// 模拟连续多次调用，只会真正发1次网络请求
httpGetList({ page: 1 }).then((res) => console.log("第一次", res));
httpGetList({ page: 1 }).then((res) => console.log("第二次", res));
httpGetList({ page: 1 }).then((res) => console.log("第三次", res));
```

> 上面三次调用，**网络只发出1次**，三个then都会拿到同一个返回结果。

## 两种策略选择

### 策略A：并发重复请求 → 复用同一个Promise（上面代码，默认）

> 短时间多次调用，全部等待第一次请求结果，全部拿到相同返回。
> 适合：查询接口 GET。

### 策略B：并发重复请求 → 后面的直接丢弃，不返回（忽略重复调用）

如果希望：正在请求中，再来调用直接 reject，不等待。
修改判断分支：

```js
if (pendingRequest.has(key)) {
  return Promise.reject(new Error("请求重复，已丢弃"));
}
```

## Vue3 按钮提交场景结合（POST提交防重复点击）

POST提交**禁止取消请求**，这种方案非常合适。

```js
async function submitForm(data) {
  return requestDeduplicate(() => axios.post("/api/save", data), {
    method: "post",
    url: "/api/save",
    data,
  });
}
```

短时间连续点提交按钮：只会发出一次POST。

## ⚠️重要坑点

1. **请求异常一定要finally删除key**，否则Map永远不释放，接口永久无法再次请求。
2. key生成必须带上 `params/data`，参数不一样不能去重。
3. **不适合长轮询、流式接口**，会一直占用key。
4. 这个方案不会终止旧请求。旧请求哪怕很久才回来，也不会被打断。
5. 如果接口返回不同时间的数据，多次并发调用会拿到第一次的结果；如果需要每次拿最新数据，此方案不适合。

## 和 AbortController方案对比

| 方案                  | 行为                                | 适合场景                               |
| --------------------- | ----------------------------------- | -------------------------------------- |
| AbortController       | 新请求直接把旧请求取消              | tab切换、筛选查询，不需要旧结果        |
| 本方案（Promise复用） | 不取消旧请求，并发复用同一个Promise | 按钮提交、防重复点击，不能中断后端逻辑 |

## 拓展：集成到axios拦截器

```js
// 请求拦截器
axios.interceptors.request.use((config) => {
  const key = genRequestKey(config);
  // 如果正在pending，抛出，或者复用
  if (pendingRequest.has(key)) {
    // 方式1：复用Promise；axios拦截器return Promise，会把这个promise作为本次请求
    return pendingRequest.get(key);
  }
  // ...正常逻辑
});
```

> 小缺陷：axios拦截器内复用Promise写法有坑，更推荐外面包装一层函数，而不是完全塞到拦截器。
