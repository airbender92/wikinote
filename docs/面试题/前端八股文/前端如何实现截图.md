# 前端页面截图实现方案

前端截图分两大类：

1. **DOM转图片方案：`html2canvas`**：把页面DOM渲染成canvas，再导出图片；最常用。
2. **浏览器原生API：`MediaDevices.getDisplayMedia`**：调用浏览器系统截图，捕获整个屏幕/窗口/标签页。

> 两者有本质区别：
>
> - html2canvas：**基于DOM模拟绘制**，不真正截图屏幕；有部分CSS、样式兼容性坑。
> - getDisplayMedia：**系统级录屏/截图**，拿真实画面；需要用户手动授权选择窗口。

## 一、html2canvas（DOM转截图，业务最常用）

原理：遍历DOM树，解析样式，在Canvas上重新绘制一遍DOM，最后导出图片。

> ⚠️不是真的抓取屏幕，是“复刻绘制”，部分CSS特性不支持。

### 1.安装

```bash
npm install html2canvas
```

### 2.基础示例

```tsx
import html2canvas from "html2canvas";

// targetDom：需要截图的DOM节点
async function takeScreenshot(targetDom: HTMLElement) {
  const canvas = await html2canvas(targetDom, {
    scale: window.devicePixelRatio, // 适配高清屏，避免模糊
    useCORS: true, // 处理跨域图片（图片服务器需要配置CORS）
    logging: false,
  });
  // 1.转base64
  const base64 = canvas.toDataURL("image/png");

  // 2.下载图片
  const a = document.createElement("a");
  a.href = base64;
  a.download = "screenshot.png";
  a.click();

  return base64;
}
```

### 常见坑点（高频踩坑）

1. **截图模糊**：设置 `scale: devicePixelRatio`。
2. **跨域图片截图空白**
   - 图片服务开启CORS；图片标签加上 `crossOrigin="anonymous"`；html2canvas开启 `useCORS:true`。
   - 如果图片CDN不允许跨域，html2canvas无法绘制这张图。
3. **部分CSS不支持**：
   - 部分 `filter`、`box‑shadow`、部分渐变、transform 有兼容问题；
   - 伪元素 `::before / ::after` 老版本支持有限。
4. **滚动区域**：如果DOM内部有滚动，html2canvas默认会截取完整高度，不是可视区域。
5. **canvas大小超限**：DOM很大时生成超大canvas，浏览器会报错。
6. **iframe内容无法绘制**。
7. 动画：截图那一刻会截取DOM当前状态，动画最好截图前暂停。

> 局限：**只能截取当前页面DOM，不能截取浏览器外部内容**。

## 二、浏览器原生 getDisplayMedia（系统捕获屏幕）

> 调用浏览器系统弹窗，让用户手动选择：整个屏幕 / 某个窗口 / 当前标签页；拿到媒体流，再绘制到canvas截图。
> ⚠️**HTTPS环境才可用；localhost本地开发允许；HTTP普通页面不可用。**

示例：

```js
async function systemScreenShot() {
  // 唤起选择窗口弹窗
  const stream = await navigator.mediaDevices.getDisplayMedia({
    video: true,
  });
  const video = document.createElement("video");
  video.srcObject = stream;
  await video.play();

  const canvas = document.createElement("canvas");
  canvas.width = video.videoWidth;
  canvas.height = video.videoHeight;
  const ctx = canvas.getContext("2d");
  ctx.drawImage(video, 0, 0);

  const base64 = canvas.toDataURL("image/png");

  // 停止捕获，释放屏幕权限
  stream.getTracks().forEach((track) => track.stop());
  return base64;
}
```

特点：
✅ **拿到真实屏幕画面**，不受CSS、跨域图片限制；可以截取浏览器外面内容。
❌ 需要用户手动弹窗授权选择窗口；**不能静默截图，代码无法绕过用户确认**。
❌ 不能指定截取页面某个DOM元素，只能选整个窗口/屏幕。

## 三、二者对比

| 方案            | 原理            | 能否指定DOM        | 是否需要用户授权    | 跨域图片     |
| --------------- | --------------- | ------------------ | ------------------- | ------------ |
| html2canvas     | DOM重绘到Canvas | ✅ 指定任意DOM     | ❌ 无需授权         | 需服务端CORS |
| getDisplayMedia | 系统捕获屏幕    | ❌ 只能选窗口/屏幕 | ✅ 用户必须手动确认 | 不受限制     |

> 业务场景选型：
>
> 1. **截取页面内某一块DOM（报表、表单、卡片）**：选 html2canvas。
> 2. 需要截取完整屏幕、包含浏览器外部内容：用 getDisplayMedia。

## 四、其他补充方案

1. **后端截图服务（Puppeteer）**
   前端把DOM信息/URL传给后端，后端用无头浏览器Puppeteer打开页面截图，返回图片。
   适用：

- html2canvas大量样式兼容问题搞不定；
- 需要生成PDF、复杂报表截图；
  缺点：需要维护后端服务，有性能成本。

2. 浏览器没有API可以**静默截图用户屏幕**，出于安全，JS不能绕过用户操作偷偷截屏。

## 五、面试简答

> 前端截图主要两种方案：

1. **html2canvas**：将目标DOM解析样式，在Canvas重新绘制，再导出图片；可以指定页面任意DOM节点，不需要用户授权。
   - 坑：本质是复刻DOM不是真实屏幕截图；跨域图片需要服务端配置CORS；部分CSS（filter、伪元素等）存在兼容；高清屏需要配置scale=devicePixelRatio防止模糊。
2. **getDisplayMedia 浏览器原生API**：系统级屏幕捕获，弹出窗口让用户选择屏幕/窗口/标签页，拿到媒体流绘制canvas得到截图。
   - 优点：拿到真实画面，不受DOM、CSS、跨域图片限制；
   - 限制：必须HTTPS，**必须用户手动授权，无法静默截图，不能截取局部DOM**。

> 业务截取页面内部DOM优先使用html2canvas；截取系统屏幕画面使用getDisplayMedia；DOM绘制兼容问题严重时，可以考虑后端Puppeteer无头浏览器截图。

> 安全重点：JS不允许无感知偷偷截取用户屏幕。
