# CDN资源为什么不受同源策略限制

先理清核心：**同源策略不是所有请求都拦截，它分两种场景：资源加载、AJAX/Fetch读取响应**。

同源策略的真实规则：

> ✅**允许跨域加载外部资源**：`<script>`、`<link css>`、`<img>`、`<video>`、`<iframe>`，浏览器可以拿到资源并渲染/执行；
> ❌**禁止JS读取跨域响应内容**：`fetch`/`XMLHttpRequest` 想要用JS读取跨域返回的数据，浏览器会拦截，需要CORS。

CDN就是把静态资源（js、css、图片）放在另外域名，通过标签引入，属于**跨域资源加载，不是ajax读响应**，所以不会触发跨域报错。

## 1. CDN‑JS 例子

页面域名：`a.com`
CDN地址：`https://cdn.xxx.com/vue.global.js`

```
<!-- 允许，浏览器下载并执行JS，不受跨域限制 -->
<script src="https://cdn.xxx.com/vue.global.js"></script>
```

- 浏览器发起网络请求拿到js文本；
- 直接交给JS引擎执行；
- **页面JS不能用JS变量去读取这个http响应原始报文**，只是直接执行脚本。>

> 重点：**只是加载执行，不通过JS API去读取响应体**，同源策略不拦截。

> 但是！这里有一个著名坑：**跨域脚本报错拿不到完整堆栈，只报 `Script error.`**
> 解决：script标签加 `crossorigin="anonymous"`，CDN服务器返回CORS响应头，浏览器才允许JS读取脚本异常堆栈。

```
<script src="https://cdn.xxx.com/index.js" crossorigin="anonymous"></script>
```

## 2. CDN‑CSS / 图片

```
<link rel="stylesheet" href="https://cdn.xxx.com/style.css">
<img src="https://cdn.xxx.com/a.png">
```

同样：浏览器可以加载渲染；
JS不能直接用fetch去读取这个css/png的原始二进制；如果JS想要读取图片二进制（比如canvas绘制图片），图片CDN也需要配置CORS + `img.crossOrigin="anonymous"`。

## 3. 对比：如果你用fetch去请求CDN JS，就会跨域报错

```
// a.com页面，JS fetch请求cdn域名
fetch('https://cdn.xxx.com/vue.global.js')
```

> ❗此时会触发跨域拦截！
> 原因：`fetch` 是JS API，意图**读取响应的文本内容**，这时候同源策略生效，必须CDN服务返回CORS `Access‑Control‑Allow‑Origin`。

### 一句话区分

1. **HTML标签加载资源（script/img/link）**：浏览器内部直接消费资源（执行、渲染），JS不读取响应体 → **不需要CORS，可以CDN跨域加载**
2. **fetch / XMLHttpRequest**：JS代码想要拿到响应数据给JS变量使用 → **触发同源策略，需要CORS**

## 4. 那CDN服务器要不要配置CORS？

两种情况：

1. 仅 `<script src>`、`<img src>`、`<link>` 普通引用：**不需要CORS头，正常工作**
2. 需要JS读取资源内容时，就必须CORS：
   - canvas绘制CDN图片
   - fetch获取CDN上的js/css文本
   - script加crossorigin想要捕获完整错误堆栈

> 很多公有CDN（七牛、阿里云CDN）可以开启自动添加CORS响应头。

## 5. 补充：为什么浏览器要做这个设计？

早期网页：允许引入第三方脚本、广告图片、CDN库，这是网页基础能力，不能一刀切全部禁止跨域资源。
但是要防止：恶意网站JS读取你内网接口、读取第三方返回的敏感数据，所以**只限制JS读取响应，不限制资源渲染执行**。

## 总结表格

| 方式                    | 是否跨域 | 是否触发跨域限制 | 要求                                           |
| ----------------------- | -------- | ---------------- | ---------------------------------------------- |
| `<script src="cdn">`    | 是       | ❌不拦截         | 不需要CORS；拿完整堆栈需要crossorigin属性      |
| `<link href="cdn.css">` | 是       | ❌不拦截         | 不需要CORS                                     |
| `<img src="cdn.png">`   | 是       | ❌不拦截         | 不需要CORS；canvas使用图片需要CORS+crossOrigin |
| `fetch(cdn地址)`        | 是       | ✅拦截           | CDN必须返回CORS响应头                          |

## 高频面试一句话答案

> 同源策略限制的是**JS脚本读取跨域的响应数据**，并不是禁止浏览器加载跨域资源。CDN通过script、link、img等HTML标签引入资源，浏览器直接解析执行资源，JS不去读取HTTP响应体，所以不受跨域限制；
> 如果通过fetch/xhr去请求CDN资源，JS要读取返回内容，此时依然需要CORS。

> 延伸坑：CDN脚本跨域，不配置crossorigin，window.onerror捕获只会得到 `Script error.`，拿不到真实堆栈，前端监控经常踩这个坑。
