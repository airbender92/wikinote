# 面试题：网页加载进度条实现方式

> 页面顶部那种蓝色进度条（NProgress效果），面试常问，分**模拟伪进度**、**真实进度**两类，讲原理、优缺点、适用场景

## 场景说明

网页加载进度条两种思路：

1. **伪进度条（模拟）**：NProgress 主流方案，**没有真实百分比，只是模拟动画**。
2. **真实进度条**：基于真实资源加载事件，计算真实加载百分比。

---

## 方案1：模拟进度条（NProgress，业务最常用）

### 原理

并不是真实统计资源加载，用**动画模拟进度**。

- 页面开始加载：进度条从0开始慢慢增长，小幅度递增，不会走到100%；
- 页面 `DOMContentLoaded` / `load` 事件触发，直接跳到100%然后消失。

简单手写伪代码：

```
// 开始，进度走到30%
nprogress.start()
// 中间缓慢自动涨，比如到 60、85，不再继续
// 页面全部加载完成
window.addEventListener('load', ()=>{
  nprogress.done() // 直接到100%，隐藏
})
```

> 为什么中间不直接到100？防止页面还没渲染完进度条就走完，给用户“正在加载”心理反馈。

✅优点：

- 实现简单，兼容性好；
- 不用统计资源，性能好；
- 路由切换（SPA Vue/React）也可以用：路由beforeEach start，afterEach done。

❌缺点：
**不是真实进度，数值是假的**，网络慢的时候进度条走到85%卡住不动，用户体验上依然可用。

> SPA单页应用大多用这个，路由跳转也展示进度条。

### SPA路由使用场景

Vue示例：

```
router.beforeEach((to,from,next)=>{
  NProgress.start()
  next()
})
router.afterEach(()=>{
  NProgress.done()
})
```

## 方案2：基于真实资源的进度条（真实百分比）

原理：监听页面所有资源加载，统计已加载资源数量 / 总资源数量，算出真实进度。

1. 获取页面需要加载资源：`document.images`、script、link、css等；
2. 记录**资源总数量 total**；
3. 每个资源监听 `onload` / `onerror`，每完成一个计数+1；
4. 进度 = `loadedCount / total *100%`；
5. window load事件代表全部完成，置100%。

```
// 伪代码
const resources = [...document.images, ...document.querySelectorAll('script,link')]
const total = resources.length
let loaded = 0
resources.forEach(item=>{
  item.onload = item.onerror = ()=>{
    loaded++
    const percent = (loaded / total)*100
    updateProgressBar(percent)
  }
})
window.addEventListener('load',()=> updateProgressBar(100))
```

✅优点：进度是真实的。
❌缺点：

1. **缺陷很大**：动态创建的资源（js动态创建img、fetch请求）统计不到；
2. 接口请求、异步数据拿不到，无法计入进度；
3. 早期DOM还没解析完，拿不到全部资源列表；
4. SPA基本不适用。

> 适合传统多页MPA静态页面，SPA几乎不用。

## 方案3：Fetch / XMLHttpRequest 封装接口进度（下载大文件接口进度）

如果要展示**接口请求的下载进度**，使用 `xhr.onprogress` / fetch ReadableStream。

```
xhr.onprogress = function(e){
  if(e.lengthComputable){
    const percent = e.loaded / e.total * 100
  }
}
```

👉 这个只能用于单个ajax/大文件下载，**不能代表整个网页加载进度**。

## 坑点总结

1. **SPA单页应用**：页面已经加载完毕，切换路由只是组件加载，没有浏览器load事件，只能用模拟进度条(NProgress)。
2. 伪进度条为什么卡在85%左右不继续：模拟策略，避免还没完成就100%。
3. 真实进度无法包含异步接口请求，这是浏览器API限制。

## 手写极简模拟进度条CSS+JS（理解原理）

```
#progress-bar{
  position: fixed;
  top:0;
  left:0;
  height:3px;
  background:#409eff;
  width:0;
  transition: width 0.3s ease;
  z-index:9999;
}
```

```
<div id="progress-bar"></div>
```

```
const bar = document.getElementById('progress-bar')
// 模拟增长
function start(){
  bar.style.width = '0%'
  let timer = setInterval(()=>{
    let w = parseFloat(bar.style.width) || 0
    // 慢慢增加，但不超过85
    if(w <85){
      w += Math.random()*3
      bar.style.width = w+'%'
    }
  },200)
  window._progressTimer = timer
}
function done(){
  clearInterval(window._progressTimer)
  bar.style.width = '100%'
  setTimeout(()=> bar.style.width='0%',300)
}

// 使用
start()
window.addEventListener('load',done)
```

# 🎤面试口述1分钟精简版

网页加载进度条主要两种实现。

第一种是**模拟伪进度，代表库NProgress，项目最常用**。并不是真实统计资源，页面开始时进度条缓慢增长，一般到85%左右停止，等页面load事件完成直接拉满100%消失。SPA单页应用路由切换也可以使用，在路由守卫里控制start和done。缺点是百分比是模拟的，不是真实加载数值。

第二种是真实资源进度条，统计页面图片、脚本、样式标签资源，监听onload事件，用已加载/总资源计算真实百分比。但缺点是统计不到动态创建资源和接口请求，SPA场景不适用。

另外针对单个接口、大文件下载，可以通过xhr的onprogress事件拿到下载真实进度。
实际开发中，H5和后台系统绝大多数情况使用模拟进度条方案。

## 面试官高频追问

1. SPA为什么不能用真实页面进度条？

> SPA页面整体资源已经初始化加载完成，路由切换只是组件、接口请求，没有浏览器级别的load事件，DOM资源列表不会刷新，拿不到路由对应的资源，所以只能模拟。

2. NProgress进度条中间为什么不会走到100？

> 为用户心理感知，防止业务还没渲染完成进度条就结束，等到真正完成再直接置100。
