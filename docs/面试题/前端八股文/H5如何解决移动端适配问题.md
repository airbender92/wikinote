# 面试题：H5移动端适配方案

> 面试口述版，讲清楚几种主流方案、优缺点、适用场景，以及现在项目实际怎么做

## 常见适配要解决的问题

1. 手机屏幕尺寸、分辨率五花八门；
2. 不同设备dpr（设备像素比），1px边框模糊；
3. 字体、元素在大小屏上按比例缩放；
4. 兼容iOS、安卓不同浏览器；
5. 防止页面缩放、双击放大等问题。

### 第一步：基础meta标签（必须写）

```
<meta name="viewport" content="width=device-width, initial-scale=1.0, maximum-scale=1.0, minimum-scale=1.0, user-scalable=no">
```

- `width=device-width`：视口等于设备屏幕宽度
- 禁止用户缩放，避免布局错乱>

> 注意：部分现代项目不再写`user-scalable=no`， accessibility无障碍要求允许缩放。

---

## 方案1：rem 适配（旧项目常用，阿里flexible方案）

原理：**rem 相对于根元素html的font‑size**。根据屏幕宽度动态修改 html 的font‑size，页面所有尺寸用rem，实现整体等比缩放。

flexible核心逻辑：

1. js 获取屏幕宽度，设置html的font‑size；一般把屏幕分成10份，`fontSize = document.documentElement.clientWidth / 10`
2. UI给设计稿（比如750px），开发把px换算成rem。
3. 解决1px边框：dpr>1设备，缩放viewport。

**缺点**

- 需要JS执行，页面刚出来一瞬间会有闪烁（FOUC）；
- 安卓部分机型有兼容坑；
- 现在逐渐被vw/vh替代。

## 方案2：vw/vh 视口单位（现在主流推荐）

- `vw`：视口宽度，`1vw = 视口宽度的1%`
- `vh`：视口高度，`1vh = 视口高度的1%`

750设计稿换算示例：
设计稿元素宽度150px → `150 / 750 * 100 = 20vw`

工程里一般用postcss‑px‑to‑vw插件，写px自动转vw，不用手动算。

✅优点：

1. CSS原生，**不需要JS**，无闪烁；
2. 简单，配合设计稿直接转换；

❌缺点：

1. 小屏幕/超大屏幕会无限缩放，元素会变得过小或过大；
   👉解决：外层套一层`max-width`最大限制，比如`max-width:750px;margin:0 auto;`大屏下居中固定宽度，不再继续放大。

> 现在Vue、React H5项目大多用 vw + postcss‑px‑to‑vw。

## 方案3：rem + vw混合（过渡方案）

html的font‑size用vw设置，不用JS：

```
html { font-size: 10vw; }
```

之后继续写rem，兼顾老代码。

## 方案4：响应式媒体查询 @media

针对特定屏幕区间，修改样式、字体、布局。
适合：简单页面、需要布局发生改变（不是单纯缩放），比如小屏改成单列，大屏多列。
不适合整个页面全部靠媒体查询做尺寸适配，维护成本太高。

## 方案5：固定布局（定宽布局）

设置页面最大宽度，比如`max‑width:750px`，居中，两边留白。
电商活动页经常这么做，大屏不会无限放大，体验稳定。

# 重点问题：移动端1px边框模糊问题

原因：手机dpr=2，1css像素对应2个物理像素，直接写`border:1px`实际占2物理像素，边框变粗。

解决办法：

1. transform scale(0.5) 缩放；
2. 使用伪元素 + transform；
3. postcss插件自动处理；>

> vw方案下依然会遇到1px问题，需要单独处理。

## 其他移动端兼容坑

1. **字体**：不用小于12px字体；优先系统无衬线字体 `font-family: -apple-system, BlinkMacSystemFont, sans-serif;`
2. **点击300ms延迟**：旧浏览器双击缩放导致，设置viewport禁止缩放就可以消除；现在现代浏览器已废弃。
3. **弹性布局flex**：移动端优先用flex、grid，少用固定px；
4. 图片适配：图片用`max‑width:100%;height:auto;`，使用webp，不同分辨率用srcset做高清图；
5. iOS回弹滚动、overflow滚动，加 `-webkit‑overflow‑scrolling: touch;`；
6. 安全区适配（iPhone底部小黑条）：

```
padding-bottom: env(safe-area-inset-bottom);
```

# 🎤面试口述1分钟精简版

H5移动端适配，首先配置正确的viewport元标签。
现在项目主流使用**vw/vh视口单位**，配合postcss‑px‑to‑vw插件，直接写设计稿px自动转vw，不需要JS。为了防止大屏页面无限放大，外层设置max‑width做最大宽度限制，大屏居中留白。
老项目会用rem，通过JS动态修改html根字体大小实现适配，但存在闪屏问题。
同时处理1px边框模糊、iPhone安全区、图片自适应等问题。
布局上多用flex弹性布局，必要时配合media媒体查询，在不同屏幕下调整布局。
