# 面试题：图片懒加载实现方式

> 面试高频，3种主流方案：原生IntersectionObserver、scroll事件监听、background‑image懒加载，讲原理、优缺点、适用场景

## 什么是图片懒加载

**不把视口外的图片加载出来，只有图片即将进入可视区域才去加载图片**，减少首屏请求数量，优化首屏加载性能。

原理：

1. 不直接写 `src`，把真实图片地址存自定义属性 `data‑src`；
2. 图片进入视口，把 `data‑src` 的值赋值给 `src`，浏览器才发起网络请求加载图片。

html示例：

```
<img class="lazy" data-src="real.jpg" src="placeholder.png">
```

## 方案1：scroll 事件监听（传统方案，兼容老浏览器）

### 原理

1. 监听 `scroll`、`resize`、`orientationchange` 事件；
2. 通过 `getBoundingClientRect()` 获取图片元素位置；
3. 判断图片是否进入视口：`el.getBoundingClientRect().top < window.innerHeight`；
4. 满足条件，把`data‑src`赋值给`src`。

**问题**

- scroll事件高频触发，频繁执行JS，容易造成页面卡顿；
  ✅优化手段：**节流（throttle）**，限制函数执行频率，减少计算。

❌缺点：

- 需要自己做节流；
- 滚动事件会占用主线程；
- 计算有精度问题；
  ✅优点：兼容性极好，兼容低版本浏览器。

## 方案2：IntersectionObserver 交叉观察器⭐现代主流（推荐）

浏览器原生API，**异步，不阻塞主线程**，专门监听元素是否进入视口。

### 原理

创建观察器，观察所有 `.lazy` 图片；当图片和视口发生交叉（进入可视区域）触发回调，加载图片。

```
const observer = new IntersectionObserver((entries)=>{
  entries.forEach(item=>{
    if(item.isIntersecting){ // 进入视口
      const img = item.target
      img.src = img.dataset.src
      observer.unobserve(img) // 加载完取消观察，释放内存
    }
  })
})
// 给所有懒加载图片开启观察
document.querySelectorAll('.lazy').forEach(img=> observer.observe(img))
```

还可以配置 `rootMargin`，提前加载：

```
new IntersectionObserver(callback, { rootMargin: "200px 0px" })
```

> 距离视口还有200px就提前加载，用户滚动过来图片已经加载完成，体验更好。

✅优点：

1. **异步，不在主线程执行，性能好，不需要节流**；
2. API简洁，代码量少；
3. 支持设置预加载偏移rootMargin。

❌缺点：不支持IE，需要polyfill兼容。

> Vue/React项目、现在绝大多数业务都用这个方案。

## 方案3：CSS背景图懒加载

背景图`background‑image`不能用src，思路：
真实图片地址存`data‑bg`，元素进入视口后 JS设置 `element.style.backgroundImage = url(xxx)`。

## 方案4：原生属性 loading="lazy"（浏览器原生懒加载）

```
<img src="xxx.jpg" loading="lazy" alt="">
<iframe src="xxx" loading="lazy"></iframe>
```

浏览器原生支持，一行属性搞定。

✅优点：零JS，最简单。
❌缺点：

1. **浏览器控制权，开发者无法干预**，不能控制提前加载距离；
2. 兼容性有限，部分老浏览器不识别；
3. 图片必须使用src，首屏会有标记；
4. 对背景图无效；>

> 适合简单静态页面，复杂业务一般不直接依赖它。

## 额外：Vue/React中懒加载图片

1. Vue：自定义指令 v‑lazy，内部封装IntersectionObserver；
2. React：封装高阶组件/hooks，使用IntersectionObserver；
3. UI库一般自带图片懒加载组件。

## 坑点&注意事项

1. **图片一定要设置宽高**，否则getBoundingClientRect拿不到正确高度，全部图片会被判定进入视口，全部一次性加载。
2. 占位图：可以放低质量模糊占位图、透明占位图。
3. 图片加载失败，设置error兜底。
4. 图片销毁时，要取消观察 `unobserve`，防止内存泄漏。
5. IntersectionObserver 观察的元素不能是display:none，会不触发。

# 🎤面试口述1分钟精简版

图片懒加载目的是延迟加载视口外图片，减少首屏网络请求，提升页面性能。

一共有几种实现方式。
第一种传统方案，监听scroll事件，配合getBoundingClientRect判断元素位置，需要做节流优化，缺点是scroll高频触发占用主线程，优势是兼容性好。

第二种是IntersectionObserver交叉观察器，现在主流方案，浏览器原生异步API，不阻塞主线程，不需要节流，还可以通过rootMargin实现提前预加载，元素进入视口回调中赋值真实图片地址；加载完成取消观察释放内存，缺点IE需要polyfill。

第三种是浏览器原生属性 loading="lazy"，无需JS，但无法控制加载时机，灵活性差。

背景图懒加载通过data属性存储地址，进入视口修改backgroundImage。
开发中注意图片需要设置宽高，防止判断失效，组件销毁要取消观察避免内存泄漏。

## 面试官高频追问

1. IntersectionObserver 和 scroll监听的区别？

> scroll：主线程同步执行，需要节流；IntersectionObserver浏览器异步，不占用主线程，性能更好。

2. rootMargin作用？

> 设置视口偏移，图片还没滚动到可视区域，提前一段距离就加载图片，优化用户滚动体验。

3. 如果图片容器display:none，懒加载会失效吗？

> 是的，IntersectionObserver不会触发，getBoundingClientRect top为0，会直接加载。

4. 为什么图片要指定宽高？

> 如果没有宽高，图片占位高度为0，会被判定已经进入视口，所有图片一次性全部加载，懒加载失效。
