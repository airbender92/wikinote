# Git：多次提交压缩成一次（squash）

场景：本地已经多次 commit，想把一堆小提交合并成**1个干净的 commit**，再推远程。

> ⚠️ 注意：**已经 push 到远程的提交不要随便 rebase，会改写历史，团队共用分支慎用！只处理还没推送的本地提交。**

## 方式1：交互式rebase（最常用）

假设要把**最近 N 次提交压缩成1次**，比如最近 4 次 commit：

```bash
git rebase -i HEAD~4
```

执行后会弹出编辑器：

```
pick abc111 feat: 提交1
pick def222 feat: 提交2
pick ghi333 feat: 提交3
pick jkl444 feat: 提交4
```

把除**第一行保留 pick**，剩下所有 `pick` 改成 `squash`（简写 `s`）

```
pick abc111 feat: 提交1
s def222 feat: 提交2
s ghi333 feat: 提交3
s jkl444 feat: 提交4
```

保存退出（vim：`Esc` → `:wq`）。
接着会弹出编辑框，编辑**合并之后新的commit注释**，删掉旧的，写一条新描述，保存退出。

✅ 完成：4次提交合并成1次。

> 如果已经推过远程，强制推送（**私有分支才用，公共分支禁止**）

```bash
git push -f origin 你的分支名
```

## 方式2：reset 软重置（更简单，适合全部本地提交合并）

把当前分支回到 N 个提交之前，**保留代码改动，清空提交记录，重新一次性commit**

示例：合并最近3次提交

```bash
# 软重置，代码不动，回退commit指针
git reset --soft HEAD~3

# 现在所有改动都在暂存区，重新提交一次
git commit -m "feat: 合并后的完整功能"
```

优点：简单；缺点：会丢掉所有旧commit message，只能写一条新注释。

## 方式3：合并其他分支的多个提交到当前分支

比如把 `dev` 分支全部提交压缩合并到当前分支：

```bash
git merge --squash dev
git commit -m "feat: 合并dev分支全部改动"
```

> `--squash`：把dev分支所有变更拿过来，**不携带dev的commit历史**，只生成一堆修改，需要手动commit。

---

# 关键避坑

1. **公共/多人协作分支，禁止 rebase + push -f**，会导致别人本地历史错乱；只用于自己私有特性分支。
2. rebase 过程冲突：解决冲突后 `git add .`，然后 `git rebase --continue`；想放弃：`git rebase --abort`
3. `HEAD~n`：`HEAD~4` 代表最近4笔提交（不包含HEAD本身）。
4. 如果提交已经推送到远程公共分支：不要压缩，直接新增提交即可。

## 快速记忆

- 想保留旧commit信息参考：`git rebase -i HEAD~N`，后面改为`s`
- 不在乎旧日志，只想合并代码：`git reset --soft HEAD~N` + 新commit
- 合并别的分支不要历史：`git merge --squash 分支名`
