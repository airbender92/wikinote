# 函数式编程 FP（Functional Programming）

> 函数式编程是一种**编程范式**，和面向对象OOP、命令式编程并列。
> 核心思想：**把计算看作函数的组合，尽量使用纯函数，避免可变状态、副作用**。
> 代表语言：Haskell、Scala；JS、Java8+、Python、Go都支持函数式特性，但不是纯函数式语言。

## 核心概念

### 1. 纯函数 Pure Function（最重要）

两个条件：

1. **相同输入，永远得到相同输出**，不依赖外部变量
2. **没有副作用**：不修改外部变量、不操作DOM、不请求接口、不读写文件、不打印日志

✅纯函数示例

```
// 纯函数，只依赖入参
function add(a,b){
  return a + b
}
```

❌非纯函数（有副作用/依赖外部）

```
let x = 10
function add(b){
  return x + b // 依赖外部变量，x变结果就变
}
function setName(obj){
  obj.name = "xxx" // 修改传入对象，副作用
}
```

> 纯函数好处：可预测、方便单元测试、可缓存、可并行。

### 2. 函数是一等公民（一等函数 First‑class Function）

函数可以：

- 赋值给变量
- 作为参数传给另一个函数（高阶函数）
- 作为返回值返回
- 存进数组、对象

JS天生支持：

```
const fn = ()=>{}
function hof(cb){ return cb }
```

### 3. 高阶函数 Higher‑order function

**参数是函数，或者返回值是函数**。
常见：`map`、`filter`、`reduce`、`compose`、`curry`

```
// 高阶函数，接收函数做参数
const arr = [1,2,3]
arr.map(x => x*2)
```

### 4. 不可变性 Immutability

**数据一旦创建，就不能修改，修改就返回一份新数据，不改动原数据**。
禁止直接修改对象、数组。

```
// 不推荐（可变，修改原数组）
const arr = [1,2,3]
arr.push(4)

// 函数式：返回新数组
const newArr = [...arr,4]
```

> React、Redux大量强调不可变，就是函数式思想。

### 5. 柯里化 Currying

把**多参数函数拆解成一系列单参数函数**，逐步传参。

```
//普通
function add(a,b){return a+b}

//柯里化
const curryAdd = a => b => a + b
add(1)(2) //3
```

作用：参数复用、延迟执行。

### 6. 函数组合 Compose / Pipe

把多个函数拼接，一个函数输出作为下一个函数输入。

- `compose`：**从右往左执行**
- `pipe`：**从左往右执行**

```
const f = x=>x+1
const g = x=>x*2
// pipe：先f再g
const pipe = (...fns)=>val=> fns.reduce((v,fn)=>fn(v),val)
pipe(f,g)(1) // (1+1)*2 =4
```

### 7. 闭包 Closure

函数记住定义时的作用域，配合高阶函数、柯里化大量使用。

### 8. 声明式编程 vs 命令式编程

- **命令式**：告诉计算机“怎么做”，写循环、步骤，关注过程

```
//命令式
let res = []
for(let i=0;i<arr.length;i++){
  res.push(arr[i]*2)
}
```

- **声明式（函数式推崇）**：告诉计算机“要什么”，不关心过程

```
const res = arr.map(x=>x*2)
```

### 9. 副作用 Side Effect

凡是函数对外界产生影响：修改全局变量、网络请求、DOM操作、IO、console.log。

> 函数式不是完全禁止副作用，而是**把副作用隔离到最外层**，核心业务逻辑全部用纯函数。

## JS里常用函数式API

`map`、`filter`、`reduce`、`every`、`some`、`find`

> 注意：`splice/push/pop`会改变原数组，属于可变方法，不符合函数式。

## 函数式编程优缺点

✅优点

1. 代码简洁，声明式，可读性好
2. 纯函数易于单元测试，无依赖
3. 不可变数据，减少bug，并发场景安全（没有共享变量修改冲突）
4. 函数可复用、可组合

❌缺点

1. 大量函数嵌套，容易出现回调地狱（可通过compose优化）
2. 频繁生成新对象，有一定性能开销；大对象要注意
3. 学习成本高，思维需要从命令式转换

## 面试高频问答

### Q：纯函数有什么好处？

1. 输出稳定，相同输入一定相同输出
2. 无副作用，测试简单，不需要mock外部环境
3. 可做记忆缓存（memo）
4. 多线程/并发安全，不存在共享变量修改问题

### Q：柯里化的用途？

- 参数复用；延迟计算；函数式组合。

### Q：compose和pipe区别

- compose：从右向左执行
- pipe：从左向右执行

### Q：函数式和面向对象区别

- OOP：封装状态，对象+方法，靠修改对象状态完成业务
- FP：尽量消除可变状态，靠函数转换数据，不修改原始数据
