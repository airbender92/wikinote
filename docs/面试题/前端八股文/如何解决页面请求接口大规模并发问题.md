# 面试题：如何解决页面接口大规模并发问题

> 适合后端/全栈面试，分为：前端节流防抖、网关层、应用服务层、缓存层、数据库层、架构手段、限流降级熔断保护，同时讲风险和兜底，可直接口述。

## 一、前端层面（挡掉无效请求，减少后端压力）

1. **防抖、节流**
   搜索框输入、频繁点击，用防抖，等输入停止再发请求；按钮做防重复点击，短时间禁止重复提交，避免用户重复触发大量请求。
2. **页面缓存**
   对不频繁变更的数据做前端本地缓存(localStorage/sessionStorage)，减少重复调接口；合理使用浏览器HTTP缓存（Cache‑Control、ETag）。
3. **合并请求**
   多个小请求合并成批量接口，减少网络IO；避免循环里串行大量调用接口。
4. **分页、懒加载**
   列表不一次性拉全量数据，分页/滚动懒加载，防止一次性大查询带来并发压力。

> 注意：前端只能减少无效请求，**不能作为安全防护，并发攻击依旧要靠后端防护**。

## 二、网关层（Nginx / Spring Cloud Gateway）

最外层第一道屏障

1. **限流**：IP限流、QPS限流，限制单IP单位时间请求数，拦截恶意高频访问。
2. **黑名单**：封禁异常IP。
3. **静态资源代理**：静态资源不走后端服务，由网关直接返回。
4. 请求过滤，非法参数直接在网关拒绝，不转发到业务服务。

## 三、应用服务层

1. **限流、熔断、降级**（Sentinel / Hystrix）

- **限流**：限制接口QPS、线程数，超过阈值直接返回友好提示，防止服务被打垮。
- **熔断**：下游依赖数据库/第三方大量超时失败，触发熔断，快速失败，避免连锁雪崩。
- **降级**：高并发下，关闭非核心接口，优先保证核心业务可用，返回兜底数据。

2. **异步处理**
   非实时业务，不要同步阻塞；使用消息队列（RocketMQ/Kafka）异步削峰。

> 例如提交订单：前端提交，服务接收后丢MQ，立刻返回成功；消费端慢慢执行业务逻辑，避免同步大量阻塞。
> 注意：异步要处理消息丢失、重复消费、幂等。

3. **接口幂等性**
   高并发重复请求，不会产生脏数据。方案：token、唯一业务编号、数据库唯一索引。

## 四、缓存层（扛大部分读请求，减少DB压力）

高并发大多是读多写少，**缓存是最有效的手段**

1. Redis做热点数据缓存，把高频查询结果放缓存，请求优先读缓存，不访问数据库。
2. 缓存问题处理：

- **缓存穿透**：查询不存在的数据，直接打数据库。解决方案：缓存空值、布隆过滤器。
- **缓存击穿**：热点key过期，大量请求同时打到DB。解决方案：互斥锁、热点key永不过期。
- **缓存雪崩**：大量key同时过期 / Redis宕机，大量请求压数据库。解决方案：过期时间加随机偏移、Redis集群高可用、多级缓存。

多级缓存：本地Caffeine缓存 + Redis远程缓存，优先读本地缓存，进一步降低Redis压力。

## 五、数据库层（数据库是最大瓶颈）

1. **索引优化**：合理建立索引，避免慢SQL，防止一条SQL拖垮整个库。禁止大查询、select *。
2. **读写分离**：写走主库，大量读请求分发到从库，分担主库压力。
3. **分库分表**：数据量极大时，水平分表，分散单表数据，降低单表并发压力。
4. **数据库连接池控制**：合理设置最大连接数，防止连接被打满。
5. 禁止事务过大，缩短事务执行时间，减少锁等待。

## 六、架构层面扩容

1. **水平扩容**：业务服务无状态，多实例部署，通过网关负载均衡分摊并发流量。无状态非常关键，会话放到Redis，不要存服务内存。
2. Redis集群：主从、哨兵、集群模式，保证缓存高可用。

## 七、兜底保障

1. 压测：上线前做压力测试，测出系统QPS瓶颈，提前预估并发水位。
2. 监控告警：接口QPS、错误率、Redis指标、数据库CPU/连接数，指标异常及时告警。
3. 灰度发布，故障具备回滚能力。

# 🎤面试口述1分钟精简版（直接背诵）

面对接口大规模并发，我会从前端、网关、服务、缓存、数据库全链路处理。

首先前端通过防抖节流、合并请求、缓存减少无效请求，但前端不能信任。
在网关层做IP限流，拦截恶意流量。
业务服务层使用Sentinel做限流熔断降级，保护核心接口；非实时场景引入消息队列异步削峰，同时保证接口幂等，避免重复请求造成脏数据。

读请求优先走多级缓存，解决缓存穿透、击穿、雪崩问题，尽量少访问数据库。
数据库侧优化索引，做读写分离，数据量大时分库分表，控制事务粒度。
业务服务无状态，支持水平扩容提升整体吞吐量。
同时配合压测、监控告警，出现异常可以降级兜底，保障系统不会雪崩。
