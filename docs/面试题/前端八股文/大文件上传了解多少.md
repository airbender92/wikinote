# 面试题：大文件上传

> 面试高频，核心方案：**分片上传 + 断点续传 + 秒传**，讲清原理、流程、问题、后端处理，可直接口述

## 为什么普通上传不行

大文件直接一次性上传：

1. 网络差容易中断，失败要全部重传，体验差
2. 请求体过大，网关、Nginx会限制请求大小，直接报错
3. 占用大量内存，后端一次性读整个文件，容易OOM

所以主流方案：**前端切片，分块上传**

## 核心方案：分片上传（切片上传）

### 整体流程

1. **前端对文件切片**
   把大文件按照固定大小切割（比如5MB一块），File + Blob API，切割成一个个小的chunk分片。

2. **计算文件唯一标识（MD5）**
   对整个文件做md5哈希，作为文件唯一id。

> 用途：做**秒传**、断点续传标记。

3. **并发上传各个分片chunk**
   多个分片并行请求后端，每个请求携带：文件md5、当前分片序号、分片二进制数据、总分片数量。

> 前端控制并发数，不能无限并发，防止浏览器请求超限。

4. **后端接收分片**
   后端不直接合并，先把每一块分片临时存到磁盘/对象存储，记录：文件md5、已上传分片编号。

5. **前端全部分片传完，发送合并请求**
   通知后端：所有分片上传完毕，请合并。
   后端校验所有分片是否齐全，按序号顺序拼接合并成完整文件；合并完成删除临时分片。

### 断点续传

场景：上传中途断网、刷新页面，不需要从头重传。

1. 上传前，前端拿文件MD5调用接口，查询后端**哪些分片已经上传成功**。
2. 只上传缺失的分片，跳过已经上传完成的分片，实现断点续传。

### 秒传

上传之前，用文件MD5去后端查询。

- 如果服务器已经存在相同md5的完整文件 → 直接返回上传成功，**不用传任何数据**，实现秒传。
  适合重复上传相同文件场景。

## 前端关键点

1. 使用 `File.slice()` 切割文件；
2. 计算文件MD5：大文件不能一次性读全部，使用**SparkMD5分片计算哈希**，避免内存爆掉；
3. 控制并发上传数量，避免浏览器6个请求上限占满，页面其他接口阻塞；
4. 支持暂停、继续上传；
5. 展示真实上传进度；
6. 异常重试：单个分片失败自动重试。

## 后端关键点

1. **不要把分片全部读到内存**，流模式写入磁盘，防止OOM；
2. 维护分片上传记录：Redis存md5‑已上传分片集合；
3. 分片临时文件要设置过期清理，防止磁盘占满；
4. 合并分片：按顺序读取各个临时分片流，拼接输出完整文件；
5. 校验：合并完成校验完整文件md5，防止文件损坏；
6. 限制单分片大小，防止恶意分片攻击。

> 生产环境一般不自己写本地磁盘存储，对接OSS、MinIO对象存储，对象存储本身支持分片上传API。

## 遇到的问题&解决方案

1. **分片上传后合并很慢**
   文件特别大，后端同步合并会超时。
   👉 方案：合并改成异步，前端轮询查询合并状态，或者直接使用对象存储的分片能力。

2. **临时分片堆积占满磁盘**
   👉 Redis设置过期时间，定时任务清理过期未完成的分片。

3. **网络抖动，部分分片上传失败**
   👉 前端对失败分片重试，限制重试次数。

4. **MD5计算大文件卡顿**
   👉 使用web‑worker，把md5计算放到子线程，不阻塞UI主线程。

5. 并发上传同一个文件，重复分片
   👉 后端做幂等，同一个md5+分片序号只存一份。

## 口述1分钟面试简短版

> 大文件直接上传容易受网关大小限制，网络中断需要全部重传，还会造成后端内存溢出。主流是分片上传方案。
> 前端利用Blob对大文件切分成多个小分片，通过SparkMD5计算整个文件的唯一哈希值。上传前先请求后端，判断是否可以秒传，或者哪些分片已经上传，实现断点续传。
> 控制分片并发数，逐个上传分片；后端接收分片保存临时文件，用Redis记录哪些分片已经上传。
> 全部分片上传完成后，调用合并接口，后端按顺序拼接分片生成完整文件，并且校验文件完整性。
> 分片临时文件需要定时清理避免磁盘占用，MD5计算放在WebWorker避免阻塞页面。实际项目一般直接使用对象存储的分片能力，减少自己维护分片合并的成本。

## 面试官高频追问

1. MD5计算大文件会不会卡顿？怎么优化？

> 答：会，大文件一次性读取会占内存。使用SparkMD5分片增量计算md5，并且放到WebWorker子线程，不阻塞主线程。

2. 分片上传，后端合并大文件超时怎么办？

> 改为异步合并，前端轮询任务状态；优先使用OSS/MinIO原生分片接口，不需要业务服务做合并。

3. 什么是秒传、断点续传，区别？

> 断点续传：中断后只传缺失分片；秒传：服务器已有相同文件，完全不用传数据。

4. 分片大小设置多少合适？
   一般 2‑10MB；分片太小会请求太多，分片太大断点续传粒度粗。
