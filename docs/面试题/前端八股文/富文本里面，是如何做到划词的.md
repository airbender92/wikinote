# 富文本划词原理

富文本（`contenteditable="true"` / 富文本编辑器如WangEditor、Quill、Slate）里面的**划词（鼠标拖动选中一段文字）**，底层依然是浏览器原生 **Selection + Range API**，但富文本比普通DOM文本复杂很多，因为内部DOM是碎片化的。

> 普通网页文本：文本在单一Text节点；
> 富文本：一段视觉连续文字，DOM可能被拆成多个`<span>\`\`<b>\`\`<i>`文本节点。
> 视觉上连续选中，底层跨多个DOM文本节点，靠 **Range** 记录选区起点、终点。

## 两个核心对象

1. **Selection（选区）**：全局，代表用户当前页面选中的**整体状态**，`window.getSelection()`
   - 一个页面同一时间只能有一个Selection
   - 可以包含1个或多个Range，富文本一般只有1个range
2. **Range（范围）**：真正记录选中的**精确位置**：哪个节点、偏移多少字符。```
   const sel = window.getSelection()
   const range = sel.getRangeAt(0) // 获取第一个选区范围

```

### Range 关键属性（划词核心）

```

range.startContainer // 选区开始的DOM节点（一般是Text文本节点）
range.startOffset // 开始节点内，第几个字符开始选中
range.endContainer // 选区结束DOM节点
range.endOffset // 结束节点内，第几个字符结束选中
range.toString() // 获取划词选中纯文本
range.commonAncestorContainer // 选区共同父节点

```

>
> 举例子：

```

<div contenteditable>Hello <b>World</b></div>
```

视觉选中 `llo Wor`，选中跨越了文本节点、`<b>`内部文本节点。
`startContainer` 是Hello后面的Text节点，`endContainer`是`<b>`里面的Text节点。
Range 会记录跨节点的起始/结束位置，**不需要DOM是同一个节点**，这就是富文本可以跨标签划词的根本。

## 富文本划词完整流程（用户操作）

1. 鼠标按下 `mousedown` 在富文本内部；浏览器记录起始位置，生成空Range。
2. 按住鼠标拖动 `mousemove`：浏览器不断修改Range的`endContainer / endOffset`，实时更新选区；页面出现蓝色选中背景。
3. 鼠标抬起 `mouseup`：划词完成。
4. 此时 `window.getSelection()` 拿到选区，Range保存跨节点的选中信息。
5. 事件：**`selectionchange`**，选区变化就触发，富文本编辑器大量监听这个事件。

> ⚠️富文本编辑器**不会自己实现鼠标拖动选字**，划词能力本身是浏览器原生提供。
> 编辑器做的是：读取/保存/修改浏览器原生Range，基于选区做：加粗、斜体、高亮、插入链接、右键菜单。

## 编辑器拿取划词选区做操作举例

比如选中文字点击【加粗】按钮：

```
// 1.拿到用户划词选区
const sel = window.getSelection()
if(!sel.rangeCount) return
const range = sel.getRangeAt(0)

// 2.把range包裹的文本，包裹 <strong>标签
const strong = document.createElement('strong')
range.surroundContents(strong) // range原生API，把选中内容包裹进元素
```

`surroundContents` 就是利用Range，直接把跨节点选中内容包裹标签，实现加粗。

## 富文本和普通页面划词的差异点

1. **DOM碎片化**
   富文本一段文字拆很多`<span>\`\`<b>\`\`<i>`，视觉连续，DOM分裂。普通DOM简单文本只有一个Text节点。
   Range专门设计用来处理**跨节点选区**，所以依然可以正常划词。
2. contenteditable 会修改浏览器行为
   设置 `contenteditable="true"`，浏览器允许光标定位到文本节点之间，允许拖动选择，允许修改DOM。
3. 选区丢失问题（富文本最大坑）

> 当你点击工具栏按钮，**富文本容器失去焦点，Selection选区会被浏览器清空，Range丢失**！
> 这是富文本最经典bug：选中文本，点按钮，选区没了，操作失效。

**解决方案：执行按钮操作前，把Range克隆保存到变量**

```
// 点击加粗按钮
let savedRange = null
// 编辑器失焦前，保存选区range副本
savedRange = window.getSelection().getRangeAt(0).cloneRange()

// 后续需要恢复选区
const sel = window.getSelection()
sel.removeAllRanges()
sel.addRange(savedRange) // 恢复之前划词选中的范围
```

> 几乎所有富文本库内部都有这段保存/恢复Range逻辑。

## Quill / WangEditor / Slate 各自怎么处理划词选区

1. **Quill**：封装了Selection模型，内部对原生Range做一层映射；不直接裸操作DOM range，做了归一化。
2. **WangEditor5**：基于原生contenteditable，大量使用原生Range/Selection，做选区保存恢复。
3. **Slate**：**不依赖浏览器原生Range做业务逻辑**。
   Slate把文档全部转为虚拟JSON模型；浏览器Selection只做视图展示；内部维护一套自己的selection模型，将浏览器Range和内部model互相转换。>

> Slate：浏览器选区只是UI，真实选区状态存在内存JSON中。

## 划词之后可以做什么（基于Range API）

1. 获取选中纯文本：`range.toString()`
2. 包裹标签：`range.surroundContents()`
3. 删除选中内容：`range.deleteContents()`
4. 在选区位置插入节点：`range.insertNode()`
5. 提取选中的DOM片段：`range.extractContents()`

## 常见坑

1. 编辑器失去焦点，原生Selection清空 → **提前cloneRange保存副本**。
2. 选区跨多个节点，不要直接操作 innerText，要用Range API，不要自己拼接字符串。
3. `selectionchange` 高频触发，编辑器要防抖。
4. 某些情况下Range会变成无效（DOM被删除），需要做range合法性判断。
5. iframe内富文本：父页面拿不到iframe内部Selection，必须在iframe文档内获取。

## 总结一句话

> 富文本划词**不是JS模拟鼠标拖动选字**，划词渲染蓝色选区是浏览器原生能力；
> 编辑器只是读取、克隆、修改浏览器提供的 **Selection + Range** 对象，来拿到选中范围、执行加粗/插入链接等操作；
> 最大难点：编辑器失焦选区丢失，需要手动克隆保存Range。
