# 前端国际化 i18n 实现方案

国际化（i18n）核心要处理：**多语言文本、日期、时间、数字、货币、时区、RTL从右到左布局**。
主流技术栈：Vue 用 `vue‑i18n`；React 用 `react‑i18next`；原生JS用 `i18next`。

> 核心思路：**把文案全部抽离成语言json资源文件，代码不写硬编码中文；运行时根据当前语言key读取对应文案**。

## 一、核心概念

1. **语言资源文件**
   `zh‑CN.json`、`en‑US.json`，key保持一致，value为对应语言文案。

```
// zh‑CN.json
{
  "welcome": "欢迎使用系统",
  "login": "登录",
  "msg": "你好，{name}"
}
// en‑US.json
{
  "welcome": "Welcome to system",
  "login": "Login",
  "msg": "Hello, {name}"
}
```

2. **插值**：文案里面变量占位符 `{name}`，代码传入变量渲染。
3. **语言切换**：切换语言key，更新页面文案（不需要刷新页面）。
4. **复数、性别**：比如 `1条消息 / 多条消息`，i18n库内置处理。
5. **数字/日期/货币**：使用浏览器原生 `Intl` API，不需要自己写格式化。

## 二、Vue3 + vue‑i18n@9（最常用）

### 1. 安装

```
npm install vue‑i18n@9
```

### 2. 目录结构

```
src
├── i18n
│   ├── index.js          # i18n初始化
│   └── locales
│       ├── zh‑CN.json
│       └── en‑US.json
```

### 3. i18n/index.js

```
import { createI18n } from 'vue‑i18n'
import zhCN from './locales/zh‑CN.json'
import enUS from './locales/en‑US.json'

// 获取本地缓存语言，默认中文
const locale = localStorage.getItem('lang') || 'zh‑CN'

const i18n = createI18n({
  legacy: false, // vue3组合式API必须false
  locale,
  fallbackLocale: 'zh‑CN', // 找不到key回退中文
  messages: {
    'zh‑CN': zhCN,
    'en‑US': enUS
  }
})

export default i18n
```

### 4. main.js 注册

```
import { createApp } from 'vue'
import App from './App.vue'
import i18n from './i18n'

createApp(App).use(i18n).mount('#app')
```

### 5. 组件使用

模板中：

```
<template>
  <div>{{ $t('welcome') }}</div>
  <div>{{ $t('msg', { name: '张三' }) }}</div>
  <button @click="changeLang">切换语言</button>
</template>

<script setup>
import { useI18n } from 'vue‑i18n'
const { t, locale } = useI18n()

function changeLang() {
  locale.value = locale.value === 'zh‑CN' ? 'en‑US' : 'zh‑CN'
  localStorage.setItem('lang', locale.value)
}
</script>
```

### 6. TS项目

给 `$t` 做类型提示：通过定义类型文件，对i18n的key做ts校验，写错key直接编译报错。

## 三、React 项目 i18next

1. 安装依赖

```
npm install i18next react‑i18next i18next‑http‑backend i18next‑browser‑languagedetector
```

- `i18next‑http‑backend`：**异步加载语言包**（不用打包全部语言文件，按需加载，减少包体积）
- `i18next‑browser‑languagedetector`：自动检测浏览器当前语言。

> 重要优化：**大项目不要把全部语言包打包进bundle，后端存放json，前端动态拉取语言资源，按需加载**。

## 四、关键能力点

### 1. 按需加载语言包（性能优化）

小项目直接import全部语言；**大型系统推荐按需加载**：

- 打包时只打包当前默认语言；切换英文的时候，http请求拉取en‑US.json。
- 减少首屏bundle体积。vue‑i18n、i18next都支持懒加载资源。

### 2. 复数处理

中文：`{count}条消息`；英文：`1 message / 2 messages`。
库内置复数规则，不用自己写if判断。

### 3. 日期、数字、货币格式化，浏览器原生 Intl API

不要手动写逻辑，浏览器自带 `Intl.DateTimeFormat`、`Intl.NumberFormat`

```
// 日期格式化
new Intl.DateTimeFormat('zh‑CN').format(new Date())
new Intl.DateTimeFormat('en‑US').format(new Date())

// 货币
new Intl.NumberFormat('zh‑CN', { style:'currency', currency:'CNY' }).format(1234.5)
```

### 4. RTL 从右到左布局（阿拉伯语等）

语言为阿拉伯语时，页面布局左右翻转：

- html标签设置 `dir="rtl"`；css使用 `direction: rtl`；
- flex、margin/padding尽量用逻辑属性 `margin‑inline‑start`，不要写死 `margin‑left`。

### 5. 服务端渲染 SSR

需要在服务端初始化i18n，识别请求头 `Accept‑Language`，设置初始语言，注水保证客户端和服务端文案一致。

## 五、工程化问题（真实开发踩坑）

1. **硬编码中文**：禁止模板、js里直接写中文，全部抽json。
2. key管理：层级组织key，例如 `login.title`、`login.submit`，方便维护。
3. 文案同步：大量文案，人工维护json很麻烦。
   - 方案：对接翻译平台，导出导入json，翻译人员直接操作；
   - ESLint 自定义规则检测代码中禁止出现中文字符，防止偷偷写死中文。
4. 缺失key兜底：找不到key，fallbackLocale回退到默认语言，避免页面显示key字符串。
5. 持久化：语言选择存入localStorage；页面初始化优先读取缓存，其次浏览器语言。
6. 动态文案：接口返回的内容一般不由前端i18n处理，由后端做多语言返回。
7. 第三方组件库国际化：
   Element‑Plus / Ant Design Vue 本身有i18n配置，需要同步组件库语言，否则组件弹窗、提示文字还是中文。

```
// Element‑Plus
import zhCn from 'element‑plus/dist/locale/zh‑cn'
import en from 'element‑plus/dist/locale/en'
```

## 六、两种架构选型对比

1. **全部语言包打包进项目**
   简单，适合语言少；缺点：语言多首屏包体积变大。
2. **语言资源放后端，前端按需http拉取**（大型项目首选）
   首屏只加载默认语言；切换其他语言再下载对应json。

## 七、原生JS（无框架）

直接使用 `i18next`，框架无关。

## 面试简答

> 前端国际化主流使用 i18next 生态：Vue使用vue‑i18n，React使用react‑i18next。

1. 将所有文案抽离独立JSON语言资源文件，不同语言保持key一致；代码中不写硬编码文本。
2. 初始化i18n实例，配置默认语言、降级语言、语言资源；支持本地存储保存用户语言选择。
3. 组件通过t函数根据key获取文案，支持变量插值；切换locale变量即可实现无刷新语言切换。
4. 大型项目建议**按需异步加载语言包**，优化首屏体积；日期、数字、货币使用浏览器原生Intl API。
5. 额外处理：RTL从右向左布局；同步UI组件库的多语言；工程上用eslint禁止源码写硬编码中文；接口返回业务文案一般交给后端做国际化。
6. SSR场景需要服务端识别浏览器Accept‑Language，初始化语言，保证注水一致性。

> 坑点：不要把文案写死代码；注意按需加载；第三方组件库语言需要单独配置；RTL布局要用css逻辑属性。
