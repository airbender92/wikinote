# 面试题：站点一键换肤实现方案

> 面试高频，讲清4种主流方案、原理、优缺点、适用场景，可直接口述

## 方案1：CSS类切换（Class切换，简单主题）

**原理**：给根元素(html/body)增加主题类名，比如`theme-dark`、`theme-light`，CSS通过类名区分不同主题样式。

```css
/* 默认亮色 */
.box {
  background: #fff;
  color: #333;
}
/* 暗黑主题 */
.theme-dark .box {
  background: #000;
  color: #fff;
}
```

JS只需要切换根节点class：

```js
document.documentElement.className = "theme-dark";
```

- ✅优点：实现简单，兼容性好，无额外依赖；适合主题少（2‑3套：亮/暗）
- ❌缺点：主题多的时候CSS体积膨胀；新增主题需要改大量样式；不方便动态修改颜色。

## 方案2：CSS变量（CSS Custom Properties，现在主流）⭐

**原理**：使用 `--xxx` css自定义属性定义主题色，JS动态修改根节点上的变量值。

```css
:root {
  --color-primary: #409eff;
  --bg-color: #ffffff;
}
.box {
  background: var(--bg-color);
  color: var(--color-primary);
}
```

JS切换主题：

```js
// 暗黑主题，直接修改变量
document.documentElement.style.setProperty("--color-primary", "#333333");
document.documentElement.style.setProperty("--bg-color", "#1a1a1a");
```

- ✅优点：

1. 一套DOM，一套业务CSS，只修改变量；代码简洁；
2. 可以做到**动态自定义换肤**（用户自己选颜色）；
3. 性能好，浏览器原生支持；
4. 支持持久化：把主题变量存localStorage，刷新页面恢复。

- ❌缺点：不支持IE；旧浏览器兼容差；只能修改css变量定义过的属性。

> Vue3、React项目现在大多用这套方案。

## 方案3：多套独立CSS文件动态加载（link动态切换）

准备多份完整主题css文件：`light.css`、`dark.css`。
JS动态创建/替换link标签，加载对应主题样式文件。

```js
// 切换暗黑，替换link的href
const link = document.createElement("link");
link.rel = "stylesheet";
link.href = "dark.css";
document.head.appendChild(link);
```

- ✅优点：多套主题完全隔离，样式互不干扰；适合主题数量非常多的场景。
- ❌缺点：

1. 切换时有**闪烁**（等待css网络加载）；
2. 每个主题都要维护完整一套css，维护成本高；
3. 会产生网络请求。

> 优化：预加载其他主题css，或者打包时把多个主题css内置。

## 方案4：编译期换肤（工程化方案，Element UI主题换肤原理）

基于预处理器 `Sass/Less`，变量全部由sass变量控制。
两种玩法：

1. **编译多套css**：打包阶段，根据不同变量集合编译输出多套主题css文件，运行时动态加载对应css（方案3底层）。
2. **在线实时编译**：浏览器端编译less，动态修改less变量，重新生成样式。

> 比如element-ui的`element-theme-chalk`、在线主题编辑器。

- ✅优点：适合组件库、大型后台系统；统一管理主题变量。
- ❌缺点：浏览器端编译less体积大，性能差；一般只用于构建阶段，不推荐浏览器实时编译。

## 补充：Store状态持久化

无论哪种方案，用户选择主题后，需要：

1. 把主题标识存入 `localStorage`；
2. 页面初始化优先读取localStorage，**在DOM渲染前设置主题**，避免页面闪烁。

# 各方案对比总结

| 方案                       | 适用场景                         | 缺点                             |
| -------------------------- | -------------------------------- | -------------------------------- |
| 根class切换                | 2‑3套固定主题，简单项目          | 主题多CSS臃肿                    |
| CSS变量(custom properties) | **现代项目首选，支持自定义颜色** | 不兼容IE                         |
| 动态加载多CSS文件          | 大量固定主题                     | 切换闪烁，有网络请求，维护成本高 |
| Less/Sass编译换肤          | 组件库、后台管理系统             | 浏览器编译性能差                 |

## 🎤面试口述1分钟精简版

一键换肤常见四种实现。
第一种是根节点Class切换，给html增加不同主题类名，CSS写不同主题样式，适合少量固定主题，简单但多主题时代码冗余。

第二种是CSS自定义变量，也是现在主流方案，把颜色、尺寸抽成css变量，JS动态修改根节点变量，业务样式直接使用var()引用；支持用户自定义颜色，性能好；缺点不兼容IE。

第三种是多套CSS文件，JS动态切换link标签加载不同主题样式，适合大量主题，但会有网络请求，切换容易闪屏。

第四种是工程化层面，利用Less/Sass变量，打包编译输出多套主题样式。

实际项目中优先使用CSS变量，用户选择的主题存localStorage，页面初始化优先读取，防止刷新页面主题丢失与闪烁。

## 面试官高频追问

1. 换肤出现闪烁白屏怎么解决？

> 答：页面渲染之前，JS优先读取localStorage，同步设置主题变量/class，不要等DOM挂载完再执行；不要依赖异步请求加载主题css。

2. CSS变量和class切换的区别？

> class是写死多套css；css变量只有一套css，运行时动态改变值，支持用户自定义颜色。

3. 能不能做到用户自定义主题色（用户输入任意颜色）？

> CSS变量可以；class、多css文件做不到，因为样式是编译写死的。
