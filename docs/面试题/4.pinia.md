# Pinia 完整速记（Vue3 官方状态管理，替代 Vuex）
> 对比 mitt：
> - **mitt(eventBus)**：临时事件通知，**传事件、传消息**，不存持久状态，注意卸载 off 防泄漏
> - **Pinia**：**全局共享状态仓库**，存数据、修改数据，跨组件共享，不需要手动解绑监听，无内存泄漏烦恼

## 1. 安装
```bash
pnpm add pinia
# npm install pinia
```

## 2. main.js 注册 Pinia
```js
import { createApp } from 'vue'
import { createPinia } from 'pinia'
import App from './App.vue'

const app = createApp(App)
const pinia = createPinia()
app.use(pinia)
app.mount('#app')
```

## 3. 定义 Store
> 目录：`src/stores/useUserStore.js`
- `defineStore`：第一个参数 **storeId 唯一字符串**，全局标识
- 三部分：`state`（状态数据）、`getters`（计算属性）、`actions`（修改状态，支持同步/异步）

```js
import { defineStore } from 'pinia'

// useXxxStore 约定命名，use开头
export const useUserStore = defineStore('user', {
  // state：函数，返回对象，避免多实例共享状态
  state: () => ({
    name: '张三',
    age: 18,
    token: ''
  }),

  // getters：相当于 computed，缓存，基于state派生
  getters: {
    isAdult: (state) => state.age >= 18
  },

  // actions：相当于 methods，修改state，可异步，**直接修改state，不需要mutation（没有mutation！）**
  actions: {
    // 同步
    setName(newName) {
      this.name = newName
    },
    // 异步
    async login(userInfo) {
      // 模拟接口请求
      // const res = await api.login(userInfo)
      this.token = 'xxxx-token'
    },
    resetUser() {
      // ✅内置方法：重置当前store全部state回到初始值
      this.$reset()
    }
  }
})
```

## 4. 组件中使用 store
### 基础用法 script setup
```vue
<script setup>
import { useUserStore } from '@/stores/useUserStore'

// 获取store实例
const userStore = useUserStore()
</script>

<template>
  <div>
    <p>{{ userStore.name }}</p>
    <p>是否成年：{{ userStore.isAdult }}</p>
    <button @click="userStore.setName('李四')">修改名字</button>
    <button @click="userStore.resetUser">重置状态</button>
  </div>
```

### ✏️解构注意大坑
> ❌直接解构会丢失响应式！
```js
// ❌错误，name、age 不是响应式
const { name, age } = userStore
```

✅正确两种方案：
```js
import { storeToRefs } from 'pinia'

// 1. storeToRefs：state、getters 用这个解构，保留响应式
const { name, age, isAdult } = storeToRefs(userStore)

// 2. actions 可以直接解构（方法不需要ref）
const { setName, login } = userStore
```

```vue
<template>
  <div>{{ name }}</div>
</template>
```

## 5. Pinia 常用 API
```js
const userStore = useUserStore()

userStore.$state        // 直接访问原始state对象
userStore.$patch({      // 批量修改state，推荐，多次修改合并一次
  name: '新名字',
  age: 20
})

userStore.$reset()      // state重置为初始值
userStore.$subscribe((mutation, state)=>{
  // 监听state变化，可做本地持久化
},{ detached: true })   // detached:true 组件销毁依然继续监听

userStore.$onAction(({name, args, after})=>{
  // 监听actions调用
})
```

## 6. 持久化（pinia‑plugin‑persistedstate）
> 状态默认内存中，刷新页面丢失，插件自动存 localStorage
```bash
pnpm add pinia-plugin-persistedstate
```

main.js 注册插件
```js
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate'
const pinia = createPinia()
pinia.use(piniaPluginPersistedstate)
```

store 开启持久化：
```js
export const useUserStore = defineStore('user', {
  state:()=>({/*...*/}),
  persist: true // 开启，整个state存入localStorage
})
```

只持久化部分字段：
```js
persist: {
  paths: ['token'] // 只保存token
}
```

## 7. mitt(eventBus) vs Pinia 选型对比
| 方案 | 用途 | 关注点 |
|---|---|---|
| mitt(eventBus) | **事件通知、消息触发**，少量临时跨组件通信 | 必须保存函数引用，`onUnmounted` 执行 `off`，防止内存泄漏 |
| Pinia | **全局共享状态数据**，存业务数据 | 使用 `storeToRefs` 解构；不需要手动解绑；复杂业务首选 |

> 简单记：**要发事件通知用mitt；要存共享数据用Pinia**。

## 8. 核心记忆点
1. Pinia **没有 mutation**，actions 里直接修改 state，支持异步
2. state 必须是**函数**，防止多个实例污染
3. 解构 state/getters 必须用 `storeToRefs`；actions 可直接解构
4. `$reset()` 一键重置仓库
5. 持久化靠插件 `pinia‑plugin‑persistedstate`
6. 不需要手动销毁监听，不存在 mitt 那种忘记 off 的泄漏问题
