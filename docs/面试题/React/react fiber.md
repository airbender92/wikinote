# React Fiber 总结（百字精简版）

React Fiber 是 React 核心算法的底层重写架构，核心是**可调度的增量渲染**。它将渲染任务拆解为独立工作单元，可暂停、插队、复用、中止任务。Fiber 以虚拟栈帧（JS 对象）替代原生调用栈，通过优先级调度优化UI流畅度，依托双缓存 alternate 树复用节点、减少性能开销，分离协调与渲染阶段，完美适配动画、手势等交互场景。

1. **旧版 React**：diff 直接递归遍历虚拟DOM树，**依赖 JS 原生调用栈**，一旦开始就不能中断，一口气跑完，没法利用 `requestIdleCallback`。

2. **Fiber**：
   不再依靠原生调用栈递归。改用 `child / sibling / return` 指针组成**Fiber节点链表结构**，自己在内存维护一套**虚拟栈帧**。
   任务被拆成一个个 Fiber 工作单元，每处理完一个单元，就把执行权交回浏览器。
   借此可以结合调度（`requestIdleCallback`）：**暂停、恢复、调整优先级、丢弃任务**，实现增量分片渲染。

> ⚠️注意：
> 不是“在虚拟树对比（diff）逻辑本身改算法”，**diff 的规则（type、key 判断逻辑）没变**；
> 真正改变的是**执行方式**：把同步递归，改成可中断的链表循环遍历。
> 协调逻辑还是对比新旧树，但遍历过程可控，从而支持分片、优先级调度。

简单一句话：

> diff 比对规则不变，把执行载体从不可打断的原生递归栈，换成可控制的 Fiber 链表，以此实现分片调度。
