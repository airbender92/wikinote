# React 组件性能优化

核心本质：**减少不必要的重渲染、减少昂贵计算、减少DOM操作**。

> React性能问题根源：父组件更新，默认所有子组件跟着重新执行render，哪怕子组件props没变化。

分为四大方向：**渲染优化、计算优化、列表优化、其他工程优化**

## 一、阻止不必要重渲染（最常用）

### 1. `React.memo` 组件记忆

对函数组件做props浅比较，props不变，跳过组件渲染。

```
// 只有props变化才重渲染
const Child = React.memo(({name})=>{
  return <div>{name}</div>
})
```

⚠️注意：**浅比较**

- 对象、数组直接传字面量 `data={{a:1}}`，每次父渲染生成新引用，`memo`失效。

```
// ❌ 不好，每次父渲染data是新对象，memo无效
<Child data={{list:[]}} />

// ✅ 把对象提到组件外，或者useMemo缓存
const data = {list:[]}
<Child data={data} />
```

### 2. `useMemo` 缓存计算结果

缓存**昂贵计算逻辑**，依赖不变，直接复用上次计算值，不重新计算。

```
const heavyResult = useMemo(()=>{
  // 大数组遍历、排序、过滤等耗时操作
  return bigList.filter(x=>x>100)
}, [bigList]) // 依赖数组
```

> 不要到处useMemo：简单计算不要用，有开销，只用于CPU消耗大逻辑。

### 3. `useCallback` 缓存函数

解决回调函数每次渲染生成新引用，导致`memo`子组件无效。

```
// ❌ 每次渲染生成新函数，memo子组件会重渲染
<Child onClick={()=>{}} />

// ✅ useCallback稳定函数引用
const handleClick = useCallback(()=>{
  console.log('click')
}, [])

<Child onClick={handleClick} />
```

> 记忆三件套组合：
> `React.memo`（组件） + `useMemo`（值） + `useCallback`（函数）
> 坑：依赖数组写漏，会拿到旧闭包值。

### 4. 类组件对应方案

- `PureComponent`：props+state浅比较
- `shouldComponentUpdate(nextProps,nextState)`：手动判断是否允许更新

## 二、state设计优化

1. **状态最小化**：不要把可以从state推导出来的数据存state，尽量用计算代替。
2. **状态下沉**：把频繁变化的state放到最小子组件，不要放在顶层父组件，避免整个大组件树重渲染。

```
// ❌ count在父，父一更新，所有子全部重渲染
function App(){
  const [count,setCount] = useState(0)
  return <>
    <HeavyComponent/>
    <div>{count}</div>
  </>
}

// ✅ 把count状态下沉到小组件，HeavyComponent不受影响
function Counter(){
  const [count,setCount] = useState(0)
  return <div>{count}</div>
}
```

3. 合并状态：不要拆分大量独立state，减少setState触发次数；但也不要过度合并。
4. 避免在render里生成对象/数组/函数字面量，造成引用变化。

## 三、长列表优化（高频痛点）

上千条数据直接渲染，DOM节点太多卡顿。

1. **虚拟列表（只渲染可视区域）**
   库：`react‑window` / `react‑virtualized`

> 只渲染屏幕能看见的几条，滚动时替换数据，DOM数量极少。

2. 不要用`index`做`key`

- key错误会导致diff节点复用错乱，额外DOM操作，列表卡顿、渲染错乱。
- 使用业务唯一id作为key。

3. 大数据分页，不要一次性渲染全部数据。

## 四、避免渲染阻塞（Fiber并发能力）

### 1. `useTransition`：标记非紧急更新

把搜索筛选、列表过滤这类非紧急UI标记为过渡，高优先级输入（输入框打字）优先执行，不会被大量渲染卡住输入。

```
const [isPending, startTransition] = useTransition()

// 输入是高优先级，列表渲染放到过渡
const handleChange = (e)=>{
  const text = e.target.value
  setInput(text)
  startTransition(()=>{
    setFilterText(text) // 非紧急更新，可被打断
  })
}
```

### 2. `useDeferredValue`：延迟状态

对传入的value做延迟，类似防抖，衍生出来的状态延迟更新。

```
const deferredText = useDeferredValue(inputText)
// 传给大列表，deferredText更新会让步于用户交互
<List query={deferredText}/>
```

> `useTransition / useDeferredValue` 依赖并发模式，需要开启 `createRoot`。

## 五、组件拆分与懒加载

1. **组件粒度拆分**：大组件拆小组件，隔离变化范围。
2. **代码分割 `React.lazy + Suspense`**
   路由、弹窗、非首屏组件懒加载，减少首屏js包体积。

```
const BigPage = React.lazy(()=>import('./BigPage'))

<Suspense fallback={<Loading/>}>
  <BigPage/>
</Suspense>
```

## 六、副作用优化 useEffect

1. 正确填写依赖数组，防止不必要重复执行effect。
2. 清理副作用：定时器、事件监听、请求abort，组件卸载销毁，防止内存泄漏。
3. 不要在useEffect里面频繁setState，造成循环更新。

## 七、工具定位性能问题

1. **React DevTools Profiler（分析重渲染）**
   可以看到：哪些组件重渲染、渲染耗时、为什么重渲染。

- 火焰图：看每个组件耗时
- 组件图：看每次更新，标红代表发生重渲染。>

> 重点：明明props没变却标红，就是优化点。

2. chrome Performance面板：看主线程长任务，定位JS执行耗时。

## 八、常见误区（非常重要）

1. ❌ 到处套 `memo / useMemo / useCallback`
   记忆本身有比较开销，简单组件加了反而更慢。**只给重渲染代价大的组件使用**。
2. ❌ `memo`可以解决所有性能问题
   memo只做浅比较；如果props传新引用对象，memo直接失效。
3. ❌ useTransition可以解决所有长列表卡顿
   它解决的是**渲染阻塞交互**，DOM节点太多还是要虚拟列表。
4. ❌ 虚拟DOM越快页面越快
   性能瓶颈大多不在diff，而在：组件执行、大量DOM节点、昂贵计算。

# 快速记忆优化口诀

> 状态往下沉，memo控渲染；
> 函数callback，值用useMemo；
> 长表做虚拟，key不用索引；
> 非紧急更新，transition让步；
> 大组件懒加载，profiler找问题。

## 面试高频追问

1. memo+useCallback为什么有时候还是会重渲染？

> 依赖数组写了经常变化的变量，每次生成全新函数引用；或者props传对象字面量，引用变化。

2. useMemo的依赖数组空数组会发生什么？

> 只计算一次，后续永远复用旧值，依赖变化也不会更新，容易闭包陷阱。

3. useTransition和防抖区别？

> 防抖是延迟执行；useTransition是React内部调度优先级，高优先级任务来了可以直接中断渲染，不需要等待定时器。
