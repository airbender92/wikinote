# 受控组件 vs 非受控组件

主要针对表单元素：`input`、`textarea`、`select`。
核心区别：**表单数据由谁掌控**

- **受控组件：state 接管数据，React 控制表单值**
- **非受控组件：DOM 接管数据，用 ref 获取 DOM 原生值**

## 1、受控组件 Controlled

> 值由 `state` 驱动，`value` 属性绑定 state；通过 `onChange` 更新 state。表单**完全受 React state 控制**。

```
import { useState } from 'react'

function Demo() {
  const [val, setVal] = useState('')

  return (
    {/* value绑定state，onChange更新state */}
    <input
      value={val}
      onChange={(e) => setVal(e.target.value)}
      placeholder="受控输入框"
    />
  )
}
```

### 流程

1. 用户输入 → 浏览器触发 onChange
2. React 拿到事件，调用 `setVal` 更新 state
3. 组件重新 render，把最新 state 赋值给 input 的 `value`
4. input 显示 state 的值

> 特点：**真实DOM的value永远和state保持同步**。
> 表单所有变化都要经过 React 状态。

### 受控组件特点

✅ 优点：

- 数据统一放在 state，方便做校验、格式化、实时过滤
- 可以随时设置默认值、重置、预填数据
- 符合 React「单向数据流」思想

❌ 缺点：

- 每输入一个字符就触发一次 state 更新 + 组件重渲染；复杂大表单会有一定性能开销。

> 注意坑：只写 `value` 不写 `onChange` → 输入框会变成只读，无法输入。

## 2、非受控组件 Uncontrolled

> **把数据交给原生DOM管理**，React不维护state。使用 `defaultValue` 设置初始值，通过 `ref` 读取DOM真实值。

```
import { useRef } from 'react'

function Demo() {
  const inputRef = useRef(null)

  const handleSubmit = () => {
    // 提交的时候直接从DOM拿值
    console.log(inputRef.current.value)
  }

  return (
    <>
      {/* defaultValue：只设置初始默认值，后续修改由DOM接管 */}
      <input ref={inputRef} defaultValue="初始内容" />
      <button onClick={handleSubmit}>提交</button>
    </>
  )
}
```

### 关键点

- 用 `defaultValue`（input） / `defaultChecked`（checkbox）
- **不要写 value**，写value就变成受控了
- React 不跟踪输入过程；只有提交的时候通过 ref 去 DOM 读取值。

✅ 优点：

- 输入不会触发组件重渲染，性能好；简单表单写起来省事。

❌ 缺点：

- 实时校验、格式化、动态修改值很麻烦；数据存在DOM，不在state。
- 想修改输入框内容，必须操作DOM ref，违背React的数据流。

## select / textarea / checkbox 对照写法

### 受控 select

```
<select value={selected} onChange={e=>setSelected(e.target.value)}>
  <option value="a">A</option>
</select>
```

### 受控 checkbox

```
<input type="checkbox" checked={checked} onChange={e=>setChecked(e.target.checked)} />
```

### 非受控 checkbox

```
<input type="checkbox" ref={ref} defaultChecked />
```

> 记忆：
> 受控：`value / checked` + onChange
> 非受控：`defaultValue / defaultChecked` + ref

## 核心对比表格

|                  | 受控组件                                      | 非受控组件                          |
| ---------------- | --------------------------------------------- | ----------------------------------- |
| 数据源           | React state                                   | DOM原生节点                         |
| 属性             | value / checked                               | defaultValue / defaultChecked + ref |
| 更新时机         | 用户输入 → onChange更新state → render更新视图 | DOM自己更新，提交时ref读取          |
| 实时校验、格式化 | 方便                                          | 麻烦                                |
| 重渲染           | 每次输入触发重渲染                            | 输入不触发重渲染                    |
| 适用场景         | 需要实时校验、联动、动态修改表单              | 简单提交表单，不需要实时处理        |

## 高频面试坑

1. ❌ 受控组件只写 value，不写 onChange：输入框只读，无法输入。
2. ❌ 受控组件混用 defaultValue：defaultValue 会被 value 覆盖，完全无效。
3. ❌ 非受控组件写 value：直接变成受控组件。
4. `defaultValue` **仅首次挂载生效**，后续state变化不会改变输入框值。

## 业务怎么选？

1. **绝大多数业务表单优先用受控组件**（antd、formik、react‑hook-form底层都是受控）。
2. 简单一次性提交，不需要实时校验，可以用非受控。
3. react‑hook‑form 默认可以用非受控模式提升表单性能。

## 一句话总结

> **受控组件：React state说了算，value绑定state，onChange更新state；**
> **非受控组件：DOM说了算，defaultValue设置初始值，ref读取DOM值。**
