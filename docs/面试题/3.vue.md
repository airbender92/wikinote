# Vue EventBus（mitt）少量临时组件通信
> 适用场景：**少量、临时跨组件事件通信**；不适合大型项目状态管理（大型项目用 Pinia）；**重点：组件卸载必须取消监听，防止内存泄漏**

## 1. 安装 mitt
```bash
npm install mitt
# yarn add mitt
# pnpm add mitt
```

## 2. 封装 eventBus
`src/utils/eventBus.js`
```js
import mitt from 'mitt'
// 创建总线实例
const eventBus = mitt()
export default eventBus
```

## 3. 组件内使用（Vue3 setup 语法糖）
### 发送事件（emit）
```vue
<script setup>
import eventBus from '@/utils/eventBus'

// 触发事件，可传参数
const sendMsg = () => {
  eventBus.emit('custom-event', { name: '测试', data: 123 })
}
</script>
```

### 接收事件 + 卸载取消监听（关键防泄漏）
> ❗错误写法：直接 `eventBus.on()` 不做 off，组件销毁监听还在，多次挂载会重复触发，内存泄漏
> ✅正确：保存监听函数引用，`onUnmounted` 调用 `off`

```vue
<script setup>
import { onUnmounted } from 'vue'
import eventBus from '@/utils/eventBus'

// 定义监听回调函数，必须拿到函数引用，用于off取消
const handleReceive = (payload) => {
  console.log('收到事件', payload)
}

// 注册监听
eventBus.on('custom-event', handleReceive)

// ✅组件卸载，取消监听，防止内存泄漏
onUnmounted(() => {
  eventBus.off('custom-event', handleReceive)
})
</script>
```

## 4. mitt API 速查
```js
eventBus.on(eventName, handler)   // 监听事件
eventBus.off(eventName, handler)  // 取消指定事件指定回调（必须同一个函数引用）
eventBus.emit(eventName, params)  // 派发事件
eventBus.all.clear()              // 清空全部监听（慎用，会清除全局所有订阅）
```

## ⚠️重要坑点
1. **`off` 的第二个参数必须和 `on` 是同一个函数引用**
❌不能写匿名函数，匿名函数无法 off！
```js
// 错误！匿名函数拿不到引用，onUnmounted无法off
eventBus.on('xxx', (val)=>{ console.log(val) })
```

2. 只适合**临时少量通信**：兄弟、隔代简单事件；复杂共享状态优先 Pinia。
3. 不要滥用：事件名字字符串容易写错，没有类型提示；大型项目事件散落在各处难以维护。
4. Vue2 原生 EventBus 同样存在内存泄漏问题，也是卸载 `$off`；Vue3 官方推荐替换为 mitt。

## 5. TS简单类型增强（可选）
```ts
// eventBus.ts
import mitt from 'mitt'
type Events = {
  'custom-event': {name:string, data:number}
  'refresh-list': void
}
const eventBus = mitt<Events>()
export default eventBus
```

## 记忆口诀
> mitt做事件总线，on注册存函数；
> 组件卸载要off；匿名回调不能用；
> 少量临时才用它，复杂状态上Pinia。
