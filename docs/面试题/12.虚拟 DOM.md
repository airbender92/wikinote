# 虚拟DOM（Virtual DOM）
## 什么是虚拟DOM
**虚拟DOM就是用 JS 对象来描述真实DOM节点**，是真实DOM的内存映射。
真实DOM操作很慢，JS运算很快，所以在JS层用对象模拟DOM结构。

### 简单vnode结构示例
```js
const vnode = {
  tag: 'div',         // 标签名
  props: { id: 'app' }, // 属性
  children: [         // 子节点
    { tag: 'p', children: ['hello'] }
  ],
  el: null // 对应真实DOM元素，diff后挂载
}
```
> 渲染流程：
模板 → 编译 → render函数 → 返回**VNode虚拟节点** → diff算法对比新旧VNode → 生成最小DOM操作 → 更新真实DOM。

---

## 为什么需要虚拟DOM
### 1. 真实DOM操作开销巨大
真实DOM对象属性非常多，创建、修改、重排重绘成本很高。
> 如果数据一变就直接操作真实DOM，频繁改动会大量触发浏览器重排重绘，性能差。

虚拟DOM：**先在JS中对比计算出最小变更，最后只把差异更新到真实DOM，减少DOM操作次数**。

### 2. 实现跨平台
VNode只是普通JS对象，不依赖浏览器DOM API。
- 浏览器：渲染成真实DOM
- Weex / uni-app：渲染成原生APP控件
- SSR：渲染成html字符串
> 一套VNode，多平台渲染。

### 3. 解耦视图渲染逻辑
把视图描述和DOM操作剥离开，框架只关心VNode，不用手动操作DOM。

---

## 核心流程：diff算法
当数据变化，组件重新执行`render`生成**新VNode**：
1. 拿新VNode 和旧VNode做`diff`对比
2. 找出两者之间差异（节点增删改、属性变化、子节点变化）
3. **只把差异部分更新到真实DOM**，不是全量销毁重建DOM。

> diff 策略：**同层比较，不跨层级对比**；key用来标识节点身份，提高列表diff效率。

## 误区（面试常考）
> ❌ 虚拟DOM不是一定比手动操作DOM快
✅ 虚拟DOM优势：**复杂场景下，帮你算出最小DOM改动，解放开发者**；
简单场景，手动精准操作DOM可能更快，但业务复杂手写维护成本极高。

## Vue2 vs Vue3虚拟DOM小区别
- Vue2：完整VNode，全部节点都创建vnode
- Vue3：**编译时做PatchFlags标记**，静态节点跳过diff；只对比动态节点，虚拟DOM性能进一步提升。

## 📝面试简答背诵版
1. **虚拟DOM是描述DOM结构的JavaScript对象，是真实DOM在内存中的抽象映射。**
2. **为什么需要：**
   1. **减少真实DOM操作**：真实DOM操作昂贵，通过diff算法对比新旧vnode，只更新差异部分，减少重排重绘。
   2. **跨平台渲染**：vnode是纯JS对象，可以渲染到浏览器、原生APP、SSR等不同平台。
   3. **解放开发者**：不用手动操作DOM，数据驱动视图，提升开发维护效率。
3. 数据变化生成新VNode，diff对比新旧虚拟节点，得到补丁，再更新真实DOM。
4. diff是**同层比较**，key给节点做唯一标识优化列表diff。
