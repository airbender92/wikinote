# Webpack 面试核心知识点
## 一、基础概念
1. **什么是 webpack**
webpack 是**模块打包工具**，把前端各种资源（js、css、图片、字体）都当做模块，分析模块依赖关系，打包输出浏览器可识别的静态资源。
> 核心：一切皆模块。

2. **四大核心概念**
- **entry 入口**：打包起点，分析依赖；单入口/多入口
- **output 输出**：打包后文件输出位置、文件名
- **loader 加载器**：处理非 js 文件，翻译转换文件；webpack本身只认识JS/JSON
- **plugin 插件**：作用于打包整个生命周期，做更复杂的事情；插件可以访问整个编译生命周期钩子

> loader 是转换器，plugin 是扩展器。loader 运行在文件级别，plugin 运行在编译阶段。

3. **mode 模式**
- `development`：开发模式，不压缩代码，开启调试，模块热更新，cache
- `production`：生产模式，自动开启代码压缩、tree‑shaking、scope hoisting、移除无用代码

## 二、Loader 相关高频面试
### 常用 loader
- `babel‑loader`：转译 ES6+ 语法，依赖 `@babel/core`、`@babel/preset‑env`
- `css‑loader`：解析css文件，处理 `@import`、`url()`
- `style‑loader`：把css插入页面style标签
- `less‑loader/sass‑loader`：预处理器编译
- `postcss‑loader`：css自动加浏览器前缀，`autoprefixer`
- `file‑loader`/`asset‑module`：处理图片、字体资源；webpack5废弃file‑loader，用内置`asset/resource`
- `url‑loader`：小图片转base64，大图片输出文件；webpack5合并到asset模块

### loader执行顺序
> **从右往左，从下往上执行**
`use: ['style-loader','css-loader','postcss-loader']`
执行顺序：postcss‑loader → css‑loader → style‑loader

### loader配置参数
- `test`：匹配文件正则
- `use`：使用loader数组
- `exclude`：排除文件夹（node_modules）提升打包速度
- `include`：只编译指定目录

### loader手写原理（常问）
loader本质是**导出函数的node模块**，接收源码字符串，返回处理后的源码。不能写异步（async loader除外）。

## 三、Plugin 高频考点
> 插件是一个**类**，必须实现 `apply(compiler)` 方法，compiler提供生命周期钩子。

### 常用插件
1. `HtmlWebpackPlugin`：自动生成html，自动引入打包后的js/css
2. `MiniCssExtractPlugin`：把css抽离成独立css文件（生产环境，替换style‑loader）
3. `CleanWebpackPlugin`：打包前清空dist目录
4. `DefinePlugin`：定义全局环境变量
5. `CopyWebpackPlugin`：复制静态资源
6. `SplitChunksPlugin`：代码分割，webpack5内置，拆分公共代码、第三方库
7. `TerserWebpackPlugin`：js代码压缩混淆（production模式默认开启）

### compiler 和 compilation
- **compiler**：webpack实例，全局唯一，整个编译生命周期，读取配置
- **compilation**：每次构建生成的编译对象；包含模块、依赖、打包资源；watch模式下每次重新构建都会生成新compilation。

## 四、性能优化（面试重中之重）
### 📦 打包构建速度优化
1. **缩小文件处理范围**
`include/exclude`，不编译node_modules
2. **缓存**
- `cache: true` webpack5内置文件系统缓存，二次构建提速
- babel‑loader开启`cacheDirectory:true`缓存babel编译结果
3. **多线程并行处理**
`thread‑loader`：开启多线程，适合耗时loader；线程本身有开销，小项目不要用
4. **externals 外部扩展**
第三方库不打包，CDN引入，配置externals排除（vue、react等）
5. **resolve优化**
```js
resolve:{
  extensions: ['.js','.vue'], //减少后缀尝试
  alias:{'@':path.resolve(__dirname,'src')}, //别名
  modules:[path.resolve(__dirname,'src'),'node_modules'] //优先查找src
}
```
6. 合理使用 `noParse`：完全不解析大库，跳过依赖分析（库无import require才可用）

### 📦 输出产物体积优化
1. **Tree‑Shaking 树摇**
> 移除**未使用ES6模块代码**，只支持ES Module(`import/export`)，不支持commonJS(require)
- 条件：mode:production；使用ES模块；不要写副作用代码；`sideEffects`配置package.json标记有副作用文件（css）
```json
"sideEffects":["*.css"]
```

2. **代码分割 splitChunks**
- 分割类型：
  - 入口分割：多entry
  - 动态导入分割：`import().then()` 路由懒加载
  - 公共代码分割：splitChunks抽取第三方库、公共复用模块
- splitChunks核心参数：chunks、minSize、minChunks、cacheGroups

3. **压缩资源**
- js：TerserPlugin（压缩、删除注释）
- css：`css‑minimizer‑webpack‑plugin`压缩css
4. 抽离css：`MiniCssExtractPlugin`，不要内联css到js
5. 图片压缩，asset模块处理图片

### 📦 页面加载性能
- 路由懒加载 `import()`
- preload / prefetch 预加载资源
- gzip压缩，`CompressionPlugin`，服务器开启gzip

## 五、webpack5 vs webpack4 区别（必问）
1. **内置Asset Modules**，取代 file‑loader url‑loader raw‑loader
2. **持久化缓存 cache** 内置文件缓存，不用cache‑loader
3. **模块联邦 Module Federation**，微前端模块共享，跨应用共享代码
4. 性能提升，tree‑shaking更好，处理CommonJS优化
5. 移除`NodeJsPolyfill`，不再自动注入node polyfill，需要手动安装
6. `SplitChunks`默认策略调整
7. 废弃一些旧插件API

## 六、热更新 HMR（Hot Module Replacement）
1. **HMR是什么**：模块热替换，修改代码**不刷新浏览器**，更新变化模块，保留页面状态。只用于开发环境。
2. 原理：
1) webpack‑dev‑server启动web服务，watch监听文件变化
2) 文件改动，webpack重新编译对应模块，生成更新补丁
3) websocket通信，推送变更给浏览器
4) HMR runtime接收补丁，替换更新模块，不刷新整个页面
> css文件热更新style‑loader已经支持；js需要自己写accept处理；vue‑loader/react‑hot‑loader封装好了。

⚠️ HMR不等于live‑reload（整页刷新）。

## 七、常见面试问答题
### 1. webpack的打包流程
1. 读取webpack配置，实例化compiler
2. 注册所有插件，执行插件apply
3. 触发`run`钩子开始编译
4. 根据entry入口，读取文件，创建模块
5. 调用loader转换模块源码；解析模块依赖（import/require）递归构建依赖图（dependency graph）
6. 依赖图构建完成，调用plugin各种钩子
7. 执行代码分割splitChunks，生成chunk
8. chunk转成输出资源assets
9. 输出文件写入磁盘output

> 核心流程：**读取配置 → 插件注册 → 构建依赖图 → loader转换模块 → 生成chunk → 输出文件**

### 2. Tree‑Shaking为什么不支持CommonJS？
CommonJS是**运行时动态导入**，require可以传变量，运行时才知道引入哪个文件；webpack静态分析阶段无法判断哪些代码没有使用。
ES Module import是静态，导入导出写死，编译期可以分析死代码。

### 3. chunk、module、bundle区别
- **module**：源码里每个文件都是module，各种模块（js/css）
- **chunk**：webpack打包过程中的中间产物；entry、splitChunks、动态import都会生成chunk
- **bundle**：最终输出到dist的文件，chunk经过处理输出bundle。

### 4. webpack‑dev‑server 和 webpack‑dev‑middleware区别
- webpack‑dev‑server：内部封装webpack‑dev‑middleware，开启静态服务器，watch，websocket HMR；内存打包，不输出磁盘。
- webpack‑dev‑middleware：只中间件，把打包资源输出内存交给服务器，不提供web服务。

### 5. 什么是模块联邦 Module Federation（webpack5重点）
实现**多个独立构建应用之间共享模块**。每个应用可以当做remote被其他应用引用，也可以作为host引入别人的模块。用于微前端，运行时加载远端模块，不是打包时合并。

### 6. babel‑loader和babel的区别
babel是核心库；babel‑loader是webpack的loader，调用babel对源码做转译；preset是预设插件集合。
`@babel/preset‑env` 根据目标浏览器自动选择转译插件。

> babel只转语法，不转API；Promise、Array.prototype.includes这类新API需要`core‑js`垫片。

## 八、容易踩坑点
1. tree‑shaking失效：用了require、副作用代码没标记sideEffects
2. loader顺序搞反
3. MiniCssExtractPlugin开发环境不要使用，开发用style‑loader
4. webpack5没有node polyfill，path、buffer等报错需要手动安装
5. externals只排除打包，需要html手动引入CDN脚本

## 九、手写简单plugin伪代码
```js
class DemoPlugin {
  apply(compiler) {
    compiler.hooks.emit.tap('DemoPlugin', (compilation) => {
      // emit钩子：输出文件前
      compilation.assets['test.txt'] = {
        source(){ return 'hello webpack plugin'},
        size(){ return 15 }
      }
    })
  }
}
module.exports = DemoPlugin
```
