# Redux 速记（React 生态状态管理）
> 对比记忆
- **mitt(mitt‑eventBus)**：Vue，事件消息，手动off防泄漏
- **Pinia**：Vue3，简单直接，state/getters/actions，无mutation
- **Redux**：React 经典单向数据流，**三大原则**，核心：`action → reducer → store`；现在项目大多用 **Redux Toolkit(RTK)**，避免手写样板代码

## 1. 核心概念（原生Redux）
1. **Store**：唯一全局仓库，保存整个应用state，**单一数据源**
2. **State**：只读状态，不能直接修改
3. **Action**：普通对象，描述“发生了什么”，`{type:'xxx', payload:数据}`，**唯一修改state的入口**
4. **Reducer**：纯函数 `(prevState, action) => newState`；**不能改原state，必须返回新state**；不能有副作用（异步、接口请求不能写reducer）
5. **dispatch**：派发action：`store.dispatch(action)`

> ❗原生Redux痛点：样板代码极多、异步要中间件(redux‑thunk)、手动不可变更新，几乎不手写原生Redux，都用**Redux Toolkit(RTK)**

### 原生极简示例（了解原理，不实际项目手写）
```js
import { createStore } from 'redux'

// reducer 纯函数
const counterReducer = (state = {count:0}, action)=>{
  switch(action.type){
    case 'ADD':
      // 必须返回新对象，禁止直接修改state！
      return {...state, count: state.count + action.payload}
    default:
      return state
  }
}

// 创建store
const store = createStore(counterReducer)

// 订阅state变化
store.subscribe(()=>{
  console.log(store.getState())
})

// dispatch派发action
store.dispatch({type:'ADD', payload:1})
```

## 2. Redux‑Toolkit（RTK，官方推荐，现在标准写法）
> ✅解决原生全部痛点：内置immer，**可以直接“修改”state（内部生成新state）**；内置thunk异步中间件；简化action创建；内置createSlice
```bash
npm install @reduxjs/toolkit react-redux
```

### ① createSlice 创建切片（slice：拆分模块）
`store/counterSlice.js`
```js
import { createSlice } from '@reduxjs/toolkit'

const counterSlice = createSlice({
  name:'counter', // slice命名，action type前缀
  initialState:{
    count:0
  },
  // reducers：直接写修改逻辑，immer帮我们处理不可变
  reducers:{
    add:(state, action)=>{
      // ✅允许直接赋值！不是真修改，immer生成新state
      state.count += action.payload
    },
    reset:(state)=>{
      state.count = 0
    }
  }
})

// 自动生成action creator
export const { add, reset } = counterSlice.actions
export default counterSlice.reducer
```

### ② 组合store，configureStore
`store/index.js`
```js
import { configureStore } from '@reduxjs/toolkit'
import counterReducer from './counterSlice'

export const store = configureStore({
  reducer:{
    counter: counterReducer
    // 可以放多个slice
  }
})
```

### ③ 根组件注入 Provider
main.jsx
```jsx
import React from 'react'
import ReactDOM from 'react-dom/client'
import { Provider } from 'react-redux'
import { store } from './store'
import App from './App'

ReactDOM.createRoot(document.getElementById('root')).render(
  <Provider store={store}>
    <App />
  </Provider>
)
```

### ④ 组件中使用 useSelector / useDispatch
```jsx
import { useSelector, useDispatch } from 'react-redux'
import { add, reset } from './store/counterSlice'

function Demo(){
  // 获取state
  const count = useSelector(state => state.counter.count)
  const dispatch = useDispatch()

  return (
    <div>
      <p>{count}</p>
      <button onClick={()=>dispatch(add(1))}>+1</button>
      <button onClick={()=>dispatch(reset())}>重置</button>
    </div>
  )
}
export default Demo
```

## 3. RTK 异步处理（内置thunk）
> reducer不能写异步；异步逻辑写在**createAsyncThunk**，配合slice extraReducers
```js
import { createSlice, createAsyncThunk } from '@reduxjs/toolkit'

// 异步thunk
export const fetchUserInfo = createAsyncThunk(
  'user/fetchUser',
  async (userId, { rejectWithValue })=>{
    // 模拟接口
    // const res = await api.getUser(userId)
    return {name:'张三'}
  }
)

const userSlice = createSlice({
  name:'user',
  initialState:{
    info:null,
    loading:false
  },
  reducers:{},
  // 处理异步thunk的三种状态 pending / fulfilled / rejected
  extraReducers:(builder)=>{
    builder
      .addCase(fetchUserInfo.pending, (state)=>{
        state.loading = true
      })
      .addCase(fetchUserInfo.fulfilled, (state, action)=>{
        state.loading = false
        state.info = action.payload
      })
      .addCase(fetchUserInfo.rejected, (state)=>{
        state.loading = false
      })
  }
})

export default userSlice.reducer
```

组件调用：
```jsx
dispatch(fetchUserInfo(1001))
```

## 4. 关键API速查
- `createSlice`：创建模块切片，生成reducer+action
- `configureStore`：创建store，自动配置中间件
- `createAsyncThunk`：处理异步请求
- `useSelector`：读取state（组件订阅state，state变化自动重渲染）
- `useDispatch`：拿到dispatch函数派发action
- `Provider`：把store注入组件树

## 5. 三大原则（Redux灵魂）
1. **单一数据源**：整个应用只有一个store
2. **State只读**：只能通过dispatch(action)修改，不能直接改
3. **纯Reducer函数修改**：相同输入一定相同输出，无副作用

## 6. 对比 mitt / Pinia / Redux‑Toolkit
| 方案 | 框架 | 定位 | 特点 |
|---|---|---|---|
| mitt | Vue | 事件总线 | 消息通知；手动off防泄漏；不存持久状态 |
| Pinia | Vue3 | 全局状态 | 无mutation；actions可直接异步；storeToRefs；简单；多store拆分 |
| Redux‑Toolkit(RTK) | React | 全局状态 | 单向数据流；immer可直接写修改；createAsyncThunk处理异步；单store，多slice拆分 |

> 重点区别：
> - Pinia：**多Store**，每个业务一个store；
> - Redux：**一个Store，多个Slice拆分模块**。

## 7. 高频坑点
1. 原生Redux reducer必须返回全新state，不能直接修改；RTK靠immer可以直接写赋值语法。
2. 异步不能写在reducer，RTK用`createAsyncThunk + extraReducers`。
3. `useSelector`会做浅比较；返回对象时注意：不要直接返回新对象，否则无限重渲染。
4. React‑Redux不需要手动取消订阅，内部自动处理，无mitt那种忘记off的内存泄漏。

## 记忆口诀
> Redux单向数据流，dispatch派action；
> reducer纯函数返回新状态；
> RTK简化写slice，immer允许直接改；
> 异步要用thunk，extraReducers处理结果；
> Provider注入，useSelector读，useDispatch发。
