这行是 Java 面向对象**最核心、最常考**的知识点：
**接口多态：父类型引用，指向子类型对象**

```java
Attackable warrior = new Warrior("亚瑟");
```

我用最直白的方式给你讲清楚：

---

# 1. 左边 Attackable 是什么？
`Attackable` 是**接口类型**，代表：
**“能攻击的东西”**

左边是**变量的类型**，就像：
```java
int a = 10;
```
`int` 是类型，`a` 是变量。

这里：
```java
Attackable warrior
```
= 定义一个 **能攻击类型** 的变量，名字叫 warrior。

---

# 2. 右边 new Warrior("亚瑟") 是什么？
`Warrior` 是**真正的对象**，是具体的战士。

---

# 3. 为什么能把 Warrior 赋值给 Attackable？
因为：
```java
class Warrior implements Attackable
```
**战士 实现了 可攻击接口 → 战士 是一个 可攻击的东西**

所以可以写成：
```java
Attackable warrior = new Warrior();
```

这就像：
```
动物 x = new 狗();
```
狗是动物 → 可以用动物类型接收狗对象。

---

# 4. 这么写有什么好处？（重点）
## 好处1：统一行为，只关注“能攻击”
不管你是战士、法师、弓箭手，
只要实现了 Attackable，我都可以这样写：

```java
Attackable a = new Warrior("亚瑟");
Attackable b = new Mage("吉安娜");
Attackable c = new Archer("艾琳");
```

它们的类型统一是 **Attackable**，
我只需要调用：
```java
a.attack(目标);
b.attack(目标);
c.attack(目标);
```
不用关心具体是谁。

## 好处2：方便扩展，代码不用改
以后你加新职业，只要实现 Attackable，
左边代码完全不变：

```java
Attackable x = new 刺客("阿轲");
```

这就是**面向接口编程**，扩展性极强。

---

# 5. 能不能不写 Attackable，直接写 Warrior？
可以，完全可以：
```java
Warrior warrior = new Warrior("亚瑟");
```
这也对，只是**没有使用多态**。

---

# 6. 最简单的总结
```java
Attackable warrior = new Warrior("亚瑟");
```

翻译成人话：

> 我定义一个**能攻击的角色**，
> 它具体是**战士亚瑟**。

- 左边：规定它**能做什么**（能攻击）
- 右边：规定它**具体是谁**（战士）

这就是 Java 多态最标准的写法。

这句和上一句是**一对儿的多态写法**，我给你用最直白的方式讲透：

```java
Character mage = new Mage("吉安娜");
```

# 1. 拆开看
- 左边：`Character mage`
  定义一个**角色类型**的变量，名字叫 mage
- 右边：`new Mage("吉安娜")`
  创建一个具体的**法师对象**

# 2. 为什么可以这么写？
因为：
```java
class Mage extends Character
```
**法师 继承自 角色**
→ 法师 **是一个** 角色

所以可以用父类 `Character` 接收子类 `Mage` 对象。

---

# 3. 为什么要这么写？
因为我们只关心：
- 它**是个角色**
- 有名字
- 有血量
- 能被攻击、能掉血

不关心它能不能打人、是什么职业。

在你的战斗代码里：
```java
attacker.attack(defender);
```

attack 方法需要的是一个 **目标角色（Character）**，
只要是角色就能被打，不管是战士、法师、小怪都行。

---

# 4. 和上一句对比，彻底懂
```java
Attackable warrior = new Warrior("亚瑟");
Character mage  = new Mage("吉安娜");
```

- `warrior` 用 `Attackable` 接收
  → 强调：**它能发动攻击**

- `mage` 用 `Character` 接收
  → 强调：**它是一个可被攻击的目标**

一个负责**打人**，一个负责**挨打**，
这就是接口和继承在战斗逻辑里的完美分工。

---

# 5. 最简单总结
```java
Character mage = new Mage("吉安娜");
```

意思就是：
> 这是一个**角色**，具体身份是**法师吉安娜**。
> 它可以被攻击、掉血、判断死活，但暂时不强调它会放法术。
