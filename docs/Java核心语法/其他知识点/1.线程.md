# 一、线程是什么？
- **进程**：操作系统分配资源的基本单位（一个运行中的程序）
- **线程**：进程内的执行单元，**CPU 调度的最小单位**
- 一个进程里可以有多个线程，**共享内存**，所以效率高、但会有线程安全问题

一句话：
**进程是车间，线程是工人；一个车间可以多个工人同时干活。**

# 二、创建线程的 4 种方式（必须背）
## 1. 继承 Thread 类
```java
class MyThread extends Thread {
    @Override
    public void run() { }
}
new MyThread().start();
```

## 2. 实现 Runnable 接口（常用）
```java
class MyRunnable implements Runnable {
    @Override
    public void run() { }
}
new Thread(new MyRunnable()).start();
```

## 3. 实现 Callable + FutureTask（可以有返回值、抛异常）
```java
class MyCallable implements Callable<String> {
    @Override
    public String call() { return "ok"; }
}

FutureTask<String> task = new FutureTask<>(new MyCallable());
new Thread(task).start();
String res = task.get(); // 阻塞获取结果
```

## 4. 使用线程池（企业开发唯一推荐）
```java
ExecutorService pool = Executors.newFixedThreadPool(5);
pool.submit(() -> { });
pool.shutdown();
```

# 三、启动线程为什么必须用 start()，不能直接 run()？
- **start()**：启动线程，进入就绪态，等待 CPU 调度，**真正异步执行**
- **run()**：只是普通方法调用，**还是在当前线程同步执行**，没有开启新线程

# 四、线程生命周期（6 种状态）
1. **NEW**：新建，还没 start
2. **RUNNABLE**：可运行（包含正在运行+等待CPU）
3. **BLOCKED**：阻塞（等锁）
4. **WAITING**：等待（wait、join、park）
5. **TIMED_WAITING**：计时等待（sleep、wait(1000)）
6. **TERMINATED**：终止

# 五、常用线程方法（必考）
## 1. sleep()
- 线程休眠，**不释放锁**
- 属于 Thread 类静态方法

## 2. wait() / notify() / notifyAll()
- 属于 Object 的方法
- **必须在同步代码块里使用**
- wait 会**释放锁**，进入等待池

## 3. join()
- 调用线程会**等待该线程执行完毕**再继续
- 常用于：线程执行完再做下一步

## 4. yield()
- 让出 CPU，回到就绪态
- 大概率还是自己继续运行

## 5. interrupt()
- 中断线程（设置中断标志位）
- 不是强制杀死
- 配合 `isInterrupted()` / `Thread.interrupted()` 使用

# 六、sleep 和 wait 区别（高频面试题）
| 对比项        | sleep()               | wait()                     |
|--------------|-----------------------|----------------------------|
| 所属类        | Thread               | Object                    |
| 是否释放锁    | **不释放**           | **释放**                  |
| 使用位置      | 任意地方             | **必须在 synchronized 内** |
| 唤醒方式      | 时间到自动醒         | notify() / notifyAll()     |
| 用途          | 暂停一段时间         | 线程间通信、等待条件       |

# 七、线程安全问题 & 解决方案
多个线程同时操作**共享数据**，就会出现安全问题。

## 解决方案 1：synchronized（自动锁）
- 修饰方法
- 修饰代码块
- 可重入锁、非公平、阻塞

```java
synchronized (obj) { }
```

## 解决方案 2：Lock 接口（手动锁）
```java
Lock lock = new ReentrantLock();
lock.lock();
try { } finally { lock.unlock(); }
```

## 解决方案 3：volatile
- 保证可见性
- 禁止指令重排
- **不保证原子性**

## 解决方案 4：ThreadLocal
- 线程本地变量，每个线程一份副本
- 无竞争、无锁

2. 请求与保持

# 九、线程池（企业开发 99% 场景用它）
## 为什么要用线程池？
- 避免频繁创建销毁线程
- 控制并发数量
- 统一管理

## 核心参数（必须背）
```java
new ThreadPoolExecutor(
    corePoolSize,      // 核心线程数
    maximumPoolSize,   // 最大线程数
    keepAliveTime,     // 非核心线程空闲时间
    unit,              // 时间单位
    workQueue,         // 阻塞队列
    threadFactory,     // 线程工厂
    handler           // 拒绝策略
);
```

## 常用线程池
1. **newFixedThreadPool** 固定线程
2. **newCachedThreadPool** 缓存线程
3. **newSingleThreadExecutor** 单线程
4. **newScheduledThreadPool** 定时任务

⚠️ **阿里规范：不允许使用 Executors 创建，避免 OOM**
手动 new ThreadPoolExecutor

# 十一、高频面试题精简版
1. **创建线程几种方式？**
   继承 Thread、实现 Runnable、Callable、线程池
2. **start 和 run 区别？**
   start 开启线程；run 只是普通方法
3. **sleep 和 wait 区别？**
   sleep 不释放锁，wait 释放锁
4. **synchronized 和 Lock 区别？**
   synchronized 自动，Lock 手动，更灵活
5. **volatile 作用？**
   可见性、禁止重排，不保证原子
6. **线程池参数？**
   核心、最大、队列、工厂、拒绝策略
7. **死锁条件？**
   互斥、请求保持、不可剥夺、循环等待
