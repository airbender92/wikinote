Maven 在 Java 世界中，**相当于前端的 `npm` + `Webpack` / `Vite` 的结合体**，但更偏向于 `npm` 的依赖管理角色，同时具备标准化的项目构建能力。

可以这样拆解对比：

| 功能 | Java (Maven) | 前端生态 |
|------|--------------|----------|
| **依赖管理** | 通过 `pom.xml` 声明依赖，从 Maven 中央仓库下载 jar 包 | 通过 `package.json` 声明依赖，从 npm registry 下载包 |
| **本地仓库** | `~/.m2/repository` | `node_modules` |
| **构建与打包** | 生命周期 `mvn clean compile package` → 生成 jar/war | `npm run build` → Webpack/Vite 打包出 dist |
| **约定目录结构** | `src/main/java`, `src/test/java` 等 | 无强制约定，但通常 `src`, `dist` 等 |
| **插件机制** | 通过 `<plugin>` 扩展功能（如编译、测试、打包） | 通过 Webpack/Vite 插件或 npm scripts |
| **项目元信息** | `groupId:artifactId:version` 唯一坐标 | `name` + `version` |

### 具体对应关系

- **依赖管理**：Maven 的 `pom.xml` 完全等同于前端的 `package.json`。`npm install` 对应 Maven 的 `mvn compile`（首次会下载依赖）。
- **构建工具**：Maven 本身也负责**编译**（`javac`）、**测试**（`mvn test`）、**打包**（`mvn package`）。这需要前端里 `Webpack` / `Vite` 配合 `Babel`、`Jest` 等才能完成。
- **生命周期**：Maven 定义了三套标准生命周期（clean, default, site），前端通常通过 `npm scripts` 组合实现（如 `"build": "webpack --mode production"`）。

### 为什么不是直接等于 `npm`？

因为 `npm` **只解决依赖管理**，而打包构建需要额外工具。Maven 则**内置了整个构建流程**（编译、测试、打包），所以它更像 `npm` + `Webpack` 的合体。但 Maven 本身不处理 Java 代码的转译（Java 编译由 `javac` 完成，Maven 只是调用），所以类比时更强调**依赖管理 + 标准化构建流程**。

### 一句话总结

> **Maven 之于 Java，就像 npm 之于前端 —— 都是包管理器，但 Maven 还自带了项目构建和生命周期管理，相当于 `npm` + `Webpack` / `Vite` 的集成体。**

如果你熟悉前端，理解了 `package.json` + `node_modules` + `npm run build` 的组合，就几乎完全理解了 Maven 的 `pom.xml` + `~/.m2` + `mvn package`。
