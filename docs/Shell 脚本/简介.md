# .sh 文件

`.sh` 是 **Shell脚本文件**，Linux / macOS（类Unix系统）的脚本，相当于 Windows 的 `.bat` / `.cmd` 批处理文件。

## 简单类比

| 系统               | 脚本后缀 | 解释器     |
| ------------------ | -------- | ---------- |
| Linux/macOS        | `.sh`    | bash / sh  |
| Windows cmd        | `.bat`   | cmd.exe    |
| Windows PowerShell | `.ps1`   | powershell |

`.sh` 里面写的就是一条条终端命令，可以批量执行。

### 示例 demo.sh

```bash
#!/bin/bash
echo "hello shell"
echo "当前时间：$(date)"
```

第一行 `#!/bin/bash` 叫**shebang**，声明用bash解释器执行这个脚本。

## 怎么运行（Linux）

1. 给执行权限

```bash
chmod +x demo.sh
```

2. 运行

```bash
./demo.sh
```

或者直接交给bash解释器执行（不需要执行权限）

```bash
bash demo.sh
```

## 和你现在Windows环境关系

> 你现在用 Windows，**Windows默认不能直接双击运行 .sh**

- Windows原生cmd不认识sh脚本
- Windows想要跑sh：可以用 Git‑Bash、WSL(Windows子系统Linux)、cygwin
- nginx windows版本，配置文件是 `.conf`，**不是sh**；windows nginx没有sh脚本，用cmd命令

## 常见看到 .sh 的场景

1. Linux服务器部署项目：启动脚本 `start.sh`、`stop.sh`、`reload.sh`
   ```bash
   # 比如nginx linux启动脚本示例 start.sh
   #!/bin/bash
   /usr/sbin/nginx -t
   /usr/sbin/nginx
   ```
2. 后端项目一键构建、一键启动、一键重启
3. 网上复制的Linux教程经常给`.sh`脚本，**不要直接放到Windows cmd执行**

## 关键点

1. `.sh` = shell脚本，Linux脚本，不是Windows程序。
2. 里面是linux命令，不能在cmd直接跑。
3. Windows看到`.sh`文件，要么用Git‑Bash打开，要么WSL。
4. 你现在操作的Windows nginx、node，不需要写sh脚本，继续用cmd。

### 容易混淆

- `.conf`：nginx配置文件
- `.js`：node脚本
- `.sh`：Linux shell脚本
- `.bat`：Windows批处理脚本

> 如果你网上搜nginx教程，很多linux例子会写 `./nginx.sh`，那是Linux版本，你的Windows不要照搬。Windows执行的是 `start nginx`、`nginx -s reload`。
