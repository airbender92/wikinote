## 环境变量文件解读

### 三个文件对比

| 文件 | 生效场景 | 用途 |
|------|---------|------|
| `.env` | 所有环境 | 通用配置，始终加载 |
| `.env.development` | 开发环境 | `npm run dev` 时加载 |
| `.env.production` | 生产环境 | `npm run build` 后加载 |

### 各自内容

**`.env` — 通用配置（所有环境共享）**
```bash
VITE_APP_TITLE=Vue Demo 管理后台   # 应用标题
VITE_API_PREFIX=/api              # API 前缀
VITE_APP_VERSION=0.1.0            # 版本号
```

**`.env.development` — 开发环境**
```bash
VITE_APP_ENV=development          # 标记开发环境
VITE_API_BASE_URL=http://localhost:8080  # 代理到本地后端
```

**`.env.production` — 生产环境**
```bash
VITE_APP_ENV=production           # 标记生产环境
VITE_API_BASE_URL=/api           # 使用相对路径（后端同域名）
```

### 加载规则

Vite 会**按顺序合并**环境变量：

```
开发时 (npm run dev)：
  .env          → 通用配置
  .env.development  → 开发配置（覆盖同名变量）
  ↓
最终配置

生产构建 (npm run build)：
  .env          → 通用配置
  .env.production   → 生产配置（覆盖同名变量）
  ↓
最终配置
```

### 命名规范

| 规则 | 说明 |
|------|------|
| 必须以 `VITE_` 开头 | 只有 `VITE_*` 才会被注入到客户端代码 |
| `VITE_APP_ENV` | 约定俗成，标识当前环境 |
| `VITE_API_BASE_URL` | API 基础地址 |

### 使用方式

```typescript
// vite.config.ts 中使用
const baseURL = import.meta.env.VITE_API_BASE_URL

// Vue 组件中使用
const title = import.meta.env.VITE_APP_TITLE
```

### 为什么开发用 localhost，生产用 /api？

| 环境 | 原因 |
|------|------|
| 开发 | 后端可能运行在不同端口，用 `http://localhost:8080` 明确指向 |
| 生产 | 前端后端部署在同一域名，用 `/api` 是相对路径，自动匹配当前域名 |

### 开发与生产的区别

```
开发时：
  http://localhost:3000  → 访问 → 代理到 http://localhost:8080

生产时：
  https://example.com    → 访问 → 后端也在 https://example.com/api
```
