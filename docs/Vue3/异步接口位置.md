在 Vue 应用中发起接口请求（如获取数据、提交表单等），选择正确的位置至关重要。不同场景（初始化数据、用户交互、路由变化、轮询等）对应不同的触发点。下面按**选项式 API**、**组合式 API (Vue 3)**、以及**特殊场景**分别说明。

## 一、初始化数据请求（页面/组件加载时拉取数据）

### 1. 选项式 API (Vue 2 & 3)

**最佳位置：`created` 或 `mounted`**

- **`created`**：此时组件实例已创建，`data`、`props`、`methods` 可用，但 DOM 尚未挂载。适合获取初始化数据，特别是数据不依赖 DOM 时（例如 SSR 中也支持 `created`）。
- **`mounted`**：DOM 已挂载，可以访问 `$el`、操作子组件或第三方 DOM 库。如果数据依赖 DOM 尺寸或位置，必须放这里。

```js
export default {
  data() {
    return { list: [], loading: false }
  },
  created() {
    this.fetchList()  // 推荐：早于 DOM 渲染，SSR 兼容
  },
  methods: {
    async fetchList() {
      this.loading = true
      try {
        this.list = await api.getList()
      } finally {
        this.loading = false
      }
    }
  }
}
```

> **注意**：`beforeCreate` 中 `data`/`methods` 未初始化，不适合发请求。

### 2. 组合式 API (Vue 3 `<script setup>`)

**最佳位置：直接在 `<script setup>` 顶层调用异步函数**（相当于 `created` 阶段）

```vue
<script setup>
import { ref, onMounted } from 'vue'
const list = ref([])
const loading = ref(true)

// 方式一：顶层 async (推荐，简单)
const fetchData = async () => {
  loading.value = true
  try {
    list.value = await api.getList()
  } finally {
    loading.value = false
  }
}
fetchData()

// 方式二：放在 onMounted (如果需要 DOM 就绪)
onMounted(async () => {
  // 依赖 DOM 的操作
  await fetchData()
})
</script>
```

**区别**：
- 顶层调用：代码更清晰，请求与组件初始化并行，无 DOM 依赖时首选。
- `onMounted`：适合需要等待 DOM 渲染完毕（如获取元素尺寸、初始化图表库）。

## 二、用户交互触发的请求

这类请求不依赖生命周期，直接在事件处理函数中调用：

```vue
<template>
  <button @click="submitForm">提交</button>
</template>

<script setup>
const submitForm = async () => {
  await api.submit(formData)
  // 处理响应...
}
</script>
```

## 三、路由变化时重新请求数据

### 1. 在路由组件内监听路由参数变化

**选项式**：
```js
watch: {
  '$route.params.id': {
    handler: 'fetchDetail',
    immediate: true
  }
}
```

**组合式**：
```js
import { watch } from 'vue'
import { useRoute } from 'vue-router'

const route = useRoute()
watch(() => route.params.id, (newId) => {
  fetchDetail(newId)
}, { immediate: true })
```

### 2. 利用路由守卫 (例如 `beforeRouteUpdate`)

```js
// 选项式
beforeRouteUpdate(to, from, next) {
  this.fetchDetail(to.params.id)
  next()
}
```

### 3. Vue Router 4 (Vue 3) 的 `onBeforeRouteUpdate`

```js
import { onBeforeRouteUpdate } from 'vue-router'
onBeforeRouteUpdate((to) => {
  fetchDetail(to.params.id)
})
```

## 四、依赖响应式数据变化的请求

当某个响应式数据（如 `selectedId`）改变，需要自动重新请求数据时，使用 `watch`：

```js
import { watch, ref } from 'vue'
const selectedId = ref(1)
const detail = ref(null)

watch(selectedId, async (newId) => {
  detail.value = await api.getDetail(newId)
}, { immediate: true })  // immediate 立即执行一次
```

## 五、组件销毁前的清理（如轮询/长连接）

如果接口是轮询或 WebSocket，需要在组件卸载时清除：

```js
let timer = null
onMounted(() => {
  timer = setInterval(() => fetchLatest(), 5000)
})
onBeforeUnmount(() => {
  clearInterval(timer)
})
```

## 六、服务端渲染 (SSR) 特别注意事项

- **只能在 `beforeCreate` 或 `created` 中发请求**，因为 SSR 没有 `mounted`、`onMounted` 等客户端钩子。
- **不要直接调用异步修改数据的操作**，应该将数据预取逻辑放在路由 `asyncData` (Nuxt) 或组件的 `serverPrefetch` 钩子中。

**Nuxt 3 / Next 风格**：使用 `useAsyncData` 或 `onServerPrefetch`。

```vue
<script setup>
// 仅服务端执行
onServerPrefetch(async () => {
  const data = await fetchData()
  initialState.data = data
})
// 客户端会复用初始数据，避免重复请求
</script>
```

## 七、常见错误位置（避免）

- ❌ **`beforeCreate`**：`data`/`methods` 不可用，且无必要。
- ❌ **`watch` 里不加防抖/节流**：频繁触发（如用户输入）时应使用 `debounce`。
- ❌ **在模板表达式中调用请求函数**：每次重新渲染都会触发，造成死循环。
- ❌ **`computed` 中发请求**：计算属性应同步，且会因依赖变化而频繁执行。

## 八、总结：最佳实践速查表

| 场景 | 推荐位置 |
|------|----------|
| 页面初始化加载数据（不依赖 DOM） | `created` / `<script setup>` 顶层 |
| 页面初始化加载数据（依赖 DOM） | `mounted` / `onMounted` |
| 用户点击/表单提交 | 事件处理函数 |
| 路由参数变化 | `watch` 路由参数 / `onBeforeRouteUpdate` |
| 响应式数据驱动请求 | `watch` (带 `immediate`) |
| 轮询/长连接 | `onMounted` 启动 + `onBeforeUnmount` 清理 |
| SSR 预取数据 | `serverPrefetch` / Nuxt `useAsyncData` |

**一句话原则**：让请求的触发点 **可预测、可控制、无副作用** —— 优先在生命周期早期（`created` 或顶层）发起，避免在渲染过程中触发。
