你这句话对应的就是：**AES-128 加密**
- **密钥（key）**：必须 **16 字节**
- **初始化向量（IV）**：必须 **16 字节**

注意：这里的**“16位”在开发里默认指 16 字节（16 bytes）**，不是 16 比特。

---

## 1. 明确规则
- AES-128：
  - Key = **16 字节**
  - IV = **16 字节**
- 不能多、不能少，否则直接报错。

---

## 2. 字符串 vs UTF-8 字节数组（关键点）
你要加密的密码是**字符串**，但：
- **密钥、IV 必须是字节数组**
- 通常做法：
  1. 给定一个字符串密钥，比如 `"1234567890123456"`
  2. **用 UTF-8 编码成字节数组**
  3. 保证结果长度 **正好 16 字节**

---

## 3. 合法示例
### 密钥字符串（16 个英文字符）
```
keyStr = "1234567890123456"
```
转 UTF-8 字节数组：**正好 16 字节**

### IV 字符串
```
ivStr = "abcdef1234567890"
```
转 UTF-8 字节数组：**16 字节**

这两组就能直接用于 AES-128-CBC 等常见模式。

---

## 4. 常见错误
### 错误 1：长度不够
```
keyStr = "123456"
```
UTF-8 只有 **6 字节** → 报错

### 错误 2：用中文导致变长
```
keyStr = "密钥123456789012"
```
一个中文 UTF-8 占 3 字节 → 总长度**不是 16** → 报错

### 错误 3：以为是 16 比特
16 比特 = 2 字节，完全不对。
开发说的 16 位密钥 = **16 字节**。

---

## 5. 前端加密通用正确流程
1. 用户名、密码是 **字符串**
2. 转为 **UTF-8 字节数组**
3. 使用：
   - key：**16 字节 UTF-8 数组**
   - iv：**16 字节 UTF-8 数组**
4. AES 加密
5. 结果转 Base64 传给后端
