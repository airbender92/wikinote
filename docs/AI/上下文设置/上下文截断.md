## 上下文截断 (Context Truncation)

**简单来说**：AI 能"记住"的历史消息是有限的，超过这个限制就需要丢弃一些旧消息，这就是截断。

### 为什么需要截断？

AI 模型有 **token 上限**（如 GPT-4 约 128K token），一次对话包含太多内容，超出上限就会报错。

### 两种策略

| 策略 | 说明 | 例子 |
|------|------|------|
| **滑动窗口 (Sliding)** | 丢弃**最早的**消息，保留最近的消息 | 有 10 条消息 → 只带最近 5 条给 AI |
| **截断 (Truncate)** | 按 token 数硬性截断，超出部分直接丢弃 | 最多 4096 token → 前几条消息超过就整个丢掉 |

### 你项目中的实现

```
对话历史:
消息1: "你好" (10 tokens)
消息2: "帮我写代码" (20 tokens)
消息3: "再帮我优化" (20 tokens)
...
消息10: "还有问题" (15 tokens)
                        总计: 3000 tokens

发送新消息时，携带的上下文:
├─ maxMessages=5 → 只带最近 5 条
└─ maxTokens=1000 → 如果最近 5 条总计超过 1000 tokens → 继续从最前面丢弃
                    直到 ≤ 1000 tokens
```

### 示例

```
maxMessages=3, maxTokens=50

对话历史:
消息A: "这是一段很长的话..." (30 tokens)
消息B: "另一段话..." (25 tokens)
消息C: "短消息" (5 tokens)

滑动窗口策略:
→ 先取最近 3 条: [A, B, C] 总计 60 tokens
→ 60 > 50，丢弃最前面的 A
→ [B, C] 总计 30 tokens ✅

截断策略:
→ 直接按 token 数截断，可能只保留 C + B 的部分内容
```
