# Rollup：下一代面向 ES Module 的打包工具

## 一、核心定位与设计思想
Rollup 是**以 ES Module（ESM）为原生核心**的 JS 模块打包器，主打**库/SDK/框架打包**，被称为下一代模块化打包工具，Vue、React、Svelte、Vite 生产打包底层均依赖它。
### 核心理念
1. **完全基于静态 ESM 语法**
    ESM `import/export` 是静态语法（编译期即可确定导入导出），区别于 CommonJS `require()` 运行时动态加载；Rollup 可做完整静态语法分析。
2. **Tree-Shaking（树摇）天花板**
    内置极致死代码消除，能精准移除未被引用的函数、变量、导出，输出干净无冗余代码；**仅对纯 ESM 生效**，CommonJS 因动态特性 Tree-Shaking 效果很差。
3. **多格式统一输出**
    一份源码同时输出 `esm/cjs/umd/iife/amd`，适配浏览器、Node、CDN 多场景。
4. **极简、专注**
    不内置资源处理（CSS/图片）、无开发服务器、不做复杂应用代码分割，聚焦「模块打包优化」，插件按需扩展。

## 二、核心关键特性
### 1. Tree-Shaking 树摇（最大优势）
- 原理：遍历 AST，标记未被外部导入的导出，打包时直接删除；
- 对比 Webpack：Webpack 打包库会残留大量 runtime 胶水代码，Rollup 输出近乎手写原生 JS；
- 限制：导入必须使用**具名导入**，禁止全量导入 `import * as xxx`，否则无法摇树。
```js
// ✅ 可被Tree-Shaking
import { add } from './math'
// ❌ 无法摇树，全部打包
import * as math from './math'
```

### 2. 多模块化输出格式
| format | 适用场景 |
|--------|----------|
| `es/esm` | 现代打包工具（Vite/Webpack）、浏览器原生module，最优摇树 |
| `cjs` | Node.js CommonJS 规范 |
| `umd` | 通用模块，同时兼容 Node/AMD/浏览器全局（CDN 库必备） |
| `iife` | 立即执行函数，单独script标签引入浏览器 |

### 3. External 外部依赖剥离
打包库时，将 `package.json` 的 `dependencies/peerDependencies` 标记为外部，不打进产物，减小包体积，交给使用者项目处理。

### 4. 多入口、分块输出
支持单入口打包单文件、多入口分文件输出，`preserveModules` 可保留原目录结构输出模块化文件。

## 三、适用场景 vs 不适合场景
### ✅ 最佳场景（库打包首选）
1. 公共工具库、TS SDK、组件库（Vue3/React 源码均用 Rollup）
2. 需要同时输出 ESM + CommonJS 双格式发布到 npm
3. 追求极致小包体积、充分 Tree-Shaking
4. CDN 通用 UMD 产物构建
5. Vite 生产构建底层（Vite dev 用 esbuild，build 用 Rollup）

### ❌ 不适合场景（应用开发优先选 Vite/Webpack）
1. 大型业务应用（页面多、路由分包、图片/字体/CSS复杂处理）
2. 需要热更新 HMR、开发服务器、实时调试
3. 重度资源处理（图片、字体、复杂 CSS 工程化）
4. 需要复杂代码分割、运行时 chunk 加载

## 四、Rollup / Webpack / Vite 横向对比
| 工具 | 定位 | 核心优势 | 适用场景 |
|------|------|----------|----------|
| Rollup | ESM 库打包器 | 极致Tree-Shaking、干净多格式产物 | 组件库、工具类npm包 |
| Webpack | 全能应用打包器 | Loader/Plugin生态、强大分包、资源处理 | 传统大型SPA应用 |
| Vite | 现代前端开发工具 | 开发时浏览器原生ESM、esbuild极速编译；生产复用Rollup | Vue/React业务项目 |

一句话总结：**写业务用Vite，写库用Rollup，老旧复杂项目用Webpack**。

## 五、快速上手实战
### 1. 安装依赖
```bash
# 核心包
npm i rollup -D
# 必备基础插件
npm i @rollup/plugin-node-resolve @rollup/plugin-commonjs @rollup/plugin-terser -D
# TS项目额外安装
npm i @rollup/plugin-typescript tslib -D
```
插件作用：
- `node-resolve`：解析 node_modules 第三方包
- `commonjs`：转换 CommonJS 依赖为 ESM（否则无法摇树第三方cjs包）
- `terser`：代码压缩混淆

### 2. 标准配置 rollup.config.mjs
```js
import resolve from '@rollup/plugin-node-resolve'
import commonjs from '@rollup/plugin-commonjs'
import terser from '@rollup/plugin-terser'
import pkg from './package.json' assert { type: 'json' }

// 外部依赖，不打包进产物
const external = [...Object.keys(pkg.dependencies || {})]

export default {
  input: 'src/index.ts', // 库入口
  external,
  plugins: [
    resolve(),
    commonjs(),
    terser() // 生产压缩
  ],
  output: [
    // 输出 ESM 格式
    {
      file: pkg.module,
      format: 'es',
      sourcemap: true
    },
    // 输出 CommonJS 格式
    {
      file: pkg.main,
      format: 'cjs',
      sourcemap: true
    },
    // 输出 UMD CDN 格式
    {
      file: pkg.unpkg,
      format: 'umd',
      name: 'MyLib', // 浏览器全局变量名
      sourcemap: true
    }
  ]
}
```

### 3. package.json 配置与打包脚本
```json
{
  "main": "dist/index.cjs",
  "module": "dist/index.es.js",
  "unpkg": "dist/index.umd.js",
  "scripts": {
    "build": "rollup -c",
    "watch": "rollup -c --watch"
  }
}
```
运行打包：`npm run build`

## 六、优缺点总结
### 优点
1. 原生 ESM 支持，Tree-Shaking 行业最优，产物体积最小；
2. 配置简洁，插件体系轻量，无冗余运行时代码；
3. 一键输出多模块规范，npm 库标准打包方案；
4. 插件生态成熟，Vite 官方兼容所有 Rollup 插件；
5. 打包产物可读性高，调试友好。

### 缺点
1. 对 CommonJS 支持有限，第三方cjs库摇树效果差；
2. 无内置CSS、图片、字体资源处理，需额外插件；
3. 不适合大型业务应用，缺少HMR、devServer、复杂分包；
4. 构建速度弱于 esbuild/Rolldown（Rust 重构版 Rolldown 正在开发）。
