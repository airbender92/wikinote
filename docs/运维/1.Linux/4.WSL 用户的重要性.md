# WSL yambo 用户，用户名重不重要

> `yambo` 是一个**普通Linux用户名**，大概率是做第一性原理计算YAMBO软件时专门建的账号。
> 打开WSL时登录哪个用户，**非常重要**，不是随便登录都行。

## 1、用户到底决定什么

1. **家目录不一样**

- 用户`yambo`：文件在 `/home/yambo/`，编译、配置、环境变量`.bashrc`全部存在这里。
- 用户`root`：文件在 `/root/`
- 你自己创建的普通用户：`/home/你的名字/`

> 如果你教程要求用 yambo 用户，你登录成 root 或者别的用户：
>
> - 之前编译安装的yambo程序找不到
> - 环境变量全部失效
> - 跑程序直接报错，报命令不存在

2. **权限不一样**

- `yambo`如果加入了`sudo`组，可以执行`sudo apt update && sudo apt upgrade -y`
- 如果yambo没有sudo权限，执行sudo会报错`yambo is not in the sudoers file`，就没法更新系统、装软件包。
- root 用户不用sudo，直接拥有全部权限，但日常跑仿真软件**不推荐用root跑**，容易权限错乱，生成的文件所有权变成root，普通用户读不了。

3. **环境变量完全隔离**
   Linux每个用户独立一套`.bashrc / .profile`。
   YAMBO软件通常会在`.bashrc`写一堆`export`环境变量。
   👉**换一个用户登录，这些环境变量全部消失，yambo命令直接找不到。**

## 2、怎么确认当前是谁

WSL终端输入：

```bash
whoami
```

输出 `yambo` 才是正确用户；输出root或者别的名字，就不对。

### PowerShell 启动WSL直接进入yambo用户

```powershell
wsl -u yambo
```

## 3、执行 `sudo apt update && sudo apt upgrade -y` 的坑

这条命令**必须登录的用户拥有sudo权限**：

- ✅ yambo用户有sudo：直接执行没问题
- ❌ yambo没加到sudo组：执行sudo直接报错，无法更新系统
- ❌ 你切到root用户：不用sudo，直接`apt update && apt upgrade -y`，但不建议长期root操作。

> 很多人踩坑：教程写“打开WSL(yambo用户)”，他直接点开WSL进去是别的用户，然后疑惑软件为什么不能跑。**不是WSL坏了，是登录错账号**。

## 4、快速区分三种场景

| 登录用户                  | 特点                                 | 适合做什么                               |
| ------------------------- | ------------------------------------ | ---------------------------------------- |
| yambo（普通用户，带sudo） | 家目录/home/yambo，有yambo的环境变量 | ✅编译、运行yambo仿真，日常操作          |
| root超级用户              | 最高权限，家目录/root                | ⚠️只用来修复系统、改配置，不要跑计算任务 |
| 别的普通用户              | 没有yambo的环境配置                  | ❌跑yambo会命令找不到                    |

## 5、如果你的yambo没有sudo权限（报错不在sudoers）

在root下执行，把yambo加到管理员组：

```bash
usermod -aG sudo yambo
```

然后重新登录yambo用户。

### 一句话总结

> “打开 WSL (yambo 用户)”这句话重点就是**登录身份**：
> 因为软件的编译产物、环境变量全部属于yambo这个账号；登错用户，软件就用不了。
> 但是系统更新apt命令本身，只要有sudo权限哪个用户都能干。
