# 云计算定义 + 三层架构 精简总结
## 一、云计算是什么（一句话）
云计算是一种**按需获取、弹性伸缩、按量付费**的资源服务模式，用户可以随时从共享资源池中获取计算、存储、网络等资源，快速开通、快速释放，大幅降低管理成本。

## 二、经典云计算三层架构
### 1. IaaS（基础设施即服务）
- **服务对象**：基础设施运维人员
- **提供内容**：服务器、计算、存储、网络等硬件基础资源
- **用户做法**：自己装操作系统、部署应用、管理中间件
- **例子**：阿里云ECS、AWS EC2、虚拟机

### 2. PaaS（平台即服务）
- **服务对象**：应用开发人员
- **提供内容**：运行环境、数据库、日志、监控、开发工具等平台能力
- **用户做法**：只写业务代码，不用管底层服务器、系统、中间件
- **例子**：Google App Engine、阿里云EDAS、Docker/K8s平台

### 3. SaaS（软件即服务）
- **服务对象**：普通终端用户
- **提供内容**：完整可用的软件系统
- **用户做法**：直接用，不用管技术、部署、维护
- **例子**：钉钉、企业微信、在线Office、各种云应用

---

## 三、三者关系（最通俗理解）
- **IaaS = 给你空地和水电**
- **PaaS = 给你盖好的房子+装修+家具**
- **SaaS = 给你直接能住的酒店房间**

## 一、Docker 官方定义（核心一句话）
Docker 是一个以**容器为基本单位**，封装软件运行环境，用于构建、发布和运行分布式应用的跨平台容器解决方案。
- 开发语言：Go
- 开源协议：Apache 2.0
- 核心技术：利用 Linux 内核的 **Namespace（隔离）** 和 **Cgroups（资源限制）** 实现容器的安全与隔离。

## 三、Docker/容器技术的 7 大核心优势
### 1. 持续部署与测试（环境一致性）
容器消除了线上/线下的环境差异，通过镜像保证开发、测试、生产环境完全一致，大幅简化持续集成（CI）和持续部署（CD）流程。

### 2. 跨云平台支持（不被厂商锁定）
容器镜像一次构建，可在任意支持容器的云平台（AWS、GCP、Azure、OpenStack）运行，避免了传统虚拟机被云厂商绑定的问题，支持多平台混合部署。

### 3. 环境标准化与版本控制
- 可对整个应用运行环境（代码+依赖+配置）进行版本控制，像管理 Git 代码一样管理镜像。
- 故障时可快速回滚到历史版本，启动速度和备份效率远超传统虚拟机镜像。

### 4. 高资源利用率与隔离
- 容器没有虚拟机 Hypervisor 的额外开销，直接共享宿主机内核，性能损耗极低。
- 可通过 Cgroups 精确限制 CPU、内存等资源，保证应用间互不干扰，系统能运行更多实例。

### 5. 跨平台性（构建一次，到处运行）
- Docker 为容器定义了标准化的镜像格式，将应用及其依赖打包成镜像，解决了早期 Linux 容器跨平台性差的问题。
- 镜像可在不同宿主机、不同云平台上无差别运行。

### 6. 简单易用，入门门槛低
- Docker 命令和概念非常直观，开发者通常 15 分钟内即可完成入门并部署第一个容器。
- 易用性加速了容器技术的普及，推动了容器标准化进程。

### 7. 丰富的应用镜像仓库
- Docker Hub 等镜像仓库类似“应用商店”，提供了大量现成的微服务组件、中间件镜像。
- 开发者可直接下载使用，大幅减少重复开发和配置工作。

---

## 四、一句话总结容器生态的核心价值
容器技术通过**标准化的镜像格式、统一的运行时接口和丰富的生态工具**，解决了传统分布式系统开发、部署、运维中的环境不一致、资源利用率低、厂商绑定等痛点，成为云计算从 IaaS 向 PaaS 演进的关键技术支撑。

# 1.3 进化：从容器到容器云 核心解读

## 一、为什么单容器不够用？（痛点）
Docker 虽然能轻松启动单个容器，但一旦进入**生产环境**，就会遇到一系列无法靠单容器解决的问题：
1.  **跨主机协同**：需要成百上千个容器分布在多台服务器上协同工作，而不是只跑在单机上。
2.  **复杂工作负载**：企业级应用（微服务、批处理、定时任务）需要多种类型的容器协同。
3.  **多人协作与持续交付**：需要支持团队开发、CI/CD 流水线，而不是单人维护。
4.  **生产级技术难题**：容器的网络、存储、集群调度、高可用、监控运维等，都需要系统性方案。

一句话：**单容器只是“工具”，容器云才是“平台”**。

---

## 二、什么是容器云？
容器云是以**容器为核心**，解决上述生产级问题的平台级解决方案。
- 它不局限于 Docker，比如基于 rkt 容器的 CoreOS 也是容器云。
- 但 Docker 作为里程碑式的技术，让容器真正普及，所以本书以 Docker 为核心来讲解容器云。

容器云的核心目标：
把零散的容器，变成一个**可调度、可扩展、可运维、高可用**的分布式平台。

---

## 三、主流容器云项目（对应书中后续章节）
业界主流的容器云平台，都是围绕容器技术构建的：
| 项目 | 章节 | 特点 |
| :--- | :--- | :--- |
| **Fleet** | 第6章 | CoreOS 推出的轻量集群管理工具，早期容器编排方案 |
| **Flynn / Deis** | 第7章 | 基于容器的 PaaS 平台，简化应用部署与运维 |
| **Kubernetes** | 第8章 | 谷歌开源的容器编排标准，现在是容器云的事实标准 |

---

## 四、进化的本质：从“容器”到“容器云”
- **容器阶段**：解决的是「怎么打包、运行一个应用」的问题。
- **容器云阶段**：解决的是「怎么大规模、高效、可靠地管理成千上万的容器」的问题。

这是从**单机工具**到**分布式平台**的跨越，也是云计算从 IaaS 向 PaaS 演进的关键一步。
