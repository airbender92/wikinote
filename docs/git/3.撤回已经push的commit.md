# 无法强推=分支开了保护（main/develop大多禁force），**放弃reset+强推，改用revert方案（万能、不用强推、直接普通push）**
## 方案一：首选：git revert（任何受保护分支通用，不用强制推送）
原理：新增一条**反向提交抵消错误代码**，历史不动、普通push就能上传，仓库保护拦不住
```bash
# 1.查提交号
git log --oneline
# 2.撤销最近1次错误提交
git revert HEAD --no-edit

# 撤销指定某一个commit：git revert 提交hash --no-edit

# 3.正常推送（不用-f，普通push即可）
git push origin 你的分支
```
> 连续多个提交要撤回：`git revert 最早commit..最新commit` 再正常push

## 方案二：非要reset删历史（仅自己私有分支）
被保护分支强推失败2个原因+处理：
### ① 平台开启分支保护(GitHub/GitLab/Gitee禁止force)
1. 找管理员临时关掉「禁止强制推送」开关（仓库设置→分支保护）
2. 关掉后再执行：
```bash
git reset --hard HEAD~1
git push origin 分支 --force-with-lease
```
3. 操作完管理员重新开启保护

### ② --force-with-lease报错stale info（远程有别人新提交）
```bash
# 先同步远程最新记录
git fetch origin
# 再强推
git push origin 分支 --force-with-lease
```

## 最简总结
- **线上主分支、被保护、不能强推 → 只用 revert + 普通push（必成功）**
- **个人临时分支、无保护 → 管理员放开限制再reset+强推**
