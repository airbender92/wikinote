# 用最简单的话讲清楚：
**PRD = Product Requirements Document**
中文叫：**产品需求文档**

## 1. 它是干嘛的？
就是把你脑子里想做的软件/功能，
写成**开发能看懂、能直接照着写代码**的一份说明书。

简单说：
- 你想做那个**银行灾备应急演练流程图系统**
- 你不能只说“我要个流程图”
- 要写成 PRD，前端、后端、测试才知道要做成什么样

## 2. 一份标准 PRD 一般包含什么？
- 项目背景：为什么做这个系统
- 功能清单：有哪些页面、哪些按钮、哪些操作
- 页面结构：每个页面长什么样
- 业务流程：比如灾备演练怎么开始、怎么执行、怎么结束
- 字段说明：表单里要填什么、格式是什么
- 交互规则：点击、拖拽、弹窗、状态变化
- 异常处理：报错、网络失败、重复提交怎么处理
- 非功能需求：性能、安全、兼容性

## 3. 对你现在这个项目来说
你要做的是：
**银行数据中心灾备应急演练流程图管理平台**

写 PRD 就是把你刚才说的这些整理成规范文档：
1. JSON 编辑流程图
2. 流程图管理列表（分页、保存、编辑）
3. 拖拽式流程图设计器
4. 演练执行页面（状态：执行中/成功/失败/人工确认/并行串行）
