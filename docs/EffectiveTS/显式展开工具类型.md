你遇到的情况是：鼠标悬停在 `K` 上时，TypeScript 只显示 `type K = keyof Person`，而不是你期望的 `"name" | "birth"`。这通常不是错误，而是 TypeScript 在特定条件下的**显示策略**——它保留 `keyof Person` 而不是立即展开为联合类型。

## 为什么会这样？

TypeScript 的类型系统是结构化的，但类型展示（Quick Info）会尽量保持**原始形式**，尤其是当类型别名直接引用 `keyof T` 时。这有几个原因：

1. **保持可读性**：对于复杂的泛型或交叉类型，展开后可能非常长，保留 `keyof T` 反而更清晰。
2. **延迟计算**：在某些上下文中（例如未完全解析的类型、循环引用），TypeScript 不会强制展开 `keyof`。
3. **Playground 的默认行为**：不同版本的 TypeScript、不同的编辑器（VS Code、Playground）对于 `keyof` 的展示策略有细微差异。

## 如何验证它确实是 `"name" | "birth"`？

你可以用以下几种方式强制 TypeScript 显示展开后的联合类型：

### 方法1：使用 `Extract` 或条件类型
```typescript
type K = keyof Person extends infer U ? U : never;
// 鼠标悬停在 K 上可能仍显示为 keyof Person，但实际是联合类型
```

### 方法2：赋值给一个需要明确联合类型的变量
```typescript
type K = keyof Person;
let x: K = 'name';       // 如果 'name' 可赋值，说明 K 包含 "name"
let y: K = 'birth';      // 同理
let z: K = 'death';      // 应该报错，证明 K 不包含 "death"
```

### 方法3：使用 IDE 的“Go to Type”或“Peek”
在 VS Code 或 Playground 中，**按住 Ctrl（或 Cmd）并点击 `K`**，有时会跳转到定义并展示实际类型。

### 方法4：显式展开工具类型
```typescript
type Expand<T> = T extends infer U ? { [K in keyof U]: U[K] } : never;
type K = Expand<keyof Person>;  // 现在鼠标悬停可能显示 "name" | "birth"
```
但注意 `keyof` 的结果是联合类型，不是对象，`Expand` 对它无效。更直接的方法是：
```typescript
type K = keyof Person;
type ShowMe = K;  // 鼠标悬停在 ShowMe 上？
// 或者使用断言
type K = keyof Person & {};  // 有时 & {} 会强制展开
```

### 方法5：在 Playground 中开启 `noUncheckedIndexedAccess` 或调整设置
Playground 右上角“TS Config”中，切换不同的 `target`、`strict` 标志可能会影响显示，但通常不影响 `keyof` 的展开。

## 结论

你看到的 `type K = keyof Person` 是 TypeScript **正常且合法** 的显示方式，它并不表示类型不是 `"name" | "birth"`，只是展示时没有展开。如果你希望直接看到联合类型，可以尝试将鼠标悬停在**使用 `K` 的地方**（例如 `let a: K`），或者将代码复制到本地 VS Code（通常 VS Code 会在悬停时展开简单的 `keyof`）。

如果上述方法均无效，可以尝试刷新 Playground 或使用最新版本 TypeScript（目前 5.8+）。
