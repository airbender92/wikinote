# RedisInsight：Connection unavailable 无法连接 127.0.0.1:6379

> **核心坑：RedisInsight 是容器！它里面的 `127.0.0.1` 是它自己容器，不是宿主机，也不是 redis‑server 容器**，填127.0.0.1必然连不上。

## 先确认现状

1. 查看redis服务是否正常运行

```bash
docker ps | grep redis-server
```

必须看到 redis-server 状态 Up，如果没启动：

```bash
docker start redis-server
```

2. 测试宿主机本地能不能连redis

```bash
# 宿主机测试，这个能通代表redis服务本身没问题
docker exec -it redis-server redis-cli -a 123456
```

能进入redis命令行，说明redis服务正常，**问题出在RedisInsight连接地址配置**。

---

## 三种正确连接方式（选其一）

### 方式1：两个容器加入同一个docker网络【推荐】

```bash
# 创建网络
docker network create redis-net

# redis-server 加入网络
docker network connect redis-net redis-server

# redisinsight 加入网络
docker network connect redis-net redisinsight
```

> RedisInsight网页添加连接：

- **Host：`redis-server`**（填容器名字！不是127.0.0.1）
- Port：`6379`
- Password：你的redis密码，没有就空

docker内部DNS会把`redis-server`解析到redis容器IP。

### 方式2：Linux环境填写宿主机真实局域网IP

不要填127.0.0.1，填写你本机局域网IP，例如 `192.168.x.x`

> Windows/Mac Docker Desktop可以用 `host.docker.internal`，**Linux不支持host.docker.internal**。

### 方式3：如果你用docker‑compose

compose文件里两个service写同一个`networks`，host直接填服务名`redis-server`即可。

---

## 排查清单（一步步核对）

1. ❌ 不要填 `127.0.0.1`，容器内部指向自己
2. ✅ 同网络下 host = redis容器名称 `redis-server`，端口6379
3. 确认redis启动命令带 `--requirepass xxx`，密码大小写完全一致
4. 确认redis容器AOF/配置没有绑定`bind 127.0.0.1`，会禁止容器间访问

> 如果你redis启动命令是我之前给的：`redis-server --requirepass 123456 --appendonly yes`，bind默认关闭，没问题。

### 快速测试容器之间网络通不通

进入redisinsight容器，测试能否ping通redis‑server

```bash
docker exec -it redisinsight ping redis-server
```

能ping通代表网络DNS没问题；ping不通说明不在同一个docker网络。

```bash
# 查看容器所属网络
docker inspect redis-server | grep NetworkMode
docker inspect redisinsight | grep NetworkMode
```

两个容器必须处在同一个自定义bridge网络，不能都是默认bridge。

---

## 快速复现可用整套命令，直接复制执行

```bash
# 清理旧网络容器
docker rm -f redis-server redisinsight
docker network rm redis-net

# 创建网络
docker network create redis-net

# 启动redis
docker run -d \
  --name redis-server \
  -p 6379:6379 \
  --network redis-net \
  redis redis-server --requirepass 123456 --appendonly yes

# 启动redisinsight
docker volume create redisinsight-data
docker run -d \
  --name redisinsight \
  -p 5540:5540 \
  --network redis-net \
  -v redisinsight-data:/data \
  redis/redisinsight:latest
```

浏览器打开 http://127.0.0.1:5540

> Add Redis Database：
> Host：`redis-server`
> Port：`6379`
> Password：`123456`

测试连接成功。

> 补充：默认docker的bridge网络不支持容器名DNS解析，**必须新建自定义bridge网络**，这是最容易踩的坑。

---

找到了问题！

- `redis-server`：`NetworkMode: bridge`（默认旧网桥）
- `redisinsight`：`NetworkMode: redis‑net`（自定义网络）

**两个容器不在同一个网络，所以 redisinsight 解析不到 `redis‑server` 主机名，连不上 Redis。**

## PowerShell 执行下面命令，把 redis‑server 加入 redis‑net

```powershell
docker network connect redis-net redis-server
```

> 执行完不会有输出，代表成功。

### 再校验网络是否一致

```powershell
docker inspect redis-server | findstr Networks
docker inspect redisinsight | findstr Networks
```

现在 redis‑server 应该同时存在 `bridge` 和 `redis‑net` 两个网络，redisinsight 在 `redis‑net`。

## RedisInsight Web页面配置

- Host：**`redis-server`**
- Port：`6379`
- Password：`123456`

点测试连接，现在就可以通了。

---

### 如果还是失败，排查小技巧

进到 redisinsight 容器内部测试域名解析

```powershell
docker exec -it redisinsight ping redis-server
```

Windows docker 容器 ping 不通也没关系，用 telnet 测试端口：

```powershell
docker exec -it redisinsight redis-cli -h redis-server -p 6379 -a 123456
```

✅ 如果这条命令能进入redis交互界面，说明网络完全没问题，只是网页之前缓存错误，删掉旧连接重新新建一个连接即可。

---

### 补充说明

> 默认 docker `bridge` 网络**不支持容器名DNS解析**，所以必须放到自定义 `redis‑net` 网络内，才能直接用容器名字当host访问。

### 重置备选（如果折腾很乱，直接重建一套干净环境）

```powershell
docker rm -f redis-server redisinsight
docker network rm redis-net
docker network create redis-net

docker run -d --name redis-server -p 6379:6379 --network redis-net redis redis-server --requirepass 123456 --appendonly yes

docker volume create redisinsight-data
docker run -d --name redisinsight -p 5540:5540 --network redis-net -v redisinsight-data:/data redis/redisinsight:latest
```

访问 http://127.0.0.1:5540，host填 `redis-server`，密码`123456`。

---

报错意思：**redis‑server 其实已经在 redis‑net 网络里面了**，只是它还同时挂在默认 bridge 网络。

> 刚才 `docker inspect | findstr NetworkMode` 只显示主网络，不代表它没有附加别的网络。

## 验证真实网络归属（PowerShell）

```powershell
docker inspect redis-server | Select-String "redis-net"
```

能搜到 `redis-net`，确认已经加入。

## 现在问题定位

两个容器都在 `redis‑net`，理论上 `redis-server` 域名可以解析。我们直接在 redisinsight 容器内部测试连通性，判断是网络问题还是网页配置问题：

```powershell
docker exec -it redisinsight redis-cli -h redis-server -p 6379 -a 123456
```

### 情况1：这条命令成功进入redis交互终端

👉 **容器内部网络完全正常！是 RedisInsight 网页缓存/旧连接记录问题**
解决：

1. 在网页里把旧的连接删掉
2. 重新 Add Redis Database

- Host：`redis-server`
- Port：`6379`
- Password：`123456`

> 不要编辑旧连接，删掉重建，很多时候页面会缓存错误状态。

### 情况2：上面命令报错连不上

先看 redis‑server 容器是不是真的正常运行

```powershell
docker ps | findstr redis-server
```

必须状态为 `Up`。

---

## 备选方案（Windows Docker Desktop 专属）

如果容器名访问一直玄学，改用 `host.docker.internal` 指向宿主机。

> redis已经做了端口映射 `-p 6379:6379`

RedisInsight 新建连接填写：

- Host：`host.docker.internal`
- Port：`6379`
- Password：`123456`

> `host.docker.internal` 是 Windows/Mac Docker Desktop 内置域名，指向宿主机IP，**Linux不支持**。
> 这个方式绕开容器DNS，简单粗暴，开发环境非常好用。

---

### 小提示

不要纠结移除默认bridge网络，开发环境容器多挂一个网络不影响使用。

```powershell
# 如果想把redis-server退出默认bridge（可选，非必须）
docker network disconnect bridge redis-server
```

---

哦！**redis/redisinsight 镜像里面没有 redis‑cli 工具**，所以这条命令报错，不能用这个方式测试。换别的测试办法。

## 方法1：在 redis‑server 容器内部测试（可行）

```powershell
docker exec -it redis-server redis-cli -a 123456
```

如果可以进入 redis，说明 redis 服务本身100%没问题。

## 方法2：获取 redis‑server 的容器IP，给 redisinsight 使用

```powershell
docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' redis-server
```

输出类似：`172.19.0.2`，这个就是redis在 redis‑net 网络里的内网IP。

去到 RedisInsight Web，新建连接：

- Host：粘贴上面拿到的IP（例如 `172.19.0.2`）
- Port：`6379`
- Password：`123456`

> 不要修改旧连接，**删除旧连接，新建一条**。

## 备选方案（Windows Docker Desktop，最简单）

直接使用 `host.docker.internal`，走宿主机映射端口，绕过docker容器DNS问题：
RedisInsight新建连接：

- Host：`host.docker.internal`
- Port：`6379`
- Password：`123456`

> 前提：你的 redis‑server 启动时有 `-p 6379:6379` 端口映射。

### 检查端口映射是否存在

```powershell
docker port redis-server
```

应当输出：`6379/tcp -> 0.0.0.0:6379`

---

### 总结排查顺序

1. `docker exec -it redis-server redis-cli -a 123456` ✅确认redis服务正常
2. `docker port redis-server` ✅确认6379端口映射存在
3. RedisInsight新建连接二选一：
   - 填redis容器内网IP（上面inspect拿到的172.x.x.x）
   - 填 `host.docker.internal`（Windows开发首选）

> 不要继续填 `redis-server` 主机名，如果DNS解析异常，直接用IP绕过。
