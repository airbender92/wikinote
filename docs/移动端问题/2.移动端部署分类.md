这个问题问得好——它决定了「预览版」和「真上线」之间差多少。先给结论：**这个项目是纯静态 H5（Vite 构建产物），生产流程和现在做的事本质同构：构建 → 托管 → 域名 → 手机访问**。只是把本地 preview 换成正式的 Nginx/CDN 部署，并补齐 HTTPS、真实接口、鉴权这几件事。

生产全流程如下：

## 分阶段说明

**阶段 1 · 开发联调**（你现在的状态）
本地 dev + mock 开发 → 后端 API 就绪后关掉 MSW、baseURL 指向真实网关 → 接入 SSO/token。当前项目的鉴权、推送都是预留接口，属于这个阶段的事。

**阶段 2 · 构建部署**
`pnpm build` 产物已确认是纯静态（`dist/index.html` + assets）。托管三选一，按企业条件定：

- **Nginx 静态托管**（最常见）：一个 server 块指向 dist，配置简单，内网/公网都行
- **对象存储 + CDN**（COS/OSS）：适合公网分发、流量大、要全国加速
- **容器化**（Docker + Nginx 镜像，K8s 部署）：适合已有云原生平台的公司

⚠️ **这里有一个必踩的坑**：项目用的是 `createBrowserRouter`（history 模式），URL 形如 `/switch-history`。**Nginx 必须配 `try_files $uri $uri/ /index.html;`**，否则手机在子路由刷新会 404。这是 H5 上生产最常见的问题。

**阶段 3 · 移动端分发**（B 端企业的实际形态）

- **企业 App WebView 内嵌**（最常见）：钉钉/企微/自研 App 里打开 H5，可免登录（容器注入身份）
- **浏览器直访**：链接/二维码/工作台入口，需要自己搭登录页
- **PWA 添加到主屏幕**：接入 vite-plugin-pwa 后才有，属于体验增强，非必须

## 上线配套清单

| 事项               | 说明                                   | 现状                             |
| ------------------ | -------------------------------------- | -------------------------------- |
| HTTPS              | 正式域名 + 证书，PWA/部分 API 强制要求 | ❌ 未做                          |
| Nginx history 回退 | `try_files` 配置                       | ❌ 未做（本地 preview 无此问题） |
| 真实接口 + 鉴权    | 关 MSW，接网关与 SSO                   | ❌ 预留中                        |
| PWA 接入           | manifest + service worker              | ❌ 已选型未接入                  |
| CI/CD              | push 触发构建→测试→部署→灰度           | ❌ 未做                          |
| 监控               | 错误上报（Sentry 类）/ 访问日志        | ❌ 未做                          |

## 一句话总结

**现在的 preview 就是"本地模拟生产"**：同样是静态托管 + 局域网访问，只是少了 HTTPS、真实接口、Nginx 回退三件事。真要上生产，把 dist 交给运维部署到 Nginx/CDN，配好域名和证书即可，前端代码本身不需要大改。
