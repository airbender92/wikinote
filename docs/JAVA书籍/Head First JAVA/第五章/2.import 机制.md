# Java包、类全名与import机制知识点梳理
## 一、类的完整限定名（全类名）
1. **概念**
简单类名（如`ArrayList`）不是唯一标识，**包名+简单类名**才是类的完整身份。
示例：`ArrayList`完整名称是 `java.util.ArrayList`。
2. 必须写全名的场景（除`java.lang`包外）
代码中只要用到该类，都需要让编译器识别它来自哪个包，有两种方案。

## 二、两种使用外部API类的方式
### 方式1：全程书写完整限定名（不推荐，繁琐）
在**声明变量、方法入参、方法返回值**所有位置完整写出`包名.类名`。
示例：
```java
// 定义变量
java.util.ArrayList<Dog> list = new java.util.ArrayList<Dog>();
// 作为方法形参
public void go(java.util.ArrayList<Dog> list) {}
// 作为方法返回值
public java.util.ArrayList<Dog> foo() {...}
```

### 方式2：文件头部写`import`导入（推荐）
在`.java`文件最顶部添加导入语句，后续代码可直接简写简单类名`ArrayList`，无需重复包名。

## 三、特殊豁免：`java.lang`包
只有`java.lang`下的类（`String`、`System`、`Math`等）**不需要写全类名、不用手动import**，编译器会自动隐式导入。

## 四、包(package)的三大核心作用
1. **代码分类管理**
把功能相近的类分组收纳（Swing界面类放`javax.swing`、集合工具放`java.util`），避免一堆零散文件难以维护。
2. **解决类名冲突（命名空间）**
多人开发、使用第三方库时极易出现同名类（比如自己写`Set`，API也有`java.util.Set`），完整包名区分二者，JVM不会混淆。
3. **包访问权限控制**
可以限制类、方法、变量仅能被**同包内其他类**访问，提供基础代码安全隔离，第16章详细讲解。

## 五、补充：包命名规范
业界统一域名倒置命名规范，从根源降低不同团队包名重复概率，第16章展开说明。

## 关键总结
1. 非`java.lang`的类，JVM无法仅凭简单类名定位；
2. 两种使用方式：全限定名处处书写 / 顶部`import`简写；
3. 包三大价值：分类、防重名、控制访问权限。
