# 逐段完整解读：What you’ll do in Java（Java完整开发实操流程）
这段内容以**GUI派对邀请函`Party`程序**为实例，完整演示Java从写代码→编译→运行的三步标准操作，搭配源码、命令、字节码、执行流程拆解。

## 一、第一步：编写并保存Java源代码
### 1. 源码代码解析
```java
// 导入AWT图形工具包（GUI窗口、按钮、标签依赖）
import java.awt.*;
import java.awt.event.*;
// 定义程序主类 Party
class Party {
    // 构建邀请函窗口的方法
    public void buildInvite() {
        Frame f = new Frame();       // 创建窗口容器
        Label l = new Label("Party at Tim’s"); // 文本标签
        Button b = new Button("You bet");       // 按钮1
        Button c = new Button("Shoot me");      // 按钮2
        Panel p = new Panel();                 // 面板容器
        p.add(l);                              // 把标签放入面板
        // ...此处省略剩余界面代码
    }
}
```
### 2. 操作要求
1. 在文本编辑器录入以上代码；
2. **强制文件名规则**：保存为 `Party.java`
   Java规定：公共类/主类文件名必须和类名完全一致（大小写匹配）。

## 二、第二步：使用`javac`编译源代码
### 1. 编译命令
```bash
%javac Party.java
```
`%` 是终端命令行提示符，`javac` 是JDK自带**Java编译器**。
### 2. 编译器两大行为
1. **语法全量校验**：扫描代码，语法错误、包缺失、类型不匹配都会直接报错，不会生成文件；
2. **生成字节码文件**：无报错则输出 `Party.class`，这个文件内部存储**Java字节码指令**。
### 3. 展示`Party.class`内部字节码片段
字节码是JVM专属中间指令，人类无法直接阅读，示例两段：
1. `Party`类构造方法字节码
```
Method Party()
0 aload_0
1 invokespecial #1 <Method java.lang.Object()>
4 return
```
- `aload_0`：加载当前对象`this`；
- `invokespecial`：调用父类`Object`的构造方法；
- `return`：构造方法执行完毕。

2. `buildInvite()` 方法字节码
```
Method void buildInvite()
0 new #2 <Class java.awt.Frame>
3 dup
4 invokespecial #3 <Method java.awt.Frame()>
```
- `new`：创建`Frame`窗口对象；
- `invokespecial`：执行窗口构造函数。

### 核心概念：`Party.class` = 字节码文件
不绑定Windows/Mac/Linux任何系统，**跨平台载体**，是Java实现“一次编译到处运行”的核心。

## 三、第三步：JVM运行字节码程序
### 1. 运行命令
```bash
%java Party
```
`java` 命令用于启动**Java虚拟机(JVM)**。
### 2. JVM执行逻辑
1. 读取`Party.class`字节码文件；
2. 将平台无关的字节码，实时翻译成**当前操作系统、CPU能识别的本地机器码**；
3. 执行程序，弹出GUI派对窗口（Tim的派对界面）。

## 四、四阶段完整流程总览（对应文中1/2/3/4标注）
1. **Source 源码阶段**：手写`.java`源代码
2. **Compiler 编译阶段**：执行`javac` → 生成`.class`字节码
3. **Bytecode 中间文件**：平台中立的指令文件，可任意拷贝分发
4. **Virtual Machines 运行阶段**：`java`命令启动JVM，翻译并执行字节码

## 五、补充关键说明
1. 示例说明：这段代码只是流程演示，**不作为完整GUI教学**，仅让新手建立「写代码→编译→运行」整体认知，后续章节才会完整讲解语法、GUI开发；
2. 工具区分：
   - `javac`：编译器，只做静态检查、转字节码，**不运行程序**；
   - `java`：启动JVM虚拟机，负责真正执行程序；
3. 跨平台核心逻辑：同样一份`Party.class`，Windows、Mac、Linux系统各自的JVM都能独立翻译运行，不需要修改源代码。当前文件内容过长，豆包只阅读了前 28%。
