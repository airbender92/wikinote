# 代码问题完整解析
## 一、逐行拆解原有代码逻辑
```java
public String checkYourself(String stringGuess) {
    // 1. 将输入的数字字符串转为int整数
    int guess = Integer.parseInt(stringGuess);
    // 2. 默认结果设为miss（未命中）
    String result = "miss";
    // 3. 遍历存储站点格子的数组locationCells
    for (int cell : locationCells) {
        // 4. 如果猜测数字和格子匹配
        if (guess == cell) {
            result = "hit";
            numOfHits++; // 命中计数器+1
            break; // 找到匹配值，结束循环
        }
    }
    // 5. 命中次数等于站点总格子数，判定击沉
    if (numOfHits == locationCells.length) {
        result = "kill";
    }
    System.out.println(result);
    return result;
}
```

## 二、Bug 产生的根本原因
存储格子的容器是**定长数组 `int[] locationCells`**，数组一旦初始化，内部元素无法删除。
只要数组里还存在这个数字，玩家每次输入它，都会触发：
`result = "hit"; numOfHits++;`
同一个格子会反复累加命中次数，违反游戏规则。

### 错误演示示例
假设站点格子：`locationCells = {2, 3, 4}`，总格子3个
1. 输入2：匹配成功 → `numOfHits = 1`，输出hit
2. 再次输入2：数组仍包含2，再次命中 → `numOfHits = 2`，输出hit
3. 第三次输入2：依旧匹配 → `numOfHits = 3`，满足判定条件，输出kill
玩家重复猜同一个位置就直接击沉，明显逻辑漏洞。

### 原文点明核心缺陷
代码没有区分**首次命中**和**重复猜测已命中格子**，只要数组存在该数值就统计一次命中。我们需要机制标记/移除已经命中的格子，重复输入不再计数。

## 三、修复方案（本书标准解法：ArrayList）
将固定数组替换为可变集合`ArrayList<Integer>`，命中后直接删除该坐标，后续无法再次匹配，无需额外标记：
```java
import java.util.ArrayList;
// 把 int[] locationCells 改为 ArrayList<Integer> locationCells

public String checkYourself(String stringGuess) {
    int guess = Integer.parseInt(stringGuess);
    String result = "miss";
    // 查找猜测数字在集合中的下标
    int index = locationCells.indexOf(guess);
    if (index != -1) {
        locationCells.remove(index); // 命中，直接删除该格子
        result = "hit";
        // 集合为空 = 全部格子命中，击沉
        if (locationCells.isEmpty()) {
            result = "kill";
        }
    }
    System.out.println(result);
    return result;
}
```

## 四、修复后的效果
1. 第一次输入2：集合删除2，返回hit；
2. 再输入2：集合中无该数字，index=-1，直接返回miss，不会增加命中计数；
3. 只有分别猜中2、3、4三个不同数字，集合清空才会输出kill，逻辑正常。

## 五、关键总结
1. 数组的局限性：元素不可删除，无法消除已命中坐标；
2. Bug核心：重复命中的格子依然会累加`numOfHits`；
3. 解决方案：使用`ArrayList`动态移除命中元素，天然避免重复计数，同时可以省去手动维护`numOfHits`计数器。当前文件内容过长，豆包只阅读了前 85%。
