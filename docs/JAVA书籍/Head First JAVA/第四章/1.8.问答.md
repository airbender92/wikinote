## 二、拟人访谈：ArrayList VS 普通数组（核心对比）
### 1. 共性
数组和ArrayList都存放在堆内存，都支持下标取值。

### 2. 数组致命短板（ArrayList的核心优势）
1. **数组没有内置方法，无法真正删除元素**
    数组只能把下标赋值`null`占位，元素物理上依然存在；
    ArrayList自带`remove()`，直接移除引用、集合自动收缩长度。
2. **数组长度固定，无法动态伸缩**
    创建时必须写死容量，存多了越界、存少了浪费；
    ArrayList自动扩容/缩容，无需手动新建数组、复制元素。
3. **数组无内置工具方法**
    判断包含元素、统计有效数量、查找下标都要手写循环；
    ArrayList自带`contains()/indexOf()/size()/isEmpty()`等开箱即用方法。
4. **原生基本类型存储限制**
    数组可以直接存`int/boolean`等基础类型；
    ArrayList**只能存对象**，基础类型必须包装（Java5.0自动装箱/拆箱自动完成，不用手动转换）。

### 3. 性能客观说明
极少数极端场景下纯数组存取速度微快一点，但差距极小；
牺牲大量便捷性换微小性能提升，绝大多数业务开发完全不划算；
只有大批量基础数值运算场景才优先数组。

### 4. 底层真相
ArrayList底层内部确实封装了普通数组作为存储容器，但它把扩容、删除、查找等繁琐逻辑全部封装，开发者无需手动处理底层复制。

## 三、关键知识点补充
1. **自动装箱（Java5新特性）**
    向`ArrayList<Integer>`存入`int`、取出时转回`int`，编译器自动完成`Integer`包装、拆包，不用手动写`new Integer(5)`；
2. **开发取舍**
    日常业务、游戏、数据存储优先ArrayList；
    固定长度纯数值计算、追求极致性能才使用普通数组；
3. Java编程思想：复用API，拒绝重复造轮子，内置类经过官方测试，稳定可靠。

## 四、数组 vs ArrayList 简明对照表
| 对比维度 | 普通数组 Array | ArrayList |
|--------|---------------|-----------|
| 长度 | 创建后固定，不可变 | 动态自动扩容/缩容 |
| 删除元素 | 仅能置null，无法彻底移除 | remove()直接删除，集合缩小 |
| 内置方法 | 无任何工具方法 | size/contains/indexOf/isEmpty/remove/add等 |
| 存储类型 | 可直接存基本类型、对象 | 仅存对象，基本类型自动装箱 |
| 写法 | `String[] arr = new String[5]` | `ArrayList<String> list = new ArrayList<>()` |
| 性能 | 微量更快（纯数值场景） | 绝大多数场景性能可忽略 |
| 适用场景 | 长度固定、海量基础数值运算 | 长度不确定、频繁增删查找 |当前文件内容过长，豆包只阅读了前 76%。
