# SimpleDotComGame 游戏Bug解析
## 1、正常预期运行效果
敌方站点占据连续3个格子（示例：4、5、6），玩家依次输入1、2、3、4、5、6：
- 1/2/3：miss（未命中）
- 4/5：hit（命中）
- 6：kill（击沉）
最终统计总猜测次数为6次，逻辑正常：每个坐标只计算一次命中，重复输入不会重复判定命中。

## 2、Bug错误现象
若敌方站点坐标为2、3、4，玩家连续三次输入数字`2`：
1. 第一次输入2 → hit
2. 第二次输入2 → hit
3. 第三次输入2 → kill
仅3次猜测就直接击沉站点，明显不符合游戏规则。

## 3、Bug根源
游戏代码**命中后没有移除已命中的坐标**：
数组/集合中依然保留2这个位置，重复输入同一个命中坐标时，程序会再次判定为hit，重复计数命中次数，凑够3次hit直接触发kill。
正确逻辑应当：每次命中后，把当前坐标从存储列表中删除，再次输入该数字只会提示miss，无法重复刷命中。

## 4、修复方案（本书后续解法）
使用`java.util.ArrayList`存放站点坐标，命中时调用`remove()`移除当前匹配元素：
- 每次玩家输入数字，遍历ArrayList比对；
- 匹配成功则删除该元素，返回hit；
- 列表清空时判定kill；
- 再次输入已删除数字，无匹配元素，返回miss，杜绝重复刷分漏洞。当前文件内容过长，豆包只阅读了前 90%。
