# 代码Bug完整拆解 & 问题根源 & 修复思路
## 一、原方法逻辑梳理
```java
public String checkYourself(String stringGuess) {
    int guess = Integer.parseInt(stringGuess);
    String result = "miss";
    // 遍历存放站点格子的数组 locationCells
    for (int cell : locationCells) {
        if (guess == cell) {
            result = "hit";
            numOfHits++; // 命中计数+1
            break;
        }
    }
    // 命中次数等于格子总数 → 击沉
    if (numOfHits == locationCells.length) {
        result = "kill";
    }
    System.out.println(result);
    return result;
}
```
### 执行流程
1. 将玩家输入字符串转为数字；
2. 默认结果设为`miss`；
3. 遍历数组，只要玩家数字匹配任意格子：标记`hit`、命中计数器`numOfHits`直接+1，跳出循环；
4. 总命中数等于格子数量，改为`kill`。

## 二、核心Bug原因
数组`locationCells`**不会删除已经命中的格子**：
玩家重复输入同一个命中坐标时，循环依旧能匹配到数组里的该数字，代码会**重复执行 `numOfHits++`**，重复累加命中次数。

举例：站点格子`{2,3,4}`
1. 输入2 → 匹配成功，`numOfHits = 1`
2. 再次输入2 → 数组里仍有2，再次匹配，`numOfHits = 2`
3. 第三次输入2 → 再次匹配，`numOfHits = 3`，直接判定`kill`
游戏规则被破坏：同一个位置重复猜也能叠加命中计数。

## 三、修复核心思路
不能使用固定数组`int[]`，改用**可变集合 `ArrayList<Integer>`**存储格子坐标：
匹配命中后，立刻从集合中移除当前命中数字。
下次玩家再输入该数字，集合中无匹配元素，不会触发`numOfHits++`。

## 四、修复后标准代码（本书方案）
```java
import java.util.ArrayList;

// 把 locationCells 从 int[] 改为 ArrayList<Integer>
ArrayList<Integer> locationCells;

public String checkYourself(String stringGuess) {
    int guess = Integer.parseInt(stringGuess);
    String result = "miss";
    
    // 判断集合是否包含玩家猜测数字
    int index = locationCells.indexOf(guess);
    if (index >= 0) {
        locationCells.remove(index); // 命中直接删掉该格子
        result = "hit";
        // 无需手动维护numOfHits，集合长度为0即击沉
        if (locationCells.isEmpty()) {
            result = "kill";
        }
    }
    System.out.println(result);
    return result;
}
```
### 修复后逻辑优势
1. 命中坐标被永久移除，重复输入不会再判定hit；
2. 不需要单独`numOfHits`计数器，直接通过集合是否为空判断是否击沉；
3. 彻底解决重复刷命中、快速kill的漏洞。

## 五、关键总结
1. 原数组缺陷：元素无法删除，重复匹配会重复计数；
2. 漏洞本质：没有标记/清除已命中的格子；
3. 解决方案：使用`ArrayList`动态删除命中元素，保证同一个坐标仅能算一次命中。当前文件内容过长，豆包只阅读了前 90%。
