# 《Sink a Dot Com》完整版项目改造需求总结
## 一、整体架构调整
项目拆分3个核心类，运行时共生成5个对象、4个`ArrayList`容器：
### 三大类职责分工
1. **DotComBust（游戏主类）**
    游戏入口与逻辑调度，负责创建站点、接收玩家输入、循环游戏直到全部站点击沉。
2. **DotCom（站点实体类）**
    单个网站站点对象，存储站点名称、坐标集合，提供判断猜测命中的方法。
3. **GameHelper（预制工具类 Ready-bake）**
    封装两大工具逻辑：控制台读取玩家输入、随机生成网格上站点坐标，主类直接调用无需手写算法。

### 运行时对象&容器
- 5个对象：1个DotComBust、3个DotCom实例、1个GameHelper
- 4个ArrayList：游戏主类1个（存放3个站点）、每个DotCom各1个（存放自身占据的网格坐标）

## 二、DotCom 类需要修改的内容
1. **新增实例变量 `name`**，用于存储站点名称（Pets.com / Go2.com / AskMe.com）；
2. 配套`setter`方法，供游戏主类传入站点名称；
3. 站点被击沉时，可以打印自身名称；
4. 内部使用`ArrayList`存储网格坐标，替代原先固定数组，解决重复命中Bug。

## 三、DotComBust 游戏主类改造清单
1. **创建3个DotCom对象**，不再只创建1个；
2. 逐个调用站点的setter方法，为每个站点赋予专属名称；
3. 调用GameHelper工具，**在二维网格随机放置3个站点**（旧版本仅单行坐标）；
4. 玩家每次猜测，循环校验**全部3个存活站点**，而非仅单个站点；
5. 游戏循环机制：持续接收玩家输入、校验猜测，直到所有站点全部击沉；
6. 重构代码逻辑，把复杂业务移出`main()`方法，避免全部逻辑堆在主函数；
7. 使用`ArrayList`统一管理3个DotCom站点对象，方便遍历、移除已击沉站点。

## 四、GameHelper 工具类作用（无需修改，直接复用）
预制现成代码，封装复杂随机坐标算法与控制台输入逻辑，简化主类代码量：
1. 读取玩家在控制台输入的猜测坐标；
2. 自动生成网格内不重叠、连续的站点坐标，省去手写随机数学逻辑。

## 五、核心技术改动亮点
1. 全面替换固定数组为`ArrayList`：站点集合、每个站点坐标都用动态集合，彻底解决重复猜测刷kill的漏洞；
2. 面向对象拆分：职责分离（实体/游戏调度/工具类），代码结构清晰，不再把所有逻辑写在一处；
3. 二维网格随机布局，升级原单行简易地图；
4. 多对象批量遍历：主集合存放全部站点，循环校验每一次玩家猜测。当前文件内容过长，豆包只阅读了前 76%。
