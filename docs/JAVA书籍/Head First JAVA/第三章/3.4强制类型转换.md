# 基础类型强制转换 & 字符串转int 知识点总结
## 一、原生基本类型强制转换（Cast）
### 1. 自动转换规则（隐式转换）
小范围基本类型**可以直接赋值给大范围类型**，编译器自动完成，无需强转：
```java
int x = 42;
long y = x; // 合法，int自动提升为long
```
反过来**大范围不能直接赋值给小范围**，编译报错：
```java
long y = 42;
int x = y; // 编译失败：long范围大于int，存在数据丢失风险
```

### 2. 强制转换语法（显式强转）
格式：`(目标小类型) 变量`，强制把大范围数值截断为小类型尺寸
```java
long y = 42;
int x = (int) y; // 强制把long转为int，x=42
```
#### 两种典型场景
1. **整数截断，数值溢出失真**
当大数超出小类型存储上限时，二进制直接截断，结果变成奇怪负数（基于补码、符号位规则）：
```java
long y = 40002;
short x = (short) y; // short仅16位，截断后x = -25534
```
2. **浮点数转整数：直接舍弃小数部分，不四舍五入**
```java
float f = 3.14f;
int x = (int) f; // x = 3，小数0.14直接丢掉
```

### 3. 绝对禁止的强转
`boolean` 和所有数字基本类型**不能互相强转**，不存在任何转换方式。

## 二、字符串 String 与 int 不能用强转互通
### 1. 核心报错示例
基本类型、字符串是完全两类体系，`==`、强制转换都不兼容：
```java
String num = "2";
int x = 2;
if (x == num) // 编译报错：== 不能同时用于int和String
int a = (int) num; // 同样编译失败，String无法强转为数字
```
原因：
- `int` 是**基本原生类型**，存二进制数字；
- `String` 是**引用对象类型**，存字符文本；
二者底层结构完全不同，cast强制转换不起作用。

### 2. 正确方案：Integer.parseInt()
使用包装类`Integer`的静态方法，把数字格式字符串解析为int值：
```java
String stringGuess = "2";
int guess = Integer.parseInt(stringGuess);
```
#### 方法拆解
- `Integer`：Java内置数字包装类（对应基本类型`int`）
- `parseInt(String s)`：接收数字字符串，解析并返回对应int整数
适用场景：控制台输入、页面输入全部是字符串，需要转数字做数值比较、运算。

## 三、强转 vs parseInt 核心区分
| 操作 | 适用对象 | 作用 | 限制 |
|------|---------|------|------|
| `(类型)变量` 强制转换 | 仅**数字基本类型**（byte/short/int/long/float/double） | 二进制层面截断/提升数值 | 不能转String、不能转boolean |
| `Integer.parseInt()` | 数字格式`String` → `int` | 文本数字解析为原生整数 | 字符串必须是纯数字，含字母会抛运行异常 |

## 四、关键总结
1. 小→大数字类型：自动隐式转换；大→小数字类型：必须手动`(类型)`强转，可能丢失数据；
2. 浮点数强转整数直接舍弃小数，不进位；
3. boolean和任何数字不能互转；
4. String和int无法强制转换，必须使用`Integer.parseInt()`解析字符串数字；
