# 文档：Objectville 故事 · 方法重写（Override）
## 核心问题
Larry 质疑：
变形虫的旋转和发声逻辑完全不一样，如果它从 Shape 继承，怎么可能表现不同？

## Brad 的答案：**方法重写（Override）**
**重写 = 子类重新定义父类中已有的方法**
当子类需要和父类不一样的行为时，直接在子类里写一个同名、同参数的方法，把父类的方法覆盖掉。

---

## 1. 继承结构回顾
```
Shape（父类）
  ↳ rotate()
  ↳ playSound()

  Triangle（子类）→ 继承 rotate() / playSound()
  Square（子类）   → 继承 rotate() / playSound()
  Circle（子类）    → 继承 rotate() / playSound()
  Amoeba（子类）    → 重写 rotate() 和 playSound()
```

- **父类 Shape**：更抽象、通用
- **子类 Amoeba**：更具体、特殊

---

## 2. Amoeba 重写方法
Amoeba 虽然继承自 Shape，但它**重新实现**了这两个方法：

```java
class Amoeba extends Shape {
    // 重写父类方法
    rotate() {
        // 变形虫专属旋转逻辑（绕一端旋转）
    }

    // 重写父类方法
    playSound() {
        // 播放 .hif 格式的特殊声音
    }
}
```

运行时，JVM 会自动调用**子类自己的版本**，而不是父类版本。

---

## 3. OO 的核心思想：对象自己照顾自己
Larry 还在用过程式思维：
“你要调用一个过程，再告诉它要旋转哪个物体。”

Brad 解释真正的 OO 方式：
- 你告诉**三角形对象**去旋转
- 你告诉**变形虫对象**去旋转
- 每个对象自己知道该怎么做
- 外部代码不需要关心内部实现

```java
triangle.rotate();
amoeba.rotate();
```

- 程序不用管内部逻辑
- 要加新形状，只加新类
- 旧代码完全不用改

---

## 4. 关键术语总结
- **继承（Inheritance）**：子类获得父类的方法，实现代码复用
- **重写（Override）**：子类重新定义继承来的方法，实现独特行为
- **父类（superclass）**：更通用、抽象
- **子类（subclass）**：更具体、特殊
