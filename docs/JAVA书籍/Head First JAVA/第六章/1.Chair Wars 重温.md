# Chair Wars 重温：继承核心知识点总结
## 一、故事背景回顾
第2章中过程式程序员Larry批评Brad的设计：Square、Circle、Triangle、Amoeba四个图形类都重复写了`rotate()`、`playSound()`方法，存在大量重复代码，维护成本极高。
Brad通过**继承（Inheritance）**重构代码，解决代码冗余问题。

## 二、继承三步设计思路
1. **抽取公共逻辑**
找出所有子类（Square/Circle/Triangle/Amoeba）共有的行为：旋转`rotate()`、播放音效`playSound()`。
2. **创建父类（超类 superclass）**
新建顶层通用类`Shape`，把公共方法全部放入`Shape`，只保留一份实现。
3. **建立继承关系**
让四个图形类成为`Shape`的**子类（subclass）**，子类自动拥有父类全部可继承方法。
语法理解：`Square extends Shape`，读作“Square继承自Shape”。

## 三、核心概念定义
1. **超类（父类 superclass）**：存放多个子类通用属性/方法的顶层类（本例`Shape`）。
2. **子类（subclass）**：继承父类，复用父类代码，还能扩展独有逻辑（Square、Circle等）。
3. **继承核心能力**
子类**自动复用父类非私有方法**，全局只维护一份公共代码，修改仅需改动父类，不用逐个修改所有子类，大幅降低维护成本。

## 四、继承解决的核心痛点（Larry提出的问题）
原设计：4个类各写一套`rotate()`，修改旋转逻辑要改4处，极易漏改、产生不一致bug。
继承优化后：仅在`Shape`写一次`rotate()`，所有子类共享；统一修改只需改动父类一处代码。

## 五、补充伏笔（后文会讲）
如果某个子类（如Amoeba）需要和父类不一样的旋转逻辑，可以**方法重写(override)**：在Amoeba中重新定义`rotate()`，运行时优先执行子类自己的方法，兼顾代码复用与个性化实现。

## 核心一句话
继承通过抽取公共代码到父类，消除重复，实现代码复用，简化程序维护。


# 核心内容通俗拆解（不用逐字翻译，讲懂继承+重写）
## 1 对话背景
之前设计图形程序：正方形、圆形、三角形、变形虫都属于**Shape（图形）**，所以提取公共代码放到父类Shape里，自带`rotate()`旋转、`playSound()`播放声音两个通用方法。
但需求出问题：普通图形都是绕中心旋转，**变形虫要绕端点转**，音效也不一样。Larry疑惑：既然变形虫继承了父类的旋转方法，怎么改它独有的逻辑？

## 2 Brad给出解决方案：方法重写（Override）
### 重写是什么？
子类把从父类继承过来的方法**重新写一遍**，换成自己专属的逻辑。
- 父类Shape：通用rotate（绕中心）、通用音效
- 子类Amoeba（变形虫）：重写rotate，改成绕端点旋转；同时重写播放声音的方法，用专属音效
### 运行原理（多态核心）
程序跑起来（runtime）的时候，JVM会识别你当前是哪个对象：
如果是正方形/圆形 → 执行父类原版rotate；
如果是变形虫 → 自动执行它重写后的rotate，不用改父类一行代码。

### 好处
公共逻辑全部复用在父类，只给特殊子类单独改写行为，不用复制一大堆重复代码，需求变更只改子类就行，不破坏已经测好的父类代码。

## 3 课后思考题：老虎和家猫的继承设计
### 核心判断标准：IS-A规则（继承的硬性前提）
只有**子类是父类的一种特殊品类**，才能用继承。
1. 能不能让老虎当父类、家猫当子类？
不行。家猫并不是“一种老虎”，逻辑不成立，IS-A不满足。
2. 正确分层：顶层父类 Feline（猫科动物）
所有猫科通用行为写在父类：睡觉、奔跑、捕猎、叫声
3. 两个子类：Tiger老虎、HouseCat家猫
需要重写的方法：
- hunt()捕猎：老虎捕猎大型野兽，家猫抓老鼠，逻辑完全不同，各自重写
- makeSound()发声：老虎吼叫，猫咪喵喵叫，单独重写
其余通用动作（睡觉、走路）直接复用父类代码，不用重复写。

## 补充关键知识点
1. 重写只针对**继承来的方法**，变量不能重写；
2. 运行时多态：同一个父类引用，指向不同子类，调用同一个方法会跑出不同效果，这是重写最大价值；
3 继承不能乱用，违背IS-A逻辑的类不要父子关系，改用组合（HAS-A）。


# 用通俗思路讲这段继承知识点
## 一、继承核心定义
做程序设计时，把**所有子类共用的代码**抽出来放到一个通用父类（抽象类），其他细分类去继承它。
Java 语法：子类 `extends`（扩展）父，子类会自动拿到父类的**实例变量 + 方法**（类的成员）。

举例子：
父类 `SuperHero`（超级英雄，通用抽象模板）
所有英雄都有的属性：战衣、紧身裤、专属能力；
所有英雄通用行为：释放能力、穿上战衣。
子类 `PantherMan`（黑豹侠）继承它，自动拥有上面所有属性和方法。

## 二、子类能做两件事
1. **新增独有的变量/方法**：父类没有的功能，自己加；
2. **重写(override)继承来的方法**：父类通用逻辑不适合自己，重新写一套专属实现。

## 三、两个子类对比看懂重写
1. `FriedEggMan`（煎蛋侠）
他的行为完全符合父类通用逻辑，不需要改动，**不用重写任何方法**，直接复用父类所有代码。
2. `PantherMan`（黑豹侠）
穿战衣、释放能力的逻辑和普通英雄不一样，所以**重写 `putOnSuit()`、`useSpecialPower()` 两个方法**，替换成自己专属逻辑。

## 四、重点：实例变量不存在“重写”
只有方法能重写，成员变量不用重写。
原因：变量只是存数据，没有行为逻辑。子类直接给继承来的变量赋不同值就行。
例子：
父类有 `tights`（紧身裤）变量；
黑豹赋值紫色，煎蛋侠赋值白色，直接赋值区分，不需要改写变量本身。

## 五、整体类结构梳理
父类 SuperHero（通用模板）
属性：suit、tights、specialPower
方法：useSpecialPower()、putOnSuit()

子类1 FriedEggMan：完全复用父类，无重写
子类2 PantherMan：继承全部属性，重写两个行为方法

# 逐题拆解+答案（结合继承规则）
## 类结构梳理
### 父类 Doctor
实例变量：`worksAtHospital`（1个）
方法：`treatPatient()`（1个）

### 子类 FamilyDoctor extends Doctor
1. 继承父类全部实例变量：`worksAtHospital`
2. 自己新增变量：`makesHouseCalls`
3. 继承父类方法：`treatPatient()`（没有重写）
4. 自己新增方法：`giveAdvice()`

### 子类 Surgeon extends Doctor
1. 继承父类实例变量：`worksAtHospital`（无新增变量）
2. 继承父类方法并重写：`treatPatient()`
3. 自己新增方法：`makeIncision()`

---
## 问题答案
1. Surgeon 有多少实例变量？
**1个**，只有从Doctor继承的`worksAtHospital`，自己没定义新变量。
2. FamilyDoctor 有多少实例变量？
**2个**：继承的`worksAtHospital` + 自己的`makesHouseCalls`。
3. Doctor 有多少方法？
**1个**：`treatPatient()`。
4. Surgeon 有多少方法？
**2个**：重写后的`treatPatient()` + 新增`makeIncision()`。
5. FamilyDoctor 有多少方法？
**2个**：继承的`treatPatient()` + 新增`giveAdvice()`。
6. FamilyDoctor 能执行 treatPatient() 吗？
**可以**，继承了父类这个方法，且没有重写，直接复用父类逻辑。
7. FamilyDoctor 能执行 makeIncision() 吗？
**不能**，这个方法是Surgeon独有的，父类、其他子类都没有。

## 补充关键知识点
1. 继承会全盘拿到父类的实例变量和方法；
2. 子类新增变量/方法不会影响父类、其他子类；
3. 重写只修改当前子类的方法实现，不改变父类；
4. 子类只能访问自己 + 父类的成员，其他子类独有的方法无法调用。

# 一、设计思路：抽取通用父类 Animal
## 1. 为什么要抽 Animal 父类
Dog、Wolf、Cat、Tiger、Hippo、Lion 这些动物全都重复拥有：图片、食物、活动范围、坐标、饥饿值，还有吼叫、进食、睡觉、游荡行为。
如果每个动物类单独写一遍变量和方法，会大量重复代码。利用**继承**，把所有动物共有的状态、行为全部放到顶层父类 `Animal`，各个动物子类直接 `extends Animal`，不用重复写通用代码。

## 2. 父类 Animal 完整成员
### 实例变量（所有动物通用状态）
1. `picture`：动物图片文件名
2. `food`：食物（meat 肉 / grass 草）
3. `hunger`：饥饿度 int
4. `boundaries`：活动区域宽高
5. `location`：XY 坐标位置

### 通用方法（所有动物都有的行为）
1. `makeNoise()`：发出叫声（父类提供通用空实现，食肉猛兽子类可重写专属叫声）
2. `eat()`：进食，减少饥饿值
3. `sleep()`：睡觉行为
4. `roam()`：空闲时四处游荡

# 二、各个动物子类设计（Dog / Wolf / Cat / Tiger / Hippo / Lion）
所有子类只需要写**独有的属性、独有的行为，重写差异化方法**，通用内容全部继承 Animal，不用重复定义 picture/food/hunger 等。
## 统一独有变量：`prey`
所有猛兽子类都新增独有变量 `prey`（猎物），这是 Animal 父类没有的专属属性。

## 差异化重写：`makeNoise()`
不同动物叫声完全不一样，因此每个子类都**重写父类 makeNoise()**，实现专属叫声逻辑；
其余方法 `eat()` / `sleep()` / `roam()` 如果不需要特殊逻辑，直接复用父类，不用改动。

### 举例：
1. Dog 子类
```java
public class Dog extends Animal {
    // 独有属性：猎物
    String prey;
    // 重写叫声
    @Override
    void makeNoise() {
        System.out.println("Woof woof");
    }
}
```
2. Tiger 子类
```java
public class Tiger extends Animal {
    String prey;
    @Override
    void makeNoise() {
        System.out.println("Roar!!!");
    }
```
Hippo、Lion、Wolf、Cat 写法同理，仅修改 `makeNoise()` 里的叫声内容。

# 三、这套继承方案的好处
1. **消除代码重复**：图片、坐标、饥饿、游荡、睡觉等通用代码只写一次在 Animal，6 个子类直接继承；
2. **便于统一修改**：如果以后要修改动物饥饿度计算逻辑，只改父类 `eat()`，全部动物生效，不用挨个改 Dog、Tiger 等；
3. **灵活扩展差异化逻辑**：只有叫声、猎物这种独有内容写在子类，代码干净清晰；
4. 符合 OO 的 IS-A 规则：Dog IS Animal、Tiger IS Animal，继承逻辑合理。

# 四、补充区分
- 通用内容：全部放在父类 Animal（复用）
- 子类独有：`prey` 变量 + 重写 `makeNoise()`（差异化定制）
- 无特殊需求的方法（sleep、roam、eat）：完全继承，不用重写

# 这段内容核心解读（动物继承设计思路）
## 1、实例变量：全部放在父类Animal，不用子类修改
所有动物（狮子、河马、老虎、狗）共用同一套成员变量：图片、食物、饥饿值、活动边界、坐标。
每个动物只是**变量存的值不一样**（比如狮子food是肉，河马是草），但变量本身不需要子类新增/改写，直接继承父类即可。

## 2、行为方法：区分通用 & 必须重写的方法
### ① 不需要重写（通用逻辑，所有动物行为一致）
`sleep()` 睡觉、`roam()` 四处游荡
不管是狮子还是河马，睡觉、闲逛的底层逻辑没有专属差异，父类写一套通用实现，所有子类直接复用。

### ② 必须被子类重写（每个动物行为完全不同）
`makeNoise()` 发出叫声、`eat()` 进食
理由：
1. 叫声差异极大：狗吠、狮子咆哮、猫喵喵、河马低吼，不能统一写一套通用逻辑；
2. 进食方式有区分：食肉猛兽和食草动物进食动作、逻辑不一样；
3. 进阶场景：同一动物不同场景叫声不同（进食/遇到天敌两种声音），父类统一写法无法覆盖这种个性化需求。

## 3、设计原则（面向继承的3步判断法）
设计父子类时判断规则：
1. 提取所有子类**共有的状态（实例变量）**，放到顶层父类；
2. 提取所有子类**完全通用、无差异化的行为**，父类实现，子类直接继承；
3. 如果某个方法的逻辑**每个子类都有专属独特实现**，就交给子类重写（override）。

## 4、类比之前图形案例
和前面 Shape/Amoeba 逻辑完全一致：
父类Shape通用旋转逻辑，变形虫行为特殊，重写`rotate()`；
父类Animal通用睡觉、游荡；狮子、狗、河马进食和叫声特殊，重写`eat()`、`makeNoise()`。

## 5、补充书中否定的偷懒方案
本来可以在父类只存一个声音文件变量，`makeNoise()`统一播放这个文件，不用重写。
但作者不推荐：这种写法太单薄，无法实现“同一种动物不同场景发出不同声音”的复杂行为，丧失面向对象多态的灵活性，所以选择重写方案。

## 最终类设计结论
父类 Animal：
变量：picture / food / hunger / boundaries / location
方法：
- 通用实现：sleep()、roam()（子类直接用）
- 空/通用模板：eat()、makeNoise()（所有动物子类必须重写，实现专属行为）
各个动物子类（Dog/Lion/Hippo等）：
1. 继承全部5个实例变量，仅修改变量存储的值；
2. 重写 eat()、makeNoise()；
3. 直接复用 sleep()、roam()，无需改动。

# 分层继承优化思路（多层父类，减少重复代码）
## 一、现有问题
目前所有动物都直接继承顶层`Animal`，`Dog/Wolf`、`Cat/Tiger/Lion`每组内部有大量重复代码：
1. Dog、Wolf 都是犬科，二者除了叫声、进食细节外，大量特征一致；
2. Cat、Tiger、Lion 都是猫科，共享一套独有属性、行为；
现在全部平铺在Animal下，犬科、猫科各自的通用逻辑会在每个子类重复写，代码冗余。

## 二、新增中间抽象父类，分层继承
采用**三层继承结构**：顶层通用父类 → 分科中间父类 → 具体动物子类
### 第一层（顶层父类）：Animal
保存**所有动物通用**的状态与行为
成员变量：picture、food、hunger、boundaries、location
通用方法：sleep()、roam()
预留待重写方法：makeNoise()、eat()

### 第二层（中间分类父类，只给同科动物继承）
1. Canine（犬科，Dog、Wolf的父类）
独有共同属性/行为：比如锋利犬齿、群居相关逻辑、专属捕猎方式
Dog、Wolf 不再直接继承Animal，改为`extends Canine`，自动继承Animal全部内容 + 犬科专属通用代码，二者只需要重写各自差异化的makeNoise()、eat()即可，不用重复写犬科公共逻辑。

2. Feline（猫科，Cat、Tiger、Lion的父类）
独有共同属性/行为：利爪、独居捕猎、潜行漫游逻辑等
Cat、Tiger、Lion 继承Feline，间接继承Animal，共享全部猫科通用代码。

### 第三层（最底层具体动物子类）
Dog、Wolf、Cat、Tiger、Lion、Hippo
- Hippo（河马）不属于犬/猫科，直接继承顶层Animal；
- 犬/猫的具体动物只需要重写自身独有的`makeNoise()`、`eat()`，同科重复代码放到中间父类复用。

## 三、完整继承层级结构
```
Animal（所有动物顶层父类）
├─ Canine 犬科中间类（Dog、Wolf的父类）
│  ├─ Dog
│  └─ Wolf
├─ Feline 猫科中间类（Cat、Tiger、Lion的父类）
│  ├─ Cat
│  ├─ Tiger
│  └─ Lion
└─ Hippo 河马（无中间父类，直接继承Animal）
```

## 四、这么设计的好处
1. 进一步消除重复代码：犬科共有逻辑只写一次在Canine，猫科共有逻辑只写一次在Feline，不用每个子类复制；
2. 分层清晰，符合现实生物分类逻辑，可读性更强；
3. 后续新增同类动物（比如狐狸属于犬科），直接继承Canine，自动拥有犬科全部通用代码，扩展简单；
4. 差异化逻辑仅保留在最底层具体动物，只重写专属叫声、进食方法，代码干净。

## 五、核心设计思想
设计继承体系时不要只分两层（总父类+所有子类），**多组子类存在共性时，新增中间分层父类**，把该分组独有的公共代码抽离出来，最大化代码复用。


# 完整分层类层级设计（最终版）
## 整体继承树
```
Animal（顶层总父类，全部生物通用）
├─ Feline 猫科中间父类
│  ├─ Lion 狮子
│  ├─ Tiger 老虎
│  └─ Cat 家猫
├─ Canine 犬科中间父类
│  ├─ Wolf 狼
│  └─ Dog 狗
└─ Hippo 河马（无中间分类，直接继承Animal）
```
## 1. 顶层父类 Animal（所有动物共享）
### 实例变量（全局通用）
picture、food、hunger、boundaries、location、size、prey
### 方法
- `sleep()`：全部动物逻辑一致，通用实现，所有子类直接复用
- `roam()`：**通用默认游荡逻辑**（独居/群居无特殊行为的动物使用）
- 待子类重写模板：`makeNoise()`、`eat()`

## 2. 中间分类父类：Feline（猫科）、Canine（犬科）
### Feline 猫科（Lion/Tiger/Cat 的父类）
1. 继承 Animal 全部属性、sleep()
2. **重写 `roam()`**：猫科天性独居，游荡逻辑统一（单独行动、避开同类），所有猫科动物直接复用这个专属 roam，不用各自重写
3. 不实现 makeNoise()、eat()，留给 Lion/Tiger/Cat 各自重写专属叫声、进食方式

### Canine 犬科（Wolf/Dog 的父类）
1. 继承 Animal 全部属性、sleep()
2. **重写 `roam()`**：犬科群居，游荡逻辑统一（成群活动），狼、狗直接复用
3. makeNoise()、eat() 交由底层子类单独重写

## 3. 底层具体子类
### 猫科子类（Lion、Tiger、Cat）
继承 Feline → 间接继承 Animal
- 复用：Animal全部变量、sleep()、Feline重写后的独居 roam()
- 必须重写：`makeNoise()`（狮吼/虎啸/猫叫）、`eat()`（各自进食行为）

### 犬科子类（Wolf、Dog）
继承 Canine → 间接继承 Animal
- 复用：全部成员变量、sleep()、犬科群居版 roam()
- 重写：专属叫声、进食逻辑

### Hippo 河马（直接继承 Animal）
无中间分类父类
- 复用 Animal 原生通用 `roam()`，不需要单独改写游荡行为
- 仅重写 makeNoise()、eat()

# 核心设计亮点
1. 贴合生物分类，层级清晰，复用最大化
2. 区分三层抽象：
   全局通用逻辑（Animal）→ 分科独有通用逻辑（Feline/Canine）→ 物种专属差异化逻辑（各个动物重写 eat/makeNoise）
3. roam 方法分层处理：
   - 犬科统一群居漫游逻辑，放 Canine
   - 猫科统一独居漫游逻辑，放 Feline
   - 河马无特殊习性，直接用 Animal 默认漫游方法
4. 只有每个物种独有的叫声、进食行为才需要重写，大量公共代码只写一次，彻底消除重复代码

# 逐行拆解调用逻辑 + 核心规则
## 继承层级回顾（从上到下，上层=通用，下层=更具体）
`Animal`（顶层） → `Canine`（犬科中间类） → `Wolf`（狼，最底层子类）
各层方法实现情况：
1. Animal：`sleep()`、通用`roam()`、空模板`makeNoise()`/`eat()`
2. Canine：**重写父类`roam()`**（犬科群居漫游逻辑），没有写`makeNoise()`、`eat()`、`sleep()`
3. Wolf：重写`makeNoise()`、`eat()`，没有重写`roam()`、`sleep()`

## 四句代码分别调用哪个类的方法
```java
Wolf w = new Wolf();
w.makeNoise();
w.roam();
w.eat();
w.sleep();
```
1. `w.makeNoise()`
JVM 先找 Wolf 类，里面有重写的该方法 → **执行 Wolf 的 makeNoise()**
2. `w.roam()`
先查 Wolf：无此方法；向上找父类 Canine，Canine 重写了 roam → **执行 Canine 的 roam()**
3. `w.eat()`
先查 Wolf：存在重写版本 → **执行 Wolf 的 eat()**
4. `w.sleep()`
先查 Wolf：没有；再查 Canine：也没有；向上到顶层 Animal，找到方法 → **执行 Animal 的 sleep()**

## 核心规则：底层优先（最低层级获胜）
调用对象方法时，JVM 查找顺序**从当前最具体的子类逐层向上回溯**：
1. 优先在当前对象所属类（最底层）找对应方法，找到直接执行；
2. 当前类没有，就往上找直接父类；
3. 持续向上遍历继承链，直到找到匹配方法；
4 重写的方法会覆盖上层父类的实现，永远优先使用子类自定义版本。

## 举例辅助理解
如果是 Tiger 对象，调用`roam()`：
查找顺序 Tiger → Feline → Animal，Feline 重写了 roam，最终执行猫科的独居漫游逻辑。
如果是 Hippo 对象调用`roam()`：
Hippo 无中间父类，自身没有 roam，直接使用 Animal 默认漫游方法。

# IS-A（继承）与 HAS-A（组合）核心区分
## 一、IS-A 关系 → 对应 `extends` 继承
### 判断标准
一句话：**X IS A Y（X是一种Y）** 逻辑通顺，才能用继承。
### 合法示例
1. Triangle IS-A Shape → 三角形是一种图形 ✔，`Triangle extends Shape`
2. Cat IS-A Feline → 猫是一种猫科动物 ✔，`Cat extends Feline`
3. Surgeon IS-A Doctor → 外科医生是一种医生 ✔，`Surgeon extends Doctor`

### 反例：浴缸 & 浴室
Tub IS-A Bathroom（浴缸是一种浴室）❌
Bathroom IS-A Tub（浴室是一种浴缸）❌
两者不存在“一类属于另一类”，**绝对不能用继承**。

## 二、HAS-A 关系 → 组合（类中放另一个类的实例变量）
### 判断标准
**X HAS-A Y（X里面包含/拥有Y）** 逻辑通顺，就用组合。
实现方式：在X类里定义Y类型的引用变量。
### 浴缸案例拆解
1. Bathroom HAS-A Tub（浴室拥有一个浴缸）
```java
class Bathroom {
    Tub bathtub; // 组合：浴室包含浴缸对象
    Sink theSink;
}
```
2. Tub HAS-A Bubbles（浴缸有泡泡）
```java
class Tub {
    int size;
    Bubbles b; // 组合
}
class Bubbles {
    int radius;
    int colorAmt;
}
```
三个类互相持有对方对象，但**没有任何 `extends` 继承**。

## 三、两者核心区别总结
| 关系 | 语法 | 核心含义 | 使用场景 |
|------|------|----------|
| IS-A 继承 | `class X extends Y` | X 是 Y 的特殊子类，共享大量通用属性/行为 | 多个事物属于同一大类，提取公共代码复用 |
| HAS-A 组合 | 类内声明另一个类变量 `Y y;` | X 内部包含、持有 Y 对象 | 两个事物是“包含/拥有”关系，无从属分类 |

## 四、设计避坑重点
不要滥用继承！只要套不上「X是一种Y」这句话，一律改用组合。
错误设计：`Bathroom extends Tub`
原因：浴室并不是浴缸，两者是包含关系而非分类关系，继承会造成逻辑混乱、代码冗余。

# 核心知识点：继承链全程满足 IS-A 规则
## 1. IS-A 具有传递性
只要存在完整继承链，子类对**所有上层父类**都满足 `X IS-A Y`：
- `Canine extends Animal` → Canine IS-A Animal
- `Wolf extends Canine` → Wolf IS-A Canine
- 传递推导：Wolf IS-A Animal

无论父类隔了多少层，这条规则永久成立。只要某个类在继承树的上方，子类就属于这个大类。

## 2. 对象能调用整条继承链里所有方法
Wolf 继承 Canine，Canine 继承 Animal，因此 Wolf 对象天然拥有三层所有方法：
`makeNoise()`、`eat()`、`roam()`、`sleep()`
哪怕 Wolf 重写了部分方法、Canine 重写了`roam`，**对外调用不受影响**。
外部代码只关心“狼具备动物的全部行为”，不用关心方法是在哪一层实现的。
- 外部代码只需要写 `wolf.makeNoise()`，JVM 自动找最底层重写版本；
- 从外部视角看：只要是 Animal 子类，就一定能执行 Animal 定义的全部行为。

## 3 继承的对外设计意义
这套层级对外传递的逻辑：
Wolf 是犬科，犬科是动物 → 狼拥有犬科所有能力，同时拥有所有动物通用能力。
重写只是**内部实现细节**，不会改变对外可用的方法列表。
举个例子：
别的代码拿到一个 Wolf 引用，不需要区分它是狼、犬科还是普通动物，直接调用动物标准方法即可，这就是多态的基础。

## 4 反例对比（区分 IS-A / HAS-A）
Wolf 和 Tub 这种包含关系不满足 IS-A；
但 Wolf → Canine → Animal 整条继承链路，全部符合 IS-A 判断，这是继承和组合最关键的分界线。

## 一句话总结
继承链上 IS-A 可无限向上传递；子类天然拥有整条继承树的全部方法，方法重写只改变内部实现，不对外暴露差异。

# 答疑+继承设计完整准则通俗解读
## 一、两个核心疑问解答
### Q1：父类能反过来调用子类重写后的方法吗？
**不能，不存在反向继承**
1. 编写父类时，它完全不知道未来会出现哪些子类，甚至程序运行前子类都还没写出来；
2. 继承是单向的：子类继承父，父母不会继承孩子；父类代码无法主动感知、调用子类独有的实现。
3. 补充：多态场景下，**父类引用指向子类对象**时，调用方法会执行子类重写版本，但这不是父类主动调用子类，是对象本身的类型决定执行逻辑，父类源码依旧看不到子类。

### Q2：重写方法时，想先执行父类原有逻辑，再加自己的代码怎么做？
用关键字 `super.方法名()` 调用父类同名方法
示例（犬科Canine重写roam）：
```java
@Override
void roam() {
    // 先执行Animal里通用的漫游逻辑
    super.roam();
    // 再追加犬科独有的群居逻辑
    System.out.println("狼群集体行动");
}
```
`super` 代表直接父类，先复用父类实现，再拓展子类专属逻辑，这才是`extends`“拓展功能”的本意，不是完全替换父方法。

## 二、继承设计四大硬性准则
### ✅ 推荐使用继承（DO）
1. **满足IS-A关系**：子类是父类的细分特殊类型
例：柳树(Willow) extends 树(Tree) → 柳树是树，逻辑成立
2. **多个同类子类共享大量通用代码**，抽去父类复用，方便维护
例：正方形、圆形、三角形都要旋转、发声，公共逻辑放到Shape父类。
> 提醒：继承只是代码复用方案之一，更灵活的方案会在《Head First设计模式》中讲解。

### ❌ 禁止使用继承（DO NOT）
1. **仅为复用代码强行继承，不满足IS-A**
错误案例：Alarm闹钟类有打印代码，钢琴Piano也需要打印，就让Piano extends Alarm。
问题：钢琴根本不是闹钟，正确做法：新建Printer打印类，用HAS-A组合，Piano持有Printer对象。
2. **通不过IS-A测试，绝对不用继承**
例：Tea IS-A Beverage（茶是饮品 ✔），反过来Beverage IS-A Tea（饮品是茶 ❌），不能反过来继承。

## 三、补充关键知识点
1. `super` 只能在子类重写的方法内部使用，用来调取父类同名方法；
2 访问控制（public/private/protected）会影响子类能继承哪些成员，第16章和附录会详细讲；
3. 继承核心价值：归类同类事物、复用通用代码；违背IS-A就破坏面向对象逻辑，后续维护灾难。

# 本段核心内容通俗拆解
## 一、继承 = 定义统一对外协议（契约）
1. 父类定义一套公开方法，就等于定下一份**通用协议**：所有它的子类（无论隔几层继承），都一定具备这套行为。
2. 以 `Animal` 举例：
父类声明 `makeNoise()、eat()、sleep()、roam()` 四个公开方法，就对外承诺：**任何动物（Animal、猫科、犬科、狮子、狼等）都能执行这四个方法**。
方法的名字、入参、返回值全部统一，只是每个子类内部实现逻辑可以重写不一样的版本。
3. 补充：这里说的可继承方法现阶段指`public`公共方法，后续会细化访问修饰符规则。
4. 覆盖范围：只要类的继承链上层存在这个父类，就必须遵守这份协议（比如 Wolf、Tiger、Hippo 全都属于 Animal 体系，都要实现这套行为）。

## 二、多态的核心铺垫（本段重点）
父类体系带来最大好处是**多态（polymorphism）**，多态的核心规则：
**需要父类类型引用的地方，完全可以传入任意子类对象**。
简单说：可以用父类变量，去接收、指向子类实例。

示例：
```java
// 父类引用，指向Wolf子类对象
Animal animal = new Wolf();
animal.makeNoise(); // 实际执行Wolf重写的叫声方法
```

## 三、多态带来的巨大代码优势
1. **代码极度灵活、简洁**
不用为每一种动物单独写一套处理逻辑，统一用父类`Animal`类型接收所有动物对象，一套代码兼容所有动物子类。
2. **后期扩展零侵入**
后续新增动物（狐狸、豹子等），只需要新建一个继承 Animal 的子类、重写四个方法，**原有业务代码完全不用修改**。
同事扩展程序时，不需要改动你当初写的核心源码，维护成本极低。
3. 开发效率大幅提升，后续迭代维护成本大幅降低。

## 四、逻辑串联总结
1. 父类定义统一行为协议 → 所有子类强制拥有这套方法；
2. 依托这套继承体系诞生多态；
3. 多态允许父类引用接收任意子类；
4. 最终实现可扩展、低维护的高质量代码。

# 核心讲解：对象创建三步 + 铺垫多态原理
## 一、创建对象完整三步 `Dog myDog = new Dog();`
### 步骤1：声明引用变量 `Dog myDog`
1. JVM 在栈内存开辟一块空间，创建名为 `myDog` 的引用变量；
2. **类型固定终身**：这个遥控器只能操控 `Dog` 类型对象，不能指向 Cat、按钮、网络套接字等其他任何类型；
3. 此时变量为空，还没有关联任何堆上的实体对象。

### 步骤2：堆上新建对象 `new Dog()`
`new` 关键字命令 JVM 在**可回收堆内存**分配内存，创建一个真实的 Dog 对象，对象里存储所有实例变量、方法。

### 步骤3：绑定引用与对象 `=`
把堆上 Dog 对象的地址存入 `myDog` 引用变量，相当于给遥控器配对实体小狗；
之后用 `myDog.bark()` 这种点操作，就能调用对象的属性和行为。

可视化类比：
引用变量 = 遥控器（栈）
对象 = 真实小狗（堆）
赋值操作 = 遥控器绑定小狗

## 二、本段作用：为多态做铺垫
这是**普通写法（引用类型 = 对象类型完全一致）**：引用 Dog，创建 Dog。
而多态的核心改动就是：**引用写父类类型，实际创建子类对象**，下一部分会对比两种写法，展示多态效果。
普通写法：`Dog myDog = new Dog();`
多态写法示例：`Animal myDog = new Dog();`
引用是顶层父类 Animal，但堆里真实对象是 Dog，这就是多态的基础语法。

# 核心对比：普通引用 vs 多态引用
## 1. 常规写法（引用类型 = 对象类型）
```java
Dog myDog = new Dog();
```
- 引用变量 `myDog` 的声明类型：`Dog`
- 堆上实际创建的对象类型：`Dog`
- 二者类型完全一致
- 遥控器只能控制Dog，只能指向Dog对象，只能调用Dog里所有方法（包括Dog独有的方法）

## 2. 多态写法（引用 ≠ 对象）
```java
Animal myDog = new Dog();
```
- 引用变量 `myDog` 声明类型：**父类 Animal**
- 堆中真实对象：**子类 Dog**
- 引用类型和实际对象类型不一样，这就是多态的基础形式

## 关键两条规则
### 规则1：编译期（编译器看引用类型）
代码编译时，只认引用的类型`Animal`。
只能直接调用`Animal`类中定义的方法（`makeNoise/eat/sleep/roam`），Dog独有的方法直接调用会编译报错。
想要调用子类独有方法，必须向下转型。

### 规则2：运行期（JVM看真实对象）
程序运行调用方法时，会看堆里真实的Dog对象。
如果Dog重写了Animal的方法，执行的一定是Dog重写后的版本。
示例：
```java
Animal myDog = new Dog();
my.makeNoise(); // 运行执行Dog的makeNoise()，不是Animal的空实现
```

## 通俗类比
普通写法：遥控器是Dog专用遥控器，只能控制小狗；
多态写法：通用Animal万能遥控器，但现在绑定的实体是小狗；
遥控器能操作所有动物通用功能，小狗专属按键按不了，但通用按键触发时小狗专属动作会生效。

# 多态实战案例完整解读
## 1 多态数组代码示例
```java
// 定义Animal类型数组，数组里只能存满足IS-A Animal的对象
Animal[] animals = new Animal[5];
// 数组每个位置存入不同Animal子类实例
animals[0] = new Dog();
animals[1] = new Cat();
animals[2] = new Wolf();
animals[3] = new Hippo();
animals[4] = new Lion();

// 循环统一调用父类定义的方法
for (int i = 0; i < animals.length; i++) {
    animals[i].eat();
    animals[i].roam();
}
```

## 2 核心原理
1. **引用类型规则**
只要某个类满足 `子类 IS-A 引用类型`，这个子类对象就可以赋值给该引用。
数组元素的声明类型是`Animal`，所有继承Animal的子类（Dog/Cat/Wolf/Hippo/Lion）都符合`X IS-A Animal`，因此全部能放进数组。

2. **编译 & 运行两层逻辑**
- 编译阶段：编译器只识别`Animal`类型，只允许调用Animal中定义的`eat()、roam()、makeNoise()、sleep()`，子类独有的方法无法直接调用；
- 运行阶段：JVM会识别数组里**真实对象类型**，自动执行对应子类重写的方法。

## 3 代码运行效果
循环里两行统一代码，不同对象执行完全不同逻辑：
- `animals[0].eat()` → 执行Dog重写的进食逻辑
- `animals[1].eat()` → 执行Cat重写的进食逻辑
- `animals[2].roam()` → 执行Wolf（Canine）群居漫游逻辑
- `animals[3].roam()` → 执行Hippo继承的Animal默认漫游逻辑

不需要写大量if/else区分动物种类，一套循环代码适配所有Animal子类，这就是多态最大价值。

## 4 多态数组的巨大优势
1. **代码极简统一**：不需要为每种动物单独写处理逻辑；
2. **极易扩展**：新增老虎、狐狸等动物，只新建继承Animal的类，数组循环代码完全不用修改；
3. **低维护**：新增、修改某类动物的行为，只改对应子类，核心遍历代码不受影响。

## 一句话总结
只要引用声明为父类，所有子类对象都能存入、统一调用父类方法；运行时自动匹配子类专属实现，这就是多态的核心作用。

# 多态方法参数 + 返回值 案例讲解
## 一、多态方法参数（核心示例：兽医打针）
### 代码梳理
1. `Vet` 兽医类，方法 `giveShot(Animal a)`
方法形参类型是**父类 Animal**，这就是多态参数。
2. `PetOwner` 宠物主人类，创建 Dog、Hippo 两个子类对象，直接传给 `giveShot()`
```java
class Vet {
    // 参数是Animal（父类），支持所有Animal子类传入
    public void giveShot(Animal a) {
        // 打针后让动物叫一声
        a.makeNoise();
    }
}

class PetOwner {
    public void start() {
        Vet v = new Vet();
        Dog d = new Dog();
        Hippo h = new Hippo();
        // 子类对象直接传给Animal类型参数，完全合法
        v.giveShot(d);
        v.giveShot(h);
    }
}
```

### 运行逻辑
1. 编译层面：方法只规定入参是 Animal，所有满足 `IS-A Animal` 的子类（Dog、Cat、Wolf、Hippo）都能传进去，不用给每种动物单独写打针方法；
2. 运行层面：执行 `a.makeNoise()` 时，JVM 识别堆上真实对象：
   - 传入 Dog → 执行 Dog 重写的 `makeNoise()`
   - 传入 Hippo → 执行 Hippo 重写的 `makeNoise()`

### 巨大优势
不用重载一堆 `giveShot(Dog)`、`giveShot(Hippo)`，**一个方法统一处理所有动物**。后续新增狮子、老虎等动物，方法代码完全不用改。

## 二、拓展：多态返回值（文中提的另一特性）
和参数逻辑对称：方法返回值声明为父类，实际可以 return 任意子类对象。
示例：
```java
// 返回类型Animal，实际返回Dog/Cat都行
public Animal getAnyPet() {
    return new Dog();
    // 也可以 return new Cat();
}
```

## 三、统一多态核心规则回顾
只要变量/数组元素/方法入参/方法返回值声明为**父类**，就可以接收、传递、返回任意它的子类对象；调用父类定义的方法时，永远执行子类重写的实现。

# 问答内容完整解读
## 问题1：继承层级最多能写多深，有没有实际限制？
### 回答
1. Java 语法层面没有硬性深度上限，但**工业规范推荐继承树浅、宽**（横向多子类，纵向少层级）；
2. 绝大多数业务类只有1~2层继承，GUI图形类是少数深层例外；
3. 继承层级过深会大幅提升维护成本，调试、修改逻辑都变得复杂，日常开发尽量少多层嵌套继承。

## 问题2：没有类源码，想修改它某个方法的逻辑怎么办？
### 回答
可以！通过**子类重写目标方法**实现自定义逻辑。
不用重写整个原类，只需继承它，重写需要改动的方法，其余原有功能直接继承复用，解决无源码改造的难题。

## 问题3：所有类都能被继承吗？什么情况无法`extends`？
不存在普通`private`顶级类，但三类场景禁止子类化：
1. **非public（包访问权限）类**
   没加`public`的类，仅同包内的类能继承；其他包完全无法访问、继承该类。
2. **`final`修饰的类**
   `final class`是继承终点，任何类都不能继承它，整条继承链到此截断。
3. **全部构造器都是`private`的类**
   子类实例化时必须调用父类构造器，父类构造器全私有则无法继承（第9章讲构造器）。

## 问题4：为什么要定义`final`类？有什么作用？
### 核心目的：杜绝方法重写，保证类行为固定不变
1. 安全稳定：类里所有方法永远是原始实现，不会被子类篡改逻辑；
2. Java标准库大量使用，典型例子：`String`类是`final`；
   如果允许继承重写String方法，整个字符串底层逻辑会被破坏，引发大量程序异常。
3. 适用场景：核心基础、底层工具类，不希望外部开发者修改内部行为。

## 问题5：能不能只锁定单个方法不被重写，不用把整个类设为final？
### 可以
- `final 方法`：仅当前方法禁止子类重写，类依然能正常继承，其他方法仍可重写；
- `final 类`：类内全部方法自动无法重写，完全断绝继承。

## 关键知识点总结
1. 开发规范：继承层级尽量浅层化；
2. 无源码改造方案：继承并重写目标方法；
3 阻止继承三种方式：非public类、final类、全私有构造器类；
4 final细分：
   - final 类：不可继承，所有方法不能重写
   - final 方法：类可继承，仅此方法禁止重写
