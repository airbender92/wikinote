# Encapsulation 封装 全文翻译+核心深度解读
## 一、开篇：不做封装会埋下巨大缺陷
在此之前我们一直犯了面向对象最严重的错误：**把实例变量完全暴露给外部，任何人都能直接读写数据**。

直接用 `.` 操作对象属性：
```java
theCat.height = 27;
```
风险极大：外部可以随意赋值非法值，比如：
```java
theCat.height = 0;
```
猫的身高不可能为0，这种错误数据会导致整个程序逻辑崩溃。

### 解决方案核心思路
不让外部直接碰变量，强制所有读写走 **setter/getter 方法**，在方法内部加校验规则，拦截非法数据。
```java
public void setHeight(int ht) {
    if (ht > 9) { // 校验：猫身高最小值9
        height = ht;
    }
}
```

## 二、Java 实现封装标准写法（黄金规则）
依靠权限修饰符 `private` / `public` 实现数据隐藏：
1. **所有实例变量用 private 修饰**：仅本类内部可见，外部完全无法直接访问；
2. **对外提供 public 的 getter、setter**：作为唯一合法读写通道。

## 三、访谈：对象自述封装的价值
### 1. 保护数据完整性，拦截非法数值
对象的变量都有业务边界约束：房间卫生间数量、飞机速度、体重、手机号、烤箱功率等，都不能是负数、超出合理范围。
- 变量公开：外部想赋什么值就赋什么，没有任何阻拦；
- 走 setter：赋值前可校验、修正、抛异常、拒绝非法输入，守住数据规范。



### 2. 内部实现可随意修改，不会破坏外部代码
如果变量是 public，全项目代码都会直接依赖这个字段；某天你想增加校验、修改存储逻辑、更换字段类型，所有外部代码全部报错。
使用封装后，外部只依赖 public 方法，只要方法名、返回值、参数不变，内部逻辑怎么改都不会影响调用方。

### 3. 哪怕 setter 现在没有校验，也要写
很多人觉得“字段没有范围限制，写setter多此一举、有性能损耗”，但性能差距微乎其微；
真正收益是**未来扩展无成本**，后续需要加校验、日志、联动计算时，不用改动外部代码。

## 四、封装完整定义与三大核心好处
### 1. 定义
封装 = 将**数据（实例变量）+ 操作数据的方法**捆绑在类中，使用权限修饰符隐藏内部数据，仅对外暴露可控的公共访问接口。

### 2. 三大核心优势
1. **数据安全**：通过 setter 做参数校验，杜绝无效、错误数据；
2. **低耦合易维护**：内部实现与外部代码解耦，修改内部逻辑不影响调用处；
3. **简化使用**：使用者只需要调用公开方法，不用关心底层存储、复杂计算细节。

## 五、完整封装标准代码示例（猫类）
```java
class Cat {
    // 1. 变量私有化，外部不可直接访问
    private int height;

    // 2. public setter：受控修改，带校验
    public void setHeight(int ht) {
        if (ht > 9) {
            height = ht;
        }
    }

    // 3. public getter：读取私有变量
    public int getHeight() {
        return height;
    }
}
```
外部调用只能通过方法：
```java
Cat c = new Cat();
c.setHeight(15); // 合法
c.setHeight(2);  // 被校验拦截，赋值失败
System.out.println(c.getHeight());
```

## 六、一句话背诵总结
**变量私有，方法公开；读写走方法，校验藏内部；内部随便改，外部不受殃。**
