## Pinia 插件开发：结构、增强、全局回调与第三方库

Pinia 插件允许你**扩展所有 Store**，例如添加全局方法、包装 action、持久化状态等。插件在 `app.use(pinia)` 后通过 `pinia.use()` 注册。

---

### 一、插件基本结构

```ts
import { createPinia } from 'pinia'

const pinia = createPinia()

pinia.use((context) => {
  // 插件逻辑
  console.log(context)
  // 可选：返回一个对象，其属性会合并到每个 store
  return { hello: 'world' }
})

app.use(pinia)
```

#### `context` 对象属性

| 属性 | 类型 | 说明 |
|------|------|------|
| `store` | `Store` | 当前正在初始化的 store 实例（每个 store 初始化时都会执行插件） |
| `app` | `App` | Vue 应用实例（通过 `createApp` 创建） |
| `options` | `DefineStoreOptions` 或 `SetupStoreOptions` | 定义 store 时传入的配置（id、state、getters、actions） |
| `pinia` | `Pinia` | 当前的 pinia 实例 |

> **注意**：插件对**每个 store** 都会执行一次（当 store 被首次使用时）。这意味着你可以针对单个 store 进行增强，也可以利用 `store.$id` 做条件判断。

---

### 二、增强 Store – 添加属性、方法、计算属性

#### 1. 添加普通属性或方法

```ts
pinia.use(({ store }) => {
  // 添加一个方法
  store.$hello = (name: string) => console.log(`Hello ${name} from ${store.$id}`)
  
  // 添加一个普通属性（非响应式）
  store.$version = '1.0.0'
})
```

#### 2. 添加响应式计算属性（computed）

```ts
import { computed } from 'vue'

pinia.use(({ store }) => {
  // 为每个 store 添加一个 $doubleCount 的计算属性（如果 store 有 count）
  if ('count' in store) {
    store.$doubleCount = computed(() => store.count * 2)
  }
})
```

#### 3. 包装 action（实现全局 loading 或日志）

```ts
pinia.use(({ store }) => {
  // 保存原始的 action 方法
  const originalActions = { ...store }
  
  for (const key in originalActions) {
    if (typeof originalActions[key] === 'function') {
      const originalAction = originalActions[key]
      // 替换为包装后的函数
      store[key] = async function (...args: any[]) {
        console.log(`Action ${key} started`, args)
        try {
          const result = await originalAction.apply(store, args)
          console.log(`Action ${key} succeeded`, result)
          return result
        } catch (error) {
          console.error(`Action ${key} failed`, error)
          throw error
        }
      }
    }
  }
})
```

#### 常见坑点 ⚠️

| 坑点 | 说明 | 正确做法 |
|------|------|----------|
| **直接添加属性无响应式** | `store.newProp = 'value'`，后续如果修改该属性不会触发 UI 更新 | 如果需要响应式，使用 `store.$state.newProp = 'value'` 或 `store.$patch`；或者用 `ref` / `computed` 包装 |
| **插件多次执行导致重复添加** | 插件对每个 store 每个实例只执行一次，但若 store 被多次使用，仍然只执行一次（因为 store 是单例）。但如果手动销毁并重新创建，可能再次执行 | 在添加属性前检查是否已存在：`if (!store.$hello) store.$hello = ...` |
| **在插件中修改 store 原始方法导致递归** | 包装 action 时如果不小心调用了自身，会造成无限循环 | 保存原始引用（如 `const original = store.action`），包装函数内部调用 `original` |
| **TypeScript 类型丢失** | 添加 `$hello` 后，`store.$hello` 会报类型错误 | 需要扩展 `PiniaCustomProperties` 接口（见下文） |
| **忘记返回对象** | 插件如果返回一个对象，其属性会直接合并到 store，优先级高于直接修改 `store.xxx` | 根据需求选择返回或直接修改。返回的形式更适合添加一批静态属性 |

### 三、扩展 State（通过 `store.$state`）

如果你需要在所有 store 中**动态添加新的 state 字段**，可以通过修改 `store.$state` 实现，但必须确保该字段是响应式的且符合 TypeScript。

```ts
pinia.use(({ store }) => {
  // 为每个 store 添加一个 _loading 状态
  const loading = ref(false)
  store.$state._loading = loading  // 注意：_loading 会出现在 $state 中
  
  // 暴露一个方法供组件使用
  store.$setLoading = (value: boolean) => {
    loading.value = value
  }
})
```

**更标准的方式**：直接向 `store` 添加 `ref`，但为了让它出现在 `store.$state` 中（以便序列化、devtools 等），需要同时添加到 `$state`。

#### 坑点 ⚠️

- **不推荐随意扩展 state**：因为 `$state` 是用于序列化、持久化的，动态添加字段会导致初始 state 与运行时不一致。
- **TypeScript 报错**：`store._loading` 不存在。需要类型声明（见下文）。
- **非响应式陷阱**：如果直接 `store._loading = false`，不会触发响应式更新。必须用 `ref` 或 `reactive`。

**更好的做法**：如果只是临时状态（如 loading），直接添加到 store 实例即可，不必放到 `$state` 中。

### 四、TypeScript 类型增强

为了让 TypeScript 识别插件添加的属性和方法，你需要在项目中扩展 `PiniaCustomProperties` 或 `PiniaCustomStateProperties`。

#### 扩展普通属性/方法
```ts
// types/pinia.d.ts 或 shims-vue.d.ts
import 'pinia'

declare module 'pinia' {
  export interface PiniaCustomProperties {
    $hello: (name: string) => void
    $version: string
    $setLoading: (value: boolean) => void
  }
}
```

#### 扩展计算属性（ComputedRef）
```ts
declare module 'pinia' {
  export interface PiniaCustomProperties {
    $doubleCount: ComputedRef<number>
  }
}
```

#### 扩展 State 中的自定义字段
如果通过 `store.$state` 添加了新字段，需要扩展 `PiniaCustomStateProperties`：

```ts
declare module 'pinia' {
  export interface PiniaCustomStateProperties {
    _loading: Ref<boolean>
  }
}
```

#### 坑点 ⚠️
- **模块扩展必须在 `import 'pinia'` 之后**。确保 `.d.ts` 文件顶部有 `import 'pinia'`。
- **扩展不生效**：检查 `tsconfig.json` 是否包含该 `.d.ts` 文件；尝试重启 TS 服务。
- **与 store 原有属性冲突**：注意命名不要与内置属性（如 `$id`, `$state`）冲突。

### 五、全局回调 – 监听所有 Action

插件可以监听**每个 store 的每个 action**，实现横切关注点（如 loading 管理、错误上报、埋点）。

#### 示例：全局 Loading 管理

```ts
// plugins/loading.ts
import { ref } from 'vue'

const globalLoading = ref(false)
const activeRequests = ref(0)

export default function ({ store }: PiniaPluginContext) {
  // 监听所有 action 开始/结束
  store.$onAction(({ name, after, onError }) => {
    if (name === 'someAction') return // 可跳过特定 action
    
    activeRequests.value++
    globalLoading.value = true
    
    after(() => {
      activeRequests.value--
      if (activeRequests.value === 0) {
        globalLoading.value = false
      }
    })
    
    onError(() => {
      activeRequests.value--
      if (activeRequests.value === 0) {
        globalLoading.value = false
      }
    })
  })
  
  // 将 loading 状态注入到 store（可选）
  store.$globalLoading = globalLoading
}
```

#### 注意点
- `$onAction` 会自动在 store 销毁时清理监听，但如果你在插件中注册的 `after/onError` 回调中引用了外部变量，需要确保不会内存泄漏（一般无问题）。
- 多个插件同时监听 action 会依次执行。

### 六、第三方插件示例

#### 1. `pinia-plugin-persistedstate` – 持久化到 localStorage

```ts
import { createPinia } from 'pinia'
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate'

const pinia = createPinia()
pinia.use(piniaPluginPersistedstate)

// 在 store 中配置持久化
const useStore = defineStore('main', {
  state: () => ({ count: 0 }),
  persist: true,  // 或更详细的配置
})
```

**坑点**：
- 默认只持久化 `state`，不会持久化 getters 和 actions。
- 对于 Setup Store，需要额外配置（如 `persist: { paths: ['count'] }`）。
- 某些值（如 `Date`、`Map`、`Set`）需要自定义序列化。

#### 2. `pinia-plugin-undo-redo` – 撤销/重做

```ts
import { createPinia } from 'pinia'
import piniaPluginUndoRedo from 'pinia-plugin-undo-redo'

const pinia = createPinia()
pinia.use(piniaPluginUndoRedo)

const store = useStore()
store.undo()  // 撤销上一次变更
store.redo()  // 重做
```

**坑点**：
- 默认记录所有 state 变更，对于大 state 可能性能开销大，需要配置快照策略。
- 不支持异步 action 的中间状态。

#### 3. 其他常用插件
- `pinia-plugin-persist`：更早的持久化方案（已不推荐）。
- `pinia-plugin-axios`：将 $axios 注入 store。
- 你自己写的插件。

### 七、插件的执行顺序与清理

- **注册顺序**：`pinia.use(pluginA)` 先注册的先执行。如果插件B依赖插件A添加的属性，需要确保A先注册。
- **每个 store 初始化时**：插件回调会按注册顺序执行一次。
- **清理**：插件通常不需要手动清理，但如果插件创建了全局监听（如 eventBus），应在 `pinia` 实例销毁时清理（很少有这种需求）。

### 八、完整插件示例（带类型）

```ts
// plugins/myPlugin.ts
import { PiniaPluginContext } from 'pinia'
import { ref, computed } from 'vue'

declare module 'pinia' {
  export interface PiniaCustomProperties {
    $timestamp: number
    $track: (event: string) => void
  }
}

export function myPlugin({ store, app, options, pinia }: PiniaPluginContext) {
  // 1. 添加静态属性
  store.$timestamp = Date.now()
  
  // 2. 添加方法
  store.$track = (event: string) => {
    console.log(`[${store.$id}] ${event}`)
    // 可调用 app.config.globalProperties.$analytics
  }
  
  // 3. 如果有 count 字段，添加计算属性
  if ('count' in store) {
    const double = computed(() => store.count * 2)
    store.$doubleCount = double
    // 注意：需要扩展 PiniaCustomProperties 包含 $doubleCount
  }
  
  // 4. 包装所有 action 进行埋点
  store.$onAction(({ name, args }) => {
    store.$track(`action:${name}`)
  })
}
```

使用：
```ts
// main.ts
import { myPlugin } from './plugins/myPlugin'
pinia.use(myPlugin)

// 在任一 store 中
const store = useStore()
console.log(store.$timestamp)
store.$track('page_view')
```

### 九、总结与记忆口诀

| 要点 | 描述 |
|------|------|
| 注册插件 | `pinia.use(callback)` |
| 增强 store | 直接修改 `store` 属性，或用 `computed` / `ref` |
| 扩展 state | 通过 `store.$state.newField`（不推荐常规使用） |
| 类型声明 | 扩展 `PiniaCustomProperties` 和 `PiniaCustomStateProperties` |
| 全局 action 监听 | 在插件中调用 `store.$onAction` |
| 第三方插件 | 持久化、撤销/重做等 |

**记忆口诀**：

> **插件结构 `pinia.use`，`context` 里有 `store`；**
> **增强属性直接加，响应式用 `computed` 修；**
> **扩展类型写声明，`onAction` 全局钩；**
> **持久化用 `persistedstate`，撤销重做解烦忧。**

掌握插件开发，你就能为 Pinia 注入无限扩展能力，并安全地集成第三方生态。
