## Pinia 持久化状态：三种方案详解与最佳实践

Pinia 的持久化是指将 Store 中的 state 保存到本地存储（如 `localStorage`、`sessionStorage`），使得页面刷新后状态不丢失。下面是三种主流方案的详细对比和使用方法。

---

### 一、手动配合 localStorage（简单场景）

**适用场景**：只有少数几个字段需要持久化，且希望完全控制读写逻辑。

#### 实现方式
```ts
const useUserStore = defineStore('user', {
  state: () => ({
    token: localStorage.getItem('token') || '',
    userInfo: JSON.parse(localStorage.getItem('userInfo') || 'null')
  }),
  actions: {
    login(token: string, info: any) {
      this.token = token
      this.userInfo = info
      localStorage.setItem('token', token)
      localStorage.setItem('userInfo', JSON.stringify(info))
    },
    logout() {
      this.token = ''
      this.userInfo = null
      localStorage.removeItem('token')
      localStorage.removeItem('userInfo')
    }
  }
})
```

#### 优点
- 零依赖，完全可控。
- 适合非常简单的场景（如单个 token）。

#### 缺点
- 每个字段都需要手动读写，代码冗余。
- 容易遗漏同步，导致 state 与存储不一致。
- 不支持深层对象的部分持久化。

---

### 二、pinia-plugin-persistedstate（官方推荐）

**适用场景**：绝大部分项目，尤其是需要精细控制持久化路径、使用 Setup Store 的项目。

#### 安装
```bash
npm i pinia-plugin-persistedstate
# 或 yarn add pinia-plugin-persistedstate
```

#### 基本用法
```ts
// main.ts
import { createPinia } from 'pinia'
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate'

const pinia = createPinia()
pinia.use(piniaPluginPersistedstate)
app.use(pinia)

// 在某个 Store 中启用持久化
const useSettingsStore = defineStore('settings', {
  state: () => ({ theme: 'dark', fontSize: 14 }),
  persist: true   // 开启后，整个 state 自动存入 localStorage
})
```

#### 进阶配置（推荐）
```ts
const useCartStore = defineStore('cart', {
  state: () => ({ items: [], total: 0 }),
  persist: {
    key: 'shopping-cart',        // 自定义存储 key（默认是 store 的 id）
    storage: sessionStorage,      // 存储引擎，默认 localStorage
    paths: ['items'],             // 只持久化 items 字段，total 不存
    serializer: {
      serialize: JSON.stringify,
      deserialize: JSON.parse
    },
    beforeRestore: (context) => {
      console.log('即将恢复', context)
    },
    afterRestore: (context) => {
      console.log('恢复完成', context)
    }
  }
})
```

#### Setup Store 用法
```ts
const useStore = defineStore('main', () => {
  const count = ref(0)
  const name = ref('pinia')
  return { count, name }
}, {
  persist: {
    paths: ['count']   // 只持久化 count
  }
})
```

#### 优点
- 自动同步，代码简洁。
- 支持选择性存储（paths），减少存储体积。
- 支持自定义序列化（例如处理 Date、Map 等）。
- 与 Pinia Devtools 兼容。
- 支持 SSR hydration。

#### 缺点
- 需要额外安装插件（但体积很小）。
- 默认序列化不能处理循环引用、Set 等复杂类型（需自定义）。

---

### 三、SSR 中持久化（避免服务端访问 localStorage）

在 SSR（如 Nuxt、Next.js、Vue SSR）中，服务端没有 `localStorage`，直接使用插件会报错。必须确保持久化只在客户端执行。

#### 解决方案 1：条件判断 + 客户端 hydration
```ts
// 插件内部已经处理了 SSR，但如果你手动实现，可以：
const useStore = defineStore('main', {
  state: () => ({
    data: process.client ? localStorage.getItem('data') : null
  }),
  actions: {
    save(data) {
      this.data = data
      if (process.client) localStorage.setItem('data', data)
    }
  }
})
```

#### 使用 `pinia-plugin-persistedstate` 时（自动兼容）
```ts
// 插件默认只在客户端运行，SSR 中自动跳过，无需额外配置。
// 如果需要手动控制，可以设置：
persist: {
  storage: process.client ? localStorage : undefined
}
```

#### Nuxt 3 专用方案（使用 `@pinia/nuxt`）
```ts
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@pinia/nuxt', '@pinia-plugin-persistedstate/nuxt']
})
// 然后直接使用 persist: true，框架会自动处理 SSR
```

#### 关键坑点
- 不要在服务端渲染时访问 `window` 或 `localStorage`。
- 确保 hydration 时客户端状态与服务端状态一致，否则会有闪烁或错误。

---

### 四、加密存储（敏感数据）

对于 token、用户手机号等敏感信息，直接明文存储不安全。可以结合插件自定义序列化函数或存储引擎，实现加密。

#### 方法 1：自定义 serializer（推荐）
```ts
import CryptoJS from 'crypto-js'

const SECRET_KEY = 'your-secret-key'

const useAuthStore = defineStore('auth', {
  state: () => ({ token: '', refreshToken: '' }),
  persist: {
    serializer: {
      serialize: (value) => {
        const json = JSON.stringify(value)
        return CryptoJS.AES.encrypt(json, SECRET_KEY).toString()
      },
      deserialize: (ciphertext) => {
        const bytes = CryptoJS.AES.decrypt(ciphertext, SECRET_KEY)
        const json = bytes.toString(CryptoJS.enc.Utf8)
        return JSON.parse(json)
      }
    }
  }
})
```

#### 方法 2：自定义 storage（包装 localStorage 加解密）
```ts
const encryptedStorage = {
  getItem: (key: string) => {
    const cipher = localStorage.getItem(key)
    if (!cipher) return null
    const bytes = CryptoJS.AES.decrypt(cipher, SECRET_KEY)
    return bytes.toString(CryptoJS.enc.Utf8)
  },
  setItem: (key: string, value: string) => {
    const cipher = CryptoJS.AES.encrypt(value, SECRET_KEY).toString()
    localStorage.setItem(key, cipher)
  },
  removeItem: (key: string) => localStorage.removeItem(key)
}

// 在 persist 配置中使用
persist: {
  storage: encryptedStorage   // 注意：此 storage 需要实现标准 API
}
```

#### 注意事项
- 加密密钥不要硬编码在前端，至少使用环境变量或动态获取。
- 加密会增加性能开销，仅对真正敏感的字段加密。
- 不要存储高价值密钥（如支付密码），而是存 token 并设置较短有效期。

---

### 五、三种方案对比总结

| 方案 | 实现复杂度 | 自动化程度 | 适用场景 |
|------|------------|------------|----------|
| 手动 localStorage | 低 | 低 | 1-2 个简单字段，无复杂对象 |
| pinia-plugin-persistedstate | 极低 | 高 | 绝大多数项目（推荐） |
| SSR 适配 | 中 | 中 | Nuxt / Next.js 等 SSR 项目 |
| 加密存储 | 中 | 中 | 敏感数据（token、手机号） |

---

### 六、记忆口诀

> **小数据手动存，插件统一省心神；**
> **SSR 防服务端，加密敏感保安全；**
> **paths 字段要精选，序列化自定义强。**

---

### 七、最佳实践建议

1. **默认使用 `pinia-plugin-persistedstate`**，配置简单，功能强大。
2. **只持久化必要字段**（通过 `paths`），避免存储大量无关数据。
3. **敏感数据必须加密**，或使用短时效的 token 并配合 refresh token。
4. **SSR 项目中**，确保持久化只在客户端运行，使用官方集成的 Nuxt 模块或手动判断 `process.client`。
5. **注意存储大小限制**（`localStorage` 通常 5-10MB），不要存图片或大 JSON。

只要遵循以上指南，你就能安全、高效地实现 Pinia 的状态持久化。
