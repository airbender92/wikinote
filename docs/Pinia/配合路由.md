## Pinia 与 Vue Router 集成：四种核心场景与实现

在实际项目中，Pinia 常常需要与 Vue Router 配合控制导航权限、数据清理等。以下是四个典型场景及标准做法。

---

### 一、路由守卫中访问 Store

#### 场景
在 `router.beforeEach` 中需要读取或修改 Pinia Store 的状态（例如检查用户是否已登录）。

#### 坑点
路由守卫是定义在 `router` 实例上的，而 `useStore()` 需要在**组件上下文**中调用（有活跃的 Vue 实例）。直接在守卫中调用 `useStore()` 会报错，因为它找不到 pinia 实例。

#### ✅ 正确做法：显式传入 pinia 实例
```ts
// router/index.ts
import { createRouter } from 'vue-router'
import { createPinia } from 'pinia'
import { useUserStore } from '@/stores/user'

const router = createRouter({ ... })

// 方法1：在守卫中直接使用已创建的 pinia 实例
const pinia = createPinia()  // 如果 pinia 已在 main.ts 创建，可以导入它
app.use(pinia)

router.beforeEach((to, from, next) => {
  // 关键：传入 pinia 实例作为参数
  const userStore = useUserStore(pinia)
  
  if (to.meta.requiresAuth && !userStore.isLoggedIn) {
    next('/login')
  } else {
    next()
  }
})
```

#### 更佳实践：统一导出 pinia 实例
```ts
// main.ts
export const pinia = createPinia()
app.use(pinia)

// router/index.ts
import { pinia } from '@/main'
import { useUserStore } from '@/stores/user'

router.beforeEach((to, from, next) => {
  const userStore = useUserStore(pinia)  // 复用同一个实例
  // ...
})
```

#### 注意事项 ⚠️
- 一定不要忘记 `pinia` 参数，否则会抛出 `getActivePinia was called with no active Pinia` 错误。
- 如果使用 `setup` 路由守卫（Vue Router 4 的 `router.beforeEach` 支持 `async`），同样需要传入实例。

---

### 二、根据状态决定导航（权限控制）

#### 场景
根据 Store 中的用户角色、登录状态等决定是否允许进入某个路由。

#### 实现
```ts
// 路由元信息定义角色
const routes = [
  {
    path: '/admin',
    component: AdminPanel,
    meta: { roles: ['admin'] }
  }
]

// 守卫逻辑
router.beforeEach((to, from, next) => {
  const userStore = useUserStore(pinia)
  const requiredRoles = to.meta.roles as string[]
  
  if (requiredRoles?.length) {
    const hasRole = requiredRoles.some(role => userStore.roles.includes(role))
    if (hasRole) next()
    else next('/forbidden')
  } else {
    next()
  }
})
```

#### 坑点 ⚠️
- 如果 Store 中的用户信息是通过异步请求获取的（例如 `fetchUser`），守卫中可能拿不到最新数据。需要**阻塞导航**直到数据加载完成。
```ts
router.beforeEach(async (to, from, next) => {
  const userStore = useUserStore(pinia)
  if (!userStore.isInitialized) {
    await userStore.fetchUser()  // 假设 fetchUser 是异步 action
  }
  // 现在可以安全判断权限
  next()
})
```
- 注意无限循环：如果未登录跳转到 `/login`，而 `/login` 也触发了需要登录的逻辑，会导致死循环。应在 meta 中标识白名单路由。

---

### 三、路由变化时清理 Store 数据

#### 场景
当用户离开某个页面时，需要重置该页面相关的 Store 数据（例如清空表单草稿、搜索条件）。避免切换到其他页面时造成数据污染。

#### 实现方式

**方法1：在组件内监听路由变化**
```vue
<script setup>
import { useRoute } from 'vue-router'
import { useFormStore } from '@/stores/form'

const route = useRoute()
const formStore = useFormStore()

// 当路由参数变化或离开当前页面时，清理数据
watch(() => route.fullPath, (newPath, oldPath) => {
  if (oldPath?.startsWith('/form') && !newPath.startsWith('/form')) {
    formStore.resetForm()
  }
})
</script>
```

**方法2：使用全局后置守卫**
```ts
router.afterEach((to, from) => {
  if (from.path.startsWith('/form')) {
    const formStore = useFormStore(pinia)
    formStore.resetForm()
  }
})
```

**方法3：利用路由组件的生命周期**
在路由对应的组件中，使用 `onBeforeRouteLeave` 导航守卫：
```vue
<script setup>
import { onBeforeRouteLeave } from 'vue-router'
import { useFormStore } from '@/stores/form'

const formStore = useFormStore()
onBeforeRouteLeave(() => {
  formStore.resetForm()
})
</script>
```

#### 坑点 ⚠️
- 不要清理被其他路由共享的 Store 数据（如用户信息）。
- 如果使用 `keep-alive`，`onBeforeRouteLeave` 不会在组件缓存时触发，需要额外处理。

---

### 四、keep-alive 下状态保留 + 刷新数据

#### 场景
使用 `<keep-alive>` 缓存组件时，组件不会被销毁重建，因此 Pinia Store 中的数据可能仍然是旧的。当用户再次进入该路由时，需要刷新数据（如重新拉取列表）。

#### 核心思路
在组件被**激活**时（`onActivated`）重新请求数据，而不是依赖 `onMounted`（因为 `keep-alive` 下 `onMounted` 只执行一次）。

```vue
<script setup>
import { onActivated } from 'vue'
import { useProductStore } from '@/stores/product'

const productStore = useProductStore()

// 每次进入该视图时（包括从缓存中恢复）重新拉取数据
onActivated(() => {
  productStore.fetchProductList()
})

// 首次挂载时也会触发 onActivated，所以可以不用 onMounted
</script>
```

#### 配合路由元信息优化
```ts
// 路由定义
{
  path: '/products',
  component: ProductList,
  meta: { keepAlive: true, refreshOnActivate: true }
}

// 组件中
import { onActivated } from 'vue'
import { useRoute } from 'vue-router'

const route = useRoute()
const productStore = useProductStore()

onActivated(() => {
  if (route.meta.refreshOnActivate) {
    productStore.fetchProductList()
  }
})
```

#### 坑点 ⚠️
- `onActivated` 在首次挂载时也会执行，如果数据请求很重，可能导致不必要的请求。可以添加一个标志位，只在第二次及之后激活时才刷新。
- 如果 Store 中的数据可能被其他组件修改（如新增商品），需要确保刷新时机正确。
- 注意 `keep-alive` 配合多级路由缓存时的行为差异。

---

## 总结表

| 场景 | 核心做法 | 关键 API / 注意点 |
|------|----------|-------------------|
| 守卫中访问 Store | `useStore(pinia)` 传入 pinia 实例 | 必须显式传递，否则无上下文 |
| 根据状态决定导航 | 读取 userStore 角色/登录态，阻塞异步加载 | 注意白名单路由，防止死循环 |
| 路由变化清理数据 | `router.afterEach` 或 `onBeforeRouteLeave` | 识别路由路径，避免误清理共享状态 |
| keep-alive 刷新数据 | `onActivated` 中调用 action | 区分首次挂载和后续激活，可以配合元信息 |

### 记忆口诀
> **守卫访问传 pinia，权限加载防异步；**
> **路由离开清数据，keep-alive 用激活。**

掌握这四种集成模式，你就能在 Vue Router 中安全、高效地使用 Pinia。
