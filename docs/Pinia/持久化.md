## 持久化是什么？什么业务需要？

**持久化** 就是将 Pinia Store 中的状态（state）保存到**本地存储**中（如 `localStorage`、`sessionStorage`、IndexedDB 等），这样即使**页面刷新**或**关闭浏览器后重新打开**，这些状态依然能被恢复，而不是丢失。

Pinia 默认把 state 存在内存里，页面一刷新就没了。持久化就是为了解决“刷新后数据消失”的问题。

---

### 一、为什么需要持久化？

想象一下：
- 用户登录后，你存了 `token`，结果 F5 一刷，`token` 没了 → 用户被迫重新登录。
- 用户把网页主题设为“深色模式”，刷新后变回默认浅色 → 体验很差。
- 用户在购物车加了 5 件商品，不小心刷新页面 → 购物车空了，用户骂人。

持久化就是把这些“不能因刷新而丢失”的数据**牢牢存下来**。

---

### 二、典型业务场景（90% 的持久化需求都在这）

| 业务场景 | 需要持久化的数据 | 说明 |
|----------|------------------|------|
| **用户登录态** | `token`、`refreshToken`、用户基本信息 | 刷新页面后依然保持登录，直到 token 过期或主动登出 |
| **主题/外观设置** | `theme`（dark/light）、字体大小、侧边栏折叠状态 | 用户个性化设置，下次访问自动生效 |
| **多步骤表单草稿** | 表单已填写的部分（如注册分步、长问卷） | 刷新页面后不用重填，提升用户体验 |
| **购物车** | 商品列表、数量、选中状态 | 即使关闭浏览器，下次打开购物车内容还在 |
| **列表筛选/分页偏好** | 搜索关键词、筛选项、当前页码、每页条数 | 返回列表页时保持用户之前的筛选状态 |
| **音视频播放进度** | 当前播放时间点、播放状态 | 刷新页面或下次打开，从上次位置继续播放 |
| **最近浏览/历史记录** | 用户点击过的商品、文章 ID 列表 | 用于展示“最近看过”功能 |
| **离线缓存数据** | 基础字典、配置信息 | 减少网络请求，提升离线体验 |
| **游戏进度** | 关卡、得分、道具 | 下次进入游戏能继续 |

### 三、如何实现持久化？（Pinia 中）

#### 1. 手动实现（不推荐，但能理解原理）
```ts
// 在 store 中
const useUserStore = defineStore('user', {
  state: () => ({
    token: localStorage.getItem('token') || ''
  }),
  actions: {
    setToken(token: string) {
      this.token = token
      localStorage.setItem('token', token)  // 每次变化都存
    },
    logout() {
      this.token = ''
      localStorage.removeItem('token')
    }
  }
})
```
**问题**：每个字段都要手动读写，容易遗漏、代码重复。

#### 2. 使用 `pinia-plugin-persistedstate`（推荐）
```bash
npm i pinia-plugin-persistedstate
```

```ts
// main.ts
import { createPinia } from 'pinia'
import piniaPluginPersistedstate from 'pinia-plugin-persistedstate'

const pinia = createPinia()
pinia.use(piniaPluginPersistedstate)
app.use(pinia)

// 在 store 中开启持久化
const useUserStore = defineStore('user', {
  state: () => ({ token: '', userInfo: null }),
  persist: true   // 开启后，整个 state 自动存到 localStorage
})

// 也可以精细控制
const useSettingsStore = defineStore('settings', {
  state: () => ({ theme: 'dark', fontSize: 14, sidebarCollapsed: false }),
  persist: {
    key: 'app-settings',      // 自定义存储 key
    paths: ['theme', 'fontSize'], // 只持久化这两个字段
    storage: sessionStorage,   // 默认 localStorage，也可用 sessionStorage
  }
})
```

**Setup Store 用法**：
```ts
const useStore = defineStore('main', () => {
  const token = ref('')
  return { token }
}, {
  persist: true
})
```

### 四、持久化的坑点与注意事项

| 坑点 | 说明 | 正确做法 |
|------|------|----------|
| **敏感信息不要持久化** | 密码、支付密码、身份证号等存到本地有安全风险 | 只存 token（短时效）和脱敏数据 |
| **存储大小限制** | `localStorage` 通常限制 5-10MB，不要存大对象（如图片 base64） | 大文件存 IndexedDB，或只存引用 |
| **数据版本更新** | 修改了 state 结构后，旧数据可能导致反序列化错误 | 在插件中做版本迁移（`version` 字段） |
| **服务端渲染（SSR）** | `localStorage` 只在浏览器存在，SSR 中会报错 | 只在客户端访问（`if (process.client)` 或 `onMounted`） |
| **多标签页不同步** | 一个标签页修改了 state，另一个标签页不会自动更新 | 使用 `storage` 事件监听跨标签页同步 |
| **忘记清除** | 用户登出时只清除了内存中的 state，未清除本地存储 | 调用 `store.$reset()` 后手动 `localStorage.removeItem`，或使用插件的 `clear` 方法 |
| **类型不安全** | 从 `localStorage` 读取的值是字符串，需要 JSON.parse | 插件自动处理，但要注意自定义反序列化 |

---

### 五、总结：什么时候需要持久化？

**记住一个判断标准：**  
> 刷新页面后，如果这个数据丢失会让用户感到**困惑或重复操作**，就需要持久化。

- **必须持久化**：登录 token、用户偏好、购物车、草稿。
- **不需要持久化**：临时搜索关键词、当前选中的 Tab（除非用户希望记住）、一次性消息提示。

### 记忆口诀
> **刷新丢失难忍受，持久化来解忧愁；**
> **登录主题购物车，草稿筛选都得留；**
> **敏感信息不要存，版本清理记心头。**

合理使用持久化，能极大提升用户体验。多数项目只需要 `pinia-plugin-persistedstate` 这一行配置即可。
