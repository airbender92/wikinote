根据我们之前关于 Pinia 在大型项目中使用的讨论，以及 Pinia 作为 Vue 官方状态管理库的完整知识体系，下面整理出一份 **Pinia 需要掌握的所有知识清单**，涵盖从入门到大型项目实战的各个层面。

---

## 一、核心基础概念

| 知识点 | 说明 |
|--------|------|
| **Store 定义** | `defineStore(id, options)` 或 `defineStore(id, setup function)` |
| **Store 使用** | `useStore()` 在组件/composable 中调用（注意不要在 `setup` 外使用） |
| **State** | `state` 函数返回的对象，通过 `store.xxx` 直接读写 |
| **Getters** | 类似计算属性，有缓存，可通过 `this` 访问其他 getter/state |
| **Actions** | 支持异步，可调用其他 action，内部可以 `this.xxx` 直接修改 state |
| **实例 API** | `$patch`、`$reset`、`$subscribe`、`$onAction`、`$dispose` |

---

## 二、两种 Store 写法对比

| 写法 | 适用场景 | 核心特点 |
|------|----------|----------|
| **Options Store** | 简单、快速迁移 Vuex | 类似 Vuex 的 `state`/`getters`/`actions` 对象结构 |
| **Setup Store** (推荐) | 大型项目、复杂逻辑、TS 友好 | 使用 `ref`/`reactive` 定义 state，`computed` 定义 getter，`function` 定义 action，完全拥抱组合式 API |

---

## 三、与 TypeScript 集成

| 知识点 | 说明 |
|--------|------|
| **类型推导** | Pinia 默认自动推导 state、getters、actions 类型 |
| **为 Store 定义类型** | 使用 `defineStore<string, State, Getters, Actions>` 泛型 |
| **全局 Store 类型声明** | 扩展 `PiniaCustomProperties` 或 `PiniaCustomStateProperties` |
| **$patch 类型安全** | 部分更新时自动检查字段类型 |
| **`storeToRefs` 类型保留** | 解构后仍然是响应式 ref 且类型正确 |
| **插件中的类型增强** | 为 `this` 或 `store` 添加自定义属性时需要声明模块 |

---

## 四、在组件中使用

| 用法 | 代码示例 | 注意点 |
|------|----------|--------|
| **直接访问** | `const store = useUserStore()` | 整个 store 实例是响应式的，但解构会丢失响应性 |
| **响应式解构** | `const { name, age } = storeToRefs(store)` | 用于 state/getters，actions 可直接解构 |
| **批量修改** | `store.$patch({ name: 'new', age: 30 })` | 合并更新，触发一次响应 |
| **重置状态** | `store.$reset()` | 仅 Options Store 自动支持；Setup Store 需手动实现 |
| **订阅 state** | `store.$subscribe((mutation, state) => {})` | 在组件中订阅记得在 `onUnmounted` 中清理 |
| **订阅 action** | `store.$onAction(({ name, after, onError }) => {})` | 用于日志、埋点等横切关注点 |

---

## 五、组合式 API 中的高级模式

| 模式 | 说明 |
|------|------|
| **Store 间调用** | 一个 Store 内调用另一个 `useOtherStore()` 并直接使用其状态/方法 |
| **工厂模式 Store** | 返回一个函数，每次调用创建独立 Store 实例（非单例） |
| **依赖注入 Store** | 通过参数传入依赖（如 API 客户端），方便测试 |
| **动态 Store 注册** | `store.$id` + `useStore(storeId)` 动态创建/获取 |
| **跨请求状态隔离 (SSR)** | 使用 `createPinia()` 每次请求新建实例 |

---

## 六、插件开发

| 知识点 | 说明 |
|--------|------|
| **插件结构** | `pinia.use((context) => { ... })` |
| **context 属性** | `{ store, app, options, pinia }` |
| **增强 store** | 添加全局属性、方法、computed 等 |
| **扩展 state** | 通过 `store.$state` 添加新字段（需配合 TypeScript 声明） |
| **定义全局回调** | 例如每个 action 前后自动 loading 管理 |
| **第三方插件使用** | `pinia-plugin-persistedstate`、`pinia-plugin-undo-redo` |

---

## 七、持久化状态

| 方法 | 适用场景 |
|------|----------|
| **手动配合 localStorage** | 简单场景，在 action 中读写 |
| **`pinia-plugin-persistedstate`** | 官方推荐插件，支持选择性存储、自定义序列化、路径模块配置 |
| **SSR 中持久化** | 避免在服务端访问 localStorage，通过 `beforeMount` 客户端 hydration |
| **加密存储** | 敏感数据（token）需加密，结合插件自定义 `storage` 或序列化函数 |

---

## 八、性能优化

| 策略 | 说明 |
|------|------|
| **懒加载 Store** | 动态 `import()` Store 文件，结合路由懒加载 |
| **`$patch` 批量更新** | 减少响应式触发次数 |
| **避免不必要的订阅** | 组件卸载时 `stop()` 订阅函数 |
| **使用 `shallowRef`** | 大数组/对象时，浅响应式减少开销 |
| **合理拆分 Store** | 避免单个 Store 过大，按业务域垂直拆分 |
| **`store.$state` 替换** | 整体替换状态但保留响应式：`Object.assign(store.$state, newState)` |

---

## 九、测试

| 工具/方法 | 说明 |
|-----------|------|
| **`@pinia/testing`** | 官方测试辅助库，提供 `createTestingPinia()` |
| **隔离测试 Store** | 手动 `setActivePinia(pinia)` 然后 `useStore()` |
| **Mock actions** | 使用 `vi.spyOn` 或 `store.$onAction` 断言 |
| **测试插件** | 创建 `pinia` 实例，use 插件，然后创建 store 验证 |
| **SSR 测试** | 每次请求独立 `pinia` 实例，避免串数据 |

## 十、与 Vue Router 集成

| 场景 | 做法 |
|------|------|
| **路由守卫中访问 Store** | 在 `router.beforeEach` 中通过 `pinia` 实例调用 `useStore(pinia)` |
| **根据状态决定导航** | 例如检查用户登录状态，未登录重定向 |
| **路由变化清理数据** | 监听 `$route` 变化，在 action 中重置特定 store 数据 |
| **keep-alive 下状态保留** | 配合 `onActivated` 刷新数据 |

---

## 十一、服务端渲染 (SSR)

| 知识点 | 说明 |
|--------|------|
| **每一个请求独立的 Pinia 实例** | 避免状态跨用户污染 |
| **状态注水 (hydration)** | 服务端预取数据存入 `pinia.state.value`，客户端使用 `pinia.state.value = window.__INITIAL_STATE__` |
| **Setup Store 中的 `onServerPrefetch`** | 用于组件级数据预取 |
| **避免访问浏览器 API** | 在 `defineStore` 的 `state` 或 action 中不要直接使用 `localStorage` |
| **使用 `$subscribe` 谨慎** | 订阅会在服务端执行，可能导致内存泄漏 |

---

## 十二、最佳实践与常见陷阱

| 主题 | 建议 / 避坑 |
|------|-------------|
| **不要直接解构 store** | 使用 `storeToRefs` 保留响应性 |
| **不要在 `$patch` 中异步修改** | `$patch` 是同步的，异步请用 action |
| **不要在 getter 中产生副作用** | getter 应该纯，不要发请求或修改状态 |
| **避免在 action 中返回整个 store** | 返回具体数据或 `Promise` 即可 |
| **组合式函数中调用 store** | 确保在 `setup` 或 `callWithNuxt` 上下文中 |
| **大型项目组织** | 按业务域拆分模块，统一导出，建立 hooks 复用 store 逻辑 |
| **开发工具** | 配合 Vue DevTools 7+ 查看 Pinia 状态和时间旅行 |

## ✅ 总结：按学习路径梳理

1. **基础**：定义和使用 store、state、getters、actions、`$patch`、`$reset`
2. **进阶**：Setup Store、storeToRefs、store 间调用、订阅、插件机制
3. **大型项目**：模块化架构、TypeScript 深度集成、持久化、性能优化、测试
4. **特殊场景**：SSR、路由守卫集成、动态 store、工厂模式
