# 一、先搞懂：表与表之间的关系（你说的一对多就在这）
数据库里表和表的关系只有 **3 种**：
1. **一对一（1:1）**
2. **一对多（1:N）** —— 最常用、最重要
3. **多对多（M:N）**

---

# 1. 一对多（1 : N）⭐⭐⭐⭐⭐（必考、必用）
## 概念
**一个 A 对应多个 B，但一个 B 只属于一个 A**

最经典例子：
- 一个班级 → 多个学生
- 一个用户 → 多个订单
- 一个分类 → 多个商品
- 一个部门 → 多个员工

## 怎么实现？
**在“多”的那张表里，加一个字段，存“一”那边的 ID**
这个字段叫 **外键（foreign key）**

举个表结构：
```
班级表 class
id  className
1   高一1班
2   高一2班

学生表 student
id  name  classId（外键）
1   张三      1
2   李四      1
3   王五      2
```

学生表的 `classId` 指向班级表的 `id`
这就是**一对多**。

## 怎么查？用 JOIN
```sql
SELECT s.name, c.className
FROM student s
JOIN class c ON s.classId = c.id;
```

---

# 2. 一对一（1 : 1）
**一个 A 只对应一个 B，一个 B 只对应一个 A**

例子：
- 一个人 ↔ 一个身份证
- 一个用户 ↔ 一个用户详情

实现方式：
任意一张表加一个指向另一张表的 ID 即可。
一般用于**把大表拆小**，提高查询速度。

---

# 3. 多对多（M : N）⭐⭐⭐⭐
**多个 A 对应多个 B**

例子：
- 学生 ↔ 课程（一个学生选多门课，一门课多个学生）
- 商品 ↔ 标签
- 用户 ↔ 角色

## 怎么实现？
**必须建第三张表，叫中间表/关联表**

结构示例：
```
学生 student
id name

课程 course
id name

选课表 student_course（中间表）
studentId  courseId
```

这张表只存两个 ID，用来关联两边。

## 查询示例
```sql
SELECT s.name, c.cname
FROM student s
JOIN student_course sc ON s.id = sc.studentId
JOIN course c ON sc.courseId = c.id;
```

# 二、接下来是数据库设计核心理论：三大范式（1NF、2NF、3NF）
你学完关系，就该学**怎么把表设计得干净、不冗余**。

## 第一范式 1NF
**列不可再分，每一列都是原子数据**
比如不要把“姓名+电话”放一个字段里。

## 第二范式 2NF
**必须有主键，非主键字段完全依赖主键，不能只依赖一部分**
主要针对联合主键的表。

## 第三范式 3NF
**非主键字段之间不能互相推导，不能有传递依赖**
比如：订单表里不要存“用户姓名”，只存 userId，名字去用户表里查。

简单记：
- 1NF：字段不可分
- 2NF：非主键全依赖主键
- 3NF：不传递依赖

实际开发中，**不会严格遵守 3NF**，会适当冗余提高速度，叫**反范式**。

# 三、主键、外键、唯一键、索引（理论核心）
- **主键（PRIMARY KEY）**：唯一标识一条记录，非空、唯一
- **外键（FOREIGN KEY）**：关联另一张表的主键，保证数据完整性
- **唯一键（UNIQUE）**：值不能重复，但可以为空
- **索引（INDEX）**：加速查询，像书的目录

---

# 四、事务 ACID 理论（面试必问）
事务就是一组操作，要么全成功，要么全失败。

- **A 原子性**：不可分割
- **C 一致性**：执行前后数据合法
- **I 隔离性**：多个事务互不干扰
- **D 持久性**：一旦提交永久生效

典型场景：转账
扣钱 + 加钱必须同时成功或失败。
