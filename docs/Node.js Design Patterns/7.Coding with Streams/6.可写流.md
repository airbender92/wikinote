# 翻译
## 可写流（Writable streams）
可写流代表**数据写入目标**，比如磁盘文件、数据库表、网络套接字、标准输出/标准错误等。在 Node.js 中由 `stream` 模块提供的 `Writable` 抽象类实现。

### 向流写入数据
往可写流写入数据十分简单，核心方法 `write()`，签名如下：
```js
writable.write(chunk, [encoding], [callback])
```
- `encoding` 可选：若 chunk 是字符串可指定编码，默认 `utf8`；传入 Buffer 时该参数失效
- `callback` 可选：当前数据块完全刷入底层资源后触发回调

写入完成、告知流不再有新数据时，调用 `end()`：
```js
writable.end([chunk], [encoding], [callback])
```
可在 `end` 中传入最后一段数据；`end` 的回调等价于监听 `finish` 事件，该事件会在所有缓存数据全部落盘/发送完成后触发。

> 注意：不要在内存中一次性创建超大数组。举个例子，如果要遍历全球百万条山脉数据，全部存入数组会占用大量内存。即便数组再转为可读流，数据也已经全量加载到内存，彻底丧失流的内存优势。推荐使用原生文件流、自定义流、生成器/异步迭代器配合 `Readable.from` 实现分片懒加载，第9章会举例讲解。

### 示例：随机字符串输出HTTP服务 entropy-server.js
```js
import { createServer } from 'http'
import Chance from 'chance'
const chance = new Chance()
const server = createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' }) // (1)
  while (chance.bool({ likelihood: 95 })) { // (2)
    res.write(`${chance.string()}\n`) // (3)
  }
  res.end('\n\n') // (4)
  res.on('finish', () => console.log('所有数据发送完毕')) // (5)
})
server.listen(8080, () => {
  console.log('服务监听：http://localhost:8080')
})
```
HTTP 回调里的 `res`（`http.ServerResponse`）本身就是可写流，逻辑拆解：
1. 写入HTTP响应头；`writeHead` 是HTTP专属方法，不属于通用Writable接口
2. 循环生成随机布尔值，95%概率继续执行写入，5%退出循环
3. 每次循环写入一行随机字符串到响应流
4. 循环结束调用 `end()`，写入两行换行作为末尾数据，并标记流写入终止
5. 监听 `finish` 事件，所有数据推送至客户端后打印日志

测试方式：浏览器访问 `http://localhost:8080`，或终端执行 `curl localhost:8080`
提示：部分浏览器会做数据缓冲，可能看不到实时流式输出效果。

# 核心解读
1. **write()**：写入数据块，返回布尔标识缓冲区是否饱和（背压信号）；调用 `end()` 后禁止再调用 write，会抛错。
2. **end()** 双重作用：写入最后一段数据 + 关闭流；全部数据刷新完成触发 `finish` 事件。
3. 常见Writable实例：HTTP响应对象、`fs.createWriteStream`、`process.stdout`/`stderr`。
4. 内存优化要点：避免一次性加载全量数据到数组，流的核心优势是分片懒加载。
5. `finish` 事件：仅在调用 end 且所有缓冲区数据落盘后触发，代表写入流程彻底完成。

# 翻译
## 背压（Backpressure）
就像现实管道中液体输送会遇到瓶颈一样，Node.js 的流也存在数据流速失衡问题：数据写入速度远快于下游消费速度。
应对方案是内置缓冲区缓存待处理数据，但如果写入端收不到缓冲区满的反馈，缓存会持续堆积，造成内存占用失控。

为避免该问题，当可写流内部缓冲区超过 `highWaterMark`（水位上限）时，`writable.write()` 会返回 `false`，提示写入方暂停发送数据；缓冲区清空后会触发 `drain` 事件，告知可以恢复写入。这套流量控制机制就叫**背压**。

背压只是提示性机制：即便 `write()` 返回 false，代码仍可强行继续写入，缓冲区会无限膨胀，流不会主动阻断程序。开发时必须遵循背压信号，合理控流。

我们改造上一节的随机字符串 HTTP 服务，演示背压处理逻辑：
```js
// ...
const server = createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' })
  function generateMore () { // (1)
    while (chance.bool({ likelihood: 95 })) {
      const randomChunk = chance.string({ // (2)
        length: (16 * 1024) - 1
      })
      const shouldContinue = res.write(`${randomChunk}\n`) // (3)
      if (!shouldContinue) {
        console.log('触发背压')
        return res.once('drain', generateMore)
      }
    }
    res.end('\n\n')
  }
  generateMore()
  res.on('finish', () => console.log('所有数据发送完毕'))
})
// ...
```
代码核心逻辑说明：
1. 所有生成写入逻辑封装为 `generateMore` 函数；
2. 分片大小设为 16KB - 1，贴近默认缓冲区上限，更容易触发背压；
3. 接收 `write()` 返回值：若为 false 代表缓冲区已满，停止写入，监听 `drain` 事件，等缓存释放后再恢复生成数据。

补充：背压机制同样作用于可读流。可读流中调用 `push()` 返回 false 时也会触发背压，但这是流实现者需要处理的逻辑，日常业务开发很少接触。

再次启动服务，用 curl 请求，由于服务生成数据速度远超网络传输速度，大概率会打印背压日志。

# 核心解读
1. **核心定义**：下游消费速度跟不上上游生产速度，缓冲区饱和产生的流量限制机制；
2. 关键标识：`write()` 返回 `false` = 缓冲区达到高水位，暂停写入；`drain` 事件 = 缓存清空，恢复写入；
3. 默认 `highWaterMark`：二进制流16KB，对象流16个对象；
4. 风险：无视背压持续写入会造成内存泄漏、程序卡顿甚至OOM；
5. `pipe()` / `stream.pipeline()` 内部自动处理背压，无需手动判断，是官方推荐方式。

---

你遇到的问题非常典型：
**触发背压后，代码只监听了 `drain` 并重新调用 `generateMore`，但没有处理「流已经被客户端断开 / 结束」的情况**，导致服务端一直卡在等待 `drain`，响应永远不结束，浏览器就一直转圈加载。

---

## 根本原因
原版背压代码有两个缺陷：
1. **只监听 `drain`，没处理客户端断开（`close`/`error`）**
2. 一旦进入背压等待，循环被挂起，**永远不会走到 `res.end()`**
浏览器收不到结束标志，就一直等。

---

## 修复版代码（关键改动）
```js
import { createServer } from 'http'
import Chance from 'chance'
const chance = new Chance()

const server = createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/plain' })

  let finished = false // 标记流是否已结束

  function generateMore() {
    // 如果已经结束，直接退出
    if (finished) return

    while (chance.bool({ likelihood: 95 })) {
      const randomChunk = chance.string({
        length: 16 * 1024 - 1
      })

      // 写入并检查背压
      const ok = res.write(randomChunk + '\n')
      if (!ok) {
        console.log('back-pressure')

        // 监听 drain 恢复写入
        res.once('drain', generateMore)
        return
      }
    }

    // 循环正常结束，关闭流
    finished = true
    res.end('\n\n')
  }

  // 监听客户端断开，避免卡死
  req.on('close', () => {
    finished = true
  })

  // 监听错误
  res.on('error', (err) => {
    console.error('res error', err)
    finished = true
  })

  generateMore()

  res.on('finish', () => {
    console.log('All data sent')
  })
})

server.listen(8080, () => {
  console.log('listening on http://localhost:8080')
})
```

---

## 为什么这样就不转圈了？
1. 加了 `finished` 标志，防止流结束后还继续写
2. 监听客户端断开 `req.on('close')`，立刻标记结束
3. 正常循环退出时**一定会走到 `res.end()`**
4. 浏览器收到 `end`，就知道响应完成，停止加载

---

## 最简单的“不踩坑”方案
如果你只是学习演示，**不想手动处理背压**，直接用 `pipe`，Node 会自动处理一切：
```js
import { Readable } from 'stream'
// ...
const stream = Readable.from(function*() {
  while (chance.bool({ likelihood: 95 })) {
    yield chance.string(1024) + '\n'
  }
}())

stream.pipe(res)
```
`pipe` 内部自动处理背压、结束、错误、客户端断开，永远不会卡死加载。

# 翻译
## 实现可写流
我们可以通过继承 `Writable` 类并实现 `_write()` 方法，来创建自定义可写流。下面边写代码边讲解细节。

### 需求
实现一个可写流，接收如下格式的对象：
```js
{
  path: "文件路径",
  content: "字符串或Buffer"
}
```
流会自动把 `content` 写入到 `path` 指定的文件中。
因为输入是**对象**而非字符串/Buffer，所以流必须运行在**对象模式**。

### 代码实现：to-file-stream.js
```js
import { Writable } from 'stream'
import { promises as fs } from 'fs'
import { dirname } from 'path'
import mkdirp from 'mkdirp-promise'

export class ToFileStream extends Writable {
  constructor (options) {
    // 强制开启对象模式
    super({ ...options, objectMode: true })
  }

  _write (chunk, encoding, cb) {
    // 自动创建目录 → 写入文件
    mkdirp(dirname(chunk.path))
      .then(() => fs.writeFile(chunk.path, chunk.content))
      .then(() => cb())         // 成功：调用回调通知流完成
      .catch(cb)                // 失败：传递错误
  }
}
```

### 要点说明
1. **继承 Writable**
   自定义可写流必须继承 `stream.Writable`。

2. **构造函数配置**
   - `super({ objectMode: true })`：强制开启**对象模式**，让流可以接收普通 JS 对象
   - 其他可配置项：
     - `highWaterMark`：背压阈值（默认 16KB）
     - `decodeStrings`：是否自动把字符串转成 Buffer（对象模式下无效）

3. **必须实现 `_write()`**
   这是可写流的核心方法，参数含义：
   - `chunk`：写入的数据块（这里是我们的对象）
   - `encoding`：编码（对象模式下无用）
   - `cb`：**完成回调**
     - 操作成功 → `cb()`
     - 操作失败 → `cb(error)`，流会自动触发 `error` 事件

---

## 使用自定义可写流
```js
import { join } from 'path'
import { ToFileStream } from './to-file-stream.js'

const tfs = new ToFileStream()

// 写入多个对象
tfs.write({
  path: join('files', 'file1.txt'), content: 'Hello'
})
tfs.write({
  path: join('files', 'file2.txt'), content: 'Node.js'
})
tfs.write({
  path: join('files', 'file3.txt'), content: 'streams'
})

// 结束流，并监听完成
tfs.end(() => console.log('All files created'))
```

运行后会自动创建 `files` 目录，并生成 3 个文件。

---

# 核心总结
1. 自定义 Writable 固定套路：
   - 继承 `Writable`
   - 实现 `_write(chunk, enc, callback)`
   - 操作完成必须调用 `callback()`

2. **对象模式**
   - `objectMode: true` 后可以直接 write 对象
   - 不再是二进制流，而是“对象流”

3. 异步友好
   `_write` 天然支持异步操作，只需在异步结束后调用回调即可。

4. 背压
   Node 会自动根据 `highWaterMark` 管理背压，不用手动处理。
