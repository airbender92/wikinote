# 多路复用与解复用（Multiplexing / Demultiplexing）
**多路复用（mux）**：把**多个逻辑流**，通过**同一个物理流**传输。
**解复用（demux）**：在接收端，从同一个流里，还原出原来的多个逻辑流。

它和普通的**合并流（merge）**不一样：
- merge：只是简单把数据混在一起，无法再分开
- multiplex：数据带有**标识**（通道号/流名），接收端可以**精准还原出原始多条流**

就像网络通信里的**一条光纤跑上千路电话**，或者 TCP 协议里的**端口复用**。

---

# 核心思想
1. 发送端（mux）
   - 给每个流编号：`channel 1`、`channel 2`…
   - 给每个 chunk 加上**通道标识**
   - 全部塞进同一条流发送

2. 接收端（demux）
   - 读取带标识的 chunk
   - 根据通道号，分发到不同的输出流
   - 还原出和发送端一模一样的多个流

---

# 典型应用场景
- **网络通信**：单条 TCP 连接传输多个数据流（HTTP/2 多路复用）
- **IPC / 进程间通信**：一个 socket 同时传日志、控制信令、数据
- **日志与监控**：一条流里同时传输 metrics、logs、traces 并在远端分离
- **文件打包**：类似 tar，但流式、不解压就能提取单条流

---

# 一句话区别
- **merge = 搅在一起，分不开**
- **multiplex = 打包在一起，还能原样拆开**

这是构建**高性能网络协议、RPC、IPC 系统**的核心流模式。

# 构建远程日志系统（多路复用 + 解复用实战）
这个例子实现：
- 客户端：启动子进程，把 **stdout + stderr** 打包在**同一条 TCP 连接**发送
- 服务端：从一条 TCP 流里拆分出两条独立流，分别写入 `stdout.log` 和 `stderr.log`

用到核心技术：**分组交换（packet switching）**
每个数据包格式：
`[1字节 通道ID][4字节 数据长度][数据体]`

---

## 1. 客户端（多路复用）client.js
把子进程的 stdout、stderr 复用到一条 TCP socket

```javascript
import { fork } from 'child_process'
import { connect } from 'net'

function multiplexChannels(sources, destination) {
  let openChannels = sources.length

  for (let i = 0; i < sources.length; i++) {
    sources[i]
      .on('readable', function () {
        let chunk
        while ((chunk = this.read()) !== null) {
          // 构造数据包：通道ID(1) + 长度(4) + 数据
          const outBuff = Buffer.alloc(1 + 4 + chunk.length)
          outBuff.writeUInt8(i, 0)           // 通道 0=stdout, 1=stderr
          outBuff.writeUInt32BE(chunk.length, 1)
          chunk.copy(outBuff, 5)
          destination.write(outBuff)
        }
      })
      .on('end', () => {
        if (--openChannels === 0) {
          destination.end() // 所有流结束才关闭socket
        }
      })
  }
}

// 连接服务端并启动子进程
const socket = connect(3000, () => {
  const child = fork(process.argv[2], process.argv.slice(3), {
    silent: true
  })
  // 多路复用 stdout + stderr
  multiplexChannels([child.stdout, child.stderr], socket)
})
```

## 2. 服务端（解复用）server.js
从一条 TCP 流解析出两条独立日志流

```javascript
import { createWriteStream } from 'fs'
import { createServer } from 'net'

function demultiplexChannel(source, destinations) {
  let currentChannel = null
  let currentLength = null

  source
    .on('readable', () => {
      // 读通道ID
      if (currentChannel === null) {
        const chunk = source.read(1)
        if (!chunk) return
        currentChannel = chunk.readUInt8(0)
      }

      // 读数据长度
      if (currentLength === null) {
        const chunk = source.read(4)
        if (!chunk) return
        currentLength = chunk.readUInt32BE(0)
      }

      // 读真实数据
      const chunk = source.read(currentLength)
      if (!chunk) return

      // 写入对应通道
      destinations[currentChannel].write(chunk)

      // 重置状态，准备下一个包
      currentChannel = null
      currentLength = null
    })
    .on('end', () => {
      destinations.forEach(dest => dest.end())
      console.log('Client disconnected')
    })
}

// 启动TCP服务器
const server = createServer((socket) => {
  const stdoutStream = createWriteStream('stdout.log')
  const stderrStream = createWriteStream('stderr.log')
  demultiplexChannel(socket, [stdoutStream, stderrStream])
})

server.listen(3000, () => console.log('Server listening on 3000'))
```

# 核心模式总结
- **多路复用（mux）**：多逻辑流 → 打包 → 单物理流
- **解复用（demux）**：单物理流 → 拆包 → 还原多逻辑流
- **应用**：远程日志、HTTP/2、RPC、网络隧道、IPC
- **关键**：自定义数据包格式 + 状态机解析

这是 Node.js 流在**网络通信**中最强大、最实用的高级模式。
