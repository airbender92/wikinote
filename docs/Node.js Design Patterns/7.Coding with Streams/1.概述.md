# Chapter 6 核心概览：Coding with Streams（Node.js 流编程）

这一章是 **Node.js 真正核心、最具特色、也是面试最爱考** 的内容。
一句话定位：
**Stream = 把数据切成一段一段流动处理，而不是一次性全部加载**。

## 本章要讲什么（按书的结构）
1. **为什么 Stream 是 Node 的灵魂**
   - 处理大文件 / 大量数据不爆内存
   - 延迟处理、低内存占用
   - 组合性极强：像管道一样拼接

2. **Stream 基础**
   - 四种流类型：
     - **Readable**：可读流（数据源）
     - **Writable**：可写流（目的地）
     - **Duplex**：双工（可读又可写）
     - **Transform**：转换流（数据流过时修改）

3. **背压（Backpressure）机制**
   - 读得快、写得慢时自动调节
   - 这是 Node 内置的，不用自己处理

4. **使用与创建流**
   - 用内置流：`fs.createReadStream`、`http` 请求/响应
   - 自定义 Readable / Writable / Transform

5. **流式编程范式**
   - 用 `.pipe()` 串联多个处理步骤
   - 模块化、函数式、优雅

6. **高级流式模式**
   - 并行流
   - 合并流
   - 异步迭代器 `for await...of` 与流结合
   - 错误处理、多管道组合

---

## 一句最通俗的比喻
- **不用流**：把整桶水倒进碗里 → 碗炸了（内存溢出）
- **用流**：用水管一段一段流过去 → 碗稳稳接住，内存永远很小

# 翻译
## 流的重要性初探
在 Node.js 这类基于事件的平台中，处理IO最高效的方式就是实时处理：数据一就绪就读取消费，程序一产生数据就向外输出。
本节会为你初步介绍 Node.js 流及其优势。注意此处仅作概述，本章后续会更细致地讲解流的使用与组合方法。

# 核心解读
1. 核心逻辑：Node 事件驱动模型适配流式IO，无需缓存完整数据再处理；
2. 核心价值：实时分片处理，节省内存、提升IO处理效率；
3. 内容铺垫：本段仅做概念引入，本章后半段才会展开流的实操与组合用法。
