2. 流是官方标准通用接口，不同模块的流可无缝通过`pipe`拼接；
3. 下文将系统拆解四类基础流、底层运行机制。

# 翻译
## 流的内部构成
Node.js 中的所有流，都实现了 `stream` 核心模块提供的四种抽象基类之一：
- 可读流（Readable）
- 可写流（Writable）
- 双工流（Duplex）
- 转换流（Transform）

所有流同时都是 EventEmitter 的实例，能够触发多种事件：例如可读流读取完毕时触发 `end`、可写流写完所有数据时触发 `finish`、发生异常时触发 `error`。

流具备极高灵活性的一大原因是：它不只可以处理二进制数据，几乎能承载任意 JS 值。流分为两种工作模式：
1. 二进制模式：以 Buffer、字符串这类数据块作为流分片传输
2. 对象模式：以独立 JS 对象作为流的传输单元（支持几乎所有 JavaScript 类型）

两种工作模式让流不止用于 IO 读写，还能以函数式的方式优雅组合各类数据处理单元。本章后续会详细讲解。

我们先从可读流（Readable）开始深入学习。

# 核心解读
1. 四类基础流是所有流式API的底层抽象，全部继承事件发射器，靠事件驱动数据流转；
2. 二进制模式多用于文件、网络等底层IO；对象模式适合处理结构化业务数据；
3. `error` 是流的关键事件，必须监听，否则程序会直接崩溃。

# 翻译
## 可读流
可读流代表**数据源**。在 Node.js 中，它由 `stream` 模块提供的 `Readable` 抽象类实现。

### 从流中读取数据
从可读流获取数据分为两种模式：**非流动模式（暂停模式）**、**流动模式**，下面详细解析两种模式。

# 核心解读
1. Readable = 数据生产者，文件读取、HTTP 请求体等都是典型可读流；
2. 两种读取模式是可读流核心特性，决定数据推送/拉取的工作逻辑。

---

# 翻译
## 非流动模式（暂停模式）
非流动模式是可读流**默认**的读取方式。我们需要给流绑定 `readable` 事件监听器，该事件代表有新数据就绪；随后循环调用 `read()` 方法持续读取，直到内部缓冲区清空。
`read()` 会同步从缓冲区取出一段数据，返回 Buffer 对象，方法签名：
```js
readable.read([size])
```
该模式是**按需主动拉取**数据。

示例：新建 `read-stdin.js`，从标准输入（可读流）读取内容并打印输出
```js
process.stdin
  .on('readable', () => {
    let chunk
    console.log('收到新数据')
    while ((chunk = process.stdin.read()) !== null) {
      console.log(`读取分片（${chunk.length}字节）："${chunk.toString()}"`)
    }
  })
  .on('end', () => console.log('流读取完毕'))
```
`read()` 是同步方法，从可读流内部缓冲区拉取数据；二进制模式下返回值默认为 Buffer。
读取逻辑必须写在 `readable` 事件回调内，该事件在新数据抵达时触发。
缓冲区无数据时，`read()` 返回 `null`，此时需要等待下一次 `readable` 事件；若数据全部读完则触发 `end` 事件。
二进制模式下可传入 `size` 参数，指定读取固定字节，实现网络协议、特定格式解析等场景。

运行程序：控制台输入字符回车即可打印数据；
发送文件结束符终止流：Windows 使用 `Ctrl+Z`，Linux/macOS 使用 `Ctrl+D`。

# 核心解读
1. 非流动模式（默认）：开发者主动调用 `.read()` 拉取数据，不会自动推送；
2. `readable` 事件：缓冲区有数据才触发，循环读取至 `read()` 返回 null；
3. 适用场景：需要精确控制读取字节长度、自定义分片解析。

# 翻译
## 流动模式
读取流的另一种方式是监听 `data` 事件。一旦绑定该监听器，流会自动切换为**流动模式**：数据抵达后会主动推送到 `data` 回调，无需手动调用 `read()` 拉取。

用流动模式改写上一节标准输入示例 `read-stdin.js`：
```js
process.stdin
  .on('data', (chunk) => {
    console.log('收到新数据')
    console.log(`读取分片（${chunk.length}字节）："${chunk.toString()}"`)
  })
  .on('end', () => console.log('流读取完毕'))
```

相比非流动模式，流动模式对数据流的可控性更弱。流默认是非流动模式；开启流动模式有两种方式：绑定 `data` 监听器，或是显式调用 `resume()`。
调用 `pause()` 可以临时暂停推送 `data` 事件，新数据会存入内部缓冲区，同时流切回非流动模式。

我们还可以借助 Shell 管道符 `|` 将其他进程的输出接入当前程序，它会把前一个进程的标准输出重定向为后一个进程的标准输入，示例命令：
```
cat 文件路径 | node read-stdin.js
```
这个场景直观体现：流是通用标准接口，不同语言、不同程序之间都能依靠流式模型互通数据。

# 核心解读
1. 流动模式：数据自动推送至 `data` 回调，无需手动拉取，写法更简洁；
2. 模式切换规则：默认暂停模式；监听`data`/`resume()`→流动；`pause()`切回暂停；
3. 短板：无法精准控制读取字节，大量数据涌入时易出现背压问题；
4. 通用性：流式接口跨进程、跨语言通用，和 Linux 管道设计思想完全一致。

# 翻译
## 异步迭代器
可读流同时也是异步迭代器，因此我们可以用下面的写法重写 `read-stdin.js`：
```js
async function main () {
  for await (const chunk of process.stdin) {
    console.log('收到新数据')
    console.log(`读取分片（${chunk.length}字节）："${chunk.toString()}"`)
  }
  console.log('流读取完毕')
}
main()
```
我们会在第9章「行为型设计模式」深入讲解异步迭代器，现在不必深究这段语法。你只需要记住一个关键点：如果需要编写一个消费完整可读流、并返回 Promise 的函数，`for await...of` 这种语法会非常好用。

# 核心解读
1. 所有 Readable 可读流原生支持异步迭代协议，可直接搭配 `for await...of` 遍历；
2. 语法简洁，天然基于 Promise，异步逻辑同步化书写，是现代读取流的推荐写法；
3. 内部自动处理数据分片、流结束逻辑，无需手动监听 `data` / `end` 事件。

# 翻译
## 实现自定义可读流
掌握如何消费可读流后，下一步学习自定义实现可读流。
需要继承 `stream` 模块的 `Readable` 抽象类，并强制实现内部方法 `_read()`，方法签名：
```js
readable._read(size)
```
`Readable` 基类会自动调用 `_read()`，我们在该方法内通过 `push()` 向流内部缓冲区填充数据：
```js
readable.push(chunk)
```
区分重点：
外部使用者调用 `read()`；`_read()` 是子类实现的内部方法，**禁止直接手动调用**，下划线代表私有内部接口。

### 示例：随机字符串生成可读流
新建 `random-stream.js`，借助 `chance` 随机库实现自定义可读流：
```js
import { Readable } from 'stream'
import Chance from 'chance'
const chance = new Chance()

export class RandomStream extends Readable {
  constructor (options) {
    super(options)
    this.emittedBytes = 0
  }

  _read (size) {
    const chunk = chance.string({ length: size }) // (1)
    this.push(chunk, 'utf8') // (2)
    this.emittedBytes += chunk.length
    if (chance.bool({ likelihood: 5 })) { // (3)
      this.push(null)
    }
  }
}
```
1. 引入依赖：`chance` 是随机数据生成第三方库，可生成数字、字符串、句子等；
2. `RandomStream` 继承 `Readable`，构造函数执行 `super(options)` 初始化父类流内部状态；
   若自定义构造函数仅执行 `super(options)`，可直接省略构造函数。
3. `options` 常用配置：
   - `encoding`：Buffer 转字符串编码，默认 `null`
   - `objectMode`：开启对象模式，默认 `false`
   - `highWaterMark`：缓冲区最大阈值，默认16KB

#### _read 方法逻辑说明
1. 根据传入 `size` 生成指定长度随机字符串；
2. 通过 `push()` 将字符串写入缓冲区，字符串需指定编码；若传入 Buffer 则无需编码；
3. 5% 概率调用 `push(null)`，`null` 代表流结束（EOF）。

> 注意：`_read` 的 `size` 只是建议值，最好遵循该长度返回数据，但并非强制要求。

### 使用自定义可读流（index.js）
```js
import { RandomStream } from './random-stream.js'
const randomStream = new RandomStream()

randomStream
  .on('data', (chunk) => {
    console.log(`收到分片（${chunk.length}字节）：${chunk.toString()}`)
  })
  .on('end', () => {
    console.log(`总共生成随机数据：${randomStream.emitted} 字节`)
  })
```
补充要点：调用 `push()` 时需要判断返回值；若返回 `false`，代表缓冲区达到 `highWaterMark` 上限，此时应停止写入数据，该机制称为**背压**，下一节详细讲解。

直接运行 `index.js`，控制台会持续输出随机字符串，直到流随机终止。

# 核心解读
1. 自定义 Readable 固定模板：继承 Readable + 实现 `_read(size)`；
2. `push(data)` 填充缓冲区，`push(null)` 标记流读取完成；
3. `push()` 返回 false = 触发背压，必须暂停生产数据，防止内存溢出；
4. options 三大核心配置控制编码、对象模式、缓冲区上限；
5. `_read` 由流内部自动触发，开发者永远不要手动调用。

# 翻译
## 简化构建方式
对于简单的自定义流，无需新建子类，可以使用可读流的简化创建语法：直接 `new Readable(options)`，在配置项中传入 `read` 方法。这个 `read` 方法和前面继承类写法里的 `_read` 逻辑完全一致。

我们用简化写法重写随机字符串流：
```js
import { Readable } from 'stream'
import Chance from 'chance'
const chance = new Chance()
let emittedBytes = 0

const randomStream = new Readable({
  read(size) {
    const chunk = chance.string({ length: size })
    this.push(chunk, 'utf8')
    emittedBytes += chunk.length
    if (chance.bool({ likelihood: 5 })) {
      this.push(null)
    }
  }
})
// 直接使用 random 流实例
```

这种写法适合无需维护复杂内部状态的场景，代码更简洁。
如果需要多次创建该流实例，我们可以把创建逻辑封装成工厂函数，多次调用工厂生成不同实例。

# 核心解读
1. 简化API：无需继承class，实例化时直接传 `read` 回调，等价于重写 `_read`；
2. 适用场景：简单一次性流、无复杂实例属性；
3. 多实例方案：封装工厂函数，每次调用 `new Readable` 生成独立流。

# 翻译
## 从可迭代对象创建可读流
借助 `Readable.from()` 工具方法，可以轻松基于数组、生成器、迭代器、异步迭代器等可迭代对象创建可读流。
下面举个例子，将数组转为可读流：
```js
import { Readable } from 'stream'
const mountains = [
  { name: 'Everest', height: 8848 },
  { name: 'K2', height: 8611 },
  { name: 'Kangchenjunga', height: 8586 },
  { name: 'Lhotse', height: 8516 },
  { name: 'Makalu', height: 8481 }
]
const mountainsStream = Readable.from(mountains)
mountainsStream.on('data', (mountain) => {
  console.log(`${mountain.name.padStart(14)}\t${mountain.height}m`)
})
```
`Readable.from()` 使用方式十分简单：第一个参数传入任意可迭代对象（本例是数组）；还支持第二个可选参数，用来配置流参数（如 `objectMode`）。

运行代码输出结果：
        Everest	8848m
             K2	8611m
Kangchenjunga	8586m
          Lhotse	8516m
          Makalu	8481m

注意：我们无需手动开启 `objectMode`。`Readable.from()` 默认自动开启对象模式，除非你主动将该配置设为 false。流配置项可作为第二个参数传入该方法。

# 核心解读
1. `Readable.from()` 快速创建可读流，支持数组、同步/异步迭代器；
2. 默认开启 `objectMode`，可直接流转对象，不用手动配置；
3. 第二个参数可传入流配置，关闭对象模式、设置缓冲区上限等。
