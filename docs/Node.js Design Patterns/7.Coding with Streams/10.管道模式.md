# 翻译
## 管道组合模式（Piping patterns）
就像现实中的水管工程，Node.js 流也可以按不同模式连接：
- 合并多条流为一条
- 把一条流分叉到多个管道
- 根据条件动态切换流向

本节讲解最核心的**流组合模式**（combining streams）。

---

## 流的组合：把整条管道封装成单个流
我们一直在强调：流可以模块化、可复用。
但还差最后一步：
**如何把一整条管道封装成一个独立、可复用的流？**

如图所示：
- 往**组合流**里写数据 = 写入管道**第一个流**
- 从**组合流**读数据 = 从管道**最后一个流**读

组合流本质是一个 **Duplex 流**，对外隐藏内部复杂的管道结构。

### 为什么需要组合流？
1. **封装成黑盒**
   内部是一串管道，对外只暴露一个流，方便复用和分发。

2. **简化错误处理**
   不用给每个子流都监听 `error`，只监听组合流即可。

3. `.pipe()` 和 `stream.pipeline()` 的缺陷
   ```js
   streamA.pipe(streamB).pipe(streamC) // 返回 streamC
   pipeline(a, b, c, cb)               // 也只返回最后一个流
   ```
   它们**只返回最后一个可读流**，拿不到最前面的可写端，无法整体作为一个流使用。

---

## 解决方案：使用 pumpify
`pumpify` 是专门用来**封装管道为单个 Duplex 流**的库。

用法几乎和 `pipeline()` 一样，只是**没有回调，返回组合流**：
```js
import pumpify from 'pumpify'

// 把多个流打包成一个组合流
const combined = pumpify(streamA, streamB, streamC)
```

特点：
- 对外是**一个流**，可读可写
- 内部自动 pipe 所有流
- 错误自动冒泡到组合流
- 可以继续被外部 pipe：
  ```js
  someReadable.pipe(combined).pipe(someWritable)
  ```

---

## 背景知识
- `pumpify` 内部基于 `pump`
- `pump` 是早于官方 `stream.pipeline()` 的社区方案
- 官方 `pipeline()` 实际上借鉴了 `pump` 的设计

---

# 本节核心总结
- **组合流 = 整条管道封装成一个 Duplex 流**
- 解决 `.pipe()` / `pipeline()` 只能返回最后一个流的问题
- 优势：封装性、可复用、统一错误处理
- 生产常用库：`pumpify`、`duplexer2`、`duplexify`

这是构建**流式中间件、可复用处理器、复杂数据流引擎**的标准模式。

# 翻译
## 实现一个组合流
下面用一个实用示例演示**流组合**：
- 创建一个流：**先压缩、再加密**
- 创建另一个流：**先解密、再解压**

用 `pumpify` 可以把多步操作封装成**单个黑盒流**。

---

### 步骤 1：定义组合流（combined-streams.js）
```js
import { createGzip, createGunzip } from 'zlib'
import { createCipheriv, createDecipheriv, scryptSync } from 'crypto'
import pumpify from 'pumpify'

// 生成密钥
function createKey(password) {
  return scryptSync(password, 'salt', 24)
}

// 组合流：压缩 + 加密
export function createCompressAndEncrypt(password, iv) {
  const key = createKey(password)
  const combinedStream = pumpify(
    createGzip(),            // 先压缩
    createCipheriv('aes192', key, iv) // 再加密
  )
  combinedStream.iv = iv
  return combinedStream
}

// 组合流：解密 + 解压
export function createDecryptAndDecompress(password, iv) {
  const key = createKey(password)
  return pumpify(
    createDecipheriv('aes192', key, iv), // 先解密
    createGunzip()                       // 再解压
  )
}
```

---

### 步骤 2：使用组合流归档文件（archive.js）
```js
import { createReadStream, createWriteStream } from 'fs'
import { pipeline } from 'stream'
import { randomBytes } from 'crypto'
import { createCompressAndEncrypt } from './combined-streams.js'

const [,, password, source] = process.argv
const iv = randomBytes(16) // 生成随机向量
const destination = `${source}.gz.enc`

pipeline(
  createReadStream(source),
  createCompressAndEncrypt(password, iv), // 直接当作单个流用
  createWriteStream(destination),
  (err) => {
    if (err) {
      console.error(err)
      process.exit(1)
    }
    console.log(`${destination} 已创建，iv: ${iv.toString('hex')}`)
  }
)
```

---

## 运行
```bash
node archive.js mypassword file.txt
```
生成：
```
file.txt.gz.enc
```
并输出用于后续解密的 IV（初始向量）。

---

## 核心优势
1. **内部多步流程对外完全透明**
   外部只看到一个流，不用关心是先压缩还是先加密。

2. **高度可复用**
   这个“压缩+加密”流可以在任何管道中直接插入使用。

3. **错误统一处理**
   内部多个流的错误都会冒泡到组合流，只需一个错误监听。

---

## 练习（扩展）
你可以用
`createDecryptAndDecompress(password, iv)`
写一个反向脚本：
- 输入：加密文件 + 密码 + iv
- 输出：还原后的原始文件

这就是**流组合模式**在生产中的典型用法：
构建可插拔、可复用、链式处理的数据流组件。

# 分流模式（Forking streams）
**分流 = 一个可读流，同时 pipe 到多个可写流**
和 Unix 里的 `tee` 命令完全一样：一份数据，同时发往多个目的地。

典型用途：
- 同一份数据同时写入多个文件 / 发送到多个 socket
- 对相同数据做不同处理
- 按规则把数据分到不同下游管道

---

## 核心特点
- 一个 Readable
- 多个 Writable / Transform
- 数据会被**自动复制**到每条分支
- 分支之间互不影响

## 注意事项
1. **背压是独立的**
   每个分支消费速度不同，流会自动协调。
2. **错误不会互相传染**
   一个分支报错，不影响其他分支和主源流。
3. **`end` 事件默认只影响对应分支**
   可以通过 `{ end: false }` 控制是否在数据结束时关闭对应可写流。

---

简单说，分流就是实现**“一份数据，多路分发”**的标准流模式，也是构建复杂数据流拓扑的基础。
下一节我们会用代码实例看具体写法和坑点。

---

# 实现多校验和生成器（分流模式实例）
下面用**分流（forking）**模式实现一个小工具：
同时计算一个文件的 **sha1** 和 **md5** 哈希，并分别写入文件。

## 代码：generate-hashes.js
```js
import { createReadStream, createWriteStream } from 'fs'
import { createHash } from 'crypto'

const filename = process.argv[2]

// 创建两个哈希流
const sha1Stream = createHash('sha1').setEncoding('hex')
const md5Stream  = createHash('md5').setEncoding('hex')

// 同一个可读源流
const inputStream = createReadStream(filename)

// 分流 1：计算 sha1 并写入文件
inputStream
  .pipe(sha1Stream)
  .pipe(createWriteStream(`${filename}.sha1`))

// 分流 2：计算 md5 并写入文件
inputStream
  .pipe(md5Stream)
  .pipe(createWriteStream(`${filename}.md5`))
```

运行：
```bash
node generate-hashes.js file.txt
```
会生成：
- `file.txt.sha1`
- `file.txt.md5`

---

# 分流模式背后的关键要点（必考）
1. **同一份数据自动复制到所有分支**
   源流只读一次，数据被拷贝到每个 pipe 目标。

2. **默认所有分支会在源结束时自动 end**
   不想自动关闭可写流可以用：
   ```js
   .pipe(dest, { end: false })
   ```

3. **不要在分流中修改原始数据**
   一个分支里对 chunk 做副作用操作，会影响所有分支。

4. **背压由最慢的分支决定**
   任何一个分支卡住、消费慢，**整个源流都会被暂停**。
   → 一个分支阻塞 = 整条流阻塞。

5. **中途新增 pipe 会丢失之前的数据**
   如果源已经开始流动，再 pipe 新流，只能收到后面的数据。
   解决办法：中间放一个 `PassThrough` 缓存数据。

---

# 一句话总结
**分流 = 一读多写，一份数据多路复用**
适合：同时生成多哈希、同时日志落盘+输出、多目的地转发等场景。
但要注意：**最慢的分支决定整体速度**。

# 合并流模式（Merging streams）
**合并 = 多个可读流 → 汇入同一个可写流**
是分流（forking）的反向操作。

---

## 关键坑点
默认 `.pipe()` 会使用 `{ end: true }`：
**任意一个源流结束 → 目标流立即结束**
其他还在写的源流就会报错：`write after end`。

## 正确做法
1. 所有源流 pipe 时使用：
   ```js
   .pipe(destStream, { end: false })
   ```
2. 手动计数，**等所有源流都 end 后**，再调用：
   ```js
   destStream.end()
   ```

---

# 实例：按行合并多个文件
`merge-lines.js`
```js
import { createReadStream, createWriteStream } from 'fs'
import split from 'split'

const dest = process.argv[2]
const sources = process.argv.slice(3)

const destStream = createWriteStream(dest)

let endCount = 0

for (const source of sources) {
  const sourceStream = createReadStream(source, { highWaterMark: 16 })

  // 计数：等所有源都结束才关闭目标流
  sourceStream.on('end', () => {
    if (++endCount === sources.length) {
      destStream.end()
      console.log(`${dest} 创建完成`)
    }
  })

  sourceStream
    .pipe(split(line => line + '\n')) // 按行切分
    .pipe(destStream, { end: false }) // ✅ 关键：不自动结束
}
```

运行：
```bash
node merge-lines.js all.txt a.txt b.txt c.txt
```

---

# 特点
- **数据是交错混合的**
  哪个源流先读到数据，就先写入目标流。
- 设置 `highWaterMark: 16` 会让交错效果更明显。
- 适合：日志合并、无序对象流合并。

---

# 有序合并（顺序拼接）
如果想要**按顺序拼接**（先读完 A → 再读 B → 再读 C），可以用社区库：
**multistream**
它会串行消费多个可读流，保证顺序输出。

---

# 模式总结
| 模式 | 行为 | 关键选项 |
|------|------|----------|
| 分流 Fork | 1 读 → 多写 | 注意背压 |
| 合并 Merge | 多读 → 1 写 | `{ end: false }` + 手动计数 |
