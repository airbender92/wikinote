# 翻译
## 基于流的异步控制流模式
从前面的例子可以看出：流不仅适用于 I/O，还可以作为一种优雅的编程模式处理**任意类型的数据**。
更重要的是，流可以把复杂的**异步控制流**转化为简单的**数据流控制**。

---

## 顺序执行（Sequential execution）
默认情况下，流会**按顺序处理数据**。
比如 Transform 流的 `_transform()` 方法，必须等上一个 chunk 调用 `callback()` 完成后，才会处理下一个 chunk。

这一特性让流天然适合实现**异步任务串行执行**，可以替代传统的回调链、async/await 循环。

### 示例：按顺序合并多个文件
实现一个函数，**严格按照传入顺序**合并多个文件内容。

文件：`concat-files.js`
```js
import { createWriteStream, createReadStream } from 'fs'
import { Readable, Transform } from 'stream'

export function concatFiles(dest, files) {
  return new Promise((resolve, reject) => {
    const destStream = createWriteStream(dest)

    Readable.from(files)                // 1. 把文件列表转为对象流
      .pipe(new Transform({
        objectMode: true,
        transform(filename, enc, done) { // 2. 逐个处理文件
          const src = createReadStream(filename)
          // 管道写入目标文件，不自动关闭
          src.pipe(destStream, { end: false })

          src.on('error', done)
          src.on('end', done)           // 3. 当前文件读完，才处理下一个
        }
      }))
      .on('error', reject)
      .on('finish', () => {             // 4. 全部处理完成
        destStream.end()
        resolve()
      })
  })
}
```

执行流程：
1. `Readable.from(files)` 把文件数组转为**对象模式流**，按数组顺序发射文件名
2. Transform 流每次只处理一个文件
3. 创建该文件的读取流，pipe 到目标流
4. 只有当前文件完全读完（`end` 事件），才调用 `done()`，进入下一个文件
5. 全部完成后关闭目标流，resolve Promise

### 使用：`concat.js`
```js
import { concatFiles } from './concat-files.js'

async function main() {
  try {
    await concatFiles(process.argv[2], process.argv.slice(3))
    console.log('All files concatenated successfully')
  } catch (err) {
    console.error(err)
    process.exit(1)
  }
}

main()
```

运行：
```bash
node concat.js all.txt file1.txt file2.txt
```

结果：`all.txt` 会**严格按 file1 → file2 的顺序**合并内容。

---

# 核心要点
- **流天然实现异步串行**：不需要 async/await 循环，不需要递归 next()
- `_transform` 必须等 `callback` 才会处理下一个 chunk
- 适合：顺序合并、批量上传/下载、队列处理
- 代码比纯 Promise 更简洁，数据流更直观

下一节我们会看如何用流实现**无序并行执行**模式。

# 翻译
## 无序并行执行
我们刚刚看到，流默认是**按顺序逐个处理数据块**的，但这有时会成为性能瓶颈，无法充分利用 Node.js 的并发能力。

如果每个数据块都要执行一个**较慢的异步操作**，并行处理能显著提升整体速度。
当然，这种模式**只适用于数据块之间相互独立、顺序无关**的场景：
- 对象流常用
- 二进制流几乎不用（顺序通常至关重要）

要让 Transform 流并行处理，我们可以复用第 4 章学到的**异步并行模式**，并适配到流的机制上。

---

## 实现无序并行流
下面实现一个通用的并行转换流基类 `ParallelStream`，可以并行执行自定义转换逻辑。

文件：`parallel-stream.js`
```js
import { Transform } from 'stream'

export class ParallelStream extends Transform {
  constructor(userTransform, opts) {
    super({ objectMode: true, ...opts })
    this.userTransform = userTransform  // 业务转换逻辑
    this.running = 0                    // 正在并行执行的任务数
    this.terminateCb = null            // 保存_flush的结束回调
  }

  _transform(chunk, enc, done) {
    this.running++
    // 执行用户定义的异步转换逻辑
    this.userTransform(
      chunk,
      enc,
      this.push.bind(this),    // 用于向下游推送数据
      this._onComplete.bind(this)
    )
    done()  // 立即调用，不等任务完成 → 实现并行
  }

  _flush(done) {
    // 还有任务在跑，先不结束流
    if (this.running > 0) {
      this.terminateCb = done
    } else {
      done()
    }
  }

  _onComplete(err) {
    this.running--
    if (err) {
      return this.emit('error', err)
    }
    // 全部任务完成，真正结束流
    if (this.running === 0) {
      this.terminateCb?.()
    }
  }
}
```

---

## 代码逐段解析
1. **构造函数**
   - 接收自定义转换函数 `userTransform`
   - 默认开启 `objectMode`
   - 维护并行任务计数 `running` 和结束回调

2. **_transform（核心并行点）**
   - 启动异步任务，计数 +1
   - **立刻调用 `done()`**，不等任务完成
   → 流会立即继续处理下一个 chunk，实现并行
   - 任务完成后通过 `_onComplete` 通知

3. **_flush**
   - 流即将结束时，如果还有任务在跑，先**挂起结束流程**
   - 把 `done` 存到 `terminateCb`

4. **_onComplete**
   - 每个异步任务完成时计数 -1
   - 计数为 0 时，调用之前保存的 `terminateCb`，正式结束流

---

# 关键特点
- **并行执行**：不等上一个任务完成就处理下一个 chunk
- **无序输出**：谁先完成谁先 push，不保证原顺序
- **自动控制结束**：等所有并行任务跑完才真正结束流
- **只适合对象流**：顺序无关的任务（爬虫、批量处理、统计等）

---

# 模式总结
- 并行流的核心技巧：**在 _transform 里立刻调用 done()**
- 用计数 `running` 跟踪并行任务数
- 用 `_flush + terminateCb` 延迟流结束
- 适合：批量下载、API 调用、数据处理等**无序任务**

# 翻译
## 实现一个 URL 状态监控应用
现在我们把 **ParallelStream** 用到一个真实场景：
批量检测大量 URL 是否可访问（UP/DOWN），并把结果写入文件。

URL 列表放在一个文本文件里，**每行一个**，我们用流高效处理。

### 代码实现：check-urls.js
```js
import { pipeline } from 'stream'
import { createReadStream, createWriteStream } from 'fs'
import split from 'split'                  // 按行切分流
import superagent from 'superagent'        // 发送 HTTP 请求
import { ParallelStream } from './parallel-stream.js'

pipeline(
  createReadStream(process.argv[2]),        // 1. 读取 URL 文件
  split(),                                 // 2. 按行切分每个 URL
  new ParallelStream(async (url, enc, push, done) => { // 3. 并行检查
    if (!url) return done()

    try {
      // 发送 HEAD 请求探测是否可达
      await superagent.head(url, { timeout: 5 * 1000 })
      push(`${url} is up\n`)
    } catch (err) {
      push(`${url} is down\n`)
    }

    done()
  }),
  createWriteStream('results.txt'),        // 4. 结果写入文件
  (err) => {
    if (err) {
      console.error(err)
      process.exit(1)
    }
    console.log('All urls have been checked')
  }
)
```

---

## 工作流程
1. **读取文件流**
   从命令行参数传入的文件（如 `urls.txt`）创建可读流。

2. **按行切分**
   使用 `split` 流，把文件内容按换行符切成一个个独立 chunk（每个 chunk 是一个 URL）。

3. **并行检测**
   使用我们写的 `ParallelStream`：
   - 对每个 URL 并发发送 HEAD 请求
   - 超时 5 秒
   - 在线则 push `is up`，不可达则 push `is down`

4. **写入结果**
   所有结果通过管道流入 `results.txt`。

---

## 运行方式
```bash
node check-urls.js urls.txt
```

`urls.txt` 内容示例：
```
https://mario.fyi
https://loige.co
http://thiswillbedownforsure.com
```

运行后 `results.txt` 示例：
```
http://thiswillbedownforsure.com is down
https://mario.fyi is up
https://loige.co is up
```

---

# 关键现象
**结果顺序 ≠ 输入文件中的 URL 顺序**
这就是并行执行的铁证：哪个请求先完成，就先写入哪个结果。

---

# 本节要点
- 用流 + 并行模式处理**海量 URL 检测**，内存占用极低
- 不需要一次性把所有 URL 读到内存
- 并发异步任务天然由 `ParallelStream` 管理
- 代码简洁、声明式，比手动写 Promise.all 更优雅

# 翻译
## 带并发限制的无序并行执行
如果用之前的 `check-urls.js` 去检测**成千上万甚至上百万个 URL**，程序会瞬间创建大量并发连接，很可能：
- 把本地网络/文件句柄耗尽
- 被目标服务器封禁
- 程序直接崩溃

所以必须**限制最大并行数**，这就是**有限并行流**。

下面基于之前的 `ParallelStream` 改造，实现带并发控制的流。

---

## 实现：LimitedParallelStream
文件：`limited-parallel-stream.js`

### 构造函数
```js
export class LimitedParallelStream extends Transform {
  constructor(concurrency, userTransform, opts) {
    super({ ...opts, objectMode: true })
    this.concurrency = concurrency // 最大并发数
    this.userTransform = userTransform
    this.running = 0              // 当前运行任务数
    this.continueCb = null        // 暂存的 _transform 回调
    this.terminateCb = null       // 暂存的 _flush 回调
  }
```

### _transform 方法（核心限流逻辑）
```js
_transform(chunk, enc, done) {
  this.running++

  this.userTransform(
    chunk,
    enc,
    this.push.bind(this),
    this._onComplete.bind(this)
  )

  // 未达最大并发 → 直接处理下一个
  if (this.running < this.concurrency) {
    done()
  } else {
    // 已满载 → 暂停流，暂存回调
    this.continueCb = done
  }
}
```

### _onComplete 方法（释放一个并发槽）
```js
_onComplete(err) {
  this.running--

  if (err) {
    return this.emit('error', err)
  }

  // 释放暂停的 _transform，继续处理下一个 chunk
  const tmpCb = this.continueCb
  this.continueCb = null
  tmpCb && tmpCb()

  // 所有任务结束 → 真正结束流
  if (this.running === 0) {
    this.terminateCb && this.terminateCb()
  }
}
```

### _flush 方法（和之前完全一样）
```js
_flush(done) {
  if (this.running > 0) {
    this.terminateCb = done
  } else {
    done()
  }
}
```

---

# 工作原理（极简版）
1. 每次执行任务，`running++`
2. **小于并发限制**：立刻调用 `done()`，流继续读取下一个 chunk
3. **达到并发限制**：不调用 `done()`，流**自动暂停**，不再读取数据
4. 一个任务完成 → `running--` → 调用暂存的 `continueCb`
5. 流恢复运行，处理下一个 chunk

这就实现了**严格的并发控制**。

---

# 在 URL 检测中使用
回到 `check-urls.js`，把：
```js
new ParallelStream(...)
```
换成：
```js
new LimitedParallelStream(8, ...) // 最多同时 8 个请求
```

即可安全、高效地处理海量 URL。

# 对比总结
| 流类型                | 顺序 | 并发 | 适用场景                     |
|-----------------------|------|------|------------------------------|
| Transform（普通）| 保证 | 1个  | 顺序敏感、二进制流           |
| ParallelStream        | 无序 | 无上限| 极速处理、不怕目标压力       |
| LimitedParallelStream | 无序 | 可限制| 生产环境、批量爬虫/API 调用 |

这是 Node.js 流式处理**最实用、最生产级的并发模式**。

# 翻译
## 有序并行执行
前面实现的并行流会**打乱数据输出顺序**，但有些场景下**顺序必须严格保持和输入一致**。

解决思路：
- 任务仍然**并行执行**（快）
- 但用一个**缓冲区**把输出结果**重新排序**，保证输出顺序 = 输入顺序

这种流需要内部维护序号和缓冲，等前面的任务完成后再按序推送。由于实现代码较长，书中没有手写，而是直接使用 npm 上成熟的包：
**`parallel-transform`**
它支持：
- 并行执行
- 并发限制
- **严格保证输出顺序**

---

## 改造 URL 检测为有序并行版
修改 `check-urls.js`，使用 `parallel-transform`：

```js
// ...
import parallelTransform from 'parallel-transform'

pipeline(
  createReadStream(process.argv[2]),
  split(),
  // 并发 4，且保持顺序
  parallelTransform(4, async function (url, done) {
    if (!url) return done()

    try {
      await superagent.head(url, { timeout: 5000 })
      this.push(`${url} is up\n`)
    } catch (err) {
      this.push(`${url} is down\n`)
    }

    done()
  }),
  createWriteStream('results.txt'),
  (err) => {
    if (err) {
      console.error(err)
      process.exit(1)
    }
    console.log('All urls have been checked')
  }
)
```

---

## 效果
- **检测依然是并行的**（速度快）
- 但 `results.txt` 中的结果顺序
  **严格等于输入文件中的 URL 顺序**

即使某个后面的 URL 先检测完成，也会被缓冲，等前面的结果输出后才按序写入。

# 三种并行流模式总结（全书核心）
1. **普通 Transform**
   - 顺序：✅ 保证
   - 并发：1
   - 速度：慢

2. **无序并行流**
   - 顺序：❌ 打乱
   - 并发：可限制
   - 速度：最快
   - 适用：顺序无关任务（爬虫、批量检查）

3. **有序并行流**
   - 顺序：✅ 严格保证
   - 并发：可限制
   - 速度：较快（并行执行 + 顺序输出）
   - 适用：既要快又要保序（处理文件、日志、数据流）
