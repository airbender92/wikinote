# 翻译
## 双工流（Duplex streams）
双工流**同时兼具可读流 + 可写流**的功能。
适合用来描述**既是数据源、又是数据目标**的实体，最典型的例子就是**网络套接字（socket）**。

Duplex 流同时继承 `stream.Readable` 和 `stream.Writable` 的所有方法，所以你可以：
- 使用 `read()` / `write()`
- 监听 `readable`、`drain` 等两边的事件

### 实现自定义 Duplex 流
要创建自定义双工流，必须**同时实现两个方法**：
- `_read()` —— 可读流部分
- `_write()` —— 可写流部分

传给 `Duplex()` 构造函数的配置会自动同时作用于可读、可写两端。
可用配置和之前一致，额外多一个：
- `allowHalfOpen`（默认 `true`）
  - 如果设为 `false`：只要一端结束，另一端也会自动结束

# 核心要点
1. **Duplex = Readable + Writable 合体**
2. 两边读写通道**相互独立**
3. 实现时必须同时写 `_read()` 和 `_write()`
4. 典型场景：TCP socket、网络通信流

---

# 翻译
## 转换流（Transform streams）
转换流是一类**特殊的双工流**，专门用于处理**数据转换**。
举几个具体例子：本章前面用到的 `zlib.createGzip()`（压缩）和 `crypto.createCipheriv()`（加密），创建的都是转换流。

在普通双工流（Duplex）中，**写入的数据和读出的数据之间没有直接关联**（流本身不关心二者关系）。
比如 TCP socket，只是收发远端数据，并不关心输入和输出有什么对应关系。
下图展示了双工流的数据流向：
图 6.4：双工流示意图

如果需要双工流的**一端工作在对象模式、另一端工作在二进制模式**，可以分别使用配置项
`readableObjectMode` 和 `writableObjectMode` 独立设置。

---

而**转换流**则不同：它会对从可写端接收到的每个数据块**执行某种转换逻辑**，然后把转换后的数据从可读端输出。
下图展示了转换流的数据流向：
图 6.5：转换流示意图

从外部接口上看，Transform 流和 Duplex 流完全一样。
但实现方式有明显区别：
- 实现自定义 **Duplex**：必须实现 `_read()` + `_write()`
- 实现自定义 **Transform**：只需实现 `_transform()` + `_flush()`

下面我们用示例来看如何创建一个新的转换流。

---

# 核心要点
1. **Transform = 自带处理逻辑的双工流**
   可写端进 → 转换 → 可读端出

2. 与普通 Duplex 的核心区别
   - Duplex：读写两条独立通道，互不相干
   - Transform：写入的数据经过处理后变成读出的数据

3. 实现只需两个核心方法
   - `_transform(chunk, encoding, callback)`
     对数据块做转换，并通过 `push()` 输出结果
   - `_flush(callback)`
     流结束前，输出剩余缓冲数据

4. 典型应用
   压缩、加密/解密、数据过滤、格式转换、日志清洗等。

   # 翻译
## 实现转换流
下面我们实现一个**替换指定字符串**的 Transform 流。
新建模块 `replaceStream.js`：

```js
import { Transform } from 'stream'

export class ReplaceStream extends Transform {
  constructor(searchStr, replaceStr, options) {
    super({ ...options })
    this.searchStr = searchStr
    this.replaceStr = replaceStr
    this.tail = ''
  }

  _transform(chunk, encoding, callback) {
    // 1. 把上次遗留的尾部 + 当前块合并后按搜索字符串分割
    const pieces = (this.tail + chunk).split(this.searchStr)

    // 2. 处理最后一段，避免跨块匹配被截断
    const lastPiece = pieces[pieces.length - 1]
    const tailLen = this.searchStr.length - 1
    this.tail = lastPiece.slice(-tailLen)
    pieces[pieces.length - 1] = lastPiece.slice(0, -tailLen)

    // 3. 把处理好的片段推入可读端
    this.push(pieces.join(this.replaceStr))
    callback()
  }

  _flush(callback) {
    // 流结束前，把最后剩余的尾部推出去
    this.push(this.tail)
    callback()
  }
}
```

代码说明：
- 继承 `Transform` 基类
- 构造函数接收：要搜索的字符串、替换字符串、流配置
- 用 `tail` 变量保存**跨数据块的残留字符**，防止匹配被截断

### _transform 核心逻辑
`_transform` 签名和可写流的 `_write` 很像，但它不是写入外部资源，而是通过 `this.push()` 把转换后的数据推到可读端缓冲区，这就是转换流“可写进 → 转换 → 可读出”的连接方式。

由于数据是流式分片到达的，**待匹配的字符串可能被分到两个 chunk 里**，所以算法需要：
1. 把上一次残留的尾部 `tail` 和当前 chunk 拼接
2. 按 `searchStr` 分割
3. 把最后一段中可能不完整的匹配前缀存到 `tail`，留给下一个 chunk 处理
4. 其余部分用 `replaceStr` 连接后推出去

### _flush
流即将结束时会调用 `_flush`，这里是最后一次推送剩余数据的机会，我们把残留的 `tail` 推完再结束流。

---

## 使用转换流
```js
import { ReplaceStream } from './replaceStream.js'

const replaceStream = new ReplaceStream('World', 'Node.js')

replaceStream.on('data', chunk => console.log(chunk.toString()))

// 故意把 "World" 拆成两段写入
replaceStream.write('Hello W')
replaceStream.write('orld!')
replaceStream.end()
```

运行输出：
```
Hel
lo Node.js
!
```

虽然我们把 `World` 拆成 `W` 和 `orld` 写入两个分片，流依然能正确匹配并替换为 `Node.js`。

---

# 核心要点
1. **Transform 流必须实现两个方法**
   - `_transform(chunk, enc, cb)`：转换每一块数据
   - `_flush(cb)`：流结束前清理剩余数据

2. **转换流内部工作方式**
   可写端接收数据 → `_transform` 处理 → `push()` 到可读端

3. **处理跨块匹配是关键**
   流式数据不能假设完整匹配在一个 chunk 内，必须用 `tail`/`buffer` 处理边界情况。

4. **push() 是核心**
   在 `_transform` 和 `_flush` 中，`this.push(data)` 就是把数据输出到流的可读侧。

## 简化构建方式
不出所料，**Transform 转换流也支持简化构造**。到这里你应该已经熟悉这种 API 风格了，我们直接用简化写法重写上面的替换流示例：

```js
import { Transform } from 'stream'

const searchStr = 'World'
const replaceStr = 'Node.js'
let tail = ''

const replaceStream = new Transform({
  defaultEncoding: 'utf8',

  transform(chunk, encoding, cb) {
    const pieces = (tail + chunk).split(searchStr)
    const lastPiece = pieces[pieces.length - 1]
    const tailLen = searchStr.length - 1
    tail = lastPiece.slice(-tailLen)
    pieces[pieces.length - 1] = lastPiece.slice(0, -tailLen)
    this.push(pieces.join(replaceStr))
    cb()
  },

  flush(cb) {
    this.push(tail)
    cb()
  }
})

// 使用方式和之前一样
replaceStream.on('data', chunk => console.log(chunk.toString()))
replaceStream.write('Hello W')
replaceStream.write('orld!')
replaceStream.end()
```

和之前一样，简化构造就是直接实例化 `Transform`，并在配置对象里传入：
- `transform()` 对应 class 写法里的 `_transform()`
- `flush()` 对应 class 写法里的 `_flush()`

注意这里方法名**没有下划线**。

---

# 核心要点
- 不用写 class 继承，直接一行创建转换流
- `transform` + `flush` 实现完整逻辑
- 适合简单、无复杂内部状态的转换逻辑
- 同样支持 `objectMode`、`highWaterMark` 等所有配置

# 翻译
## 使用转换流实现数据过滤与聚合
正如上一节所说，**转换流是构建数据处理管道的理想组件**。除了文本替换，它还常用于**数据过滤**和**数据聚合**。

下面通过一个实际案例学习：
假设需要分析一个超大 CSV 销售数据文件，计算 **Italy（意大利）地区的总利润**。

CSV 格式示例：
```csv
type,country,profit
Household,Namibia,597290.92
Baby Food,Iceland,808579.10
Meat,Italy,413270.00
...
```

### 整体流式处理 pipeline
```js
import { createReadStream } from 'fs'
import parse from 'csv-parse'
import { FilterByCountry } from './filter-by-country.js'
import { SumProfit } from './sum-profit.js'

const csvParser = parse({ columns: true })

createReadStream('data.csv')   // 1. 读取文件流
  .pipe(csvParser)             // 2. 解析为 JS 对象
  .pipe(new FilterByCountry('Italy')) // 3. 只保留意大利数据
  .pipe(new SumProfit())       // 4. 累加利润
  .pipe(process.stdout)        // 5. 输出结果
```

整个流程分为 5 步：
1. 以流形式读取 CSV 文件
2. 使用 `csv-parse` 将每行转为对象 `{ type, country, profit }`
3. 过滤：只保留 country 为 Italy 的记录
4. 聚合：累加所有利润，只输出最终总数
5. 打印结果到控制台

---

## 实现 1：FilterByCountry（过滤流）
只放行指定国家的记录，其他直接丢弃。

```js
import { Transform } from 'stream'

export class FilterByCountry extends Transform {
  constructor (country, options = {}) {
    options.objectMode = true
    super(options)
    this.country = country
  }

  _transform (record, enc, cb) {
    // 符合条件才 push 到下一级
    if (record.country === this.country) {
      this.push(record)
    }
    // 无论是否过滤，都必须调用 cb
    cb()
  }
}
```

要点：
- 开启 `objectMode: true`，处理对象而非二进制
- 条件满足才 `push`，否则不传递数据
- 必须调用 `cb()` 表示当前块处理完成

---

## 实现 2：SumProfit（聚合流）
接收所有记录，只在最后输出一个总和。

```js
import { Transform } from 'stream'

export class SumProfit extends Transform {
  constructor (options = {}) {
    options.objectMode = true
    super(options)
    this.total = 0
  }

  _transform (record, enc, cb) {
    // 只累加，不 push
    this.total += Number.parseFloat(record.profit)
    cb()
  }

  _flush (cb) {
    // 流结束前，一次性推送最终结果
    this.push(this.total.toString())
    cb()
  }
}
```

要点：
- `_transform` 中**只计算、不推送**数据
- 所有数据处理完后，在 `_flush` 中**一次性 push 总和**
- `_flush` 是流关闭前的最后执行机会

---

# 核心模式总结
### 1）Transform 过滤模式
- 有条件地调用 `this.push()`
- 符合条件才往下游传递数据
- 必须始终调用 `cb()`

### 2）Transform 聚合模式
- `_transform` 只做累积计算，不 push
- 最终结果在 `_flush` 中一次性 push
- 适合求和、计数、统计、合并等场景

---

整个程序会以**极低内存占用**处理超大 CSV，
最终只输出一行数字：意大利地区的总利润。

# 翻译
## 直通流（PassThrough streams）
还有第五种非常值得一提的流：**PassThrough**。
它是一种特殊的 **Transform 流**，特点是：**收到什么数据，就原封不动输出什么数据，不做任何转换**。

PassThrough 可能是最被低估的流，但在很多场景里非常实用，比如：
- **数据监控 / 可观测性**
- **延迟管道连接（late piping）**
- **实现懒加载流模式**

---

## 1）可观测性（监控流量）
如果想观察管道里流过多少数据，可以在 pipeline 中插入一个 PassThrough，监听 `data` 事件统计流量。

示例：
```js
import { PassThrough } from 'stream'

let bytesWritten = 0
const monitor = new PassThrough()

monitor.on('data', (chunk) => {
  bytesWritten += chunk.length
})

monitor.on('finish', () => {
  console.log(`${bytesWritten} bytes written`)
})

monitor.write('Hello!')
monitor.end()
```

真实场景用法：插入到流管道中监控流量
```js
createReadStream(filename)
  .pipe(createGzip())
  .pipe(monitor)       // 监控压缩后大小
  .pipe(createWriteStream(`${filename}.gz`))
```

优点：
- **完全非侵入式**，不用改动其他流
- 可以随意移动到管道任意位置监控不同阶段流量

---

## 2）延迟管道连接（Late piping）
有些 API 需要你**立刻传入一个流**，但你真正的数据源/处理流**还没准备好**。
这时 PassThrough 可以充当**占位符流**。

典型场景：上传 SDK
```js
function upload(filename, contentStream) {
  // 内部立刻开始消费 contentStream
}
```

如果你需要先异步处理流（压缩、加密）再上传，可以这样做：

```js
import { PassThrough } from 'stream'

// 1. 先创建占位符
const contentStream = new PassThrough()

// 2. 立刻调用上传 API
upload('file.br', contentStream)

// 3. 之后再把真正的流接上去
createReadStream(file)
  .pipe(createBrotliCompress())
  .pipe(contentStream)  // 数据才真正开始流动
```

工作原理：
- upload 会立刻尝试消费 `contentStream`
- 但因为还没有数据，它会**等待**
- 等你把真实流 `pipe` 进来，数据才开始走
- 上游结束时会自动 end PassThrough，上传完成

---

## 3）优雅封装 API
把“需要传入流”的 API，改造成“返回一个可写流”的 API，用 PassThrough 做连接器非常优雅。

例如把：
```js
upload(filename, readableStream)
```

改造成：
```js
const writableStream = createUploadStream(filename)
```

实现只用一行 PassThrough：
```js
function createUploadStream(filename) {
  const connector = new PassThrough()
  upload(filename, connector)
  return connector // 返回可写流给外部使用
}
```

使用：
```js
const out = createUploadStream('test.txt')
out.write('some data')
out.end()
```

---

# 核心模式总结
- **PassThrough = 透明中继流**
- 不修改数据，只传递
- 适合做**监控、占位、桥接、流接口适配**

你可以把它理解成：
**流世界里的“透明转接头”**。
