```js
process.stdin
  .on('readable', () => {
    let chunk
    console.log('收到新数据')
    while ((chunk = process.stdin.read()) !== null) {
      console.log(`读取分片（${chunk.length}字节）："${chunk.toString()}"`)
    }
  })
  .on('end', () => console.log('流读取完毕'))
```

这段代码是 Node.js 中**监听标准输入流（控制台输入）**的典型示例，我给你**逐行+原理+运行效果**彻底讲明白。

# 逐行解读
```js
process.stdin
  .on('readable', () => {
```
- `process.stdin`：Node.js 标准输入流（控制台输入，可读流）
- `.on('readable', ...)`：**流内部缓冲区有数据可读时触发**
  你敲键盘、粘贴内容、输入数据，都会触发这个事件

```js
let chunk
console.log('收到新数据')
```
- 每次有数据可读，先打印一句提示

```js
while ((chunk = process.stdin.read()) !== null) {
```
- `process.stdin.read()`：**尝试从缓冲区读一块数据**
- 返回一个 `Buffer`（字节数据）
- 读完缓冲区所有数据后会返回 `null`，循环结束
- 这是**“读空缓冲区”**的标准写法

```js
console.log(`读取分片（${chunk.length}字节）："${chunk.toString()}"`)
```
- 打印这块数据的**字节长度**
- `chunk.toString()`：把 Buffer 转成字符串（默认 UTF-8）
- 输出你输入的内容

```js
}
})
```
结束 readable 回调

```js
.on('end', () => console.log('流读取完毕'))
```
- `end` 事件：**输入流结束时触发**
- 比如在控制台按：
  - **Windows：Ctrl + Z 回车**
  - **macOS / Linux：Ctrl + D**

# 核心原理（非常重要）
1. **`readable` 不是“来一个字节触发一次”**
   是**缓冲区有数据可读**时触发，你需要自己 `.read()` 去读

2. **`read()` 会一次性读空缓冲区**
   所以要用 `while` 循环读到 `null`

3. **流是异步、分片的**
   数据大、输入慢，都会分成多个 `chunk`

4. **process.stdin 是 Node.js 内置的标准可读流**
   和文件流、网络流 API 完全一致
