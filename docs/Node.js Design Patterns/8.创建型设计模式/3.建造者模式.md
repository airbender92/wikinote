# 建造者模式（Builder）
建造者模式的核心：**一步步构造复杂对象，用链式流畅接口提升可读性和安全性**。

## 问题场景
一个类的构造函数参数极多，会出现两个致命问题：
1. 代码难以阅读，容易传错参数
2. 关联参数没有约束（比如选了发动机就必须填品牌型号）

```js
// 噩梦级构造函数
new Boat(true, 2, 'Best Motor Co.', 'OM123', true, 1, 'fabric', 'white', 'blue', false)
```

即使改成对象传参，依然存在问题：
- 没有提示，必须查文档
- 关联参数无法强制约束
- 代码不够自解释

---

## Builder 模式解决方案
通过链式方法分步设置属性，最后统一 `build()` 生成对象：

```js
class BoatBuilder {
  // 一组关联属性一起设置
  withMotors(count, brand, model) {
    this.hasMotor = true
    this.motorCount = count
    this.motorBrand = brand
    this.motorModel = model
    return this // 链式关键：返回自身
  }

  withSails(count, material, color) {
    this.hasSails = true
    this.sailsCount = count
    this.sailsMaterial = material
    this.sailsColor = color
    return this
  }

  hullColor(color) {
    this.hullColor = color
    return this
  }

  withCabin() {
    this.hasCabin = true
    return this
  }

  build() {
    return new Boat({
      hasMotor: this.hasMotor,
      motorCount: this.motorCount,
      motorBrand: this.motorBrand,
      motorModel: this.motorModel,
      hasSails: this.hasSails,
      sailsCount: this.sailsCount,
      sailsMaterial: this.sailsMaterial,
      sailsColor: this.sailsColor,
      hullColor: this.hullColor,
      hasCabin: this.hasCabin
    })
  }
}
```

### 使用时极度清晰
```js
const myBoat = new BoatBuilder()
  .withMotors(2, 'Best Motor Co.', 'OM123')
  .withSails(1, 'fabric', 'white')
  .withCabin()
  .hullColor('blue')
  .build()
```

---

## Builder 模式核心规则
1. **把复杂构造拆成多个语义化步骤**
2. **相关参数放在同一个方法里设置**
3. **自动推导隐含状态**（如调用 withMotors 则自动 hasMotor=true）
4. **内置校验、格式化、归一化逻辑**
5. **最后统一 build() 生成最终对象**

---

## 优势总结
- **代码自解释**，不用文档也知道怎么填
- **链式调用流畅美观**
- **强制约束关联参数**，减少错误
- **封装构造逻辑**，外部代码更干净
- **非常适合配置复杂的对象：数据库连接、HTTP 请求、日志器、任务等**

在 Node.js 中几乎所有流畅 API 都是 Builder 模式：
- `knex` 查询构造器
- `superagent` / `axios` 请求构造
- 很多 ORM 的查询链式写法

# 建造者模式实战：实现 URL 构造器
这个例子完美体现 Builder 模式的核心价值：
**把复杂、多参数、易出错的构造，变成语义清晰、链式调用、自带约束的构造过程**。

---

## 1. 定义 URL 类（url.js）
负责存储、校验、格式化 URL
```javascript
export class Url {
  constructor(
    protocol,
    username,
    password,
    hostname,
    port,
    pathname,
    search,
    hash
  ) {
    this.protocol = protocol
    this.username = username
    this.password = password
    this.hostname = hostname
    this.port = port
    this.pathname = pathname
    this.search = search
    this.hash = hash

    this.validate()
  }

  // 校验必填项
  validate() {
    if (!this.protocol || !this.hostname) {
      throw new Error('Must specify at least a protocol and a hostname')
    }
  }

  // 拼接成完整 URL 字符串
  toString() {
    let url = ''

    url += `${this.protocol}://`

    if (this.username && this.password) {
      url += `${this.username}:${this.password}@`
    }

    url += this.hostname

    if (this.port) {
      url += `:${this.port}`
    }

    if (this.pathname) {
      url += this.pathname
    }

    if (this.search) {
      url += `?${this.search}`
    }

    if (this.hash) {
      url += `#${this.hash}`
    }

    return url
  }
}
```

---

## 2. 实现 URL 建造者（urlBuilder.js）
链式设置参数，最后 `build()` 生成 `Url` 实例
```javascript
import { Url } from './url.js'

export class UrlBuilder {
  setProtocol(protocol) {
    this.protocol = protocol
    return this
  }

  // 把关联参数组合在一起，语义更强
  setAuthentication(username, password) {
    this.username = username
    this.password = password
    return this
  }

  setHostname(hostname) {
    this.hostname = hostname
    return this
  }

  setPort(port) {
    this.port = port
    return this
  }

  setPathname(pathname) {
    this.pathname = pathname
    return this
  }

  setSearch(search) {
    this.search = search
    return this
  }

  setHash(hash) {
    this.hash = hash
    return this
  }

  // 最终构造
  build() {
    return new Url(
      this.protocol,
      this.username,
      this.password,
      this.hostname,
      this.port,
      this.pathname,
      this.search,
      this.hash
    )
  }
}
```

---

## 3. 使用建造者（index.js）
```javascript
import { UrlBuilder } from './urlBuilder.js'

const url = new UrlBuilder()
  .setProtocol('https')
  .setAuthentication('user', 'pass')
  .setHostname('example.com')
  .build()

console.log(url.toString())
```

输出：
```
https://user:pass@example.com
```

# 核心亮点总结

## 1. 解决了多参数构造函数的混乱
直接 `new Url(...)` 要传8个参数，极易传错顺序：
```javascript
new Url('https', null, null, 'example.com', null, null, null, null)
```
用建造者后，**每个参数语义明确**，顺序无关。

## 2. 对关联参数进行语义分组
```javascript
setAuthentication(username, password)
```
明确表达：要认证就必须同时传账号密码，**自带设计约束**。

## 3. 链式调用 + 自解释接口
代码像自然语言一样流畅，**几乎不需要文档**。

## 4. 构造与使用分离
`Url` 专注于表示 URL 与校验
`UrlBuilder` 专注于分步构造
**单一职责，结构清晰**

# 实战场景：Node.js 中的建造者模式（In the wild）
建造者模式在 JS/Node.js 生态里**极其常见**，核心就是用**流畅链式接口**构造复杂对象，替代一堆零散参数。

## 典型案例：superagent
原生 `http.request()` 配置项极多、可读性差，而 `superagent` 用 Builder 模式彻底优化：

```js
superagent
  .post('https://example.com/api/person')
  .send({ name: 'John Doe', role: 'user' })
  .set('accept', 'json')
  .then(res => {
    // 发送请求
  })
```

特点：
- 每个方法语义明确
- 链式调用，顺序自由
- **没有显式 `build()`**
- 调用 `.then()` 时才真正“构建并执行”

这是 Builder 模式的**变体**，非常适合异步/请求类库。

---

## 独立 Builder vs 类自身链式
书中重点对比了两种实现，非常关键：

### 1. 独立建造者（推荐，如 UrlBuilder）
- 建造者负责收集参数
- `build()` 时才创建目标对象并**统一校验**
- **最终对象永远处于合法状态**
- 目标类（Url）保持纯粹、不可变、安全

### 2. 类自身实现链式（不推荐）
```js
class Url {
  setProtocol() { return this }
  setHostname() { return this }
  // ...
}
```

问题：
- 对象在构造过程中**处于不完整、不合法状态**
- 中途调用 `toString()` 会得到无效 URL
- 必须加大量额外校验，复杂度飙升

---

## 一句话总结
> **Builder 模式 = 用流畅、分步、链式的方式，构造复杂对象，并保证最终对象合法有效。**

在 Node.js 里随处可见：
- superagent / axios
- knex 查询构造器
- webpack 链式配置
- 各类 ORM 的查询 API
