# 揭示构造器模式（Revealing Constructor）
这是**JS / Node.js 原创模式**，GoF 23 种设计模式里没有，专门解决一个很刁钻的问题：
**只在对象创建那一刻，临时开放一部分私有能力，创建完成后彻底关闭。**

---

## 核心结构（三要素）
```js
const object = new SomeClass(function executor(revealedMembers) {
  // 只有这里能访问 revealedMembers
})
```

1. **构造器**：接收一个函数
2. **执行器函数（executor）**：创建时同步调用
3. **被暴露的内部成员（revealedMembers）**：
   - 只在执行器里可用
   - 对象创建完成后，外部**永远无法再访问**

目的：
- 对象**只能在创建时被修改/初始化**
- 创建后就是**不可变、安全、稳定**的实例
- 既灵活初始化，又保证封装与安全性

---

## 最经典、最标准的现实例子：**Promise**
你每天都在用，只是不知道它叫 Revealing Constructor：

```js
const p = new Promise((resolve, reject) => {
  // 只有这里能调用 resolve / reject
  setTimeout(() => resolve('ok'), 1000)
})

// 外部永远拿不到 resolve、reject
p.resolve() // ❌ 不存在
```

这完全符合模式定义：
- 构造器接收执行器函数
- 执行时暴露 `resolve` / `reject`
- 外部无法获取，只能在创建时控制状态

这就是该模式**最成功的应用**。

---

## 模式解决的核心问题
如果不用这个模式，我们面临两难：
1. **把 resolve 设为公共方法**
   → 外部可以随意调用，破坏状态安全
2. **完全私有化 resolve**
   → 使用者根本无法完成异步逻辑

Revealing Constructor 给出完美解：
**只在构造那一刻暴露，用完即封死。**

---

## 简化模拟实现（帮助理解原理）
```javascript
class MyPromise {
  constructor(executor) {
    // 内部状态，外部不可访问
    let state = 'pending'
    let value

    // 仅在构造阶段暴露的方法
    const resolve = (val) => {
      state = 'fulfilled'
      value = val
    }

    // 执行器运行，暴露 resolve
    executor(resolve)

    // 构造结束后，外部再也拿不到 resolve
    this.getState = () => state
  }
}

// 使用
const promise = new MyPromise((resolve) => {
  resolve('done') // ✅ 可以
})

promise.resolve() // ❌ 不存在
```

这就是 Revealing Constructor 的本质。

---

## 模式适用场景
- 需要**一次性初始化**，之后不可变
- 需要**控制对象状态**，但不允许外部随意操作
- 需要在创建时注入自定义行为
- 典型：Promise、EventEmitter、安全的流、不可变配置对象

---

## 一句话记住
**揭示构造器 = 只在对象出生时，临时给你一把钥匙，出生后立刻回收，从此永不开放。**

在 Node.js 中，它最大的成名作就是 **Promise**，也是流、安全 API 常用的高级模式。

# Revealing Constructor 实战：实现不可变缓冲区 ImmutableBuffer
## 核心目标
利用**揭示构造器模式**实现：
缓冲区**仅在实例创建阶段允许写入/修改**；一旦构造完成，外部只能读取，再也无法修改内部二进制数据，达成简易不可变 Buffer。

## 完整源码（immutableBuffer.js）
```js
const MODIFIER_NAMES = ['swap', 'write', 'fill']
export class ImmutableBuffer {
  constructor(size, executor) {
    // 1. 内部真实可变Buffer，外部永远无法直接访问
    const buffer = Buffer.alloc(size)
    // 存放所有修改方法，仅暴露给executor
    const modifiers = {}

    // 遍历原生buffer所有方法
    for (const prop in buffer) {
      if (typeof buffer[prop] !== 'function') continue

      // 判断：属于修改类方法 → 放入modifiers
      if (MODIFIER_NAMES.some(m => prop.startsWith(m))) {
        modifiers[prop] = buffer[prop].bind(buffer)
      } else {
        // 只读方法直接挂载到实例上对外开放
        this[prop] = buffer[prop].bind(buffer)
      }
    }

    // 【揭示构造器核心】同步执行executor，临时暴露修改API
    executor(modifiers)
  }
}
```

## 逐行逻辑拆解
1. `const buffer = Buffer.alloc(size)`
内部真实可变缓冲区，保存在构造函数局部作用域；**构造结束后外部无法获取**。

2. 区分两类方法
- **修改方法（mutator）**：以 `swap` / `write` / `fill` 开头（`writeInt8`、`fill()`、`swap16`）
  存入 `modifiers` 对象，**只传给 executor**，不会挂载到 `ImmutableBuffer` 实例。
- **只读方法**：`readInt8`、`toString` 等，直接绑定到实例，永久对外开放。

3. `executor(modifiers)`
构造阶段同步调用传入的回调函数，**临时开放修改权限**。
构造函数执行完毕，`modifiers` 变量生命周期结束，外部再也拿不到写入方法。

## 使用示例 index.js
```js
import { ImmutableBuffer } from './immutableBuffer.js'

const hello = 'Hello!'
const immutable = new ImmutableBuffer(hello.length, ({ write }) => {
  // ✅ 只有在这里可以调用write/fill等修改API
  write(hello)
})

console.log(String.fromCharCode(immutable.readInt8(0))) // 输出 H

// ❌ 运行时报错：immutable.write is not a function
// immutable.write('Hello?')
```

## 模式关键点（重中之重）
### 1. 权限隔离
- 创建期间：拥有修改能力；
- 创建完成：**永久收回所有修改入口**。
外部只能调用只读接口，保证缓冲区内容稳定不变。

### 2. 和普通闭包封装的区别
普通闭包：所有API全部在外部决定；
揭示构造器：**仅在对象诞生瞬间授予临时权限**，诞生之后权限回收。

### 3. 天然优势：不可变对象
不可变对象好处：
- 传递给任意函数无需担心被意外篡改；
- 简单 `===` 即可做变更检测；
- 多线程/异步共享数据时消除大量竞态风险。

## 局限（书中注明）
这是教学示例，生产环境存在缺陷：
1. 简单通过方法名前缀区分读写，识别规则不完善；
2. 没有屏蔽 `buffer` 其他潜在逃逸方式；
3. 没有封装字节长度、边界校验等配套属性。

## 和 Promise 对照理解（同一种模式）
```js
// Promise 标准揭示构造器
new Promise((resolve, reject) => {
  // 创建阶段才能调用resolve/reject
})
// 外部无法访问 resolve、reject
```
二者结构完全一致：
`new 类(executor => 接收临时暴露的内部控制方法)`

## 一句话总结本案例
**ImmutableBuffer 在构造回调里临时开放写入能力；构造执行完毕，所有修改入口永久关闭，得到一份只读、安全的二进制缓冲区。**

# 实战场景：揭示构造器模式在真实世界中的应用（In the wild）
揭示构造器最大的特点是：**极强的封装性 + 严格的状态控制**，因此特别适合需要**绝对安全、不可被外部篡改**的核心 API。

## 最经典、最普及的实例：**JavaScript Promise**
```js
return new Promise((resolve, reject) => {
  // 只有这里能改变 Promise 状态
})
```

它完美符合 Revealing Constructor 模式：
1. 构造器接收一个 **executor 函数**
2. 执行器被同步调用，并传入 **resolve、reject**
3. 这两个方法**只在构造阶段暴露**
4. 实例创建完成后，外部**永远无法再获取或调用 resolve/reject**
5. Promise 状态只能被设置**一次**，之后不可变

这就是为什么 Promise 状态安全、可预测、不会被意外篡改。

---

## 为什么这种模式如此重要？
- **状态只允许在创建时修改**，创建后只读
- **杜绝外部滥用、篡改内部状态**
- 接口干净、安全，适合给大量开发者使用
- 共享对象给第三方时**无需担心被破坏**

---

## 一句话总结
**揭示构造器 = 只在对象创建时开放一次控制权，之后永久锁死，让对象状态绝对安全。**

而它在整个 JS 世界里最成功、最家喻户晓的落地，就是 **Promise**。
