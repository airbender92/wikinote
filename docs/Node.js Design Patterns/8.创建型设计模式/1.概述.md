# 创建型设计模式（Creational Design Patterns）
设计模式是对**反复出现的设计问题**的**可复用解决方案**。
大家常说的“设计模式”，一般指 **GoF（四人帮）** 在经典书籍《设计模式》中总结的 23 种面向对象模式。

但在 JavaScript / Node.js 中，这些模式不会像在 Java/C++ 里那样刻板、形式化，因为：
- 基于**原型**，而非严格类继承
- **函数是一等公民**
- 支持函数式风格
- 动态类型，无真正的抽象类/接口

所以本章重点是：
**用 Node.js 的风格重新理解创建型模式**——关注模式的**思想**，而不是死板语法。

---

## 创建型模式概览
创建型模式解决的核心问题：**对象如何创建、如何实例化、如何依赖组装**。

本章会重点讲：
1. **工厂模式（Factory）**
   封装对象创建逻辑，统一入口。
2. **揭示构造函数模式（Revealing Constructor）**
   只在构造阶段暴露私有成员，常用于 Stream、Promise 这类 API。
3. **建造者模式（Builder）**
   分步构造复杂对象，链式调用风格。
4. **单例模式（Singleton）**
   保证一个类只有一个实例。
5. **依赖注入（Dependency Injection）**
   解耦依赖创建与使用，便于测试、模块化。

---

简单说：
**创建型模式 = 更好地“造对象”的套路**，让对象创建更灵活、可控、可扩展、可测试。
