# 工厂模式（Factory）
工厂模式是 **Node.js 中最常用的设计模式之一**，核心就是：**用函数来创建对象，而不是直接用 new**。

## 核心作用
1. **解耦对象创建与使用**
   调用方只管要对象，不用管内部怎么 new、依赖什么。

2. **运行时动态决定创建哪种对象**
   根据配置、环境、参数，自动返回不同实例。

3. **接口更小、更安全**
   工厂只是一个函数，不像 class 可以被继承、修改，更稳定。

4. **借助闭包实现真正封装**
   可以隐藏内部状态，只暴露需要的方法。

---

## 最简示例
```js
// 工厂函数
function createUser(name, role) {
  return {
    name,
    role,
    greet() {
      return `Hi, I'm ${name}, a ${role}`
    }
  }
}

// 使用
const admin = createUser('Alice', 'admin')
const guest = createUser('Bob', 'guest')
```

这就是工厂：**一个函数，返回对象**。

---

## Node.js 里的典型用法
### 1. 根据类型创建不同实例
```js
function createLogger(type) {
  if (type === 'file') {
    return new FileLogger()
  }
  if (type === 'console') {
    return new ConsoleLogger()
  }
}

const logger = createLogger('file') // 调用方不用关心具体类
```

### 2. 隐藏构造细节，简化 API
```js
function createServer(port) {
  const server = http.createServer()
  server.listen(port)
  return server
}

// 外部直接用，不用关心 listen、初始化逻辑
const server = createServer(3000)
```

### 3. 闭包封装私有变量
```js
function createCounter() {
  let count = 0 // 真正私有

  return {
    inc() { count++ },
    get() { return count }
  }
}

const counter = createCounter()
counter.inc()
console.log(counter.get()) // 1
// count 外部完全访问不到
```

---

## 一句话记住
**工厂 = 造对象的函数**
好处：灵活、封装、安全、调用方简单。

Node.js 内置模块里到处都是工厂，比如：
- `fs.createReadStream()`
- `http.createServer()`
- `crypto.createHash()`

它们全是工厂模式。

# 解耦对象创建与具体实现
工厂模式最核心的价值，就是**把“要什么对象”和“怎么造这个对象”分开**。

## 为什么不用直接 `new`？
直接 `new Image(name)` 看上去简单，但有一个硬伤：
**你的代码和 `Image` 这个具体类强绑定了**。

一旦底层重构，比如把 `Image` 拆成：
- `ImageJpeg`
- `ImageGif`
- `ImagePng`

所有直接 `new Image` 的地方**全部要改**，代码完全不灵活。

---

## 工厂模式如何解决？
对外只暴露一个工厂函数，内部怎么实现全隐藏：

```js
// 对外接口不变
function createImage(name) {
  // 内部逻辑可以随便改
  if (name.match(/\.jpe?g$/)) {
    return new ImageJpeg(name)
  } else if (name.match(/\.gif$/)) {
    return new ImageGif(name)
  } else if (name.match(/\.png$/)) {
    return new ImagePng(name)
  } else {
    throw new Error('Unsupported format')
  }
}
```

外部调用代码**一行不用改**：
```js
const image = createImage('photo.jpeg')
```

这就是**解耦**：
- 上层：只关心要一个 image
- 下层：工厂内部可以随意重构、替换实现

---

## 额外好处：隐藏类，缩小公开接口
在 Node.js 模块里，你可以：
- 不导出 `ImageJpeg` / `ImageGif` 等类
- **只导出工厂函数**

外部完全拿不到具体类，也就不能：
- 随意继承
- 直接修改原型
- 绕过你预设的创建逻辑

这就是书中说的 **small surface area（小公开接口）**，更安全、更易维护。

---

## 一句话总结
- **直接 `new` = 写死实现**
- **工厂 = 封装创建逻辑，随时可换底层实现**

这是工厂模式在 Node.js 里无处不在的根本原因。

# 作为封装机制的工厂模式
工厂模式借助**闭包**，可以实现真正意义上的**封装**——也就是隐藏内部状态，只暴露可控的公共接口。

## 什么是封装？
- 禁止外部直接修改内部数据
- 只能通过预设的公共方法交互
- 内部实现可以随意改，不影响外部代码

这是面向对象设计的核心原则之一。

---

## 代码示例解析
```js
function createPerson(name) {
  // 完全私有，外部永远访问不到
  const privateProperties = {}

  // 公共接口
  const person = {
    setName(name) {
      if (!name) {
        throw new Error('A person must have a name')
      }
      privateProperties.name = name
    },
    getName() {
      return privateProperties.name
    }
  }

  person.setName(name)
  return person
}
```

### 关键点
1. **`privateProperties` 是真正私有**
   外部无法读取或修改，只能通过 `setName` / `getName` 操作。

2. **可以强制校验逻辑**
   比如保证名字不能为空，如果直接把 `name` 挂在对象上，外部可以随便改，无法控制。

3. **闭包 + 工厂 = 完美私有变量**
   JS 没有 class private 字段时，这是最可靠的封装方式。

---

## 对比直接对象
```js
// 不封装，不安全
const person = { name: 'Tom' }
person.name = '' // 直接改，没有任何校验
```

使用工厂模式：
```js
const p = createPerson('Tom')
p.setName('') // 会抛出错误，保证数据合法
```

---

## 一句话总结
**工厂 + 闭包 = 可控的、安全的、真正的封装**
外部只能用你给的接口，不能乱改内部状态，这是 Node.js 模块设计非常常用的稳健写法。

# 构建一个简单的代码分析器（工厂模式实战）
这个例子完美展示了工厂模式**解耦创建与实现**的核心威力：
- 开发环境：输出真实的性能分析日志
- 生产环境：直接返回空实现（空方法），完全禁用分析器

---

## 1. 定义分析器类 + 工厂（profiler.js）
```js
class Profiler {
  constructor(label) {
    this.label = label
    this.lastTime = null
  }

  start() {
    // 记录高分辨率开始时间
    this.lastTime = process.hrtime()
  }

  end() {
    // 计算时间差并打印
    const diff = process.hrtime(this.lastTime)
    console.log(
      `Timer "${this.label}" took ${diff[0]} seconds ` +
      `and ${diff[1]} nanoseconds.`
    )
  }
}

// 空实现：生产环境用
const noopProfiler = {
  start() {},
  end() {}
}

// 工厂函数：对外唯一接口
export function createProfiler(label) {
  if (process.env.NODE_ENV === 'production') {
    return noopProfiler // 空对象，啥也不干
  }
  return new Profiler(label) // 真实实例
}
```

---

## 2. 使用分析器（index.js）
```js
import { createProfiler } from './profiler.js'

function getAllFactors(intNumber) {
  // 只调用工厂，不关心内部实现
  const profiler = createProfiler(`Finding all factors of ${intNumber}`)

  profiler.start()
  const factors = []
  for (let factor = 2; factor <= intNumber; factor++) {
    while ((intNumber % factor) === 0) {
      factors.push(factor)
      intNumber = intNumber / factor
    }
  }
  profiler.end()

  return factors
}

const myNumber = process.argv[2]
console.log(`Factors of ${myNumber} are: `, getAllFactors(myNumber))
```

---

## 3. 两种运行模式对比
### 开发模式（默认）
```bash
node index.js 2201307499
```
输出：
```
Timer "Finding all factors of 2201307499" took 0 seconds and 1234567 nanoseconds.
Factors of ... are: [...]
```

### 生产模式
```bash
NODE_ENV=production node index.js 2201307499
```
输出：
```
Factors of ... are: [...]
```
**没有任何性能日志**，因为返回的是空实现对象。

---

# 核心要点总结
1. **工厂隐藏了实现细节**
   外部只调用 `createProfiler()`，完全不知道底层是真实类还是空对象。

2. **基于环境动态切换实现**
   利用 `NODE_ENV` 无缝切换功能，业务代码**完全不用修改**。

3. **鸭子类型（Duck Typing）**
   真实 Profiler 和空对象都有 `start()`/`end()`，外部调用完全无感。

4. **无侵入式功能开关**
   这是 Node.js 中非常经典的用法：
   日志、监控、分析、调试工具都可以用工厂模式实现环境自适应。

---

一句话记住：
**工厂模式让你可以“换底层实现，不换上层代码”。**

# 实战案例：Knex 库中的工厂模式（In the wild）
Knex 是 Node.js 生态知名 SQL 查询构建器，它的顶层 API 是**教科书级别的工厂函数实现**。

## Knex 标准用法
```js
import knex from 'knex'

// 调用工厂函数，得到数据库实例
const db = knex({
  client: 'mysql2',
  connection: { host, user, database }
})
```
> 注意：**不是 `new knex()`**，直接调用函数。

## 底层运作逻辑（工厂核心行为）
1. 入参配置中读取 `client`（mysql2 / pg / sqlite3 / mssql）；
2. 根据客户端类型，动态加载对应的**数据库方言 Client**；
3. 内部完成初始化、连接池构建；
4. 返回统一接口的 Knex 实例。

伪代码还原它工厂的核心逻辑：
```js
// knex 顶层导出的工厂函数
function knex(config) {
  // 根据配置选择对应数据库驱动方言
  let Client
  switch(config.client) {
    case 'mysql2':
      Client = require('./dialects/mysql/client')
      break
    case 'pg':
      Client = require('./dialects/postgres/client')
      break
    case 'sqlite3':
      Client = require('./dialects/sqlite/client')
      break
  }
  // 内部组装实例
  const client = new Client(config)
  return new KnexInstance(client)
}
```

## 完美契合工厂模式的所有优势
1. **创建逻辑与实现解耦**
使用者只传入配置，不需要关心底层不同数据库的 Client 类，完全不用手动导入各类方言。

2. **运行时动态选择实现**
同一套调用代码，切换 `client` 配置就能无缝更换数据库，上层业务代码无需改动。

3. **缩小公开接口（small surface area）**
模块对外只暴露一个函数，不导出内部各类方言 Client 类；
使用者无法直接操作底层 Client，避免滥用。

4. **统一对外接口（鸭子类型）**
无论底层是 MySQL / Postgres / SQLite，返回实例拥有完全一致的查询 API。

## 延伸对照我们前面的理论
- 直接 `new XXXClient()` = 强绑定具体实现，切换数据库需要大量改动；
- `knex(config)` 工厂 = 隔离变化点，所有差异收敛在工厂内部。

Node.js 大量内置 API 也是同类设计：
`fs.createReadStream()`、`crypto.createHash()`、`zlib.createGzip()`，全部都是工厂函数。
