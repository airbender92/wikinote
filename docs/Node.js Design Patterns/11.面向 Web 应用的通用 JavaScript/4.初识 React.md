# 译文 + 核心知识点
## 译文：初识 React
话不多说，我们直接上手实操一个 React 基础示例。这是极简 Hello World 案例，用来讲解 React 核心基础概念，后续再搭建更贴近真实业务的同构应用。

### 1. 初始化项目并安装依赖
```bash
# 初始化 package.json
npm init -y
# 安装 webpack 打包开发依赖
npm install --save-dev webpack webpack-cli
# 执行 webpack 交互式初始化配置
node_modules/.bin/webpack init
# 安装 React 核心运行依赖
npm install --save react react-dom
```

### 2. 入口文件 `src/index.js`
```js
import react from 'react'
import ReactDOM from 'react-dom'
// 简写 createElement 工具函数
const h = react.createElement

// 自定义 Hello 组件，继承 React 基类
class Hello extends react.Component {
  // 所有组件必须实现 render 方法
  render () {
    return h('h1', null, [
      'Hello ',
      this.props.name || 'World' // 读取传入的 name 属性，无则默认 World
    ])
  }
}

// 将根组件挂载到页面 body
ReactDOM.render(
  h(Hello, { name: 'React' }),
  document.getElementsByTagName('body')[0]
)
```

### 代码分步解析
1. 别名简写：`h = react.createElement`
`createElement` 是 React 底层创建虚拟 DOM 的核心方法，可生成普通 HTML 标签、自定义组件两类元素。
2. 定义组件：`class Hello extends react.Component`
类组件必须继承 React 内置组件基类。
3. `render()` 强制要求
所有类组件必须实现该方法，返回 React 元素，描述组件渲染结构。
4. `createElement(tag/props/children)` 参数说明
- 参数1：标签名字符串（`h1`/`div`）或自定义组件类；
- 参数2：属性对象（props），无属性传 `null`；
- 参数3及后续：子元素（文本、其他组件/标签），支持数组或多参数平铺。
5. `this.props` 读取外部传入属性
父组件传递的数据存在 `props` 中，只读不可修改；本例无 `name` 时兜底展示 `World`。
6. `ReactDOM.render()` 挂载应用
接收组件实例 + 页面真实 DOM 容器，将 React 组件渲染到浏览器页面。本例挂载至 `<body>`，也可指定任意页面已有 DOM 节点。

### 运行预览
执行开发脚本
```bash
npm start
```
浏览器页面会展示 `Hello React`，你的第一个 React 应用就完成了。

### 补充：虚拟 DOM（Virtual DOM）核心特性
React 依靠虚拟 DOM 做渲染优化：
页面数据变更时不会完整重绘 DOM，而是在内存中对比新旧虚拟 DOM 树（diff 差分算法），只计算并应用最少的真实 DOM 修改，大幅提升前端渲染性能。

## 核心知识点
### 1. React 底层无 JSX 原生写法
示例完全使用 `react.createElement`，不依赖 JSX 语法糖，是 React 最原始运行形式；JSX 只是语法糖，打包时会编译为 `createElement` 调用。
### 2. 类组件基础规范
- 必须继承 `React.Component`；
- 必须实现 `render()`，返回 React 元素；
- `props` 只读，组件内部不能修改传入属性。
### 3. createElement 三参数固定格式
标签/组件 + 属性对象 + 子节点（文本/元素）。
### 4. ReactDOM.render 作用
客户端渲染入口，将组件树挂载到真实 DOM 容器，仅浏览器可用（Node 服务端渲染使用独立 API）。
### 5. Virtual DOM Diff 优化核心
不整页刷新，最小化 DOM 操作，是 React 高性能渲染的底层核心原理。

# 译文 + 核心知识点
## 译文
### react.createElement 的替代方案
频繁嵌套调用 `react.createElement`（哪怕简写为 `h`）会严重降低组件代码可读性，多层嵌套后很难直观看出页面 HTML 结构。因此开发中几乎不会直接使用该底层 API，React 官方主推 **JSX** 作为替代语法。

JSX 是 JavaScript 的语法超集，可以在 JS 代码中直接书写类 HTML 标记，写组件时和原生 HTML 观感一致，代码可读性大幅提升。我们把之前的 Hello 组件改写成 JSX 版本：
```js
import react from 'react'
import ReactDOM from 'react-dom'

class Hello extends react.Component {
  render () {
    return <h1>Hello {this.props.name || 'World'}</h1>
  }
}

ReactDOM.render(
  <Hello name="React"/>,
  document.getElementsByTagName('body')[0]
)
```
代码直观清晰很多。但 JS 标准本身不支持 JSX，必须经过编译转换为 `createElement` 才能运行。而本章要搭建**同构应用**（浏览器+Node 两端运行），两端都需要额外编译流程，为简化示例，本章后续不使用 JS。

### 基于标准模板字符串的替代方案
近年出现了无需预编译、仅靠原生 JS **标签模板字符串（tagged template literals）** 的替代方案，兼顾可读性且省去编译步骤，代表库：`htm`、`esx`。本章全程使用 `htm`，重写示例：
```js
import react from 'react'
import ReactDOM from 'react-dom'
import htm

// 1. 绑定 createElement，生成模板标签函数 html
const html = htm.bind(react.createElement)

class Hello extends react.Component {
  render () {
    // 2. 使用模板字符串书写标签，${} 插值嵌入动态变量
    return html`<h1>
      Hello ${this.props.name || 'World'}
    </h1>`
  }
}

// 3. 使用占位符渲染自定义组件，直接写属性传 props
ReactDOM.render(
  html`<${Hello} name="React"/>`,
  document.getElementsByTagName('body')[0]
)
```

### htm 使用说明
1. 绑定生成模板函数：`htm.bind(react.createElement)`，运行时自动调用底层创建元素 API；
2. 基础 DOM 标签：使用反引号模板字符串，`${}` 插入 JS 动态表达式；
3. 自定义组件渲染：用 `<${组件类} />` 格式，属性写法和 HTML 一致传递 props；组件有子元素可闭合 `<${Hello}>子节点</>`。

掌握基础组件结构后，下一节讲解 React 组件状态管理，这是真实业务开发的核心概念。

## 核心知识点
### 1. 三种 React 写法对比
1. 原生 `createElement`
    - 优点：纯标准 JS，两端直接运行，无需编译；
    - 缺点：多层嵌套可读性极差，业务几乎不用。
2. JSX（行业主流）
    - 优点：类 HTML，开发体验最好；
    - 缺点：非标准 JS，必须 babel 预编译，同构项目两端都要配置编译流程。
3. htm（本章选用）
    - 优点：基于原生标签模板字符串，**零构建编译**，兼顾可读性；
    - 缺点：生态不如 JSX 完善，大型项目很少采用。

### 2. 关键语法区分
- JSX：尖括号标签，单/双引号属性，编译期转换；
- htm：反引号模板字符串，`${}` 插值渲染组件/变量，运行时解析；
- 自定义组件渲染：htm 必须 `<${Comp}>`，JSX 直接 `<Comp />`。

### 3. 同构场景选择逻辑
本章为简化 Node+浏览器双端配置，放弃需要编译的 JS，选用无需转译的 htm，省去两端 babel 配置成本。

### 4. 标签模板字面量（tagged template literals）
ES 原生标准语法，函数紧跟反引号字符串，字符串分段与插值会自动传入函数处理，htm 底层完全依托该原生特性实现。

# 译文 + 核心知识点
## 译文
### 有状态组件
上一节我们实现了无状态组件：仅通过外部传入的 `props` 接收数据，组件内部不存储、管理任何动态信息，渲染完全依赖入参。
但实际业务中大多需要维护内部动态数据，React 通过**组件状态（state）** 实现该能力。我们搭建一个示例：拉取 GitHub 最近更新项目列表的组件。
封装 `RecentGithubProjects` 组件，通过 `query` 属性筛选仓库，属性传入关键词（javascript / react），组件自动请求对应 GitHub API。

### 组件代码：RecentGithubProjects.js
```js
import react from 'react'
import htm from 'htm'
const html = htm.bind(react.createElement)

function createRequestUri (query) {
  return `https://api.github.com/search/repositories?q=${
    encodeURIComponent(query)
  }&sort=updated`
}

export class RecentGithubProjects extends react.Component {
  // 1. 构造函数，接收props
  constructor (props) {
    super(props) // 2. 必须调用父类构造函数
    // 3. 初始化内部状态
    this.state = {
      loading: true,
      projects: []
    }
  }

  // 4. 异步拉取数据、更新状态
  async loadData () {
    this.setState({ loading: true, projects: [] })
    const response = await fetch(createRequestUri(this.props.query), { mode: 'cors' })
    const responseBody = await response.json()
    this.setState({
      projects: responseBody.items,
      loading: false
    })
  }

  // 5. 挂载生命周期：组件插入DOM后执行
  componentDidMount () {
    this.loadData()
  }

  // 6. 更新生命周期：props变化时触发
  componentDidUpdate (prevProps) {
    if (this.props.query !== prevProps.query) {
      this.loadData()
    }
  }

  // 7. 渲染函数
  render () {
    if (this.state.loading) {
      return 'Loading ...'
    }
    // 8. 列表渲染，设置唯一key
    return html`<ul>
      ${this.state.projects.map(project => html`
        <li key=${project.id}>
          <a href=${project.html_url}>${project.full_name}</a>:
          ${project.description}
        </li>
      `)}
    </ul>`
  }
}
```

#### 代码分段讲解
1. **constructor(props)**：组件构造器，接收父组件传入的所有 props；
2. **super(props)**：继承 React.Component 时必须执行，初始化父类逻辑；
3. **this.state**：组件私有内部状态，仅能通过 `setState` 修改，初始化时定义加载标识、空项目数组；
4. **loadData()**：异步请求函数，`this.setState()` 更新状态，触发组件重渲染；请求前置 loading，请求结束回填列表、关闭加载；
5. **componentDidMount**：挂载生命周期钩子，组件首次插入 DOM 后执行，适合初次接口请求；
6. **componentDidUpdate(prevProps)**：组件更新钩子，参数为更新前的 props；对比新旧查询关键词，变更则重新拉取接口；
7. **条件渲染**：`render` 根据 `state.loading` 区分加载文案 / 列表；
8. **列表 key**：渲染数组元素必须绑定唯一 `key`，辅助虚拟 DOM 差分算法提升渲染性能。

> 补充：示例未处理接口异常，优雅方案是封装 ErrorBoundary 错误边界组件，留给读者练习。

### 根组件 App.js
提供导航栏，点击切换查询关键词，通过内部 state 管理选中标签，向下传递给子组件：
```js
import react from 'react'
import htm from 'htm'
import { RecentGithubProjects } from './RecentGithubProjects.js'
const html = htm.bind(react.createElement)

export class App extends react.Component {
  constructor (props) {
    super(props)
    this.state = {
      query: 'javascript',
      label: 'JavaScript'
    }
    // 绑定this指向，点击事件内可用this.setState
    this.setQuery = this.setQuery.bind(this)
  }

  setQuery (e) {
    e.preventDefault()
    const label = e.currentTarget.text
    this.setState({ label, query: label.toLowerCase() })
  }

  render () {
    return html`<div>
      <nav>
        <a href="#" onClick=${this.setQuery}>JavaScript</a>
        <a href="#" onClick=${this.setQuery}>Node.js</a>
        <a href="#" onClick=${this.setQuery}>React</a>
      </nav>
      <h1>Recently updated ${this.state.label} projects</h1>
      <${RecentGithubProjects} query=${this.state.query}/>
    </div>`
  }
}
```
关键点：
事件处理函数 `setQuery` 在构造器通过 `bind(this)` 绑定组件实例；若不绑定，点击时函数内 `this` 为 `undefined`，无法调用 `setState` 更新状态。

## 核心知识点
### 1. props vs state
- **props**：外部传入，只读，父组件控制，跨组件通信；
- **state**：组件内部私有数据，可通过 `setState` 修改，仅组件自身管理；
- `setState` 是异步批量更新，调用后自动触发组件重渲染。

### 2. 两大核心生命周期（类组件）
1. `componentDidMount`：组件首次渲染到 DOM 后执行，适合初始化接口、DOM 操作；
2. `componentDidUpdate(prevProps)`：props / state 变更后执行，接收变更前属性，用于监听属性变化重新请求。

### 3. 列表渲染 key
渲染数组元素必须设置唯一标识，帮助 React 高效对比虚拟 DOM，减少真实 DOM 操作。

### 4. 事件 this 绑定问题
类方法直接作为点击回调时，`this` 会丢失；三种解决方案：
1. 构造器 `bind(this)`（示例方案）；
2. 箭头函数 `onClick={() => this.setQuery(e)}`；
3. 类箭头语法 `setQuery = (e) => {}`。

### 5. 条件渲染
`render` 中通过 if 判断不同状态，返回不同 UI，是 React 最基础的分支渲染方案。

### 6 开发注意点
代码使用 `async/await`，旧版 webpack 配置需补充转译相关 loader，否则打包报错。
