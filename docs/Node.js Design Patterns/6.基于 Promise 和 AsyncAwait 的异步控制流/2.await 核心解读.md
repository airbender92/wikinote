# async/await 核心解读

## 一、为什么要有 async/await
- Promise 已经比回调好太多，但**串行流程还是要写 `.then()`**
- 代码依然不够像“同步”，不够直观
- 社区需要一种**看起来阻塞、实际异步**的写法

于是 ES 标准推出了：**async / await**

## 二、核心一句话
**async/await 是 Promise 的语法糖，让异步代码写起来和同步代码一模一样。**

底层完全还是 Promise，只是写法更舒服。

## 三、基本规则
1. **`async` 修饰函数**
   - 函数内部可以用 `await`
   - 函数**自动返回 Promise**

2. **`await` 后面跟 Promise**
   - 会“等待”这个 Promise 完成
   - 如果成功：返回结果值
   - 如果失败：直接抛出异常（可用 `try/catch` 捕获）

## 四、直观对比

### Promise 链式
```js
function download(url) {
  return get(url)
    .then(res => save(res.text))
    .then(() => console.log('done'))
}
```

### async/await 版
```js
async function download(url) {
  const res = await get(url)
  await save(res.text)
  console.log('done')
}
```

**完全同步写法，完全异步执行。**

## 五、错误处理
用经典的 `try/catch`：
```js
async function download(url) {
  try {
    const res = await get(url)
    await save(res.text)
  } catch (err) {
    console.error('下载失败', err)
  }
}
```

## 六、和 Promise 的关系
```
async/await
      ↑
    Promise
      ↑
   Callback
```

- 没有抛弃之前的知识
- 只是**更高级、更易读**的写法
- 所有异步工具（`Promise.all`、`race` 等）依然可用

## 七、本书接下来要做什么
用 **async/await 重写整个爬虫**：
- 串行下载
- 并行下载
- 全局并发限流
- 代码会精简到极致，结构清晰到离谱

这就是**现代 Node.js 异步编程的最终形态**。

# Async 函数与 await 表达式（核心精讲）

## 1. 什么是 async 函数
- 使用 `async` 关键字声明的函数
- **内部可以使用 `await`**
- **永远返回一个 Promise**
  即使你 return 一个普通值，也会自动包装成 `Promise.resolve(...)`

## 2. await 到底做了什么
`await` 后面放一个 Promise，作用是：
- **暂停当前 async 函数的执行**
- 把控制权交还给事件循环（不阻塞主线程）
- 等到 Promise 敲定（fulfilled 或 rejected）
- 如果成功：返回结果值
- 如果失败：抛出异常（可以用 `try/catch` 捕获）

`await` 也可以接普通值，会自动当成 `Promise.resolve(value)` 处理。

---

## 3. 示例代码逐行解释
```js
async function playingWithDelays() {
  console.log('Delaying...', new Date())

  // 等待 1 秒，拿到 resolve 出来的日期
  const dateAfterOneSecond = await delay(1000)
  console.log(dateAfterOneSecond)

  // 再等待 3 秒
  const dateAfterThreeSeconds = await delay(3000)
  console.log(dateAfterThreeSeconds)

  // 最终返回值会变成 Promise 的结果
  return 'done'
}
```

调用方式：
```js
playingWithDelays().then(result => {
  console.log('After ~4 seconds:', result)
})
```

总耗时约 **4 秒**，但代码**完全像同步一样顺序**。

---

## 4. 关键真相（必须懂）
- **async/await 并没有把异步变同步**
- 只是**写法看起来同步**
- 底层依然是 Promise + 事件循环
- 每遇到 `await`，函数就暂停，事件循环继续跑

所以：
- 不阻塞主线程
- UI/事件依然响应
- 性能和纯 Promise 完全一样，只是更好读

---

## 5. 一句话总结
> **async 让函数能 await，await 让 Promise 等待得像同步代码。**

这是目前 JavaScript 世界里**最简洁、最安全、官方推荐**的异步写法。

接下来我们就会用它**重写整个爬虫**，代码会精简到你不敢相信。

# async/await 错误处理（核心 + 避坑）

## 一、统一的 try/catch
async/await 最大优势之一：
**同步错误、异步 Promise 错误，能用同一个 catch 捕获**

```js
async function playingWithErrors(throwSyncError) {
  try {
    if (throwSyncError) {
      // 同步抛错
      throw new Error('同步错误')
    }
    // 异步 reject
    await delayError(1000)
  } catch (err) {
    // 🔥 两类错误都能抓到
    console.error('出错：', err.message)
  } finally {
    console.log('无论如何都执行')
  }
}
```

---

## 二、经典陷阱：return 与 return await

### 1. 错误示例：直接 return Promise
```js
async function errorNotCaught() {
  try {
    return delayError(1000) // 没有 await
  } catch (err) {
    // 🔥 根本进不来
    console.error('本地抓到')
  }
}

errorNotCaught().catch(err => {
  console.error('调用者抓到：', err.message) // ✅ 只有这里能抓到
})
```
原因：
`return delayError(1000)` 只是把 Promise **原样返回**给外层，
函数没有等待它，所以**本地 catch 捕获不到**。

### 2. 正确写法：return await
```js
async function errorCaught() {
  try {
    return await delayError(1000) // 加了 await
  } catch (err) {
    // ✅ 本地能捕获
    console.error('本地抓到：', err.message)
  }
}
```
加了 `await`，函数会**等待 Promise 敲定**，错误就能被本地 catch 接住。

---

## 三、极简总结（面试常考）
1. **async/await + try/catch** 可以统一处理：
   - 同步 `throw`
   - 异步 Promise.reject

2. **return Promise ≠ 本地捕获**
3. **return await Promise = 本地可以捕获**

这就是 async/await 错误处理的全部核心。
接下来就会用这套语法，把整个爬虫重写成**最清爽的最终版本**。

# async/await 串行执行与迭代（最终极简版）

这一节直接把**爬虫 v2（串行下载）**用 async/await 重写，代码精简、扁平、近乎同步写法，是全书最舒服的版本。

---

## 1. download —— 纯顺序异步逻辑
```js
async function download(url, filename) {
  console.log(`Downloading ${url}`)

  // 等待网络请求完成
  const { text: content } = await superagent.get(url)

  // 等待创建目录
  await mkdirpPromises(dirname(filename))

  // 等待写入文件
  await fsPromises.writeFile(filename, content)

  console.log(`Downloaded and saved: ${url}`)
  return content
}
```
- 完全**没有嵌套**
- 一行一个步骤，顺序清晰
- 回调版要十几个函数，这里**7 行搞定**

---

## 2. spiderLinks —— 串行循环迭代
```js
async function spiderLinks(currentUrl, content, nesting) {
  if (nesting === 0) return

  const links = getPageLinks(currentUrl, content)

  // 直接 for 循环 + await，串行依次爬取
  for (const link of links) {
    await spider(link, nesting - 1)
  }
}
```
- 不再需要手动拼 Promise 链
- 不再需要 reduce 技巧
- **for + await 就是串行异步迭代**

> 注意：`forEach` 不支持 await，要用 `for...of`

---

## 3. spider 主函数 —— try/catch 处理错误
```js
export async function spider(url, nesting) {
  const filename = urlToFilename(url)
  let content

  try {
    // 尝试读取本地文件
    content = await fsPromises.readFile(filename, 'utf8')
  } catch (err) {
    // 文件不存在才下载
    if (err.code !== 'ENOENT') throw err
    content = await download(url, filename)
  }

  return spiderLinks(url, content, nesting)
}
```
- 同步、异步错误**统一捕获**
- 逻辑清晰，结构扁平
- 完全摆脱回调与链式冗余

---

# 本节核心总结
1. **串行执行**
   用 `await` 一行接一行写，像同步代码一样自然。

2. **串行迭代**
   `for...of` 循环里直接 `await` 即可，无需任何设计模式。

3. **代码收益**
   - 体积大幅缩小
   - 无嵌套、无回调地狱、无长链
   - 错误处理统一、自然
   - 可读性达到**异步代码的天花板**

这就是 **Node.js 异步编程的现代标准写法**。
后面还有并行、限流版本，同样简单到离谱。

# 反面教材：async/await + forEach 实现串行迭代（千万别这么写）

## 问题代码（错误写法）
```js
links.forEach(async function iteration(link) {
  // 这里的 await 根本达不到串行效果
  await spider(link, nesting - 1)
})
```

## 为什么不行？
1. **`forEach` 根本不关心回调函数返回的 Promise**
   它只管挨个执行，不会等待前一个 `async` 函数完成。

2. **所有 `spider()` 会在同一轮事件循环里同时启动**
   变成**并行执行**，而不是你想要的串行。

3. **外部代码不会等待任何任务完成**
   forEach 执行完立刻继续往后走，而不是等所有爬取结束。

---

## 结论
- 想要**串行异步迭代**：
  ✅ 使用 **`for...of` + await**
- 绝对不要用：
  ❌ `Array.forEach(async () => { await ... })`

这是前端/Node 异步里**最经典的坑之一**，一定要记牢。

# async/await 并行执行两种写法（推荐用 Promise.all）

## 一、写法 1：先全部启动，再逐个 await（不推荐）
```js
async function spiderLinks(currentUrl, content, nesting) {
  if (nesting === 0) return

  const links = getPageLinks(currentUrl, content)
  // 1. 一次性全部启动，生成 promises 数组
  const promises = links.map(link => spider(link, nesting - 1))

  // 2. 然后再逐个等待
  for (const promise of promises) {
    await promise
  }
}
```

### 缺点
- 某个 Promise **提前 reject 了**，也要等前面的都 resolve 才会抛出错误
- 失败反馈不及时，不符合大多数业务需求

---

## 二、写法 2：await Promise.all（✅ 官方推荐）
```js
async function spiderLinks(currentUrl, content, nesting) {
  if (nesting === 0) return

  const links = getPageLinks(currentUrl, content)
  const promises = links.map(link => spider(link, nesting - 1))

  // 直接 await 全部并行任务
  return await Promise.all(promises)
}
```

### 优点
- **任意一个失败，立刻整体 reject**
- 性能最优、行为标准、语义清晰
- 可以直接接收结果数组：`const results = await Promise.all(promises)`

---

# 核心总结
1. **并行固定套路**
   - 先用 `.map()` 启动所有异步任务，得到 promises 数组
   - 再用 `await Promise.all(promises)` 等待全部完成

2. **async/await 并没有替代 Promise**
   它只是**更舒服的语法**，`Promise.all / race / allSettled` 依然是核心工具。

3. 全书异步最终最佳实践：
   - 串行：`for...of + await`
   - 并行：`map + await Promise.all`
   - 限流：`TaskQueue` 或 `p-limit` + async/await

   # 基于 async/await 的限流并行：生产者 - 消费者模式（TaskQueuePC）
这是本书**最高级、最优雅**的并发限流实现，完全基于 async/await 思想，用**生产者 - 消费者模型**重构 TaskQueue。

## 一、整体设计思路
- 开启 **concurrency 个消费者**（无限循环的 async 函数）
- 消费者空闲时会“休眠”，直到有任务到来
- 外部调用 `runTask()` 作为**生产者**，往队列塞任务
- 消费者数量 = 最大并发数

## 二、完整代码解析

### 1. 构造函数
```js
export class TaskQueuePC {
  constructor(concurrency) {
    this.taskQueue = []       // 任务队列
    this.consumerQueue = []   // 休眠的消费者（存放 resolve）

    // 启动固定数量的消费者
    for (let i = 0; i < concurrency; i++) {
      this.consumer()
    }
  }
}
```

### 2. 消费者（核心）
```js
async consumer() {
  while (true) {
    try {
      // 等待任务，没有任务就会“休眠”
      const task = await this.getNextTask()
      // 执行任务
      await task()
    } catch (err) {
      console.error(err)
    }
  }
}
```
- 无限循环不占 CPU，因为 `await getNextTask()` 会让出事件循环
- 一个消费者 = 一个并发槽位

### 3. 获取下一个任务（休眠机制）
```js
async getNextTask() {
  return new Promise(resolve => {
    if (this.taskQueue.length > 0) {
      // 有任务直接给
      return resolve(this.taskQueue.shift())
    }
    // 没任务：把 resolve 存入消费者队列，进入休眠
    this.consumerQueue.push(resolve)
  })
}
```

### 4. 生产者：添加任务
```js
runTask(task) {
  return new Promise((resolve, reject) => {
    // 包装任务，用于传递结果
    const taskWrapper = () => {
      const taskPromise = task()
      taskPromise.then(resolve, reject)
      return taskPromise
    }

    if (this.consumerQueue.length > 0) {
      // 有休眠的消费者，直接唤醒它
      const consumerResolve = this.consumerQueue.shift()
      consumerResolve(taskWrapper)
    } else {
      // 消费者都忙，任务入队
      this.taskQueue.push(taskWrapper)
    }
  })
}
```

## 三、工作流程（极简版）
1. 启动 N 个消费者，都调用 `getNextTask()`，队列空 → 全部休眠
2. 外部调用 `runTask(task)`
3. 有休眠消费者 → 取出一个 `resolve`，把任务传给它，消费者继续执行
4. 无空闲消费者 → 任务加入队列排队
5. 任务执行完，消费者再次 `await getNextTask()`，循环往复

## 四、关键点总结
- **完全不浪费并发槽位**
- 休眠 = Promise + 延迟 resolve
- 唤醒 = 调用存起来的 resolve
- 外表像多线程，底层仍是事件循环 + Promise
- 接口和之前的 TaskQueue 完全一致，爬虫代码不用大改

## 五、全书异步控制流最终结论
1. **串行**：`for...of + await`
2. **并行**：`map + Promise.all`
3. **限流并行**：
   - 经典版：TaskQueue（计数器 + 队列）
   - 高级版：TaskQueuePC（**async/await + 生产者 - 消费者**）
4. **async/await 不是替代 Promise，而是它的终极语法糖**

到这里，《Node.js Design Patterns》第5章所有核心内容就全部结束啦。

# 无限递归 Promise 链的内存泄漏问题（全书高级重点）

这是一个**底层规范级别的坑**：
**无限递归、永远不敲定的 Promise 链式调用，会造成内存泄漏。**
所有符合 Promises/A+ 标准的实现（包括原生 JS Promise）都受影响。

---

## 1. 泄漏代码（典型反例）
```js
function leakingLoop() {
  return delay(1)
    .then(() => {
      console.log('Tick', Date.now())
      return leakingLoop() // 👈 递归 return Promise
    })
}
```

### 为什么泄漏
- 每一层 Promise **都等待下一层 resolve**
- 整个链条**永远不完成**
- 所有 Promise、上下文、作用域、`.then` 回调全都**无法被 GC 回收**
- 内存无限上涨 → 进程崩溃

---

## 2. 解法 1：断掉链式依赖（最简单）
```js
function nonLeakingLoop() {
  delay(1)
    .then(() => {
      console.log('Tick', Date.now())
      nonLeakingLoop() // 👈 不再 return
    })
}
```

### 原理
- 不把下一轮 Promise 返回给上一层
- 每层 Promise 都会**独立完成**
- 作用域可以被正常垃圾回收

缺点：
- 内部错误**无法向外传递**

---

## 3. 解法 2：保留错误传递（推荐工程版）
```js
function nonLeakingLoopWithErrors() {
  return new Promise((resolve, reject) => {
    (function internalLoop() {
      delay(1)
        .then(() => {
          console.log('Tick', Date.now())
          internalLoop()
        })
        .catch(reject) // 👈 错误统一往外 reject
    })()
  })
}
```

### 优点
- 无内存泄漏
- 任意一层出错，外层 Promise 都会 reject

---

## 4. 解法 3：async/await 无限循环（最优雅 ✅）
```js
async function nonLeakingLoopAsync() {
  while (true) {
    await delay(1)
    console.log('Tick', Date.now())
  }
}
```

### 为什么安全
- **不是递归**
- 每一轮 await 结束，上一轮上下文就可以释放
- 没有永远挂起的 Promise 链
- 错误可以正常向外抛出

---

## 5. 反面教材：async 递归依然泄漏
```js
async function leakingLoopAsync() {
  await delay(1)
  console.log('Tick', Date.now())
  return leakingLoopAsync() // 👈 递归 return → 依然泄漏
}
```

---

# 极简终极总结
- **无限递归 + return Promise = 内存泄漏**
- 根源：Promise 链永远不 settle，上下文无法 GC
- 最佳实践：
  - 用 **while(true) + await** 实现无限异步循环（首选）
  - 或断掉链式返回，不要递归 return Promise

这是生产环境**长服务、流式处理、监控、定时任务**里非常致命的隐藏坑，也是高级 Node 面试高频考点。
