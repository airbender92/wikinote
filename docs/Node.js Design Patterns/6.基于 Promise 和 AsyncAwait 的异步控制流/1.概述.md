# Promise 核心知识点精读（原文通俗翻译+总结）

## 一、Promise 是什么
- 是**异步操作的结果占位符**
- 三种状态：
  - **pending**（进行中）
  - **fulfilled**（成功）
  - **rejected**（失败）
- 一旦 settled（fulfilled / rejected）就**不可再变**

## 二、基本用法
回调风格：
```js
asyncOperation(arg, (err, result) => {
  if (err) { /* 处理错误 */ }
  // 正常逻辑
})
```

Promise 风格：
```js
asyncOperationPromise(arg)
  .then(result => { /* 成功 */ })
  .catch(err => { /* 失败 */ })
```

## 三、最关键特性：**then() 可以链式调用**
- `then()` 会**返回一个新的 Promise**
- 回调里 return 一个值 / Promise，会自动传递到下一个 then
- 异常会**自动穿透整条链**，直到被 catch 捕获

串行流程瞬间变简单：
```js
asyncOp1()
  .then(result1 => asyncOp2(result1))
  .then(result2 => asyncOp3(result2))
  .then(final => console.log(final))
  .catch(err => console.error('整条链任意一步出错都到这', err))
```

## 四、Promise 彻底解决 Zalgo 问题
- 无论 Promise 是同步立刻完成，还是异步完成
- `then` 回调**一定异步执行**
- 不会出现“有时同步、有时异步”的不可预测行为
- 代码行为稳定统一

## 五、异常处理革命性提升
- 在 then 内部 throw 异常
- 会**自动变成 Promise 失败**，跳到最近的 catch
- 不用再手动传递 err，不会丢失错误
- 同步异步错误统一捕获

---

# 极简总结（记住这 5 点就掌握 Promise）
1. Promise = 异步结果的“未来容器”
2. 状态：pending → fulfilled / rejected
3. `.then()` 返回新 Promise，支持链式串行
4. 错误自动穿透整条链，统一 `.catch()`
5. 绝对异步，彻底杜绝 Zalgo 问题

# Promises/A+ 与 thenable（核心概念）

## 一、Promises/A+ 是什么
- 是一套**Promise 标准规范**
- 解决早年各种 Promise 类库互不兼容的问题
- 规定了 `then()` 的精确行为，让不同库的 Promise 可以**互相链式调用**
- 现在 JS / Node.js 原生 Promise 完全遵守这一规范

## 二、thenable 是什么
- 定义：**任何带有 `.then()` 方法的对象**
- 会被 JS 引擎**自动当成 Promise** 处理
- 作用：
  - 不同 Promise 实现可以无缝互操作
  - 自定义对象也能接入 Promise 链

示例（一个最简单的 thenable）：
```js
const thenable = {
  then(onFulfilled) {
    onFulfilled('hello')
  }
}

// 可以直接当作 Promise 使用
Promise.resolve(thenable).then(console.log)
```

## 三、意义
- 统一了整个 JS 生态的异步行为标准
- 让 Promise 链可以跨库、跨实现自由组合
- 为后来的 `async/await` 铺平了道路

一句话记住：
**有 then 就是 thenable，符合 Promises/A+ 就能无缝链式玩。**

# 原生 Promise API 核心速览（全书最常用的全部在这里）

## 一、创建 Promise
```js
const promise = new Promise((resolve, reject) => {
  // 异步操作

  if (成功) resolve(结果)
  if (失败) reject(错误)
})
```

- `resolve(value)`：改为成功状态
- `reject(err)`：改为失败状态
- 执行器函数会**同步立即执行**

---

## 二、静态方法（最实用）

### 1. `Promise.resolve(obj)`
快速创建一个**已成功**的 Promise：
```js
Promise.resolve(42)          // 成功值 42
Promise.resolve(thenableObj) // 自动转成标准 Promise
```

### 2. `Promise.reject(err)`
快速创建一个**已失败**的 Promise：
```js
Promise.reject(new Error('出错'))
```

### 3. `Promise.all([…])` 🔥
- 并行执行所有 Promise
- **全部成功才成功**
- 任意一个失败，整体立即失败（短路失败）
```js
Promise.all([p1, p2, p3])
  .then(results => { /* 所有结果数组 */ })
```

### 4. `Promise.allSettled([…])`
- 并行执行
- 等待**全部结束**（无论成功失败）
- 返回每个任务的状态：`{ status: 'fulfilled'|'rejected', value|reason }`

### 5. `Promise.race([…])`
- 竞速：**谁先结束用谁**（无论成功失败）

---

## 三、实例方法

### 1. `.then(onFulfilled, onRejected)`
核心方法，接收成功/失败回调，并且**返回新 Promise**，支持链式。

### 2. `.catch(onRejected)` 🔥
等价于 `.then(null, onRejected)`
捕获**整条链**的所有错误。

### 3. `.finally(onFinally)`
- 无论成功/失败**一定会执行**
- 不接收参数
- 不改变最终结果（除非内部抛错）
常用于：清理、关闭连接、隐藏加载态。

---

## 四、一句话记忆
- `new Promise(...)`：包装回调
- `.then()` / `.catch()`：链式处理
- `Promise.all()`：并行等待全部成功
- `Promise.allSettled()`：并行等待全部结束
- `finally()`：无论如何都执行

这就是现代 JS 异步的**全部基础 API**，后面所有 async/await 都建立在它们之上。

# 创建 Promise（核心用法）

## 1. 基本模式：把回调 API 包装成 Promise
```js
function delay(milliseconds) {
  // 返回一个新 Promise
  return new Promise((resolve, reject) => {
    // 异步逻辑
    setTimeout(() => {
      // 成功：调用 resolve(结果)
      resolve(new Date())
    }, milliseconds)
  })
}
```

- `new Promise((resolve, reject) => { ... })` 是固定写法
- 异步成功 → **resolve(结果)**
- 异步失败 → **reject(错误)**

## 2. 使用这个 Promise
```js
console.log('开始', new Date().getSeconds(), '秒')

delay(1000).then(newDate => {
  console.log('结束', newDate.getSeconds(), '秒')
})
```

1 秒后会触发 `.then()`，拿到 `resolve` 传出来的值。

---

### 一句话总结
**创建 Promise = 用 resolve/reject 把传统回调包裹一层**
这就是把老的 callback 函数“promise 化”的标准方式。

# Promisification（Promise 化）

## 一、什么是 promisification？
把**遵循 Node.js 回调规范的函数**
自动转换成**返回 Promise 的函数**，这个过程叫 promisification。

Node.js 回调规范：
- 回调是**最后一个参数**
- 回调第一个参数是 `err`
- 成功时 `err === null`，后面跟着结果

---

## 二、手写通用 promisify 工具
```js
function promisify(callbackBasedApi) {
  return function promisified(...args) {
    return new Promise((resolve, reject) => {
      // 给原函数拼接一个自定义回调
      const customCallback = (err, result) => {
        if (err) return reject(err)
        resolve(result)
      }

      // 调用原回调式 API
      callbackBasedApi(...args, customCallback)
    })
  }
}
```

### 工作原理
1. 包一层返回新函数
2. 新函数返回 Promise
3. 调用原函数时，自动追加一个回调
4. 回调里：
   - 有 err → `reject(err)`
   - 没 err → `resolve(result)`

---

## 三、实际使用
```js
import { randomBytes } from 'crypto'

// 转成 Promise 版本
const randomBytesP = promisify(randomBytes)

// 直接用 then / catch
randomBytesP(32)
  .then(buffer => console.log('随机数据:', buffer))
  .catch(err => console.error('失败:', err))
```

---

## 四、现实中不用手写
Node.js 内置了：
```js
import { promisify } from 'util'

// 直接用官方版
const randomBytesP = promisify(randomBytes)
```

而且现在几乎所有核心 API 都自带 Promise 版本：
```js
// fs 自带 promise API
import fs from 'fs/promises'

fs.readFile('file.txt', 'utf8').then(console.log)
```

---

## 一句话总结
**promisify = 自动把 (err, result) 回调函数变成 Promise 函数**
是连接传统回调与现代异步代码的桥梁。

## 一、串行执行（爬虫 v2）
### 1. 准备：Promise 化依赖
```js
import { promises as fsPromises } from 'fs'
import mkdirp from 'mkdirp'
import { promisify } from 'util'

const mkdirpPromises = promisify(mkdirp)
```

### 2. download() —— 清晰的串行链
```js
function download(url, filename) {
  console.log(`Downloading ${url}`)
  let content

  return superagent.get(url)
    .then(res => {
      content = res.text
      return mkdirpPromises(dirname(filename))
    })
    .then(() => fsPromises.writeFile(filename, content))
    .then(() => {
      console.log(`Saved: ${url}`)
      return content
    })
}
```
- 一步接一步，**完全扁平**
- 不用嵌套，不用传递 callback
- 错误自动往后抛

### 3. spiderLinks() —— 循环构建串行 Promise 链
```js
function spiderLinks(currentUrl, content, nesting) {
  let promise = Promise.resolve()

  if (nesting === 0) return promise

  const links = getPageLinks(currentUrl, content)

  // 循环串联：一个完成再下一个
  for (const link of links) {
    promise = promise.then(() => spider(link, nesting - 1))
  }

  return promise
}
```
**模式：用循环动态拼接 Promise 链**

更简洁的 `reduce` 写法（等价）：
```js
const links = getPageLinks(currentUrl, content)

return links.reduce((promiseChain, link) => {
  return promiseChain.then(() => spider(link, nesting - 1))
}, Promise.resolve())
```

### 4. spider() 主逻辑
```js
export function spider(url, nesting) {
  const filename = urlToFilename(url)

  return fsPromises.readFile(filename, 'utf8')
    .catch(err => {
      // 文件不存在才下载
      if (err.code !== 'ENOENT') throw err
      return download(url, filename)
    })
    .then(content => spiderLinks(url, content, nesting))
}
```

### 5. 入口调用
```js
spider(url, nesting)
  .then(() => console.log('Done'))
  .catch(err => console.error(err))
```

## 二、并行执行（爬虫 v3）
只需要改 `spiderLinks()`，用 **`Promise.all`** 实现并行：

```js
function spiderLinks(currentUrl, content, nesting) {
  if (nesting === 0) {
    return Promise.resolve()
  }

  const links = getPageLinks(currentUrl, content)
  const promises = links.map(link => spider(link, nesting - 1))

  // 并行执行所有任务
  return Promise.all(promises)
}
```

- 所有任务**同时开始**
- 全部完成后 `Promise.all` 才 resolve
- 任何一个失败，整体立即失败

---

## 三、本节核心总结
1. **串行流程**
   - `.then()` 链式
   - 循环 / reduce 拼接 Promise 链
   - 顺序执行，一步一个

2. **并行流程**
   - 生成一组 Promise
   - `Promise.all([...])` 并行等待全部完成

3. **巨大优势**
   - 无回调地狱，代码扁平易读
   - 错误**自动穿透**，不用手动传递 err
   - 统一 `.catch()` 捕获整条链所有错误
   - 行为统一，不会触发 Zalgo 问题

# Promise 并行执行核心解析

## 一、并行实现代码
```js
function spiderLinks (currentUrl, content, nesting) {
  if (nesting === 0) {
    return Promise.resolve()
  }

  const links = getPageLinks(currentUrl, content)
  // 一次性发起所有爬取任务
  const promises = links.map(link => spider(link, nesting - 1))

  // 等待全部完成
  return Promise.all(promises)
}
```

## 二、关键逻辑
1. **`links.map(...)` 一次性启动所有任务**
   - 不会等待前一个完成
   - 所有请求几乎同时发出
   - 真正的并行（并发）

2. **`Promise.all(promises)`**
   - 等待**所有 Promise 变为 fulfilled**
   - 任何一个 reject，**整体立刻 reject**（失败熔断）
   - 最终结果是按**原数组顺序**返回的结果列表

## 三、和串行的本质区别
- **串行**：`promise = promise.then(() => spider())`
  等上一个结束，再开始下一个
- **并行**：`links.map(() => spider())`
  同一时间全部启动，再一起等结束

## 四、书中附带的 reduce 串行简写
```js
const promise = tasks.reduce((prev, task) => {
  return prev.then(() => task())
}, Promise.resolve())
```
这是串行迭代的**更简洁写法**，和循环拼链完全等价。

---

一句话总结：
**并行 = 一次性全部启动 + Promise.all 等全部结束**
这是 Promise 最常用、最简洁的并发模式。

# Promise 版 TaskQueue 类完整解析
这就是**上一章回调版队列的现代化 Promise 实现**，结构几乎一样，但更简洁、错误处理更安全。

## 一、核心：`next()` 方法（任务调度）
```js
next() {
  while (this.running < this.concurrency && this.queue.length) {
    const task = this.queue.shift()

    // 任务执行 + 无论成功失败都释放槽位
    task().finally(() => {
      this.running--
      this.next()
    })

    this.running++
  }
}
```

### 关键点
- 任务 `task()` **返回 Promise**
- `.finally()` 完美替代原来的回调收尾
  → 成功/失败都会执行
  → 统一减少运行计数
  → 自动调度下一个任务
- 不再需要手动处理错误传递

## 二、入口：`runTask()` 方法（入队 + 返回 Promise）
```js
runTask(task) {
  return new Promise((resolve, reject) => {
    // 推入包装函数
    this.queue.push(() => {
      return task().then(resolve, reject)
    })

    process.nextTick(this.next.bind(this))
  })
}
```

### 工作流程
1. 外部调用 `runTask(task)`，得到一个 Promise
2. 队列里塞一个**包装函数**
   执行真正任务，并把结果转发给外层 `resolve / reject`
3. `process.nextTick` 异步触发调度
   → 保证**绝对异步**，彻底避免 Zalgo
4. 任务真正执行时：
   ```js
   task().then(resolve, reject)
   ```
   成功 → resolve，失败 → reject

## 三、和回调版 TaskQueue 对比
| 回调版 TaskQueue                | Promise 版 TaskQueue                          |
|---------------------------------|-----------------------------------------------|
| 靠回调完成通知                  | 靠 Promise `.finally()` 完成通知              |
| 错误要手动 emit                 | 错误自动转发，外部直接 catch                  |
| 完成状态靠计数器判断             | 计数器逻辑不变，但代码更干净                 |
| 容易丢错误                      | 异常自动穿透，不会丢失                        |
| 需继承 EventEmitter             | 不需要事件，直接返回 Promise                  |

## 四、一句话总结
**Promise 让限流队列代码减少一半，逻辑更清晰，错误永不丢失。**

# 爬虫 v4 最终版：Promise + 全局并发限流

这是整本书**异步控制流的巅峰形态**：
Promise 化 + 限流队列 + 并行解析链接 + 全局并发控制，代码干净、健壮、可维护。

## 一、核心改动

### 1. spiderTask（真正执行爬取 + 入队限流）
```js
function spiderTask(url, nesting, queue) {
  if (spidering.has(url)) {
    return Promise.resolve()
  }
  spidering.add(url)

  const filename = urlToFilename(url)

  // 👇 关键：把“下载/读取”放进限流队列
  return queue.runTask(() => {
    return fsPromises.readFile(filename, 'utf8')
      .catch(err => {
        if (err.code !== 'ENOENT') throw err
        return download(url, filename)
      })
  })
  // 拿到内容后，再去解析链接
  .then(content => spiderLinks(url, content, nesting, queue))
}
```

- 只有**文件读取/下载**这一步进队列限流
- 解析链接、生成新任务**不在队列内**
- 避免深度爬取时发生**死锁**

### 2. spiderLinks（依然并行触发）
```js
function spiderLinks(currentUrl, content, nesting, queue) {
  if (nesting === 0) return Promise.resolve()

  const links = getPageLinks(currentUrl, content)

  // 一次性生成所有任务（由队列控制并发）
  const promises = links.map(link => spiderTask(link, nesting - 1, queue))

  return Promise.all(promises)
}
```

- 表面看是**全部并行触发**
- 实际并发由 `TaskQueue` 全局限制
- 代码结构极其清晰

### 3. 入口 spider（创建队列）
```js
export function spider(url, nesting, concurrency) {
  const queue = new TaskQueue(concurrency)
  return spiderTask(url, nesting, queue)
}
```

# 二、设计精髓（必懂）
1. **只限流 I/O 操作**
   下载、读文件是耗资源、有限制的部分，才进队列。

2. **解析链接逻辑不在队列内**
   如果把 `spiderLinks` 也放进队列，深度大时会**占满队列槽位 → 死锁**。

3. **并发控制完全交给 TaskQueue**
   业务代码只管触发任务，逻辑解耦。
