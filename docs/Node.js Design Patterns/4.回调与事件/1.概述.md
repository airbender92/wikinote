# 回调与事件（Callbacks and Events）——章节导读整理
## 一、同步编程 vs 异步编程
### 同步编程
代码被理解为一串连续执行的计算步骤；**所有操作都是阻塞式**，必须等待当前操作完成，才能执行下一行。
优势：代码直观、易于阅读、调试简单。

### 异步编程
文件读取、网络请求这类耗时操作会放到**后台执行**；发起异步调用后，程序会立刻执行后续代码，不会原地等待。
新问题：我们需要一种通知机制，在异步任务完成时收到通知，拿到执行结果继续后续逻辑。
Node.js 最基础的通知机制就是**回调函数（Callback）**。

## 二、回调函数的核心地位
回调本质：一段函数，由运行时在异步操作结束时调用，并传入异步执行结果。
> 所有 Node.js 异步机制的底层基石都是回调：
> Promise、async/await、Stream、事件系统，全部构建在回调之上。
> 弄懂回调，是掌握 Node.js 异步体系的前提。

## 三、两大核心主题
### 1. 回调模式（Callback Pattern）
本章将覆盖：
- Node.js 标准回调约定（**错误优先回调 Error-first Callback**）
- 回调典型写法、通用范式
- 常见陷阱：回调地狱、异常丢失、多次调用回调、同步/异步混杂等问题

### 2. 观察者模式（Observer Pattern）
可以看作回调模式的近亲，在 Node.js 中由 `EventEmitter` 实现。
普通回调一般处理**单次单一结果**；
`EventEmitter` 支持订阅**多种不同事件**，可以多次触发回调，是 Node 生态应用极广的组件（HTTP、Stream 全部基于它）。

2. 理解观察者模式，并学会使用 `EventEmitter` 在 Node.js 实现事件驱动

## 补充概念区分
- **普通回调**：一对一，单次通知（读取文件完成后执行一次回调）
- **EventEmitter（观察者）**：一对多，可多次触发、多类型事件（持续接收 `data`、`error`、`end` 事件）
