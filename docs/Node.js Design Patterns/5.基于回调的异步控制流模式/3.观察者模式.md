# 原文精准解读（仅围绕观察者模式与回调的核心区分）
## 一、核心定位
观察者模式（Observer Pattern）是 Node 三大底层核心模型之一：**Reactor反应堆 + 回调CPS + 观察者**，是掌握异步编程必备知识。
它和回调是互补关系，适配完全不同的业务场景。

## 二、标准定义
观察者模式：存在一个**发布者（主体 subject）**，可以维护一组订阅者（观察者 observers）；当主体状态/事件发生变化时，一次性通知所有注册过的观察者。

## 三、和传统CPS回调的核心区别（原文重点）
1. **传统回调（Callback）**
一次异步操作，只能对应**单一监听函数**，结果只会传给这一个回调，一对一传递。
典型场景：单次IO读取、单次接口请求，只需要拿到一次返回结果。

2. **观察者模式（EventEmitter 实现）**
一个事件触发时，可以同时通知**多个监听函数**，一对多广播。
典型场景：服务收到请求、数据流持续产生数据、程序多阶段进度通知，需要多处代码监听同一个事件。

## 四、简单场景对比区分
### 回调（一对一）
读取文件，只需要一处代码拿到文件内容：
```js
fs.readFile('a.txt', (err, data) => {
  // 仅有这一个回调接收结果
})
```

### 观察者（一对多）
HTTP服务收到请求，日志、鉴权、业务处理多处逻辑都要监听`request`事件：
```js
const server = http.createServer()
// 观察者1：打印日志
server.on('request', (req, res) => log(req))
// 观察者2：权限校验
server.on('request', (req, res) => authCheck(req))
// 观察者3：执行业务逻辑
server.on('request', (req, res) => handleBiz(req, res))
```
一次`request`事件触发，三个监听函数全部执行，完美体现一对多特性。
