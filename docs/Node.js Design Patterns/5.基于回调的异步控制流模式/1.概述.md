# 中文翻译
## 基于回调的异步控制流模式
从同步编程风格切换到 Node.js 这类以**续传风格（CPS）**和异步 API 为主的平台时，开发者往往会感到不适。异步代码会让语句的执行顺序变得难以预测。即使是一些简单问题，比如遍历一组文件、按顺序执行任务，或是等待一批操作全部完成，都需要开发者采用全新的思路和技巧，否则很容易写出低效且难以阅读的代码。

使用回调处理异步控制流时，最常见的错误就是陷入**回调地狱（callback hell）**：代码横向嵌套越来越深，而不是纵向延伸，这种嵌套结构会让哪怕简单的逻辑都变得难以阅读和维护。

在本章中，你会看到，只要遵循一定规范并借助一些设计模式，我们完全可以驾驭回调，写出清晰、易于管理的异步代码。掌握好回调的正确用法，也将为你后续学习 Promise、async/await 等现代方案打下坚实基础。

简单来说，本章你将学习：
- 异步编程面临的挑战
- 如何避免回调地狱，以及回调相关的最佳实践
- 常见的异步模式：顺序执行、顺序迭代、并行执行、受限并行执行
