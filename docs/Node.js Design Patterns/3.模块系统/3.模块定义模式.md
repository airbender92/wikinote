# 模块定义模式 p62
模块系统不只是加载依赖的机制，更是**定义 API 的工具**。
和所有 API 设计一样，核心是平衡**私有逻辑与公开接口**：
尽量做到信息隐藏、API 易用，同时兼顾可扩展性与复用性。

本节介绍几种最常用的 CommonJS 模块定义模式：
命名导出、导出函数、导出类/实例、猴子补丁等，它们在封装性、扩展性上各有侧重。

---

## 命名导出（Named exports）
最基础的公开 API 方式，就是给 `exports` 添加属性，把一组相关功能放在同一个导出对象里，形成一个**命名空间**。

示例：`logger.js`
```javascript
exports.info = (message) => {
  console.log(`info: ${message}`)
}

exports.verbose = (message) => {
  console.log(`verbose: ${message}`)
}
```

使用：
```javascript
const logger = require('./logger')
logger.info('This is an informational message')
logger.verbose('This is a verbose message')
```

特点：
- 导出多个公开方法，结构清晰
- Node.js 内置核心模块大量使用这种模式
- **真正完全符合 CommonJS 规范**的唯一模式
- `module.exports` 是 Node 扩展，用来支持更灵活的导出方式
