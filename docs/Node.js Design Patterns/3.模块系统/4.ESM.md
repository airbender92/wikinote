# ESM：ECMAScript 标准模块
## 一、ESM 基础定位
ESM 是 ES2015（ES6）正式推出的 JavaScript 官方标准模块体系，设计目标是一套同时兼容**浏览器、Node.js**跨运行环境的统一模块规范，吸收了 CommonJS、AMD 两套旧模块体系的优势，同时支持循环依赖、异步加载模块。

## 二、ESM 核心关键特性：静态导入（与 CommonJS 最大区别）
ESM 的 `import / export` 属于**静态语法**，有两条硬性规则：
1. 所有导入/导出语句必须写在模块**顶层作用域**，不能嵌套在 `if/for/函数` 等任何流程控制代码内部；
2. 导入路径只能是固定字符串字面量，不允许通过变量、表达式动态拼接生成模块路径。

### 非法 ESM 示例（运行直接报错）
```js
if (condition) {
  import module1 from 'module1'
} else {
  import module2 from 'module2'
}
```

### 同等逻辑 CommonJS 合法写法（动态加载）
```js
let module = null
if (condition) {
  module = require('module1')
} else {
  module = require('module2')
}
```

## 三、静态语法带来的核心优势
静态限制看似是约束，实则带来大量 CommonJS 无法实现的工程优化：
1. **Tree Shaking（死代码消除）**
打包工具可在编译阶段静态扫描依赖图，识别未被导入的函数、变量，直接删除冗余代码，大幅减小产物体积；CommonJS 动态 `require` 无法静态分析，不支持完整 Tree Shaking。
2. 编译期校验依赖：导入路径、导出名称错误可在打包/启动时提前捕获，而非运行时才暴露问题。
3. 支持类型检测、IDE 自动导入、重构等静态工具能力。

## 补充：动态导入方案
若运行时按需加载模块（如根据语言、路由动态引入资源），ESM 提供专用动态语法 `import()` 函数，返回 Promise，弥补静态导入的局限性。

## 补充猴子补丁实战案例
文中举例 `nock` 库是猴子补丁典型应用：通过篡改 Node 内置 `http` 模块，拦截真实 HTTP 请求，返回模拟数据，单元测试时无需调用真实线上接口，仅适测试场景。

# 在 Node.js 中使用 ESM
## 基础规则
Node.js 默认把所有 `.js` 文件识别为 **CommonJS** 模块。如果直接在普通 `.js` 文件里写 `import/export`，程序会直接抛出语法错误。

想要让 Node 将文件解析为 ESM，有两种主流方式：
1. **文件后缀使用 `.mjs`**
单个文件单独启用 ESM，仅当前 `.mjs` 文件遵循 ES 模块规范，同目录下 `.js` 依旧是 CommonJS。
2. **在最近的 `package.json` 添加 `"type": "module"`**
该目录下所有 `.js`、`.mjs` 文件都会被视作 ESM；若目录下存在 `.cjs` 文件，则仍按 CommonJS 解析。

## 示例配置
### 方式1：文件后缀区分
```
# ESM 文件
utils.mjs
# CommonJS 文件
app.js
```

### 方式2：全局配置 package.json
```json
{
  "type": "module"
}
```
配置后目录内所有 `.js` 自动启用 ESM。

下文将讲解 ESM 的标准语法。

# ESM 具名导出与具名导入（Named exports / imports）
## 前置说明
本书后续代码统一使用 `.js` 后缀，如需 Node 识别为 ESM，必须在项目根目录新建 `package.json`，写入 `"type": "module"`。
关键区分：ESM 关键字是单数 `export`；CommonJS 是复数 `exports / module.exports`。
ESM 内所有变量、函数、类默认私有，只有通过 `export` 导出的内容才能被外部访问。

## 一、具名导出写法（logger.js）
直接在变量/函数/类前添加 `export` 关键字完成导出：
```javascript
// 导出名为 log 的函数
export function log (message) {
  console.log(message)
}

// 导出常量 DEFAULT_LEVEL
export const DEFAULT_LEVEL = 'info'

// 导出配置对象 LEVELS
export const LEVELS = {
  error: 0,
  debug: 1,
  warn: 2,
  data: 3,
  info: 4,
  verbose: 5
}

// 导出 Logger 类
export class Logger {
  constructor (name) {
    this.name = name
  }
  log (message) {
    console.log(`[${this.name}] ${message}`)
  }
}
```

## 二、多种导入语法
### 1. 命名空间导入（一次性导入全部）
用 `import * as 别名` 接收模块所有导出项：
```javascript
import * as loggerModule from './logger.js'
console.log(loggerModule.log)
console.log(loggerModule.Logger)
```
打印结果：
```
[Module] {
  DEFAULT_LEVEL: 'info',
  LEVELS: { error: 0, debug: 1, warn: 2, data: 3, info: 4, verbose: 5 },
  Logger: [Function: Logger],
  log: [Function: log]
}
```

### 2. 按需单项/多项导入
只导入需要的指定成员：
```javascript
// 导入单个方法
import { log } from './logger.js'
log('Hello World')

// 同时导入多个成员
import { log, Logger } from './logger.js'
log('Hello World')
const logger = new Logger('DEFAULT')
logger.log('Hello world')
```

### 3. 导入重命名（解决命名冲突 as）
导入的名称和当前作用域变量重名时报错，可用 `as` 给导入项改名：
```javascript
// 报错：重复声明
import { log } from './logger.js'
const log = console.log

// 正确写法，重命名导入的 log
import { log as log2 } from './logger.js'
const log = console.log
log('原生打印')
log2('模块日志')
```

## 三、ESM 路径硬性规则（和 CommonJS 重大区别）
ESM 导入路径**必须补全完整文件后缀**：
- 合法 ESM：`import { log } from './logger.js'`
- 非法 ESM：`import { log } from './logger'`

CommonJS 无强制要求，`require('./logger')` / `require('./logger.js')` 均可自动匹配。

# ESM 默认导出与默认导入（Default exports / imports
## 1. 设计背景
CommonJS 支持 `module.exports = xxx` 导出单一核心值，贴合单一职责原则；ESM 提供 **`export default` 默认导出** 实现同等能力。

## 2. 默认导出语法示例（logger.js）
```javascript
// 默认导出类，内部名称 Logger 会被忽略
export default class Logger {
  constructor (name) {
    this.name = name
  }
  log (message) {
    console.log(`[${this.name}] ${message}`)
  }
}
```
底层逻辑：导出内容会自动挂载到模块内置的 `default` 属性上。

## 3. 默认导入语法（main.js）
导入默认导出时**无需大括号**，可自定义本地变量名：
```javascript
// 自定义名称 MyLogger，任意合法变量名都可以
import MyLogger from './logger.js'
const logger = new MyLogger('info')
logger.log('Hello World')
```
对比具名导入：不用 `{}`、不需要 `as` 关键字重命名。

## 4. 默认导出底层本质
默认导出等价于一个名为 `default` 的特殊具名导出。
验证代码：
```javascript
import * as loggerModule from './logger.js'
console.log(loggerModule)
```
输出结果：
```
[Module] { default: [Function: Logger] }
```

## 5. 语法限制
不能直接用解构 `{ default }` 导入，`default` 是 JS 保留字，会报语法错误：
```javascript
// 非法代码，直接报错 SyntaxError
import { default } from './logger.js'
```
合法访问方式：只能通过命名空间对象读取 `loggerModule.default`。

# ESM 混合导出（默认导出 + 具名导出）
## 一、混合导出写法
一个 ESM 文件可同时存在**默认导出**和多个**具名导出**，模块内部可互相调用导出内容。
### 示例 logger.js
```javascript
// 默认导出主日志函数
export default function log (message) {
  console.log(message)
}
// 具名导出 info 辅助方法
export function info (message) {
  log(`info: ${message}`)
}
```
> 注意：模块内部不能直接写 `default()` 调用默认导出，会报语法错误。

## 二、混合导入语法
默认导入写在最前面，逗号分隔，后面大括号承载具名导入：
```javascript
// mylog 接收默认导出，同时导入具名函数 info
import mylog, { info } from './logger.js'
mylog('普通日志')
info('提示日志')
```

## 三、默认导出 vs 具名导出 优缺点对比
### 1. 具名导出优势
- 名称固定统一，IDE 自动补全、一键重构、自动导入功能完美支持；
- 利于 Tree Shaking（死代码消除），未使用的导出项打包时可直接剔除；
- 多人协作接口规范清晰。

### 2. 默认导出优势
- 突出模块**唯一核心功能**，使用者无需记忆导出名称，可自定义导入变量名；
- 贴合 Substack 单一职责模块设计思想。

### 3. 默认导出短板
若默认导出是一个大对象，内部挂载大量方法，打包工具会判定整个对象被使用，**无法做 Tree Shaking**，冗余代码无法删除。

## 四、最佳实践建议
1. 模块对外暴露多个功能时，**优先使用纯具名导出**；
2. 模块只有一个核心功能、无其他附属 API 时，使用默认导出；
3. 允许混合导出，Node 内置核心模块、React 等知名库均采用该方案，可根据使用场景灵活选择。

# 模块标识符（Module identifiers / 模块说明符）
模块标识符是写在导入语句里、用于指定目标模块位置的标识，前面只讲过相对路径，完整分为四类，同时区分 ESM 与 CommonJS、浏览器/Node 差异：

## 1. 相对说明符（Relative specifiers）
格式：`./logger.js`、`../utils/logger.js`
作用：以当前导入文件所在目录为基准，定位文件。
要求：ESM 中**必须补全完整文件后缀**。

## 2. 绝对说明符（Absolute specifiers）
格式：`file:///opt/nodejs/config.js`
关键区别（ESM vs CommonJS）：
- ESM 只能使用 `file://` 文件协议 URL 代表绝对路径；直接用 `/`、`//` 开头会报错；
- CommonJS 支持直接写 `/xxx` 作为系统绝对路径，二者语法差异很大。

## 3. 裸说明符（Bare specifiers）
格式：`fastify`、`http`
两类来源：
1. Node.js 内置核心模块（http、fs、path 等）
2. npm/yarn 安装在 `node_modules` 根目录的第三方包

## 4. 深层导入说明符（Deep import specifiers）
格式：`fastify/lib/logger.js`
含义：导入 `node_modules` 中某个包内部的子文件，而非包入口。

## 补充：浏览器特有导入方式
浏览器 ESM 支持直接传入完整网络 URL 导入远程模块：
```js
import _ from "https://unpkg.com/lodash";
```
**Node.js 不支持这种网络 URL 导入方式。**

## 核心小结
1. Node ESM 绝对路径必须用 `file://` URL，不能直接 `/`；
2. 裸标识符对应核心模块 / node_modules 根包；
3. 深层标识符访问包内部子文件；
4. 远程 URL 导入仅浏览器可用，Node 无此能力。

# 异步动态导入（Async / Dynamic Imports）
## 一、静态 import 的两大限制
普通顶层 `import` 属于**静态语法**，存在硬性约束：
1. 模块路径标识符不能在运行时拼接、动态生成；
2. `import` 只能写在文件顶层，不能嵌套在 `if`、循环、函数等流程代码内部。

## 二、动态导入的适用场景
静态语法约束过强时，可用动态导入解决，典型场景：
1. 根据运行条件加载对应模块（如按用户语言、操作系统加载对应翻译/适配文件）；
2. 懒加载大型模块，只有用户触发对应功能时才加载，减少启动开销。

## 三、`import()` 语法说明
ESM 提供专用 `import(模块标识符)` 动态导入运算符：
- 写法形似函数，但属于语法关键字，并非普通函数；
- 参数支持所有合法模块标识符（相对路径、裸包、深层路径等）；
- 返回 `Promise` 对象，成功后 resolve 该模块的完整命名空间对象。

## 四、实战示例：多语言翻译工具
### 各语言翻译模块
```js
// strings-el.js
export const HELLO = 'Γεια σου κόσμε'

// strings-en.js
export const HELLO = 'Hello World'

// strings-es.js
export const HELLO = 'Hola mundo'

// strings-it.js
export const HELLO = 'Ciao mondo'

// strings-pl.js
export const HELLO = 'Witaj świecie'
```

### 主程序 main.js（需配置 `"type":"module"`）
```js
// 1. 定义支持语言列表
const SUPPORTED_LANGUAGES = ['el', 'en', 'es', 'it', 'pl']
// 2. 读取命令行传入语言标识
const selectedLanguage = process.argv[2]

// 3. 校验语言合法性
if (!SUPPORTED_LANGUAGES.includes(selectedLanguage)) {
  console.error('The specified language is not supported')
  process.exit(1)
}

// 4. 运行时拼接模块相对路径
const translationModule = `./strings-${selectedLanguage}.js`

// 5. 动态导入，返回 Promise
import(translationModule).then((strings) => {
  // 6. 模块加载完成后访问导出变量
  console.log(strings.HELLO)
})
```

### 运行命令
```bash
node main.js it
# 输出：Ciao mondo
```

## 执行流程拆解
1. 预设全部支持的语言编码；
2. 从命令行参数获取用户指定语言；
3. 校验语言是否在支持列表，不合法直接退出；
4. 动态拼接目标模块的相对路径；
5. 调用 `import(路径)` 发起异步加载；
6. Promise 的 `.then` 回调拿到模块命名空间，读取导出的 `HELLO` 打印。

## 补充说明
后文第5章会详细讲解 Promise 与 `async/await`，动态导入也可搭配 `await` 简化写法：
```js
const strings = await import(translationModule)
console.log(strings.HELLO)
```
