# Template 模板模式
模板模式 = **用继承定义算法骨架**，固定流程，子类只填具体步骤。

## 核心思想
1. 父类（模板）定义**完整流程骨架**
2. 某些步骤留空（或抛错），让**子类去实现**
3. 一套流程，多种变体，复用公共逻辑

## 和策略模式的关键区别（书中重点）
- **Strategy 策略模式**
  - 组合 / 注入
  - **运行时动态切换**算法
- **Template 模板模式**
  - 继承
  - **编译/定义时就确定**变体
  - 更“传统 OOP”

一句话记：
**策略是换插件，模板是继承改步骤。**

## JS 里的实现方式
JS 没有抽象类，所以模板方法通常：
- 要么留空
- 要么默认抛出 `必须被子类实现` 的错误

## 典型场景
- 数据导入器：读取 → 解析 → 校验 → 保存
- 报表生成器：取数 → 计算 → 格式化 → 导出
- 网络请求：建立连接 → 发数据 → 处理响应 → 关闭

整体结构非常简单，我可以直接按书里给你写一个**可运行的极简示例**，一眼看懂。

# 模板模式实战：配置管理器（与策略模式对照版）
同样是实现**多格式配置读写**，这次用**继承**来固定流程，子类只填序列化细节。

## 1. 模板父类：ConfigTemplate
定义完整流程骨架，`_serialize`、`_deserialize` 作为**模板方法**留给子类实现。
```js
import { promises as fsPromises } from 'fs'
import objectPath from 'object-path'

export class ConfigTemplate {
  async load(file) {
    console.log(`Deserializing from ${file}`)
    this.data = this._deserialize(await fsPromises.readFile(file, 'utf-8'))
  }

  async save(file) {
    console.log(`Serializing to ${file}`)
    await fsPromises.writeFile(file, this._serialize(this.data))
  }

  get(path) {
    return objectPath.get(this.data, path)
  }

  set(path, value) {
    return objectPath.set(this.data, path, value)
  }

  // 模板方法（抽象方法）
  _serialize() {
    throw new Error('_serialize() must be implemented')
  }

  _deserialize() {
    throw new Error('_deserialize() must be implemented')
  }
}
```

## 2. JSON 格式子类
```js
import { ConfigTemplate } from './configTemplate.js'

export class JsonConfig extends ConfigTemplate {
  _deserialize(data) {
    return JSON.parse(data)
  }

  _serialize(data) {
    return JSON.stringify(data, null, ' ')
  }
}
```

## 3. INI 格式子类
```js
import { ConfigTemplate } from './configTemplate.js'
import ini from 'ini'

export class IniConfig extends ConfigTemplate {
  _deserialize(data) {
    return ini.parse(data)
  }

  _serialize(data) {
    return ini.stringify(data)
  }
}
```

## 4. 使用方式
```js
import { JsonConfig } from './jsonConfig.js'
import { IniConfig } from './iniConfig.js'

async function main() {
  const jsonConfig = new JsonConfig()
  await jsonConfig.load('samples/conf.json')
  jsonConfig.set('nodejs', 'design patterns')
  await jsonConfig.save('samples/conf_mod.json')

  const iniConfig = new IniConfig()
  await iniConfig.load('samples/conf.ini')
  iniConfig.set('nodejs', 'design patterns')
  await iniConfig.save('samples/conf_mod.ini')
}

main()
```

# 核心对比：Template vs Strategy（书中最重要的区别）
|  | **Template 模板模式** | **Strategy 策略模式** |
|------------------|------------------------|------------------------|
| **实现方式** | **继承** | **组合 / 注入** |
| **绑定时机** | **定义类时就确定** | **运行时可动态切换** |
| **灵活性** | 静态，一类一种格式 | 动态，一个实例可换策略 |
| **代码结构** | 子类扩展父类 | 上下文 + 独立策略对象 |
| **OOP 风格** | 传统经典面向对象 | 更灵活、更 JS 风格 |

## 一句话总结
- **Strategy**：同一个 `Config` 实例，想 JSON 就 JSON，想 INI 就 INI，随时换。
- **Template**：`JsonConfig`、`IniConfig` 是**两个不同的类**，实例化后不能改格式。

> 模板模式 = 流程固化，通过继承做变体
> 策略模式 = 流程不变，通过插件换算法

# 模板模式真实应用：Node.js Stream
你其实**早就用过模板模式了**——就在第6章自定义流的时候。

## 核心对应关系
- **Stream 基类（Readable / Writable / Transform）**
  = **模板父类**
  定义了整套数据流流程：缓冲、背压、事件分发等。

- **`_read()` / `_write()` / `_transform()` / `_flush()`**
  = **模板方法**
  你必须实现，否则抛错。

- **你写的自定义流子类**
  = **具体模板实现**

## 典型例子
```js
class MyReadable extends Readable {
  // 模板方法 —— 必须实现
  _read(size) {
    // ...
  }
}
```

这完全就是模板模式的标准用法：
**父类定骨架，子类填步骤。**
