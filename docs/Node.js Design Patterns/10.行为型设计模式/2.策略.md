# Strategy 策略模式

## 核心思想
将**可变的逻辑/算法**抽成独立、可互换的**策略（Strategy）**，
让**上下文（Context）**可以在运行时切换策略，而不用改自身代码。

- **Context**：保留通用逻辑，持有策略实例
- **Strategy**：实现某一种具体算法/行为
- 所有策略实现**同一接口**，可随意插拔

## 生活类比
汽车换轮胎：
- 车（Context）不变
- 雪地胎、公路胎、运动胎（不同 Strategy）
- 根据路况切换，不用换车

## 解决的典型问题
- 大量 `if / else` 或 `switch` 选择不同算法
- 一个类里混杂多种业务逻辑（支付方式、压缩算法、排序规则等）
- 需要运行时动态切换行为
- 希望算法可独立扩展、测试、复用

## 书中典型场景：订单支付
- `Order`（上下文）负责商品、价格、用户信息
- `pay()` 行为委托给**支付策略**
- 支付宝、微信、信用卡、PayPal 都是独立策略
- 新增支付方式只需加新策略，不用改 Order

## 一句话记忆
**策略模式 = 算法插拔式替换，消除分支判断，行为动态可变。**

# 策略模式实战：多格式配置文件解析（书中完整案例梳理）
## 案例概述
构建通用配置管理器 `Config`（上下文 Context），**加载/保存的序列化、反序列化逻辑是可变部分**，抽离为策略。
- JSON、INI 是两套独立、可互换的序列化策略；
- `Config` 只负责通用逻辑（get/set、文件读写），**不需要修改自身代码，就能新增配置文件格式**。

## 模块代码整理
### 1. config.js（上下文 Context）
```js
import { promises as fs } from 'fs'
import objectPath from 'object-path'

export class Config {
  constructor(formatStrategy) {
    this.data = {}
    // 注入策略对象
    this.formatStrategy = formatStrategy
  }

  // 按路径读取配置，支持 "database.url" 这类写法
  get(configPath) {
    return objectPath.get(this.data, configPath)
  }

  set(configPath, value) {
    return objectPath.set(this.data, configPath, value)
  }

  // 加载文件：委托策略做反序列化
  async load(filePath) {
    console.log(`Deserializing from ${filePath}`)
    const rawText = await fs.readFile(filePath, 'utf-8')
    this.data = this.formatStrategy.deserialize(rawText)
  }

  // 保存文件：委托策略做序列化
  async save(filePath) {
    console.log(`Serializing to ${filePath}`)
    const text = this.formatStrategy.serialize(this.data)
    await fs.writeFile(filePath, text)
  }
}
```

### 2. strategies.js（策略集合，统一接口）
所有策略必须实现：`deserialize(text)`、`serialize(object)`
```js
import ini from 'ini'

// INI格式策略
export const iniStrategy = {
  deserialize: data => ini.parse(data),
  serialize: data => ini.stringify(data)
}

// JSON格式策略
export const jsonStrategy = {
  deserialize: data => JSON.parse(data),
  serialize: data => JSON.stringify(data, null, ' ')
}
```

### 3. index.js 使用入口
```js
import { Config } from './config.js'
import { jsonStrategy, iniStrategy } from './strategies.js'

async function main() {
  // 使用 INI 策略
  const iniConfig = new Config(iniStrategy)
  await iniConfig.load('samples/conf.ini')
  iniConfig.set('book.nodejs', 'design patterns')
  await iniConfig.save('samples/conf_mod.ini')

  // 使用 JSON 策略，同一套 Config 类无缝切换
  const jsonConfig = new Config(jsonStrategy)
  await jsonConfig.load('samples/conf.json')
  jsonConfig.set('book.nodejs', 'design patterns')
  await jsonConfig.save('samples/conf_mod.json')
}

main()
```

## 核心设计要点
1. **开闭原则**
新增 YAML、TOML 配置格式，只需要新增策略对象，**不用修改 Config 类源码**。
2. **消除大量 if/else**
不用在 load/save 内部写判断后缀选择解析器；
可以扩展：根据文件后缀自动匹配策略映射表，运行时自动选择。
3. **策略完全可独立测试**
序列化逻辑抽离，单元测试只需要单独验证 `iniStrategy` / `jsonStrategy`。

## 书中重点辨析：策略模式 VS 适配器模式（极易混淆）
| 维度 | Strategy 策略模式 | Adapter 适配器模式 |
|------|------------------|-------------------|
| 分类 | **行为型模式** | **结构型模式** |
| 核心意图 | **同一业务目标，多种可互换算法** | **接口转换，让两个不兼容对象互通** |
| 对象关系 | 上下文 + 多套等价方案，运行时切换 | 包装已有对象，翻译接口 |
| 功能变化 | 实现逻辑完全不同（JSON/INI两套解析） | 底层功能不变，只是调用方式翻译 |

> 一句话区分：
策略 = **换一套算法干活**；适配器 = **翻译接口，复用已有功能**。

## JS 特色扩展
在 JavaScript 中函数是一等公民，策略甚至可以直接用普通函数实现，不需要强制封装对象：
```js
// 极简函数式策略
function configContext(serializeFn, deserializeFn) {
  // ...
}
```

## 可拓展优化思路（书中提及）
1. 支持**读用A格式、存用B格式**，分离序列化/反序列化两套策略；
2. 构建 `后缀→策略` 映射，自动根据文件名选择策略；
3. 增加缓存、校验、错误处理包装到策略层。

# 策略模式真实应用：Passport 认证框架
Passport 是 Node.js 最主流的登录认证库，**完全基于策略模式设计**。

## 核心思路
- **通用逻辑（Context）**：登录流程、会话管理、验证入口
- **可变逻辑（Strategy）**：不同登录方式的具体实现
  - 本地账号密码（LocalStrategy）
  - GitHub / Google / 微博 / 微信 OAuth
  - 短信验证码、LDAP 等

## 为什么是典型策略模式？
- 统一认证接口：`authenticate()`
- 底层实现完全可插拔、可替换
- 新增一种登录方式 = 新增一个策略
- 核心框架完全不用改
- 支持同时挂载多种策略

## 一句话总结
**Passport = 策略模式在 Node.js 生态最成功的工业级案例。**
它证明了：用策略模式可以让一个核心库，支持几乎无限种扩展方案。
