# Command 命令模式
命令模式的核心一句话：
**把“要做什么”封装成一个对象，包含执行所需的全部信息，以便延迟执行、排队、记录、撤销、网络传输或组合成事务。**

不再直接调用函数，而是创建一个**意图对象**，交给调用器去执行。

---

## 经典四角色
- **Command**：封装动作、目标、参数
- **Client**：创建命令
- **Invoker**：调用器，负责执行命令
- **Receiver / Target**：最终真正执行操作的对象/函数

## 命令模式的核心价值（尤其在 Node.js 中）
- 延迟执行、异步调度
- 可序列化 → 网络传输、RPC、任务分发
- 记录操作历史 → 审计、回溯
- 支持 **撤销/重做（undo/redo）**
- 可取消未执行的任务
- 可组合成**原子事务**
- 支持操作转换（OT）→ 多人协作编辑底层基础

在 Node.js 里，命令模式无处不在：
任务队列、RPC、CLI 命令、事件回放、状态同步、协作编辑……

---

接下来会讲两种典型实现：
1. **简单命令对象**（直接封装动作）
2. **可撤销命令**（带 undo 的状态操作）

需要我直接给你**极简可运行示例**，一眼看懂命令模式吗？

# Task 模式（命令模式最简版）
**Task 模式 = 用闭包 / bind 把“要执行的动作 + 参数”打包成一个函数**，这是 JavaScript 里最原生、最轻量的命令模式实现。

## 核心实现
```javascript
function createTask(target, ...args) {
  // 返回一个“待执行”的函数
  return () => target(...args)
}
```

或者直接用 `bind`：
```javascript
const task = target.bind(null, arg1, arg2)
```

## 它为什么是 Command 模式？
- 把**调用意图 + 参数**封装成一个对象（这里是函数）
- 可以**延迟执行**
- 可以**传递、存储、排队**
- 交给另一个组件（Invoker）去调度执行

本质就是：
**不直接调用，而是把“调用”本身变成一个可传递的任务。**

## 典型用法
```javascript
function print(msg) {
  console.log(msg)
}

// 创建任务（封装动作与参数）
const task = createTask(print, 'Hello Command Pattern')

// 稍后再执行
setTimeout(task, 1000)
```

---

# 一句话总结
**Task 模式 = 命令模式的极简形态
用闭包或 bind 封装“要做什么”，实现延迟、排队、调度。**

下一部分：**更完整的命令对象（带 type、payload、可序列化、可撤销）**，这是 RPC、任务队列、协作编辑的真实形态。

# 命令模式完整实现（支持撤销 / 序列化 / 远程执行）
这是**工业级命令模式**的经典示例，包含：执行、撤销、延迟、历史记录、远程 RPC 五大能力。

## 1. 接收者 Receiver（业务服务）
```js
// statusUpdateService.js
const statusUpdates = new Map()

export const statusUpdateService = {
  postUpdate(status) {
    const id = Math.floor(Math.random() * 1e6)
    statusUpdates.set(id, status)
    console.log(`Status posted: ${status}`)
    return id
  },

  destroyUpdate(id) {
    statusUpdates.delete(id)
    console.log(`Status removed: ${id}`)
  }
}
```

## 2. 命令 Command 对象（核心）
```js
// createPostStatusCmd.js
export function createPostStatusCmd(service, status) {
  let postId = null

  return {
    run() {
      postId = service.postUpdate(status)
    },

    undo() {
      if (postId) {
        service.destroyUpdate(postId)
        postId = null
      }
    },

    serialize() {
      return { type: 'status', action: 'post', status }
    }
  }
}
```

## 3. 调用者 Invoker（执行、调度、历史、远程）
```js
// invoker.js
import superagent from 'superagent'

export class Invoker {
  constructor() {
    this.history = []
  }

  // 立即执行
  run(cmd) {
    this.history.push(cmd)
    cmd.run()
    console.log('Command executed', cmd.serialize())
  }

  // 延迟执行
  delay(cmd, delayMs) {
    setTimeout(() => {
      console.log('Executing delayed command', cmd.serialize())
      this.run(cmd)
    }, delayMs)
  }

  // 撤销上一个
  undo() {
    const cmd = this.history.pop()
    cmd?.undo()
    console.log('Command undone', cmd?.serialize())
  }

  // 发送到远程执行（RPC）
  async runRemotely(cmd) {
    await superagent
      .post('http://localhost:3000/cmd')
      .send({ json: cmd.serialize() })

    console.log('Command executed remotely', cmd.serialize())
  }
}
```

## 4. 客户端 Client（使用方）
```js
// client.js
import { createPostStatusCmd } from './createPostStatusCmd.js'
import { statusUpdateService } from './statusUpdateService.js'
import { Invoker } from './invoker.js'

const invoker = new Invoker()
const cmd = createPostStatusCmd(statusUpdateService, 'HI!')

// 立即执行
invoker.run(cmd)

// 撤销
invoker.undo()

// 延迟3秒执行
invoker.delay(cmd, 3000)

// 发送到远程服务器执行
invoker.runRemotely(cmd)
```

# 命令模式带来的能力（关键）
通过把动作封装成对象，我们获得：
- **执行历史记录**
- **撤销/重做 undo/redo**
- **延迟执行**
- **异步调度**
- **序列化 → 网络传输 → RPC / 任务分发**
- **事务、批量、重试、优先级队列**
- **多人协作 OT 算法基础**

---

# 何时用哪种命令模式
- **只需要延迟/异步** → 用最简 Task 模式（闭包 / bind）
- **需要撤销、历史、远程、事务** → 用完整 Command 对象
- **简单直接调用** → 不要用，属于过度设计

---

**命令模式 = 把“方法调用”变成可存储、可传输、可撤销、可延迟的对象，
是实现异步调度、操作历史、RPC、协作编辑的核心架构基础。**
