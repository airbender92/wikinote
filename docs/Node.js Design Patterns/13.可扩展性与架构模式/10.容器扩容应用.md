# 使用容器扩容应用
## 原文翻译
本节将演示容器与容器编排平台（例如 Kubernetes）如何帮助我们编写更简洁的 Node.js 应用。**负载均衡、弹性扩缩容、高可用**这类扩容相关的复杂问题，都可以直接委托给底层容器平台处理。

容器与容器编排涉及的主题非常宽泛，超出本书讨论范围。因此这里仅提供基础示例，带你上手在 Node.js 场景使用这套技术。最终目的是鼓励你探索用于部署、扩容 Node.js 应用的现代新模式。

### 什么是容器
由开放容器倡议 OCI 标准化的 Linux 容器，官方定义：
> 容器是一套标准化软件单元，它把代码以及全部依赖打包，让应用可以跨计算环境快速、可靠地运行。

换句话说，使用容器，你可以在不同机器上无缝打包并运行应用：从本地开发笔记本，到云端生产服务器。

容器除了极强的可移植性，运行时的开销也极低，性能几乎等同于应用直接跑在操作系统原生环境中。

> 对前面我们写的客户端负载均衡封装，一个很直观的优化就是：在客户端集成服务注册中心，动态获取后端服务器列表。

简单理解：容器就是运行在 Linux 系统上、具备隔离能力进程的标准化软件单元。

对比虚拟机，容器凭借可移植性和高性能，是巨大的技术进步。

市面上有多种工具可以构建、运行符合 OCI 标准的容器，最流行的是 Docker。
你可以查阅官方文档，按照对应操作系统的指引安装 Docker。

## 核心知识点梳理
1. **容器编排平台（K8s）接管的能力**
Node.js 业务代码不再需要手写：
- 负载均衡
- 弹性水平扩缩容
- 高可用、故障重启
- 服务注册发现

业务本身只需要专注业务逻辑，把扩容基础设施问题交给平台。

2. **容器 vs 虚拟机**
|特性|容器|虚拟机|
|---|---|---|
|内核|共享宿主机Linux内核|拥有完整独立操作系统内核|
|资源开销|极小|大，每个VM完整操作系统|
|启动速度|秒级|分钟级|
|隔离级别|进程级隔离|硬件级强隔离|

3. **OCI（开放容器倡议）**
容器行业标准规范，保证不同工具构建的容器镜像可以跨运行时兼容；Docker 是最主流实现。

4. **承接上文的知识点回顾**
上一节手写的P2P负载均衡客户端的局限：服务器列表写死。书中提示优化方向：**接入服务注册中心动态拉取实例列表**。

5. **本书定位**
不深入讲解K8s完整细节，只做概念引入；重点：Node应用如何和现代容器架构结合。
