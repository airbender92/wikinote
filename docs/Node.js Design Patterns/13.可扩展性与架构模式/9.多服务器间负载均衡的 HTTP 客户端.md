# 实现一个可在多服务器间负载均衡的 HTTP 客户端
## 译文 + 要点梳理

我们已经知道如何用 Node.js 实现负载均衡器，把进来的请求分发到多台后端服务器。
那么在**客户端实现同样的机制**，原理其实差别不大。
只需要对客户端 API 做一层封装，加上负载均衡逻辑即可。

来看下面这个模块（balancedRequest.js）：

```javascript
import { request } from 'http'
import getStream from 'get-stream'

const servers = [
  { host: 'localhost', port: 8081 },
  { host: 'localhost', port: 8082 }
]

let i = 0

export function balancedRequest (options) {
  return new Promise((resolve) => {
    // 轮询选取下一台服务器
    i = (i + 1) % servers.length
    options.hostname = servers[i].host
    options.port = servers[i].port

    // 发起真实 HTTP 请求
    request(options, (response) => {
      resolve(getStream(response))
    }).end()
  })
}
```

这段代码非常简单：
我们封装了原生的 `http.request`，用**轮询（round-robin）**算法，从服务器列表里依次选取目标地址，覆盖请求的 hostname 和 port。
为了简洁，使用 `get-stream` 把响应流完整收集成一个缓冲区。

---

封装后的 API 可以无缝使用（client.js）：

```javascript
import { balancedRequest } from './balancedRequest.js'

async function main () {
  for (let i = 0; i < 10; i++) {
    const body = await balancedRequest({
      method: 'GET',
      path: '/'
    })
    console.log(`Request ${i} completed:`, body)
  }
}

main().catch(console.error)
```

运行前需要先启动两个服务实例：
```bash
node app.js 8081
node app.js 8082
```

然后运行客户端：
```bash
node client.js
```

你会看到**每个请求轮流发往不同的服务器**，这说明我们成功在**没有独立负载均衡器**的情况下实现了负载均衡！

---

### 核心要点
1. **模式：点对点负载均衡（P2P Load Balancing）**
   - 没有中间代理
   - 客户端自己维护服务器列表
   - 客户端自己实现负载均衡算法

2. **本示例使用的策略**
   - 静态服务器列表
   - 简单轮询（round-robin）

3. **可扩展方向**
   - 从 Consul / etcd 动态获取服务列表
   - 加入随机、权重、最少连接等策略
   - 增加健康检查，自动剔除宕机节点
   - 缓存、重试、熔断

4. **书中小知识**
   点对点负载均衡在 **ZeroMQ** 这类库中被大量使用，下一章我们会用到它。
