# What is Kubernetes?（什么是 Kubernetes）
## 翻译 + 核心要点

我们刚刚用容器跑起了一个 Node.js 应用，很棒！
但这还只是容器能力的冰山一角。容器真正的威力，体现在构建**复杂应用**时——比如由多个独立服务组成、需要跨多台云服务器部署和协调的系统。

这种场景下，只靠 Docker 远远不够。
我们需要一套更复杂的系统，来**编排**云集群里所有机器上运行的容器实例——我们需要一个**容器编排工具**。

---

### 小补充：给镜像打标签（tag）
构建镜像时可以用 `-t` 给镜像命名，方便识别，不用记哈希 ID：
```bash
docker build -t hello-web:v1 .
docker run -p 8080:8080 hello-web:v1
```
规范格式：`镜像名:版本号`

---

## 容器编排工具的核心职责
- 把多台云服务器（节点）组成一个**逻辑集群**，节点可动态增删，不影响服务可用性
- 保证**零停机**：容器挂了自动重启；节点宕机，自动把任务迁移到其他节点
- 内置**服务发现 + 负载均衡**
- 统一管理持久化存储
- 支持**零停机发布与回滚**
- 密钥管理、配置管理

---

## Kubernetes 简介
Kubernetes（简称 K8s）是目前最主流的容器编排系统，2014 年由 Google 开源。
名字来源于希腊语，意为**舵手、领航者、管理者**。
它沉淀了 Google 多年大规模云平台运行经验。

### 关键特点：声明式配置
你只需要定义**期望的最终状态**（比如：跑 3 个副本），
K8s 自动计算步骤，一步步达到目标，且不破坏集群稳定性。

### 核心概念：Kubernetes 对象
一切皆“对象”，代表集群里的一种“意图记录”：
- 容器化应用
- 资源分配（CPU、内存、存储、GPU 等）
- 运行策略（重启策略、升级策略、容错策略）

K8s 会持续监控，自动维持对象状态符合你的期望。

## 工具链
- `kubectl`：K8s 命令行管理工具
- `minikube`：本地快速搭建单节点 K8s 集群，用于开发测试

### 极简总结
- **Docker**：打包、运行单个容器
- **Kubernetes**：管理成千上万容器，自动扩容、自愈、负载均衡、滚动更新
- 对 Node.js 开发者意味着：**不用手写集群、负载均衡、服务发现**，平台全部接管
