# 使用 Nginx 实现负载均衡 译文 + 完整要点梳理

## 原文翻译

为了让你理解反向代理的工作方式，我们现在基于 Nginx 搭建一套可扩展架构。首先需要安装 Nginx，可以参考官方安装指南。

### 模式
使用**反向代理**，将应用负载均衡到运行在不同端口或不同机器上的多个实例。

因为我们不再使用 `cluster` 启动多个服务实例，所以需要稍微改造应用代码，让它可以**通过命令行参数指定监听端口**，这样就能在不同端口启动多个实例。

改造后的 `app.js`：
```javascript
import { createServer } from 'http'
const { pid } = process

const server = createServer((req, res) => {
  // 模拟CPU密集任务
  let i = 1e7; while (i > 0) { i-- }
  console.log(`Handling request from ${pid}`)
  res.end(`Hello from ${pid}\n`)
})

const port = Number.parseInt(
  process.env.PORT || process.argv[2]
) || 8080

server.listen(port, () => console.log(`Started at ${pid}`))
```

这个版本和最初版本的唯一区别是：端口号可以通过 **PORT 环境变量** 或 **命令行参数** 配置。
这是必须的，因为我们要在同一台机器上启动多个实例，让它们监听不同端口。

不使用 `cluster` 后，我们会失去一个重要特性：**进程崩溃自动重启**。
不过可以用专门的**进程守护工具**轻松解决，例如：
- Node 系：`forever`、`pm2`
- 系统级：`systemd`、`runit`
- 监控工具：`monit`、`supervisord`
- 容器编排：Kubernetes、Nomad、Docker Swarm

本示例使用最简单的 `forever`：
```bash
npm install forever -g
```

接下来启动 4 个应用实例，分别运行在不同端口，并由 `forever` 守护：
```bash
forever start app.js 8081
forever start app.js 8082
forever start app.js 8083
forever start app.js 8084
```

查看运行中的进程：
```bash
forever list
```

停止所有进程：
```bash
forever stopall
```

## 配置 Nginx 作为负载均衡器

在项目目录下创建 `nginx.conf`：

```nginx
daemon off;
error_log /dev/stderr info;

events {
  worker_connections 2048;
}

http {
  access_log /dev/stdout;

  upstream my-load-balanced-app {
    server 127.0.0.1:8081;
    server 127.0.0.1:8082;
    server 127.0.0.1:8083;
    server 127.0.0.1:8084;
  }

  server {
    listen 8080;

    location / {
      proxy_pass http://my-load-balanced-app;
    }
  }
}
```

配置说明：
1. **`daemon off`**：让 Nginx 以前台方式运行，方便用 Ctrl+C 关闭。
2. **`error_log` / `access_log`**：将日志输出到终端，方便调试。
3. **`events`**：配置 Nginx 连接管理，这里设置单个 worker 最大连接数 2048。
4. **`http`**
   - `upstream`：定义一组后端 Node 服务实例列表
   - `server`：Nginx 本身监听 8080 端口
   - `location /` + `proxy_pass`：将所有请求转发给 upstream 里的服务组

启动 Nginx：
```bash
nginx -c ${PWD}/nginx.conf
```

现在访问：
```
http://localhost:8080
```

每次刷新都会看到不同的 PID 返回，说明 Nginx 正在按**轮询策略**负载均衡到 4 个 Node 实例。
也可以用 `autocannon` 压测，性能和 `cluster` 版本接近，因为都是在单机利用多核。

## 扩展到多机器集群（生产思路）

把这套示例扩展到真正分布式环境，只需要：
1. 在多台服务器上部署 Node 应用（用 forever 或 cluster 启动多实例）
2. 在 Nginx 的 `upstream` 里填写这些服务器的真实 IP 和端口
3. 把 Nginx 暴露公网 IP + 域名
4. 所有流量统一访问 Nginx 地址

## 核心知识点总结

1. **cluster vs Nginx 负载均衡**
   - `cluster`：单机多进程，简单、内置、无需额外组件
   - `Nginx`：可跨机器、功能更强、支持 sticky session、SSL、缓存、限流等

2. **为什么要支持多端口**
   同一台机器上，同一个端口只能被一个进程绑定，所以多实例必须用不同端口。

3. **为什么需要进程守护（forever / pm2）**
   不用 cluster 后，Node 进程崩溃不会自动重启，必须靠外部工具托管。

4. **Nginx 负载均衡默认策略**
   - **轮询（round-robin）**：逐个分发请求
   - 可改为：`ip_hash`、`least_conn`、`least_time` 等

5. **生产常用架构**
   - 每台机器：`pm2 + cluster` 充分利用多核
   - 多台机器上层：Nginx / 云厂商 LB 做全局负载均衡
