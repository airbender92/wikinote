# 点对点负载均衡（Peer-to-Peer Load Balancing）
## 译文 + 核心要点

当需要把复杂内部网络暴露到公网（如互联网）时，**反向代理几乎是必需的**。它能屏蔽内部架构复杂度，提供统一入口。
但如果只是扩容**内部服务**，我们可以拥有更大的灵活性与控制力。

假设：
- 服务 A 依赖服务 B 完成功能
- 服务 B 部署在多台机器上，只在内网可见

按之前学到的模式：
服务 A 通过**集中式负载均衡器**访问服务 B，由 LB 分发流量到多个服务 B 实例。

但还有另一种方案：
**去掉中间的负载均衡器，直接由客户端（服务 A）自己实现负载均衡**，把请求分发给不同的服务 B 实例。
这要求服务 A 知道服务 B 所有实例的地址，而在内网环境下这通常是可以做到的。

这种架构就是**点对点负载均衡（P2P Load Balancing）**。

---

## 集中式 LB vs P2P 负载均衡（图 12.8 对比）
- **集中式**：客户端 → LB → 服务实例
- **P2P**：客户端直接 → 多个服务实例（客户端自己做负载均衡）

---

## P2P 负载均衡的优点
- 减少网络节点，**降低架构复杂度**
- 减少一次转发，**通信更快**
- 性能不再受单个负载均衡器上限限制，**扩展性更好**
- 没有单点故障

## 缺点
- 暴露了后端服务的拓扑复杂度
- 客户端需要更“智能”：
  - 内置负载均衡算法
  - 维护服务实例列表
  - 感知节点上下线（健康检查、动态更新）

---

## 一句话总结
**P2P 负载均衡 = 客户端直连多个服务实例，自己做负载均衡，不经过中心化代理。**
