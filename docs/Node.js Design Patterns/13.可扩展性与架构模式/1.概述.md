# 《可扩展性与架构模式》章节导读 精简翻译+核心要点
## 原文翻译
Node.js 最初只是一个用C++和JavaScript编写的非阻塞Web服务器，名为web.js。创始人Ryan Dahl很快发掘了它的潜力，不断扩展能力，让开发者能够基于JavaScript与非阻塞范式搭建各类后端应用。

Node.js 的特性天生适配分布式系统，不管是少量节点，还是上万台机器通过网络互通的大规模集群，它都能胜任——Node.js 生来就是为分布式场景设计。

和其他Web开发平台不同，Node.js 开发过程中会早早接触**可扩展性**相关问题，根源在于它的单线程模型无法自动利用多核服务器全部算力，但这只是表层原因，背后还有更深层的设计逻辑需要我们理解。

本章我们会讲到：应用扩容不只是提升吞吐量、处理更多请求，它同时是实现**高可用、故障容错**的核心手段；除此之外，扩容思路还能用于拆分复杂业务，把巨型应用拆解为易维护的模块。
行业中常用**扩容立方体（Scale Cube）** 从六个维度定义可扩展性，完整覆盖扩容的各类场景。

### 本章学习清单
1. 为什么Node.js开发必须重视可扩展性
2. 扩容立方体（Scale Cube）的概念与实际价值
3. 多实例部署实现水平扩容
4. 负载均衡的使用方案
5. 服务注册中心的作用与落地方式
6. 基于Docker、K8s等容器编排平台部署扩容Node应用
7. 单体应用拆分为微服务架构的设计思路
8. 多服务集成通用架构模式

## 核心前置知识点
1. **单线程短板**：Node主线程仅占用单个CPU核心，单实例天然无法榨干多核机器，多实例/多进程/线程是基础扩容手段；
2. 扩容三层价值：提升并发承载量、实现故障隔离高可用、拆分复杂业务降低维护成本；
3. 核心模型：Scale Cube（X/Y/Z三轴扩容法）是本章核心理论，贯穿多实例、微服务、数据分片所有方案；
4. 技术栈递进：单机多进程(cluster) → 反向代理负载均衡(Nginx) → 服务注册中心 → 容器K8s → 微服务拆分。
