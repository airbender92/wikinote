# 使用 Docker 创建并运行容器
## 原文翻译 + 完整代码 + 核心知识点

### 改造后的 Web 服务 app.js
```javascript
import { createServer } from 'http'
import { hostname } from 'os'
const version = 1
const server = createServer((req, res) => {
  let i = 1e7; while (i > 0) { i-- }
  res.end(`Hello from ${hostname()} (v${version})`)
})
server.listen(8080)
```
> 改动点：返回**容器主机名**和应用版本号；本地直接运行会返回你电脑主机名。

### package.json
```json
{
  "name": "my-simple-app",
  "version": "1.0.0",
  "main": "app.js",
  "type": "module",
  "scripts": {
    "start": "node app.js"
  }
}
```

把 Node 应用容器化分为两大步骤：
1. **构建容器镜像（image）**：打包代码、依赖、运行环境，符合 OCI 标准
2. **基于镜像运行容器实例（container）**

> Dockerfile：镜像构建脚本，告诉 Docker 如何制作镜像。

#### Dockerfile
```dockerfile
FROM node:14-alpine
EXPOSE 8080
COPY app.js package.json /app/
WORKDIR /app
CMD ["npm", "start"]
```

**逐条解析指令**
1. `FROM node:14-alpine`：指定基础镜像，内置 Node.js14；alpine 是轻量 Linux 发行版，镜像体积小。
2. `EXPOSE 8080`：**仅做文档声明**，告知使用者应用会监听8080，**不会自动完成端口映射**，端口映射在`docker run`时配置。
3. `COPY app.js package.json /app/`：将本地两个文件复制到容器内`/app`目录；容器与宿主机文件系统互相隔离，必须复制代码进镜像。
4. `WORKDIR /app`：设置容器内的工作目录，等价于`cd /app`，后续命令都在此目录执行。
5. `CMD ["npm", "start"]`：容器启动时执行的默认命令，执行`npm start`，进而运行`node app.js`；node、npm 全部来自基础镜像。

### 构建镜像
```bash
docker build .
```
- `.`代表**构建上下文**（当前目录），Docker 会读取当前目录的 Dockerfile。
- 构建成功输出镜像哈希 ID，例如 `bb3bd34bac55`，后续用该 ID 启动容器。

### 运行容器实例
```bash
docker run -it -p 8080:8080 bb3bd34bac55
```
参数说明：
- `-it`：交互式终端，容器前台运行，日志直接打印终端，`Ctrl+C`停止容器。
- `-p 8080:8080`：端口映射，`宿主机端口:容器内部端口`，把本机8080流量转发给容器8080端口。

访问：`curl localhost:8080`
返回示例：`Hello from f2ffa85c8ff8 (v1)`
> hostname 是一串随机字符串，不是本机电脑名字，证明进程运行在容器沙箱隔离环境中。

## 核心知识点
1. **镜像 vs 容器**
   - **镜像 image**：静态包（代码、依赖、环境），只读模板。
   - **容器 container**：镜像运行起来的实例，可读写、独立隔离进程。

2. **EXPOSE 的常见误区**
   只做文档提示，**不会自动对外暴露端口**；端口映射必须在`docker run`使用`‑p`参数。

3. **容器隔离性**
   容器有独立主机名、网络、文件系统，默认不能访问宿主机资源。

4. **第12章上下文承接**
把 Node 应用打包成镜像之后，就可以交给 Kubernetes 这类编排平台：
- 平台自动多实例副本（X轴克隆扩容）
- 内置负载均衡、健康检查、故障重启、弹性伸缩
- 业务代码不需要手写 cluster、Consul 服务注册、自定义LB，平台接管大部分可扩展性工作。
