# Proxy（代理模式）
代理模式的核心：**创建一个代理对象，控制对另一个对象（真实主体 subject）的访问**。

代理和被代理对象拥有**完全相同的接口**，客户端可以无缝替换使用，因此也叫**替身模式（surrogate）**。

## 核心特点
- 代理与主体接口一致 → 对调用方透明
- 代理拦截对主体的操作，可以在**前后加逻辑**
- 不修改原对象，符合开闭原则

## 典型使用场景
- **数据校验**：转发前校验入参
- **权限控制**：检查是否有权限执行操作
- **缓存**：请求先查缓存，没有再访问主体
- **懒初始化**：主体创建开销大，延迟到真正使用时再创建
- **日志记录**：自动记录方法调用与参数
- **远程对象代理**：把远程对象伪装成本地对象

## 关键要点
代理模式**不是类与类之间的代理**，
而是**对一个实际对象实例进行包装拦截**。

在 JS/Node.js 中，这个模式有原生语法支持：
**`new Proxy(target, handler)`**

接下来我可以给你一个**可直接运行的 Proxy 示例**，比如：
- 带校验的代理
- 带缓存的代理
- 日志代理

# 代理模式的实现技巧
下面以 `StackCalculator`（栈式计算器）为例，学习如何用代理**拦截方法、增强行为、不改动原类**。

我们的目标：
给除法增加**除零保护**，遇到除以 0 时抛出错误，而不是返回 `Infinity`。

## 基础类：StackCalculator
```js
class StackCalculator {
  constructor() {
    this.stack = []
  }

  putValue(value) {
    this.stack.push(value)
  }

  getValue() {
    return this.stack.pop()
  }

  peekValue() {
    return this.stack[this.stack.length - 1]
  }

  clear() {
    this.stack = []
  }

  divide() {
    const divisor = this.getValue()
    const dividend = this.getValue()
    const result = dividend / divisor
    this.putValue(result)
    return result
  }

  multiply() {
    const multiplicand = this.getValue()
    const multiplier = this.getValue()
    const result = multiplier * multiplicand
    this.putValue(result)
    return result
  }
}
```

默认行为：
```js
const calc = new StackCalculator()
calc.putValue(5)
calc.putValue(0)
calc.divide() // 结果是 Infinity，不会报错
```

我们要通过**代理**改写这个行为。

---

## 接下来要讲的几种代理实现方式
1. **对象包装（Object Wrapping）**
   手动包装 subject，拦截指定方法，其余透传。

2. **ES6 原生 Proxy**（最强大、最常用）
   使用 `new Proxy(target, handler)` 统一拦截：
   - 方法调用
   - 属性访问
   - 设置属性
   - 原型判断等

3. **高阶函数 / 方法重写**
   只增强个别方法，其他直接复用。

---

## 我们要实现的效果
```js
const safeCalc = createSafeCalculator(calc)
safeCalc.putValue(5)
safeCalc.putValue(0)
safeCalc.divide() // 抛出 Error：Cannot divide by zero
```

同时**完全保留原接口**：
`putValue`、`getValue`、`multiply` 等行为不变。

# 对象组合（Object Composition）实现代理
这是最直观的代理实现方式：**包装被代理对象，保持接口一致，只增强需要控制的方法，其他直接转发**。

## 1. 类式组合代理
```js
class SafeCalculator {
  constructor(calculator) {
    // 持有被代理对象
    this.calculator = calculator
  }

  // 👉 被代理、增强的方法
  divide() {
    const divisor = this.calculator.peekValue()
    if (divisor === 0) {
      throw new Error('Division by 0')
    }
    return this.calculator.divide()
  }

  // 👇 其余方法纯粹转发
  putValue(value) { return this.calculator.putValue(value) }
  getValue()    { return this.calculator.getValue() }
  peekValue()   { return this.calculator.peekValue() }
  clear()       { return this.calculator.clear() }
  multiply()    { return this.calculator.multiply() }
}
```

使用：
```js
const calc = new StackCalculator()
const safeCalc = new SafeCalculator(calc)

safeCalc.putValue(4)
safeCalc.putValue(0)
safeCalc.divide() // ❌ 抛出除零错误
```

## 2. 工厂函数 + 对象字面量（更简洁）
```js
function createSafeCalculator(calculator) {
  return {
    divide() {
      const divisor = calculator.peekValue()
      if (divisor === 0) throw new Error('Division by 0')
      return calculator.divide()
    },

    putValue: v => calculator.putValue(v),
    getValue: () => calculator.getValue(),
    peekValue: () => calculator.peekValue(),
    clear: () => calculator.clear(),
    multiply: () => calculator.multiply()
  }
}
```

---

## 核心特点
- **接口完全透明**：外部使用方式和原对象一模一样
- **控制特定方法**：只增强 `divide`，其他原样转发
- **状态仍由原对象管理**：代理不持有 stack，只调用方法
- **实现简单、易理解**

---

## 明显缺点
- **必须手动转发所有方法**
- 对象方法一多，代码极其重复
- 原类新增方法时，代理必须同步更新，否则会“丢失”方法

## 更好的替代方案
- 使用工具库（如 `delegates`）自动生成转发方法
- **使用 ES6 原生 `Proxy`**（下一节重点）——**自动转发所有属性/方法，只拦截需要处理的**

---

# 对象增强（Object Augmentation）/ Monkey Patching
这是**最简单、最常用**的代理方式——只需要改写对象上的个别方法，其他完全不动。

## 核心代码
```js
function patchToSafeCalculator(calculator) {
  // 保存原来的 divide 方法
  const divideOrig = calculator.divide

  // 直接替换成新逻辑
  calculator.divide = () => {
    const divisor = calculator.peekValue()
    if (divisor === 0) {
      throw new Error('Division by 0')
    }
    // 调用原始方法
    return divideOrig.apply(calculator)
  }

  return calculator
}
```

使用：
```js
const calculator = new StackCalculator()
// 打补丁，让它变安全
const safeCalculator = patchToSafeCalculator(calculator)
```

---

## 优点
- **超级简单**
- 只改需要代理的方法（这里只有 `divide`）
- **不用写一堆转发方法**
- 代码量极少

## 巨大缺点：危险的副作用
它会**直接修改原对象**！

```js
// 打补丁后
calculator.divide() // 也会抛错误！

// 原对象行为被永久改变了
```

这就是 **Monkey Patching** 的问题：
- 污染原始对象
- 共享对象时会产生**隐蔽 bug**
- 其他模块依赖原行为时会全部炸掉

---

## 书中明确警告
- 对象被多处共享时**严禁使用**
- 只适合对象在**私有作用域、可控场景**下使用
- 生产环境尽量避免

---

## 三种代理方式小结
1. **对象组合**
   包装对象 → 安全、透明，但要手动转发所有方法
2. **对象增强（Monkey Patching）**
   直接改写原对象 → 极简单，但**不安全、有副作用**
3. **ES6 原生 Proxy**（下一节）
   自动拦截所有操作 → 安全、强大、零冗余代码

   ----

   # 内置 Proxy 对象（ES2015 原生代理）
这是 JS 官方提供的**最强大、最干净、最推荐**的代理实现方式，完美解决前面两种方式的缺陷。

## 语法
```js
const proxy = new Proxy(target, handler)
```
- **target**：被代理的对象（主体）
- **handler**：包含一系列**陷阱（trap）**，用来拦截操作

## 用 Proxy 实现安全计算器
```js
const safeCalculatorHandler = {
  get(target, property) {
    // 只拦截 divide 方法
    if (property === 'divide') {
      return function () {
        // 增强逻辑：除零校验
        const divisor = target.peekValue()
        if (divisor === 0) {
          throw new Error('Division by 0')
        }
        return target.divide()
      }
    }

    // 其余所有方法、属性 👉 自动透传
    return target[property]
  }
}

// 创建代理
const calculator = new StackCalculator()
const safeCalculator = new Proxy(calculator, safeCalculatorHandler)
```

---

## 核心优势
1. **不修改原对象**
   完全无副作用，不会影响其他使用原对象的代码

2. **自动转发所有属性/方法**
   不需要手动写一堆 `putValue()`、`getValue()`、`multiply()` 转发

3. **只增强需要处理的部分**
   这里只代理 `divide`，其他一概不管

4. **保留原型链**
   ```js
   safeCalculator instanceof StackCalculator // true
   ```
   对类型判断完全透明

5. **支持拦截超多操作**
   - `get`：获取属性/方法
   - `set`：设置属性
   - `apply`：调用函数
   - `has`：in 操作符
   - `deleteProperty`：删除属性
   - `construct`：new 操作符
   - 等等

---

## 对比前面两种方式

| 方式 | 优点 | 缺点 |
|------|------|------|
| 对象组合 | 安全 | 手动转发所有方法 |
| Monkey Patching | 极简 | 修改原对象，危险 |
| **原生 Proxy** | **安全 + 极简 + 强大** | 几乎无缺点 |

---

## 一句话总结
**ES6 Proxy = 不污染原对象 + 自动转发 + 精准拦截**
是现代 JS / Node.js 实现代理模式的**首选方案**。

# Proxy 对象的额外能力与局限

## 一、超能力：远不止代理模式
Proxy 是 JS 内置的**元编程（meta-programming）**机制，可以拦截并自定义对象的底层行为，实现很多以前做不到的效果。

### 示例：虚拟偶数数组
```js
const evenNumbers = new Proxy([], {
  get: (target, index) => index * 2,
  has: (target, number) => number % 2 === 0
})

console.log(2 in evenNumbers)   // true
console.log(5 in evenNumbers)   // false
console.log(evenNumbers[7])     // 14
```
特点：
- 数组**不存任何真实数据**，完全动态计算
- 拦截 `[]` 访问（get）
- 拦截 `in` 运算符（has）
- 用法和普通数组一样，但行为完全自定义

## 二、支持的常用陷阱（trap）
- `get`：读取属性 / 方法
- `set`：设置属性
- `has`：拦截 `key in obj`
- `deleteProperty`：拦截 `delete`
- `apply`：拦截函数调用
- `construct`：拦截 `new`
- `getPrototypeOf` / `setPrototypeOf`
- 等等

还支持：
- **可撤销代理（revocable proxy）**：随时“关掉”代理，恢复原对象行为

## 三、重要局限：无法完美 polyfill
- Proxy 的很多行为是**引擎底层实现**的
- 无法通过普通 JS 代码模拟
- 不能编译兼容到**不支持 Proxy 的旧环境**（很老的浏览器 / 很老的 Node.js）

## 四、重要区分
- **Proxy 对象**：是语言内置 API，用途极广
- **Proxy 设计模式**：只是它的用途之一

这个“偶数数组”例子：
- 用了 Proxy API
- **但不是在实现 Proxy 设计模式**（没有控制访问某个真实 subject）

同样，Proxy 还可以用来实现：
- 装饰器模式
- 观察者 / 响应式数据（Vue 3 的响应式就是基于 Proxy）
- 对象虚拟化
- 不可变对象
- 运行时校验、ORM、数据绑定等

## 一句话小结
Proxy 是 JS 最强大的元编程工具之一，**天然适合实现代理模式，但远不止于此**。
只是要注意：它**不能被 polyfill**，环境必须原生支持。

----
# 四种代理方式对比（精简总结）
## 1. 对象组合（包装类 / 工厂）
- 优点：**安全、不修改原对象**，接口透明
- 缺点：必须**手动转发所有方法**，代码冗余
- 适合：需要稳定、可维护、接口明确的代理

## 2. 对象增强（Monkey Patching）
- 优点：**代码最少、只改目标方法**
- 缺点：**直接污染原对象**，共享时极危险
- 适合：私有/可控对象，快速打补丁

## 3. ES6 原生 Proxy
- 优点：**不污染原对象 + 自动转发 + 全能拦截**（get/set/delete/in/new 等）
- 缺点：**无法 polyfill**，必须环境支持
- 适合：现代 Node.js，动态拦截、响应式、高级增强

## 一句话选择建议
- 简单、私有对象 → **Monkey Patching**
- 稳定、不污染原对象 → **对象组合**
- 现代环境、高级拦截、少代码 → **原生 Proxy**

# 实战：创建带日志的可写流代理
这里用 **Proxy 模式**包装一个 Node.js `Writable` 流，**自动拦截 `.write()` 并打印日志**，不改动原流、不破坏原有接口。

## 实现代码：logging-writable.js
```js
export function createLoggingWritable(writable) {
  return new Proxy(writable, {
    get(target, propKey, receiver) {
      // 只拦截 write 方法
      if (propKey === 'write') {
        return function (...args) {
          const [chunk] = args
          console.log('Writing', chunk)
          // 调用原始 write
          return writable.write(...args)
        }
      }
      // 其他属性/方法直接透传
      return target[propKey]
    }
  })
}
```

## 使用示例
```js
import { createWriteStream } from 'fs'
import { createLoggingWritable } from './logging-writable.js'

const writable = createWriteStream('test.txt')
// 包装成带日志的代理
const writableProxy = createLoggingWritable(writable)

writableProxy.write('First chunk')  // 会打印日志
writableProxy.write('Second chunk') // 会打印日志
writable.write('This is not logged') // 不走代理，不打印
writableProxy.end()
```

## 运行结果
```
Writing First chunk
Writing Second chunk
```
- 文件 `test.txt` 会收到全部三段内容
- 只有通过 **proxy 调用 write** 才会输出日志
- 原流的行为、接口、`pipe` 等完全不受影响

---

## 核心要点
- **透明代理**：外部使用方式和普通流完全一样
- **不修改原对象**：原 `writable` 保持原生行为
- **只增强关心的方法**：只处理 `write`，其余自动转发
- **典型 Proxy 模式应用**：访问控制 + 行为增强

这也是 Node.js 中**流增强、监控、埋点**非常常用的优雅写法。

# 使用 Proxy 实现变更观察器（Change Observer）
## 概念区分（书中重点提醒）
**Change Observer（变更观察器） ≠ 第三章的 Observer 观察者模式**
- **Observer 模式**：通用事件模型，基于 `EventEmitter`，适用于任意业务事件；
- **Change Observer**：专注**对象属性赋值变更检测**，监听对象状态修改。

## 基础实现代码 create-observable.js
```js
export function createObservable(target, observer) {
  const observable = new Proxy(target, {
    set(obj, prop, value) {
      // 只有新旧值不一样才触发通知
      if (value !== obj[prop]) {
        const prev = obj[prop]
        obj[prop] = value
        // 通知观察者，携带变更信息
        observer({ prop, prev, curr: value })
      }
      return true
    }
  })
  return observable
}
```
### 逻辑说明
1. 利用 `set` 陷阱拦截属性赋值；
2. 对比新旧值，避免重复触发；
3. 执行赋值，然后调用外部传入的回调函数；
4. 返回代理对象，外部操作代理即可触发监听。

## 业务示例：发票自动计算总价
```js
import { createObservable } from './create-observable.js'

// 计算发票总价
function calculateTotal(invoice) {
  return invoice.subtotal - invoice.discount + invoice.tax
}

// 原始数据
const invoice = {
  subtotal: 100,
  discount: 10,
  tax: 20
}

let total = calculateTotal(invoice)
console.log(`Starting total: ${total}`)

// 创建可观察对象
const obsInvoice = createObservable(
  invoice,
  ({ prop, prev, curr }) => {
    total = calculateTotal(invoice)
    console.log(`TOTAL: ${total} (${prop} changed: ${prev} -> ${curr})`)
  }
)

// 修改代理对象，自动触发更新
obsInvoice.subtotal = 200
obsInvoice.discount = 20
obsInvoice.discount = 20 // 值不变，不会触发回调
obsInvoice.tax = 30

console.log(`Final total: ${total}`)
```

### 输出结果
```
Starting total: 110
TOTAL: 210 (subtotal changed: 100 -> 200)
TOTAL: 200 (discount changed: 10 -> 20)
TOTAL: 210 (tax changed: 20 -> 30)
Final total: 210
```

## ⚠️ 当前实现存在明显局限（书中明确指出）
1. **仅支持单个观察者**，无法注册多个监听函数；
2. **只拦截 set 操作**，无法监听属性删除（`delete`）；
3. **不支持嵌套对象/数组深度监听**；
   ```js
   // 嵌套对象修改，无法触发set陷阱
   obsInvoice.info.address = "Shanghai"
   ```
4. 不处理原型变更、数组方法（`push/splice`）等场景；
5. 没有依赖收集机制（和 Vue3 响应式有本质区别）。

## 底层归类
该实现依托 **Proxy 设计模式**：
代理接管对象属性操作，在修改前后注入自定义逻辑（变更通知）。
前端 Vue3 的响应式系统，正是这套思想的工程化升级版本。

## 拓展思考
如果想要实现**深度观察**，需要在 `get` 陷阱中递归为子对象创建 Proxy；
想要支持多观察者，内部维护一个回调数组，变更时遍历执行所有回调。

# 实际应用中的代理模式与变更观察
这两个模式在真实项目里**应用极广**，尤其是现代前端框架和 Node.js 服务端框架，几乎都离不开它们。

## 典型知名项目
- **LoopBack（Node.js 后端框架）**
  - 用 Proxy 模式拦截控制器方法
  - 用于实现**权限校验、参数验证、日志、AOP**

- **Vue 3**
  - 响应式系统核心基于 **Proxy** 实现
  - 监听数据变化 → 自动更新视图
  - 正是你刚才看到的 Change Observer 模式的工业级实现

- **MobX（前端状态管理库）**
  - 和 Vue 3 思路一致
  - 用 Proxy 实现可观察对象
  - 数据一变，组件自动渲染

## 一句话总结
**Proxy = 现代 JS 生态里实现“透明增强、监听变化、无侵入扩展”的标配技术。**
从后端 AOP 到前端响应式，到处都是它的身影。
