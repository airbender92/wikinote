# Decorator（装饰器模式）
装饰器模式的核心：**在运行时动态给对象增加新行为/新方法**，而不通过继承。

## 与代理模式的区别
- **Proxy**：一般是**控制、拦截、增强原有接口**（接口不变）
- **Decorator**：重点是**给对象扩展新功能、新接口**

## 核心特点
- 不修改原类、不污染原对象
- 不影响同类的其他实例
- 可以多层嵌套装饰
- 比继承更灵活

## 书中图示含义
- Component：原始对象（只有 methodA、methodB）
- Decorator：包装它，并**新增 methodC**
- 原有方法通常直接转发，也可以顺便增强

## 一句话理解
**Proxy 管“控制”，Decorator 管“加功能”。**
底层实现经常很像（都是包装对象），但设计意图不一样。

## 真实应用
- 给函数/对象加缓存、日志、重试
- 前端组件高阶包装（HOC）
- Express/Koa 中间件本质也是装饰思想
- Vue/MobX 响应式也大量用到装饰模式

# 装饰器的实现技巧
装饰器和代理**实现写法几乎一样**，区别只在**设计意图**：
- 代理：控制/拦截已有接口
- 装饰：**新增接口 + 增强原有行为**

本节目标：
给 `StackCalculator` **新增 `add()` 方法**，同时增强 `divide()` 做除零校验。

---

## 1）对象组合方式实现装饰器
```js
class EnhancedCalculator {
  constructor(calculator) {
    this.calculator = calculator
  }

  // ✅ 新方法：装饰器新增功能
  add() {
    const addend2 = this.getValue()
    const addend1 = this.getValue()
    const result = addend1 + addend2
    this.putValue(result)
    return result
  }

  // ✅ 增强原有方法
  divide() {
    const divisor = this.calculator.peekValue()
    if (divisor === 0) {
      throw new Error('Division by 0')
    }
    return this.calculator.divide()
  }

  // 👇 其余方法原样转发
  putValue(v) { return this.calculator.putValue(v) }
  getValue() { return this.calculator.getValue() }
  peekValue() { return this.calculator.peekValue() }
  clear() { return this.calculator.clear() }
  multiply() { return this.calculator.multiply() }
}
```

### 使用
```js
const calculator = new StackCalculator()
const enhancedCalculator = new EnhancedCalculator(calculator)

enhancedCalculator.putValue(4)
enhancedCalculator.putValue(3)
console.log(enhancedCalculator.add()) // 4+3=7

enhancedCalculator.putValue(0)
enhancedCalculator.divide() // 抛除零错误
```

---

## 核心特点
- **新增接口**：`add()` 是原来没有的方法
- **增强原有接口**：`divide()` 增加了校验
- **转发其他接口**：保持原对象完整可用
- **不修改原类、不污染原对象**

这就是**装饰器模式**的典型结构：
**包装 + 扩展接口 + 可选增强原有方法**。

- 对象增强（monkey patching）

# 对象增强（Monkey Patching）实现装饰器
直接给原对象**挂载新方法、改写旧方法**，快速实现装饰效果：

```js
function patchCalculator(calculator) {
  // 👉 新增方法 add()
  calculator.add = function () {
    const addend2 = calculator.getValue()
    const addend1 = calculator.getValue()
    const result = addend1 + addend2
    calculator.putValue(result)
    return result
  }

  // 👉 增强原有方法 divide()
  const divideOrig = calculator.divide
  calculator.divide = () => {
    const divisor = calculator.peekValue()
    if (divisor === 0) {
      throw new Error('Division by 0')
    }
    return divideOrig.apply(calculator)
  }

  return calculator
}
```

使用：
```js
const calculator = new StackCalculator()
const enhancedCalculator = patchCalculator(calculator)
```

## 关键点
- `calculator === enhancedCalculator` → **同一个对象**
- 直接修改原对象，不是包装新对象
- 优点：**代码极少、不用转发一堆方法**
- 缺点：污染原对象，共享时会有副作用

## 和组合式装饰器的区别
- 组合：包装出新对象，原对象不动 → 安全但啰嗦
- 增强：直接改原对象 → 简单但有风险

这也是装饰器最快捷的实现方式，适合**私有对象、脚本、测试场景**。

# 使用 Proxy 对象实现装饰器
Proxy 同样可以用来做装饰器，而且写法更优雅：
- 不修改原对象
- 不用手动转发一堆方法
- 可以**动态新增方法**（实现装饰意图）

## 实现代码
```js
const enhancedCalculatorHandler = {
  get(target, property) {
    // 1. 新增 add() 方法
    if (property === 'add') {
      return function add() {
        const addend2 = target.getValue()
        const addend1 = target.getValue()
        const result = addend1 + addend2
        target.putValue(result)
        return result
      }
    }

    // 2. 增强 divide() 方法
    if (property === 'divide') {
      return function () {
        const divisor = target.peekValue()
        if (divisor === 0) {
          throw new Error('Division by 0')
        }
        return target.divide()
      }
    }

    // 3. 其余全部转发
    return target[property]
  }
}

const calculator = new StackCalculator()
const enhancedCalculator = new Proxy(calculator, enhancedCalculatorHandler)
```

## 特点
- **装饰 = 新增接口 + 增强原有接口**
- 原对象完全不变
- 只在 `get` 陷阱里判断属性名
- 外部使用和原对象一致，透明扩展功能

## 三种方式对比（极简总结）
- **对象组合**：安全、但要写大量转发
- **对象增强**：简单、但污染原对象
- **Proxy**：安全 + 简洁 + 强大，现代首选

# 实战：用装饰器模式扩展 LevelUP 数据库
这是 Node.js 社区**非常经典、真实**的装饰器用法：  
给 LevelUP 数据库**动态加一个 `subscribe` 订阅方法**，实现数据插入时的模式匹配监听。

## 一、背景：LevelUP / LevelDB
- LevelDB：Google 极简 KV 存储
- LevelUP：Node.js 封装，API 极小但可高度扩展
- 生态大量插件都是用**装饰器模式**给 db 实例加功能

## 二、插件实现：level-subscribe.js
```js
export function levelSubscribe(db) {
  // 👉 装饰：给 db 实例新增 subscribe 方法
  db.subscribe = (pattern, listener) => {
    // 监听数据库 put 操作
    db.on('put', (key, val) => {
      // 简单模式匹配：pattern 所有属性都要匹配
      const match = Object.keys(pattern).every(
        k => pattern[k] === val[k]
      )
      // 匹配成功就触发回调
      if (match) {
        listener(key, val)
      }
    })
  }

  return db
}
```

### 核心思想
- 用**对象增强（monkey patching）**实现装饰器
- 不修改原类，只给**当前实例**加方法
- 扩展出新功能：`db.subscribe(pattern, callback)`

## 三、使用示例
```js
import level from 'level'
import { levelSubscribe } from './level-subscribe.js'

// 初始化 Level 数据库
const db = level('./db', { valueEncoding: 'json' })

// 👉 装饰数据库实例
levelSubscribe(db)

// 订阅：只关心 doctype=tweet 且 language=en 的数据
db.subscribe(
  { doctype: 'tweet', language: 'en' },
  (key, value) => console.log('匹配到:', value)
)

// 第一条：匹配 → 触发回调
db.put('1', {
  doctype: 'tweet',
  text: 'Hi',
  language: 'en'
})

// 第二条：不匹配 → 无输出
db.put('2', {
  doctype: 'company',
  name: 'ACME Co.'
})
```

## 四、运行输出
```
匹配到: { doctype: 'tweet', text: 'Hi', language: 'en' }
```

## 五、为什么这是装饰器模式？
1. **动态扩展功能**：给 db 加了原本没有的 `subscribe()`
2. **不修改原类**：只增强实例，不影响其他 LevelUP 实例
3. **透明使用**：原有 API（put/get/on）完全不变
4. **实现极其简洁**：Node.js 社区最实用的装饰风格

## 六、总结（书中要点）
> 对象增强（monkey patching）是 Node.js 里**最 pragmatic、最常用**的装饰器实现方式，尤其适合编写插件、扩展第三方库。

这就是装饰器模式在**真实开源生态**里的样子：  
**小、干净、可组合、无侵入、威力巨大。**

# 真实世界中的装饰器模式

## LevelUP 生态插件（典型代表）
- **level-inverted-index**
  给数据库加**倒排索引**，实现文本搜索功能
- **levelplus**
  给 LevelUP 增加**原子更新操作**

## 其他知名项目
- **json-socket**
  装饰原生 `net.Socket`，扩展出直接收发 JSON 的能力
- **Fastify**
  内置 `decorate` 体系，允许向实例**动态挂载方法/属性**
  是 Node.js  Web 框架里装饰器模式规模化应用的典范

## 共同特点
- 不修改原类、不侵入源码
- 给**已有对象实例**动态加功能
- 插件化、可组合
- Node.js 社区最主流的扩展方式之一

一句话总结：
**装饰器模式 = Node.js 生态的“插件标准”。**

# Proxy 与 Decorator 的模糊边界（书中核心总结）
这两个模式**实现写法几乎一样**，在 JS/Node.js 里经常混用，区别主要在**设计意图**，不在代码形态。

## 经典定义区别
- **Decorator 装饰器**
  → **给对象增加新功能 / 新方法**
  → 重点是**扩展能力**（接口可能变多）

- **Proxy 代理**
  → **控制对原对象的访问**
  → 重点是**拦截、校验、缓存、延迟加载**
  → **接口一般保持不变**，可以无缝替换原对象

## 在 JavaScript / Node.js 中
- 语言是动态的，类型不严格
- 包装、改写、新增方法都非常容易
- **Proxy 和 Decorator 的界限变得非常模糊**
- 大家经常混用这两个名字，不用太纠结术语

## 实用建议（书中原话精神）
**不要死磕名词和经典定义**
把它们看作一类**包装增强模式**：
- 都是用“包装/改写对象”来解决问题
- 可以互相替代、互补使用
- 重点看你要解决什么问题，而不是叫什么模式

### 超简记忆版
- **想加新方法 / 新功能** → 偏向 Decorator
- **想拦截、控制、监听原有操作** → 偏向 Proxy
- **在 JS 里：写法一样，随便叫，能用就行**
