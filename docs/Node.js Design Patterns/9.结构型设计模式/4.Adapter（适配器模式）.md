# Adapter（适配器模式）
适配器模式的作用：**让接口不兼容的两个对象能一起工作**。

## 生活类比
USB-A 转 USB-C 转接头
- 一边是旧接口
- 一边是新接口
- 转接头本身不创造新功能，只是**做接口转换**

## 软件里的作用
- 有一个对象（adaptee），接口是 A
- 调用方（client）期望的接口是 B
- **Adapter 把 A 转换成 B**，让双方可以兼容
- 本质是**包装 + 方法映射**，不修改原有逻辑

## 核心特点
- 不改变被适配对象
- 不新增功能（不像装饰器）
- 只做**接口转换、参数转换、调用方式转换**
- 实现上最常用**对象组合**

## 一句话记忆
**适配器 = 接口翻译官**。

# 适配器模式实战：把 LevelUP 数据库伪装成 fs 文件系统
核心思路：**把 LevelUP 的 `get`/`put` 接口，转换成 Node.js 标准的 `fs.readFile`/`fs.writeFile` 接口**。
这样原本调用 fs 的代码，可以**无缝切换到底层用 LevelDB 存储**，甚至能在浏览器里跑。

## 一、适配器实现：fs-adapter.js
```js
import { resolve } from 'path'

export function createFSAdapter(db) {
  return {
    readFile(filename, options, callback) {
      // 兼容参数重载
      if (typeof options === 'function') {
        callback = options
        options = {}
      } else if (typeof options === 'string') {
        options = { encoding: options }
      }

      // 文件名 → 数据库 key
      const key = resolve(filename)

      db.get(key, { valueEncoding: options.encoding }, (err, value) => {
        // 把 LevelDB  NotFound 转成 fs 标准的 ENOENT 错误
        if (err) {
          if (err.type === 'NotFoundError') {
            const newErr = new Error(`ENOENT, open "${filename}"`)
            newErr.code = 'ENOENT'
            newErr.errno = 34
            newErr.path = filename
            return callback(newErr)
          }
          return callback(err)
        }
        callback(null, value)
      })
    },

    writeFile(filename, contents, options, callback) {
      // 同样兼容参数重载
      if (typeof options === 'function') {
        callback = options
        options = {}
      } else if (typeof options === 'string') {
        options = { encoding: options }
      }

      const key = resolve(filename)
      // 写入 → 对应 db.put
      db.put(key, contents, { valueEncoding: options.encoding }, callback)
    }
  }
}
```

## 二、使用方式
### 原来的 fs 写法
```js
import fs from 'fs'

fs.writeFile('file.txt', 'Hello!', () => {
  fs.readFile('file.txt', 'utf8', (err, content) => {
    console.log(content) // Hello!
  })
})

fs.readFile('missing.txt', 'utf8', (err) => {
  console.error(err) // ENOENT 错误
})
```

### 换成适配器 + LevelDB
```js
import level from 'level'
import { createFSAdapter } from './fs-adapter.js'

// 初始化数据库
const db = level('./db', { valueEncoding: 'binary' })
// 生成适配器
const fs = createFSAdapter(db)

// 代码完全不用改！
fs.writeFile('file.txt', 'Hello!', () => {
  fs.readFile('file.txt', 'utf8', (err, content) => {
    console.log(content) // 同样输出 Hello!
  })
})
```

**输出完全一样**，但数据实际存在 LevelDB 里，不是真实文件。

## 三、这为什么是 Adapter 模式？
1. **被适配者（adaptee）**：LevelUP（`db.get` / `db.put`）
2. **目标接口（target）**：`fs` 模块（`readFile` / `writeFile`）
3. **适配器（adapter）**：`createFSAdapter` 返回的对象
4. **做的事情**：
   - 参数格式转换
   - 错误类型映射（`NotFoundError` → `ENOENT`）
   - 方法调用映射
   - **接口完全兼容**，上层代码零改动

---

## 四、实际意义（书中重点）
- 让**只能用 fs 的代码**，可以跑在浏览器里（通过 level-js）
- 统一存储层接口：文件、数据库、内存、浏览器存储可以互换
- 是实现**同构 JavaScript（前后端一套代码）**的关键模式

---

## 一句话总结
**适配器 = 接口转换器**
不新增功能、不增强行为，只负责**让两套不兼容的 API 能互相替换使用**。
