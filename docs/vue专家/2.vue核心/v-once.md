`v-once` 实际用处非常明确：
**只渲染一次，后续数据更新不再重新渲染，用来做性能优化。**

平时业务确实不常用，但在**特定场景非常有用**，而且是 Vue 里为数不多明确用来“跳过响应式更新”的指令。

---

# 1. 最典型用途：大量静态内容优化
比如一个页面有**巨大的静态列表、说明文本、协议内容、帮助文档**。
这些内容**永远不变**，但在 Vue 里会被当成响应式节点。

```vue
<template>
  <div v-once>
    <h1>用户协议</h1>
    <p>一大段永远不变的文字...</p>
    <p>...</p>
    <ul>
      <li>...</li>
      ...很多很多个
    </ul>
  </div>
</template>
```

加了 `v-once`：
- 首次渲染完就**缓存 DOM**
- 之后组件任何更新（data、props 变化）
- 这一块**直接跳过 Diff、不更新**

能明显减少 Vue 做虚拟 DOM 对比的开销。

---

# 2. 大量列表、复杂表格只渲染一次
比如后台系统里：
- 静态数据字典
- 一次性展示的报表
- 不会再更新的历史记录

```vue
<template>
  <div v-for="item in bigStaticList" :key="id" v-once>
    {{ item.name }}
    {{ item.content }}
    ...
  </div>
</template>
```

不加 `v-once`：
父组件一更新，整个大列表会重新走 **patch diff**，白白浪费性能。

---

# 3. 组件初始化时取值，之后不再变
比如只需要**初始值**，后续变化不关心：

```vue
<template>
  <div v-once>{{ initialValue }}</div>
</template>
```

即使 `initialValue` 后来变了，视图也**永远不更新**。

---

# 4. 优化递归组件、深度嵌套组件
有些递归组件（树、菜单）渲染极重，
加 `v-once` 可以让**已经渲染过的分支不再参与更新**。

---

# 5. 真实开发里一句话总结
**你几乎不需要在普通业务里用 v-once。
但在大数据量、静态内容、性能瓶颈时，它是低成本优化神器。**

---

# 什么时候不要用？
- 内容会动态更新
- 会被 `v-if` 频繁切换
- 小组件、少量 DOM
用了反而代码更难理解，没必要。
