# 计算属性（computed）
一句话讲透：
**带有缓存的、基于响应式数据派生出来的属性。**

---

# 核心三个特点
1. **依赖响应式数据**（data、props、其他 computed）
2. **有缓存**：依赖不变，多次调用只算一次
3. **像属性一样用，不用加 ()**

---

# 1. 最简单例子
```vue
<script setup>
import { ref, computed } from 'vue'

const price = ref(100)
const count = ref(2)

// 计算属性：总价
const total = computed(() => {
  console.log('计算了！')
  return price.value * count.value
})
</script>

<template>
  <div>单价：{{ price }}</div>
  <div>数量：{{ count }}</div>
  <div>总价：{{ total }}</div>
  <div>总价：{{ total }}</div>
  <div>总价：{{ total }}</div>
</template>
```

**控制台只打印一次“计算了！”**
因为依赖没变，直接走缓存。

---

# 2. 为什么不用 methods？
对比一下：
```vue
<div>{{ getTotal() }}</div>
<div>{{ getTotal() }}</div>
```
```js
function getTotal() {
  console.log('执行了')
  return price.value * count.value
}
```

渲染多少次，就执行多少次，**没有缓存**。

---

# 3. 什么时候用 computed？
凡是 **“根据现有数据算出来的数据”** 都用它：

- 列表过滤
  ```js
  const showList = computed(() => {
    return list.filter(item => item.age > 20)
  })
  ```
- 格式化数据
  ```js
  const formatDate = computed(() => dayjs(date).format('YYYY-MM-DD'))
  ```
- 拼接、判断状态
  ```js
  const btnText = computed(() => isEdit ? '保存' : '新增')
  ```
- 复杂逻辑的视图表达式

一句话：
**模板里写复杂表达式丑、容易卡 → 丢 computed。**

---

# 4. 可写计算属性（get + set）
默认只读，也可以写 set：

```js
const fullName = computed({
  get() {
    return firstName + ' ' + lastName
  },
  set(val) {
    [firstName, lastName] = val.split(' ')
  }
})

// 使用
fullName.value = '张三 李四'
```

常用于：封装 `v-model` 逻辑。

---

# 5. 面试必问：computed vs watch
|  | computed | watch |
|--|--|--|
| 用途 | **计算派生值** | **监听变化，执行副作用** |
| 缓存 | 有 | 无 |
| 是否异步 | 不支持 | 支持异步 |
| 风格 | 声明式 | 命令式 |

- 多数据组合算出一个值 → **computed**
- 一个数据变了去发请求、改多个数据、操作DOM → **watch**

---

# 最简总结
- **模板里的复杂逻辑，一律用 computed**
- **依赖不变，就走缓存，性能好**
- **像变量一样用，干净优雅**

它就是 Vue 里最舒服、最常用的“**高级缓存 + 派生状态**”工具。
