先把结论说清楚：
**750px 设计稿 + 1rem = 100px**，本质就是为了**写 CSS 时口算就能还原设计稿，不用计算器**，同时兼顾移动端适配。

---

### 一、为什么设计稿常用 750px？
现在移动端主流是**两倍屏（2x）**：
- 手机逻辑宽度：375px（iPhone 等标准宽度）
- 实际物理像素：750px

所以 UI 出图一般用 **750px 宽度**，这样：
- 标注尺寸 = 手机物理像素
- 前端写样式时再统一**除以 2** 得到逻辑像素

---

### 二、为什么要设 1rem = 100px？
正常浏览器默认：`1rem = 16px`，换算很麻烦。
如果在项目里把根字体大小设为：

```css
html {
  font-size: 100px;
}
```

就会变成：
**1rem = 100px**

好处一眼就能看出来：

- 设计稿标注 `20px` → 直接写 `0.2rem`
- 设计稿标注 `36px` → 直接写 `0.36rem`
- 设计稿标注 `100px` → 直接写 `1rem`

**不用除法、不用小数位纠结，心算直接写**。

---

### 三、结合 750px 设计稿怎么用？
完整流程：
1. UI 给 **750px 宽设计稿**
2. 前端拿到标注，**先 ÷2** 得到 375px 体系尺寸
3. 再把 px 数值**小数点左移两位**，直接写成 rem

举个例子：
- 设计稿按钮宽：`200px`
- 实际逻辑像素：`100px`
- 转 rem：`1rem`

---

### 四、为什么这么配很舒服？
- **750px**：适配主流 2x 屏，还原最准
- **1rem=100px**：换算最简单，开发最快
- 再配合媒体查询或 flexible 等方案，不同屏幕会自动等比缩放，一套样式适配多机型
