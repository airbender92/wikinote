# 浏览器渲染流程（极简完整版）
一共 6 步，记住顺序就够：

1. **解析 HTML → 生成 DOM 树**
2. **解析 CSS → 生成 CSSOM 树**
3. **DOM + CSSOM 合并 → 生成 Render Tree（渲染树）**
4. **布局（Layout / Reflow）**：计算元素位置、大小
5. **分层（Layer）**：分成多个图层（如 z-index、3D transform）
6. **绘制（Paint / Rasterize）+ 合成（Composite）**：显示到屏幕

---

# 逐句人话翻译
## 1. 解析 HTML → DOM
浏览器把你的标签变成对象树
```html
<div>
  <p>hello</p>
</div>
```
变成一个可以用 JS 操作的树结构。

## 2. 解析 CSS → CSSOM
把样式变成一个可以被查询的结构，
**CSSOM 会阻塞渲染**，因为样式没解析完不能渲染。

## 3. 生成 Render Tree
只保留**要显示的节点**
- 不显示 `display: none` 的节点
- 只保留可见元素 + 对应样式

## 4. 布局 Layout（重排 reflow）
计算每个元素：
- 宽高
- 位置
- 文档流结构

**只要改动结构/尺寸，就会触发布局，代价很大。**

## 5. 分层 Layer
浏览器把页面分成多个图层，比如：
- 普通内容一层
- fixed 一层
- transform 一层

目的是：**改一个图层不影响其他图层**。

## 6. 绘制 + 合成
- Paint：填充颜色、图片、文字、边框
- Composite：把图层按顺序叠在一起显示

**transform / opacity 只会触发合成，性能最高。**

---

# 最重要的性能结论（开发必用）
修改不同 CSS，触发的流程不一样：

1. **修改 layout 属性**（width/top/left/margin/padding…）
   → 重新布局 → 重绘 → 合成
   **代价最大**

2. **修改 paint 属性**（color/background/box-shadow…）
   → 重绘 → 合成
   **代价中等**

3. **修改合成属性**（transform / opacity）
   → 只合成
   **代价最小，丝滑流畅**

口诀：
**能用 transform 不用 top/left，能用 opacity 不用 visibility。**

---

# 再精简成一句话
浏览器渲染 =
**构建 DOM/CSSOM → 渲染树 → 算布局 → 分层 → 绘制 → 合成**

你平时做性能优化、动画卡顿、页面抖动，
本质都是在**减少布局、减少绘制、多用合成**。
