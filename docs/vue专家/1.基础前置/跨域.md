# 跨域（最通俗、前端必懂版）
一句话：
**浏览器出于安全，限制了一个域名的 JS 去访问另一个域名的资源，这就叫跨域。**

---

# 1. 什么情况算跨域？
只要 **协议、域名、端口** 任意一个不一样，就是跨域。

- `http://a.com` → `https://a.com`（协议不同）跨域
- `http://a.com` → `http://b.com`（域名不同）跨域
- `http://a.com` → `http://a.com:8080`（端口不同）跨域

**同源 = 协议 + 域名 + 端口完全一样**

---

# 2. 为什么要有跨域限制？
防止恶意网站偷偷拿你别的网站的 cookie 发请求，
比如偷偷调你的支付宝、银行接口把钱转走。
这叫 **CSRF 攻击**。

---

# 3. 前端开发最常用的 4 种解决方案
## ① CORS（最标准、最推荐）
后端在响应头加：
```
Access-Control-Allow-Origin: *
```
浏览器看到就放行。

日常开发 90% 都是这种。

## ② 代理服务器（开发环境必用）
比如：
- webpack devServer proxy
- vite proxy

原理：
**前端请求自己域名 → 服务器转发 → 目标接口**
服务器之间不存在跨域。

## ③ JSONP（老方案，只支持 GET）
利用 `<script src>` 不受跨域限制，
后端返回一段函数调用。
现在基本不用了。

## ④ Nginx 反向代理（生产常用）
```
location /api {
  proxy_pass http://目标接口地址;
}
```
和 webpack 代理一个思路。

---

# 4. 简单记住
- 跨域是**浏览器限制**，服务器之间没有
- 开发用 **proxy**
- 生产用 **CORS 或 Nginx 代理**
- 带 cookie 要额外配置：`withCredentials: true`

---

# 一句话总结
**浏览器不让随便跨域，
解决办法就是：后端开 CORS 或 前端搭个代理。**
