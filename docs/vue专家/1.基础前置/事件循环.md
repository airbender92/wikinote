# 事件循环（Event Loop）
一句话讲透：
**JS 是单线程的，事件循环就是它用来处理异步任务、不卡死页面的调度机制。**

---

# 1. 先记住两个关键点
1. **JS 只有一个主线程**，同一时间只能干一件事
2. 遇到异步任务（定时器、ajax、DOM 事件），**不阻塞**，先挂起，等同步代码跑完再按规则执行

这套“排队 + 执行”的机制，就是**事件循环**。

---

# 2. 两个任务队列（必考 + 必懂）
## ① 微任务队列（microtask）
- 优先级 **更高**
- 执行更快
- 常见：
  - `Promise.then/catch/finally`
  - `queueMicrotask`
  - `MutationObserver`

## ② 宏任务队列（macrotask）
- 优先级低
- 等微任务空了才执行
- 常见：
  - `setTimeout/setInterval`
  - ajax/fetch
  - DOM 事件（click、load 等）
  - script 整体代码

---

# 3. 执行顺序铁律（死记就能做对所有题）
1. 先执行 **同步代码**
2. 同步执行完 → 清空 **所有微任务**
3. 微任务清空 → 执行 **一个宏任务**
4. 执行完这个宏任务 → 再清空 **所有微任务**
5. 循环往复……

口诀：
**同步先跑，微任务全清，再跑一个宏任务，循环。**

---

# 4. 经典面试题（一看就懂）
```js
console.log(1)

setTimeout(() => {
  console.log(2)
}, 0)

Promise.resolve().then(() => {
  console.log(3)
})

console.log(4)
```

执行顺序：
1 → 4 → 3 → 2

解释：
1. 先跑同步：1、4
2. 清空微任务：3
3. 再跑宏任务：2

---

# 5. 为什么要分微任务、宏任务？
- 微任务：想**尽快执行**的异步（如 Promise）
- 宏任务：可以**等下一轮**的异步（定时器、网络、DOM）

如果不分：
定时器会插队 Promise，页面交互、渲染会卡顿。

---

# 6. 和你前面学的闭包、this 有啥关系？
- 定时器、Promise 里的 **this 丢失**，就是因为进了事件循环
- 防抖里的 **timer** 也是靠闭包 + 事件循环实现

**闭包保存变量，事件循环控制执行时机。**

---

# 7. 最简总结
- JS 单线程，靠事件循环处理异步
- 同步 > 微任务 > 宏任务
- 每轮循环：同步 → 清微任务 → 执行一个宏任务 → 重复
