我用**最直白、前端开发最实用**的方式讲，一句话抓住核心：

# 一句话总结
- **重排（Reflow / Layout）：改位置、改大小 → 重新算布局 → 代价最大**
- **重绘（Repaint / Paint）：改颜色、改背景 → 只重新画像素 → 代价中等**
- **合成（Composite）：改 transform / opacity → 只拼图层 → 代价最小**

---

# 1. 重排（Reflow）
## 触发条件
只要**影响元素布局、位置、大小**的修改，都会重排：
- `width` / `height`
- `top` / `left` / `margin` / `padding`
- `display: none`
- 添加/删除 DOM
- 页面首次渲染
- 窗口 resize

## 特点
- 重排**一定伴随着重绘**
- 是**最耗性能**的操作
- 会触发浏览器重新计算整个或部分渲染树

---

# 2. 重绘（Repaint）
## 触发条件
只改**外观，不改位置大小**：
- `color`
- `background-color`
- `visibility`
- `box-shadow`
- `outline`

## 特点
- 不重新计算布局
- 只重新填充像素
- 比重排**快很多**

---

# 3. 合成（Composite）
## 触发条件
只改这两个：
- `transform`
- `opacity`

## 特点
- 不重排、不重绘
- 直接在 GPU 合成图层
- **性能最好，不会卡顿**

---

# 一张表看懂区别
| 修改方式 | 重排 | 重绘 | 合成 | 性能 |
|---------|------|------|------|------|
| top / left / width | ✅ | ✅ | ❌ | 最差 |
| color / background | ❌ | ✅ | ❌ | 中等 |
| transform / opacity | ❌ | ❌ | ✅ | 最好 |

---

# 开发中怎么优化？（实用技巧）
1. **尽量用 transform 做动画，别用 top/left**
2. **批量修改样式，不要频繁改样式**
3. **离线操作 DOM：先 display:none，改完再显示**
4. **使用 will-change 提升为独立图层**

---

# 终极口诀
**改大小位置 → 重排（最贵）
改颜色样式 → 重绘（中等）
改变形透明 → 合成（最快）**

你前面学的事件循环、渲染流程、重排重绘，
连起来就是**前端性能优化的全部核心**。
