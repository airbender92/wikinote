闭包我用**最现实、最直白、前端必用**的方式讲，不讲玄学，一听就懂。

# 一句话定义
**函数套函数，内部函数访问了外部函数的变量，并且被保留下来，这就叫闭包。**

作用只有两个：
1. **私有化变量**（外面改不到）
2. **让变量常驻内存**（不会被回收）

---

# 最简单真实例子（现实开发真这么写）
```js
function makeCounter() {
  let count = 0; // 这个变量会被闭包“关”起来

  return function () {
    count++;
    return count;
  };
}

const counter = makeCounter();

console.log(counter()); // 1
console.log(counter()); // 2
console.log(counter()); // 3
```

这里：
- `count` 外部访问不到
- 但 `counter` 函数一直能记住它
→ 这就是**闭包**

---

# 闭包到底解决什么问题？
## 1. 防止变量污染全局
不用闭包你只能这么写：
```js
let count = 0; // 全局变量，谁都能改

function counter() {
  count++;
}
```
不安全、容易被意外覆盖。

闭包可以**把变量藏起来**。

---

## 2. 保留现场（最常用场景：循环绑定事件）
这是前端最经典的闭包场景：
```js
for (var i = 0; i < 3; i++) {
  setTimeout(function () {
    console.log(i); // 输出 3 3 3
  }, 1000);
}
```

为什么？
因为 `var i` 是全局的，循环跑完才执行定时器。

用闭包保留每次循环的 i：
```js
for (var i = 0; i < 3; i++) {
  (function (index) {
    setTimeout(function () {
      console.log(index); // 0 1 2
    }, 1000);
  })(i);
}
```

现在开发用 `let` 就自动解决了，但**let 底层也是闭包机制**。

---

## 3. 模块化（早期 JS 没有模块化时全靠闭包）
```js
const module = (function () {
  let privateData = "秘密";

  function privateFn() {}

  return {
    publicFn() {
      return privateData;
    },
  };
})();

module.publicFn(); // 可以访问
module.privateData; // undefined
```

这就是**模块化的雏形**。
Vue、React 早期很多库都这么写。

---

## 4. 防抖、节流（闭包必用）
这是**真实项目天天写**的：
```js
function debounce(fn, delay) {
  let timer = null; // 闭包变量

  return function (...args) {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}
```

- `timer` 不污染全局
- 每次调用都能拿到上一次的 timer
→ 完全靠闭包

---

# 闭包的本质（一句话）
**函数执行完本该销毁的作用域，因为被内部函数引用，所以保留下来了。**

- 外部访问不到
- 内部一直能用
- 不会被垃圾回收

---

# 现实开发总结
你一定用过闭包，只是没意识到：
- 防抖节流
- 计数器、状态封装
- 循环绑定事件
- 模块化
- 缓存、私有变量
- React Hooks（useState 完全基于闭包）

**闭包不是高级技巧，是 JS 函数一等公民的必然产物。**
