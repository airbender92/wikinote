我直接用**前端开发最真实、最常用、最容易踩坑**的方式讲缓存，不绕弯子。

# 一句话
**缓存 = 把用过的数据/资源存起来，下次直接用，不再重新请求/计算。**
目的：快、省流量、减轻服务器压力。

---

# 前端缓存分 4 大类（你项目里一定都遇到过）
## 1. HTTP 缓存（浏览器自动缓存静态资源）
浏览器默认帮你做的，针对：
JS、CSS、图片、字体、接口数据。

### 关键两个
- **强缓存**
  直接用本地的，**不发请求**
  响应头：`Cache-Control: max-age=xxx`

- **协商缓存**
  发个请求问服务器：“我这个版本还能用吗？”
  服务器说 304 → 用本地
  关键：`ETag`、`Last-Modified`

**用途**：打包后的 js、css、图片永久缓存，更新靠哈希文件名。

---

## 2. 内存缓存 / 磁盘缓存
- **Memory Cache**：放内存里，刷新还在，关标签就没
- **Disk Cache**：放硬盘，重启浏览器还在

你在 Network 看到的
`memory cache`、`disk cache`
就是这俩。

---

## 3. 本地存储缓存（手动存数据）
- **localStorage**：永久存，5M左右
- **sessionStorage**：页面关闭就没
- **cookie**：会自动带到后端，大小小
- **indexedDB**：存大量结构化数据

真实场景：
- 存用户信息
- 存token
- 存不常变的字典数据
- 离线可用

---

## 4. 运行时缓存（代码里的缓存）
就是你前面学的：
- **闭包缓存**（防抖、节流）
- **WeakMap 缓存**（对象缓存，防泄漏）
- **Map/对象缓存**（计算结果缓存）

典型：
```js
const cache = new Map()

function getList() {
  if (cache.has('list')) return cache.get('list')

  const res = fetch(...)
  cache.set('list', res)
  return res
}
```

Vue 的 `computed`、React 的 `useMemo`、`useCallback` 本质都是**缓存计算结果**。

# 缓存三大问题（前端必踩）
## 1. 缓存过期
解决：
- 设置合理 max-age
- 版本号 / hash 文件名
- 手动清理 localStorage

## 2. 缓存一致性（旧数据问题）
后台更新了，但前端还拿旧的。
解决：
- 接口加版本校验
- 登录/关键操作主动清缓存
- 协商缓存

## 3. 内存泄漏
缓存一直不删，越来越大。
解决：
- 用 **WeakMap** 自动回收
- 设置过期时间
- 页面卸载时清理

---

# 最简单总结（现实开发版）
- **HTTP 缓存**：浏览器自动存静态资源
- **localStorage/sessionStorage**：手动存少量数据
- **indexedDB**：存大量离线数据
- **运行时缓存（闭包/Map/WeakMap）**：代码里缓存计算结果、接口数据

**你写的防抖、节流、computed、Vuex/Pinia 持久化，全都是缓存。**
