# 大模型可解释性（XAI for LLMs）
一句话：
**让模型“说出”为什么这么回答、依据是什么、注意力在哪、决策路径是什么。**

大模型本质是黑箱：一堆矩阵乘法 + 注意力 + 非线性激活，人类无法直接看懂它的逻辑。
可解释性就是**打开黑箱的各种方法**。

---

# 一、为什么 Decoder 大模型特别需要可解释性
1. **幻觉严重**：回答看着很对，实际瞎编，必须知道它依据什么。
2. **决策不可控**：同样问题多次回答不一样，不知道哪层、哪个注意力出问题。
3. **RAG 场景刚需**：检索-生成里，模型到底用了哪段参考资料？必须可追溯。
4. **合规要求**：金融、法律、医疗必须解释“为什么这么判断”。

---

# 二、可解释性两大流派
## 1. 全局可解释性（模型整体行为）
研究模型**整体学到了什么**：
- 语法、事实、逻辑、偏见存在哪一层
- 注意力头在做什么（指代、位置、句法）
- FFN 神经元存储了什么知识（事实神经元）

典型方法：
- 注意力权重可视化
- 探针（Classifier Probing）
- 知识定位（Knowledge Neurons）
- 层级贡献分析（哪层负责语义、哪层负责生成）

## 2. 局部可解释性（单条回答为什么这样）
针对**某一次回答**解释：
- 模型关注了输入的哪些 token
- 引用了检索资料的哪几句话
- 输出 token 由哪些输入 token 贡献最大

典型方法：
- Attention Rollout
- LLM Attribution / Input Attribution
- Feature Visualization
- Logit Lens（看每一层输出的概率分布）

---

# 三、最常用、最落地的可解释性技术
## 1. 注意力可视化（最直观）
看 Decoder 每一层、每个头，对哪些词的注意力权重高。
- 能看出：指代关系、上下文依赖、是否关注 RAG 参考资料
- 缺点：注意力 ≠ 重要性，不完全等价

## 2. Logit Lens（逐层透镜）
把每一层 Decoder 输出直接映射回词表，看：
- 模型在第几层已经“想好”答案
- 中间层是否出现幻觉苗头
- 知识是浅层编码还是深层推理

## 3. Input Attribution（输入贡献度）
计算每个输入 token 对输出 token 的**贡献梯度/积分梯度**
回答：
**“这个答案主要来自哪句话？”**
非常适合 RAG 检索-生成系统。

## 4. 知识神经元 / 概念激活
发现某些 FFN 神经元专门负责：
- 某个事实（巴黎是法国首都）
- 某种格式（日期、代码、JSON）
- 某种情感或偏见
可用于：
- 知识编辑
- 去偏见
- 错误定位

## 5. 因果干预（Causal Intervention）
强行屏蔽某层/某个头，看输出是否变化：
- 定位模型行为的因果来源
- 判断“是不是真的懂，还是死记硬背”

---

# 四、检索-生成（RAG）中的可解释性（最实用）
RAG 天然比纯大模型更容易解释，因为**知识来自外部文档**。

RAG 可解释性核心三件事：
1. **召回了哪些片段？**（来源可追溯）
2. **模型真正用到了哪几段？**（ attribution 分析）
3. **答案哪一句对应哪篇资料？**（引用标注）

工程上常用做法：
- 检索结果带来源标题、页码、段落
- 用注意力/贡献度标记模型使用的片段
- 强制模型输出引用标号（如 [1] [2]）
- 对比检索前 vs 检索后答案变化

这是目前**最合规、最容易落地**的可解释性方案。

---

# 五、Decoder 结构与可解释性的关系
Decoder-only 模型的可解释性特点：
1. **单向因果注意力**
   只能看前文，解释相对简单，没有双向纠缠。
2. **深层负责语义，浅层负责语法**
   可通过层级分析定位错误。
3. **自回归生成**
   每一步 token 都依赖之前所有输出，解释链条长。
4. **知识大量存在 FFN 中**
   更容易做知识定位与编辑。

---

# 六、当前可解释性的局限
- 没有统一标准
- 注意力≠重要性
- 复杂逻辑推理无法完全拆解
- 长文本下解释极其混乱
- 无法解释“创造性”“泛化”

所以现在业界主流是：
**用 RAG 溯源 + 注意力可视化 + 输入贡献度** 做工程可解释，
不追求完全打开黑箱。

---

# 七、极简总结
- **可解释性 = 让大模型的决策可追溯、可理解、可验证**
- **全局**：看模型学到了什么、结构在干嘛
- **局部**：看单次回答依据哪些输入
- **RAG + 可解释性** 是目前最稳、最实用的落地路线
- Decoder 结构因为单向因果，相对更容易解释
