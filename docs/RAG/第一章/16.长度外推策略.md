# 长度外推策略（Length Extrapolation）
> 承接前面 Decoder‑only、RAG文档片段：
**长度外推：模型预训练只见过最大L_train长度的序列；推理输入超过L_train，依然尽可能保持效果，即「Train Short, Test Long，短训练长推理」**。

Decoder大模型上下文窗口受限根源两点：
1. **位置编码**：RoPE/绝对位置编码，超长位置未被训练，注意力分布崩坏，困惑度飙升、长距离记忆失效、幻觉变多。
2. **自注意力复杂度 O(n²)**：序列变长，算力、KV‑Cache显存爆炸。

外推策略分4大类：**位置编码修改（推理免调优）、位置插值微调、稀疏/窗口注意力、无限上下文算法；另外RAG是工程侧替代方案**。

> 区分两个概念
- **外推 Extrapolation**：推理长度＞训练最大长度，免微调。
- **内插 Interpolation**：用长文本做微调，把训练窗口直接拉大。

## 一、RoPE体系免训练外推（工业最常用，不改动权重，推理阶段修改旋转计算）
现在LLaMA/Qwen全部使用RoPE旋转位置编码，原生外推能力很差，直接跑到超过训练长度性能暴跌。

### 1. 线性位置插值 PI（Position Interpolation）
把超长的位置索引**压缩回原训练窗口范围**
$$m' = m \times \frac{L_{train}}{L_{target}}$$
例如原训练4k，要跑8k，每个位置m除以2。
- 特点：纯推理直接用效果差，一般需要少量长文本微调，恢复性能；短距离语义会被压缩，近处质量受损。
- 缺点：一刀切缩放全部频率，高频细节被破坏。

### 2. NTK‑Aware 缩放（Neural Tangent Kernel）
**不缩放位置索引，修改RoPE基底参数`rope_theta`**，放大旋转周期，降低高频旋转速度，让超长位置落在模型熟悉的频率范围。
- ✅无需微调，直接推理生效，可外推2‑4倍原生窗口。
- ❌倍数过大，长距离指代、大海捞针任务显著衰减，不能无限放大。
- 变种：**Dynamic‑NTK**，根据输入序列长度动态自适应`rope_theta`，短序列不破坏原生性能，长序列自动开启缩放。

###3. YaRN（Yet another RoPE scaling）
NTK + 部分维度线性插值 + 注意力分数缩放修正。
- 部分高频维度做NTK缩放，低频维度做线性插值，再对Attention分数做补偿；
- 免微调，LLaMA2可直接从4K外推至64K‑128K，是开源圈主流方案。

###4. ALiBi（Attention with Linear Biases）【另一条路线，不使用RoPE】
不在Q/K做位置变换；**注意力分数上加线性距离惩罚：两个Token相距越远，直接扣减更多分数**，天然实现相对位置，理论上具备无限外推能力。
- 优点：免训练，短训练长推理；不需要修改旋转。
- 缺点：不能像RoPE那样精细建模复杂位置模式；**预训练阶段就要内置ALiBi，不能给已经训好RoPE模型直接换上ALiBi**；Mistral没有用ALiBi。

> RoPE vs ALiBi关键差异：
> RoPE把位置信息编码进Q、K向量旋转；ALiBi直接在Attention分数加距离偏置。RoPE综合能力更强，但原生外推弱；ALiBi外推强，但预训练就要确定架构。

## 二、微调式上下文扩展（内插，需要长文本数据微调权重）
1. **Position Interpolation + Fine‑tune**
先做位置插值，再用大量长文档少量步数微调，让模型适应拉伸后的位置空间；例如LLaMA‑2‑7B 4K → 32K微调版本。
- 优点：性能最好；缺点：需要长文本数据集、GPU算力成本。

2. **Continued Pre‑training（继续预训练）**
直接用超长序列继续预训练，把原生训练窗口直接拉高；商业模型（Llama3‑70B 128K）常用。

## 三、注意力改造方案：解决O(n²)算力爆炸
即使位置编码搞定，上万token的全量MHA显存、算力扛不住。

###1. 滑动窗口注意力 Sliding‑Window Attention（Mistral）
每个token**只和前后W个token做注意力**，无视更远的token；
例如窗口4096，输入总长度可以32K，但每个位置只能看邻近4096。
- 优点：算力O(n·W)，远小于O(n²)，显存可控。
- 缺点：超过窗口距离的信息完全看不到，跨窗口会丢失信息，长距离问答失效。

###2. 稀疏注意力 Longformer / BigBird
只选部分token做全局注意力，其余局部；部分token作为“全局锚点”，其余局部窗口；适合文档，但推理速度慢，开源大模型很少原生使用。

###3. GQA/MQA 不属于外推，是KV‑Cache显存优化
Grouped‑Query Attention，减少KV头数量，降低KV缓存显存占用，让你硬件能跑更长上下文；**不能解决模型本身位置外推能力，只是硬件能装下更长序列**。

## 四、无限上下文推理算法（StreamingLLM）
核心概念：**Sink Token（沉底token）**，保留开头几个关键token，循环淘汰最旧KV缓存，不存储全部历史KV。
- 可以无限长度对话；不修改模型权重，纯推理优化。
- 局限：久远历史会被丢弃，无法真正记忆全部无限内容，适合持续流式对话，不适合一次性长文档阅读理解。

## 五、工程替代方案：RAG检索‑生成（不用硬扩模型上下文）
对比外推技术：不修改Decoder、不调位置编码；超长文档切分成**文档片段Chunk**，检索召回相关片段，再把片段送入有限窗口。
> 权衡：
> - 硬做长度外推：模型需要直接读取全部长文本，对模型长距离记忆能力要求极高，外推越大，大海捞针召回准确率越低。
> - RAG：把长文档负担交给检索器，Decoder只处理少量相关片段；代价是依赖检索质量，存在检索漂移风险。

## 六、各方案对比表
|方案|是否修改权重|外推倍数|优点|缺点|
|---|---|---|---|---|
|原生RoPE直接外推|否|≈1.2‑1.5x|零成本|性能断崖下跌，几乎不可用|
|NTK‑Aware缩放|否|2‑4x|开箱即用|倍数过高长距离能力崩坏|
|YaRN|否|8‑32x|免调优，效果优秀|超大倍数依旧会衰减|
|ALiBi|预训练内置|理论无限|天然支持外推|不能直接移植给RoPE模型|
|PI+微调|✅微调|8‑16x|效果最好|需要长文本数据、算力|
|滑动窗口注意力|模型内置|总长度很大，但有效窗口受限|显存算力友好|超过窗口距离信息丢失|
|StreamingLLM|否|理论无限|无限对话流|久远历史被丢弃|
|RAG检索生成|否|不受模型窗口限制|工程落地成熟，可溯源|依赖Chunk切分、检索质量|

## 七、串联整套链路（从长文档到输出）
```
超长文档
方案A【硬外推路线】
原始长文本 → Tokenize → RoPE做YaRN/NTK外推 → Decoder‑Block(MHA+KV‑Cache) → 生成（可流式打字机输出）

方案B【RAG工程路线】
原始长文档 → 切文档片段Chunk → 向量库索引；
用户提问→检索召回TopK片段→组装Prompt送入Decoder原生窗口；Decoder生成输出。
```

> ⚠️关键误区：开启NTK/YaRN只是让模型“敢跑更长输入”，**不等于模型真的能精准记住几万token的遥远细节**。外推倍数越高，「大海捞针」准确率持续下降，这是现在大模型固有的缺陷。

## 八、面试极简总结
1. 长度外推：训练短序列，推理处理更长序列；瓶颈来自**位置编码 + O(n²)注意力复杂度**。
2. RoPE主流免训练方案：NTK、Dynamic‑NTK、YaRN，推理阶段修改旋转参数，不改动权重。
3. ALiBi在Attention分数上加距离惩罚，天然外推，但预训练就要确定架构。
4. 滑动窗口、StreamingLLM解决显存算力，但牺牲部分远距离信息。
5. RAG是工程替代方案，不需要硬扩模型外推能力。
