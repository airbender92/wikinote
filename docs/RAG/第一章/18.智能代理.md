# 智能代理（LLM‑Agent）
> 串联前面全部知识点：**Decoder大模型（大脑）、RAG检索、文档片段、知识图谱、流式输出、可解释性、长度外推**。
> Agent不是新型大模型，**是一套围绕Decoder‑Only大模型搭建的外部系统，赋予模型目标驱动、自主规划、调用外部工具、循环迭代执行任务的能力**。

普通大模型：收到输入，一次生成输出，**无状态，不会自己行动**。
Agent：接收目标，**拆解任务 → 选工具执行 → 观察结果 → 反思调整 → 循环直到完成目标**。

## 一、Agent四大核心组件
1. **大脑：LLM（Decoder‑Only大模型）**
负责理解、推理、任务拆解、决策；本身不做网络请求、数据库查询，只做思考与生成。

2. **记忆 Memory**（解决大模型无状态）
- **短期记忆（工作记忆）**：上下文窗口，保存本轮任务全部思考轨迹、工具返回结果，依赖Decoder上下文窗口、长度外推技术。
- **中期记忆**：会话摘要，把长历史压缩摘要，减少token占用。
- **长期记忆**：跨会话持久存储；两种实现：①向量库保存文本片段；②知识图谱保存实体、关系、用户偏好；需要时检索再注入Prompt。

3. **工具 Tools（Agent的手，对接外部世界）**
工具集合：RAG检索器、搜索引擎、SQL数据库、知识图谱查询、代码解释器、API调用、计算器。
> RAG、知识图谱在Agent中，只是**其中一个工具**，不等同Agent。

4. **规划与反思 Planning & Reflection**
- 规划：把复杂目标拆成多个子任务（CoT思维链）
- 反思：评估上一步结果是否达标；出错则重新规划、重试，而不是直接输出错误答案。

完整闭环：**思考(Thought) → 行动(Action，调用工具) → 观察(Observation，拿到工具返回) →（反思）循环直到任务完成**。

## 二、主流Agent范式
### 1. ReAct（Reason + Act，最经典）
`Thought → Action → Observation`循环，每一步思考后执行一个工具，拿到结果继续思考。
> 适合：多步问答、检索、简单工具调用。缺点：长任务容易漂移。

### 2. Plan‑and‑Execute（ReWOO）
**先一次性完整生成全部计划清单，再逐个执行子任务**，减少每一步推理开销。
适合：步骤固定的长任务；缺点：计划一旦错，后续全部执行出错。

### 3. Reflection反思型Agent
执行完一轮之后，LLM充当评审角色，找出错误、优化方案，多次迭代修正输出。适合高要求写作、数据分析。

### 4. Agentic‑RAG（检索增强智能体）
普通RAG流程固定：提问→检索一次→生成。
Agentic‑RAG：**Agent自主决策：要不要检索？检索几次？改写查询？是否调用知识图谱？结果够不够用，不够继续搜**。

### 5. Multi‑Agent多智能体
多个角色Agent分工协作：规划Agent、检索Agent、验证Agent、写作Agent，互相传递消息协同完成复杂任务。

## 三、完整运行链路（串联全部前置知识点）
```
用户目标输入
↓
读取长期记忆（向量库/知识图谱），把相关历史注入上下文
↓
【LLM Decoder做规划】拆解任务，确定下一步要做什么
↓
选择工具：RAG检索 / KG图谱查询 / 搜索 / SQL / 计算器
  如果调用RAG：文档片段Chunk召回、重排，返回片段文本
  如果调用知识图谱：生成Cypher查询，拿到结构化三元组结果
↓
Observation观察，把工具返回结果放回上下文
↓
反思判断：任务完成？信息充足？
  ❌不充足 → 回到规划，继续循环
  ✅完成 → 组装最终Prompt送入Decoder
↓
Decoder自回归生成，流式打字机输出答案
↓
把本次任务关键信息写入长期记忆；输出附带溯源（可解释性）
```

> 注意：工具返回全部结果，都以文本形式拼入Decoder输入；**向量、图数据库查询结果不会直接输入模型，全部转为文本token**。
> 如果循环轮次多，上下文会变长，此时依赖长度外推/或者记忆摘要压缩，避免打满窗口。

## 四、关键对比
### Agent vs RAG
|RAG|Agent|
|---|---|
|主要解决：私有文档知识获取|解决：复杂多步目标、自主工具调用、迭代完成任务|
|流程固定：提问→检索一次→生成|自主决策：可多次检索，也可以选择不检索，还可调用其他工具|
|RAG可以作为Agent其中一个工具|Agent包含RAG，但远不止RAG|

### Agent vs 普通工作流
- **工作流**：步骤硬编码，顺序写死，不会自主改流程。
- **Agent**：由LLM动态决定下一步动作，可以动态分支、重试、换工具。

## 五、Agent系统现存痛点
1. **规划漂移**：循环轮次变多，Agent偏离原始目标；
2. **工具幻觉**：虚构工具参数，错误调用；
3. **上下文爆炸**：多次工具调用，轨迹全部存入上下文，消耗大量token，依赖长度外推或记忆压缩；
4. **不可控、不可预测**：自主决策带来不确定性，生产环境需要校验层；
5. **可解释性难度上升**：需要保存完整思考轨迹、工具调用记录作为审计依据。

## 六、整套大模型应用技术栈串联总结（面试完整链条）
1. **底座**：Decoder‑Only大模型（Masked自注意力、Pre‑LN、FFN、RoPE位置编码；长度外推NTK/YaRN处理长输入）
2. **知识获取层**
    - RAG：文档分片Chunk、向量库检索、重排；
    - 知识图谱：实体‑关系‑三元组，图数据库做结构化推理；
3. **系统层：Agent智能代理**：记忆、规划、工具调用、循环闭环；把RAG、KG都作为工具；
4. **输出层**：Decoder自回归生成，流式输出（打字机效果）；
5. **可信层：可解释性**：注意力/输入贡献度、RAG片段溯源、图谱三元组溯源、Agent思考轨迹日志。

> 极简一句话记忆：
> Decoder是大脑；RAG、知识图谱是知识库工具；Agent是调度大脑、工具、记忆完成复杂目标的执行框架；流式输出是生成时的返回方式；可解释性保证可信；长度外推解决上下文过长。
