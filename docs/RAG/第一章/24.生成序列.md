# 生成序列（Generated Sequence）
结合你前面问的 Decoder、流式输出、RAG、Agent，一句话：
**生成序列 = Decoder 自回归一步一步输出的 token 序列，也就是模型最终打出的整段文字。**

---

## 一、直观理解
- 输入：Prompt（问题 + 检索片段）
- 输出：`[token₁, token₂, token₃, ..., tokenₙ]`
这串按顺序输出的 token，就是**生成序列**。

比如你问：1+1等于几
模型输出：`2`
→ 生成序列就是 `[2]`

长一点的对话：
`我` → `我是` → `我是一` → `我是一个` → `我是一个AI`
每一步追加 token，最终形成完整序列。

---

## 二、和 Decoder 结构的关系
Decoder 本质就是**序列生成器**：
1. 输入当前已有的序列
2. 预测下一个 token
3. 把新 token 拼到序列末尾
4. 重复直到停止

所以：
- Decoder 的核心任务，就是**不断延长生成序列**
- 生成序列的长度 = 模型要跑多少步自回归

---

## 三、和你前面知识点的串联

### 1. 与流式输出（打字机模式）
- 生成序列是**完整结果**
- 流式输出是**生成序列的实时推送过程**
每生成一个 token，就立刻推给前端，而不是等整段序列完成。

### 2. 与 RAG、文档片段
检索回来的片段是**输入序列**的一部分，
模型基于它**扩展出答案生成序列**。

### 3. 与长度外推
生成序列越长，越容易超出训练长度，
需要 NTK、YaRN、滑动窗口等策略保证质量。

### 4. 与吞吐量
吞吐量 = 单位时间内生成的**总 token 数**
也就是所有请求的生成序列长度之和。

### 5. 与可解释性
可以分析：
- 生成序列里每个 token 来自哪些输入 token
- 引用了哪些文档片段、知识图谱三元组

### 6. 与 Agent
Agent 的思考过程、工具调用记录，
本质也是一段**内部生成序列**。

---

## 四、控制生成序列的关键参数
- `max_new_tokens`：最大生成序列长度
- `temperature`：随机性，影响序列多样性
- `top_p / top_k`：控制候选 token 范围
- `stop`：遇到哪些词就停止序列生成
- `repetition_penalty`：防止重复 token

---

## 五、极简总结
**生成序列 = Decoder 自回归输出的一串 token，就是模型的回答本身。**
- 流式输出：边生成边推
- 长度外推：解决序列过长问题
- 吞吐量：看每秒能生成多少 token
- 可解释性：看序列里每一步依据什么
