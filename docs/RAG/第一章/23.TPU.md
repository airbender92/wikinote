# TPU（Tensor Processing Unit）
简单说：**TPU 是谷歌专门为张量（矩阵）计算设计的 AI 专用芯片**，用来加速神经网络训练和推理，对标 NVIDIA GPU。

和你前面问的大模型技术栈高度相关，我用最精炼、面试够用的方式讲。

---

## 一、TPU 是什么
- 全称：**Tensor Processing Unit**
- 谷歌自研，**专为深度学习设计的 ASIC 专用芯片**
- 主要跑谷歌框架：TensorFlow、JAX
- 云服务：Google Cloud TPU（v2/v3/v4/v5e）

核心定位：
**高吞吐、高矩阵计算效率、适合大规模分布式训练**。

---

## 二、TPU vs GPU（核心区别）
|  | TPU | GPU |
|--|--|--|
| 设计目标 | 张量计算、高吞吐、大模型分布式训练 | 通用并行计算，兼顾图形、AI、科学计算 |
| 显存/内存 | 超大带宽，**高带宽内存 HBM** | 显存大、生态极强 |
| 精度 | 主打 **bfloat16**，对训练友好 | FP16/FP8/INT 等更全 |
| 生态 | 谷歌系：JAX/TensorFlow | 极全：PyTorch、Transformers、vLLM 等 |
| 擅长场景 | 超大模型预训练、大规模分布式 | 推理、微调、RAG、Agent、科研 |
| 易用性 | 复杂，集群化使用 | 简单，单机就能跑 |

一句话：
**TPU 适合大厂训超大规模模型；GPU 适合几乎所有落地场景（RAG、推理、微调、开发）。**

---

## 三、TPU 核心架构特点
1. **脉动阵列（Systolic Array）**
   专门加速矩阵乘法（GEMM），大模型里的 **Linear、Attention 核心计算** 全靠它。

2. **bfloat16 为主**
   对训练稳定性更好，TPU 硬件原生支持。

3. **超高互联带宽**
   适合 **超大集群分布式训练**，如 PaLM、Gemini 这种万亿级模型。

4. **高吞吐、但不一定低延迟**
   TPU 追求**吞吐量**，不是单卡低延迟，更适合训练，不太适合低延迟在线推理。

---

## 四、和你前面知识点的关联
- **Decoder 大模型训练**：TPU 最擅长大规模 Transformer 训练
- **吞吐量 Throughput**：TPU 设计目标就是高吞吐
- **伸缩法则 Scaling Laws**：谷歌大量实验跑在 TPU 集群上
- **推理、RAG、Agent**：基本不用 TPU，GPU 更灵活、生态更好
- **量化、流式输出**：TPU 支持有限，GPU 生态成熟

---

## 五、极简总结（面试版）
- **TPU = 谷歌专用 AI 芯片，ASIC 架构，主打张量计算与大规模训练**。
- 优势：**高吞吐、大规模分布式训练强、bfloat16 友好**。
- 劣势：生态窄，主要支持 TensorFlow/JAX，不适合日常推理、RAG、开发。
- 现实分工：
  - 超大规模预训练 → TPU
  - 微调、推理、RAG、Agent、落地 → GPU
