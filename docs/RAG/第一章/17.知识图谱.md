# 知识图谱（Knowledge Graph）
结合你前面问的 **Decoder、RAG、文档片段、可解释性**，知识图谱就是**把知识结构化、网络化、可推理**的一种表示方式，用来解决大模型**记不住、理不清、推不出、不可信**的问题。

---

## 一、一句话定义
**知识图谱 = 用「实体-关系-实体」三元组来描述世界的结构化知识库。**

例子：
- （苹果公司，创始人，史蒂夫·乔布斯）
- （李白，朝代，唐朝）
- （高血压，并发症，脑卒中）

它不是一段文本，而是**点和边构成的图**：
- 点：实体（人、物、概念、事件）
- 边：关系（属性、动作、关联）

---

## 二、和大模型、RAG 的关系
### 1. 知识图谱 vs 大模型内部知识
- 大模型：知识存在**权重矩阵**里，黑箱、不可编辑、容易幻觉
- 知识图谱：知识存在**三元组/图数据库**里，显性、可查、可改、可解释

### 2. 知识图谱 + RAG = 增强版检索生成
普通 RAG：
- 从**文档片段**里做语义检索
- 优点：简单通用
- 缺点：逻辑弱、关系弱、容易抓错片段

知识图谱增强 RAG（KG-RAG）：
- 先用图谱做**逻辑推理、关联查询**
- 再把结果当“结构化知识”喂给 Decoder
- 答案更严谨、可溯源、少幻觉

---

## 三、典型结构
### 三元组（Triple）
```
(头实体 Head, 关系 Relation, 尾实体 Tail)
```

### 上层：本体（Ontology）
定义规则：
- 类别：人、公司、疾病、药品
- 约束：疾病→并发症→疾病；药品→治疗→疾病

### 下层：实例数据
- 张三，患有，高血压
- 阿司匹林，治疗，发热

---

## 四、在大模型系统里的四大用途
### 1. 知识精准注入
- 不让模型瞎编，强制从图谱里取事实
- 适合金融、法律、医疗、工业等**强合规场景**

### 2. 多跳逻辑推理（大模型弱项）
比如问：
> “和A公司同属一个集团，且在同一行业的竞争对手有哪些？”

大模型容易乱推；
知识图谱可以**沿着关系边跳 2～3 层**精准找到答案。

### 3. 可解释性拉满
- 答案每条都能标出：**来自哪个三元组、哪条边、哪个节点**
- 完全满足审计、合规、溯源需求
- 比纯文本 RAG 的可解释性更强、更结构化

### 4. 对话长程记忆
把用户信息、历史意图、实体状态存在图谱里，
实现**多轮对话下的持续上下文理解**。

---

## 五、和 Decoder 大模型怎么结合？
### 模式1：图谱引导生成（最常用）
1. 用户问题 → 大模型理解意图
2. 自动生成 **Cypher / SPARQL 查询语句**
3. 在图数据库（Neo4j、NebulaGraph）中查询
4. 取回结构化知识 → 拼成 Prompt
5. Decoder 生成最终答案

流程：
```
用户问题 → 意图解析 → 图谱查询 → 知识回填 → Decoder 生成
```

### 模式2：知识图谱增强注意力
在注意力层显式引入图谱结构，让模型**优先关注相关实体**
减少无关文本干扰，提升长文本、多实体场景效果。

### 模式3：用大模型自动构建知识图谱
- 文本 → 大模型抽取实体、关系
- 自动构建/更新知识图谱
- 解决传统图谱构建成本高、更新慢的问题

## 六、知识图谱 vs 向量检索（RAG）
|  | 知识图谱 KG | 向量检索 RAG |
|--|--|--|
| 表示 | 结构化三元组、图 | 非结构化文档片段 |
| 匹配 | 符号匹配、逻辑推理 | 语义相似度 |
| 推理 | 支持多跳、规则推理 | 基本无推理，靠大模型 |
| 可解释性 | 极强，可溯源到三元组 | 一般，只能定位片段 |
| 维护成本 | 高，需本体、清洗 | 低，直接分片入库 |
| 幻觉 | 极低 | 较高 |

一句话总结：
**RAG 擅长找相关文本，KG 擅长讲清逻辑与事实。**

---

## 七、和你前面知识点串联
- **Decoder**：只负责最后自然语言生成，知识来自图谱而不是纯参数记忆
- **文档片段**：可以先抽取成图谱，再检索，比纯文本更精准
- **可解释性**：图谱天然可解释，是目前最可靠的方案
- **长度外推**：用图谱后，不需要喂超长文本，减轻上下文压力
- **流式输出**：图谱查询完成后，再逐token流式打出答案

---

## 八、极简总结
- 知识图谱 = **实体-关系-实体**构成的结构化、可推理、可解释知识库
- 解决大模型**幻觉、不可信、推理弱**问题
- 与 RAG 互补：**RAG 管文本语义，KG 管逻辑事实**
- 工业落地常用：**KG + RAG + Decoder** 混合架构，效果最稳
