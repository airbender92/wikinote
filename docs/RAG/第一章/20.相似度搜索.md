# 相似度搜索（Similarity Search）
结合你前面问的 **RAG、文档片段、向量库、知识图谱、Agent**，相似度搜索就是：
**把文本变成向量，在海量向量里快速找到最相似的Top-K条**，是检索-生成系统的核心检索方式。

---

## 一、一句话核心逻辑
1. 文档片段 → 用 Embedding 模型 → 高维稠密向量
2. 用户问题 → 同样 Embedding → 查询向量
3. 在向量库中计算**距离/相似度**
4. 返回最相似的文档片段

它解决的问题：
- 传统关键词搜索：不理解语义，缺一个词就搜不到
- 相似度搜索：**按意思匹配，不是按字匹配**

---

## 二、常用相似度 / 距离度量
### 1. 余弦相似度（最常用）
- 只看**方向**，不看长度
- 适合文本、语义检索
- 范围 [-1, 1]，越大越相似

### 2. 内积（Dot Product）
- 余弦相似度的变种，向量归一化后等价
- 很多向量库默认用它加速

### 3. 欧氏距离 L2
- 看空间直线距离
- 距离越小越相似
- 推荐、特征匹配常用

### 4. 曼哈顿距离 L1
- 少用在文本检索，多用于异常检测

---

## 三、检索方式分类
### 1. 精确搜索（Brute-force）
- 挨个算相似度，结果100%准确
- 速度 O(N)，数据量大卡死
- 只适合小库

### 2. 近似最近邻 ANN（工业标准）
Approximate Nearest Neighbor
- 牺牲一点点精度，换**百万/千万级秒级检索**
- 主流索引算法：
  - HNSW（现在最常用，效果好、速度快）
  - IVF（FAISS 经典）
  - PQ 量化（压缩向量）

### 3. 混合检索（最强落地）
- **向量检索 + 关键词检索（BM25）**
- 各自召回，再融合重排
- 兼顾语义 + 精确词匹配

---

## 四、完整 RAG 相似度搜索流程
```
文档 → 切分Chunk → Embedding → 向量存入向量库
用户问题 → Embedding → 查询向量
→ ANN相似度搜索 → Top-N文档片段
→ Rerank重排 → Top-K
→ 拼Prompt → Decoder生成答案
```

---

## 五、和前面知识点串联
- **文档片段 Chunk**：相似度搜索的最小单元
- **RAG**：相似度搜索是RAG的“心脏”
- **Decoder**：只接收检索后的文本，不参与向量计算
- **Agent**：相似度搜索是Agent最常用的工具之一
- **可解释性**：返回结果带来源，天然可追溯
- **长度外推**：检索后只喂少量片段，减轻上下文压力

---

## 六、极简总结
- 相似度搜索 = **语义检索**，靠向量匹配意思
- 核心：Embedding + 向量库 + ANN（HNSW）
- 是 RAG、推荐系统、知识库问答的基础
- 关键词搜不到的，相似度搜索往往能搜到
