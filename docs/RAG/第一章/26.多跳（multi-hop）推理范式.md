# 多跳推理（Multi-hop Reasoning）范式
一句话：
**通过多步关联、层层推导，从分散在不同地方的知识里推出答案，而不是靠单条信息直接回答。**

---

## 一、通俗理解
- **单跳**：问“李白是哪个朝代的”→ 直接查一条知识就出答案
- **多跳**：问“《静夜思》的作者生活在哪个盛世”
  1. 先找《静夜思》作者 → 李白
  2. 再找李白所处朝代 → 唐朝
  3. 再找唐朝对应的盛世 → 开元盛世
  这**三步跳转**，就是 multi-hop。

多跳 = 走**关系路径**：
实体1 → 关系 → 实体2 → 关系 → 实体3 → … → 答案

---

## 二、典型范式（面试常考）
### 1. 大模型原生多跳（Chain-of-Thought, CoT）
- 模型自己一步步写推理过程
- 优点：简单通用
- 缺点：容易跳步、编造事实、不可信

### 2. 知识图谱多跳（最经典、最可解释）
- 在图上沿着**实体-关系**路径遍历
- 比如：
  病人 → 诊断 → 疾病 → 并发症 → 风险 → 用药禁忌
- 优点：路径可追溯、完全可解释、几乎无幻觉
- 缺点：依赖图谱质量，覆盖不如文本

### 3. RAG 多跳检索（检索式多跳）
1. 根据问题检索第一轮文档片段
2. 用初步结果**生成新的查询**
3. 再检索第二轮、第三轮
4. 汇总所有片段推理答案
也就是你之前问的 **Agentic-RAG**。

### 4. 模块式多跳（Pipeline）
- 拆解模块：意图识别 → 子问题生成 → 检索 → 验证 → 合成
- 工业常用，可控、可审计

---

## 三、和你前面知识点的串联
- **Decoder**：负责生成推理步骤、子问题、最终答案
- **RAG & 文档片段**：每一跳都要召回相关 chunk
- **知识图谱**：天然最适合多跳，路径就是推理链条
- **可解释性**：多跳路径 = 推理依据，完美满足合规溯源
- **Agent**：Agent 核心能力就是自主多跳推理
- **相似度搜索**：每一跳都要做向量检索
- **熵**：跳数越多，熵越高，越容易出错

---

## 四、难点（高频考点）
1. **跳数越多误差累积越严重**
   一步错，步步错
2. **查询分解难度大**
   模型不知道该拆成几个子问题
3. **检索漂移**
   越往后越偏离原始问题
4. **长上下文压力**
   多跳历史需要放进 Decoder 上下文

---

## 五、极简总结
**多跳推理 = 分步串联多个证据，形成推理链得出答案。**
- 知识图谱：路径式多跳（最可解释）
- RAG：多轮检索式多跳
- LLM：思维链 CoT 多跳
- Agent：自主规划多跳
