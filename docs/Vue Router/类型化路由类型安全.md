## 类型化路由：确保 `params` 和 `query` 类型安全

在 Vue Router 中，`params` 和 `query` 默认都是 `Record<string, string | string[]>` 类型。这意味着即使你期望一个数字 ID，从 `route.params.id` 拿到的也是 `string` 或 `undefined`，容易引发运行时类型错误。通过 TypeScript 我们可以为路由参数提供**强类型约束**，让编译器在编写代码时就检查参数的正确性。

---

### 1. 核心问题演示

```typescript
// 路由配置：期望 id 为数字
{ path: '/user/:id', name: 'user', component: UserView }

// 组件内
const route = useRoute()
const id = route.params.id   // 类型是 string | string[]，但业务需要 number
const numericId = Number(id)  // 需要手动转换
```

同样，跳转时也可能传错类型：
```typescript
router.push({ name: 'user', params: { id: 'abc' } })  // 本应是数字字符串，但 'abc' 也能通过类型检查
```

---

### 2. 解决方案总览

| 方法                               | 适用场景                                     | 类型安全程度 |
| ---------------------------------- | -------------------------------------------- | ------------ |
| **`props: true` + 组件 props 类型** | 简单路由，将 params 映射为组件 props         | 高（组件内） |
| **模块增强（RouteNamedMap）**       | 全局类型安全，`push`/`replace` 自动推断参数  | 高（全链路） |
| **自定义 useTypedRoute Hook**       | 灵活，无需修改路由库声明                     | 中等         |
| **运行时校验 + 类型断言**           | 快速修复，但易出错                           | 低           |

推荐**优先使用 `props: true` + 组件 props 类型**，再配合**模块增强**实现全项目统一类型约束。

---

### 3. 方案一：`props: true` 将 `params` 转为组件 props

开启 `props: true` 后，路由参数会作为组件的 props 传入，从而利用 Vue 的 props 类型校验。

#### 路由配置
```typescript
// router/index.ts
const routes = [
  {
    path: '/user/:id',
    name: 'user',
    component: () => import('@/views/UserView.vue'),
    props: true   // 关键：将 params.id 作为 props.id 传入
  }
]
```

#### 组件内声明 props 类型
```vue
<!-- UserView.vue -->
<script setup lang="ts">
// 声明 props 类型，id 会被自动转换为字符串（但可以进一步处理）
const props = defineProps<{
  id: string   // 虽然 params 是字符串，但可以转为 number 使用
}>()

// 如果需要数字，可以这样：
const numericId = Number(props.id)
</script>
```

**优点**：组件内 `props.id` 有明确的类型，无需 `useRoute`。  
**缺点**：`query` 参数无法通过这种方式处理；且 `props` 只能接收 `params`（以及 `props: true` 时），`query` 仍需手动处理。

---

### 4. 方案二：模块增强（`RouteNamedMap`）—— 全链路类型安全

Vue Router 4 支持通过 **TypeScript 模块增强** 为命名路由定义精确的 `params` 和 `query` 类型。

#### 步骤 1：创建类型声明文件 `router/types.ts`（或直接在 `router/index.ts` 中写）

```typescript
// router/types.ts
import 'vue-router'

declare module 'vue-router' {
  interface RouteNamedMap {
    // 键是路由的 name，值定义 params 和 query 的预期类型
    'user': {
      params: { id: string }    // id 必须是字符串（实际 URL 中就是字符串）
      query?: { tab?: string; page?: number }  // query 可选，page 可以是 number（但传递时会转为字符串，此处仅约束你传参时的类型）
    }
    'product': {
      params: { productId: string }
      query?: { sort?: 'asc' | 'desc' }
    }
    'login': {
      params: {}
      query?: { redirect?: string }
    }
  }
}
```

> 注意：`query` 中的 `number` 类型在调用 `router.push` 时会被自动转为字符串，但类型定义允许你写数字，它会经过 `String()` 转换。

#### 步骤 2：在 `router/index.ts` 中导入该声明（只需确保被包含）

```typescript
// router/index.ts
import './types'   // 导入增强声明
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(),
  routes: [
    { path: '/user/:id', name: 'user', component: () => import('@/views/UserView.vue') },
    { path: '/product/:productId', name: 'product', component: () => import('@/views/ProductView.vue') }
  ]
})
```

#### 步骤 3：使用时的类型安全

```typescript
// 在任意组件中
import { useRouter } from 'vue-router'
const router = useRouter()

// ✅ 正确：params 必须包含 id 且为 string
router.push({ name: 'user', params: { id: '123' }, query: { page: 2 } })

// ❌ 类型错误：缺少 params.id
router.push({ name: 'user', query: { page: 1 } })

// ❌ 类型错误：params.id 必须是 string 不能是 number
router.push({ name: 'user', params: { id: 123 } })

// ✅ 可以：product 路由
router.push({ name: 'product', params: { productId: 'abc' }, query: { sort: 'asc' } })
```

同时，在组件内使用 `useRoute` 时，`route.params` 和 `route.query` 也会获得对应的类型（需要确保路由的 name 被正确推断，通常需要配合 `const route = useRoute('user')` 这种形式，但 Vue Router 的类型暂时不支持泛型参数。可以使用辅助函数）。

### 5. 方案三：自定义 `useTypedRoute` Hook

在不修改全局声明的情况下，可以封装一个带泛型的 `useTypedRoute`。

```typescript
// composables/useTypedRoute.ts
import { useRoute } from 'vue-router'
import type { RouteNamedMap } from '@/router/types'  // 导入之前定义的映射

export function useTypedRoute<T extends keyof RouteNamedMap>(name?: T) {
  const route = useRoute()
  if (name && route.name !== name) {
    // 可选：运行时警告
    console.warn(`Expected route ${name} but got ${route.name as string}`)
  }
  return {
    params: route.params as RouteNamedMap[T]['params'],
    query:  route.query as RouteNamedMap[T]['query']
  }
}
```

使用：
```vue
<script setup lang="ts">
const { params, query } = useTypedRoute('user')
console.log(params.id)   // 类型为 string
console.log(query.page)  // 类型为 string | undefined（但原始定义允许 number？需注意）
</script>
```

### 6. 方案四：手动类型断言与运行时转换（不推荐）

```typescript
const route = useRoute()
const id = Number(route.params.id as string)
if (isNaN(id)) {
  // 处理错误
}
```

这种方法仅作为快速修复，无法提供编译时检查，容易遗漏错误。

---

### 7. 处理 `query` 参数的类型转换

`query` 参数在 URL 中总是字符串，但业务逻辑往往需要数字、布尔值等。推荐在获取时进行转换：

```typescript
// 定义类型工具
function getNumberQuery(query: Record<string, unknown>, key: string, defaultValue: number): number {
  const val = query[key]
  return typeof val === 'string' ? Number(val) || defaultValue : defaultValue
}

// 使用
const page = getNumberQuery(route.query, 'page', 1)
```

或者使用 Zod 等运行时校验库。

---

### 8. 最佳实践总结

1. **为每个命名路由定义 `RouteNamedMap`**，集中管理参数类型。这是目前最先进的全链路类型安全方案。
2. **开启 `props: true`**，将 `params` 映射为组件 props，并利用 `defineProps` 进行类型约束（简单场景首选）。
3. **避免在代码中直接书写路径字符串**，始终使用 `name` 配合 `params`/`query`，以享受类型检查。
4. **对于 `query` 参数**，建议定义类型并在取值时进行显式转换，或使用工具函数。
5. **如果使用组合式 API**，可以封装 `useRouteParams`、`useRouteQuery` 等辅助函数，内部进行类型转换和默认值处理。

```typescript
// 示例：useRouteParam 辅助函数
import { useRoute } from 'vue-router'
function useRouteParam<T extends string>(key: string): T {
  const route = useRoute()
  return route.params[key] as T
}
// 使用
const id = useRouteParam<string>('id')
```

通过以上方法，你可以让 Vue Router 中的路由参数变得像强类型语言的函数参数一样可靠，大幅减少因参数类型错误导致的运行时 bug。
