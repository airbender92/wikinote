## 内存历史模式：`createMemoryHistory()`

`createMemoryHistory()` 是 Vue Router 提供的一种**不操作浏览器 URL** 的历史记录模式。它内部维护一个数组来模拟浏览器的历史栈，路由的变化完全发生在内存中，不会导致地址栏更新，也不会触发浏览器的导航行为。

### 1. 核心特点

| 特性               | 说明                                                                 |
| ------------------ | -------------------------------------------------------------------- |
| **无 URL 同步**    | 地址栏始终不变，路由状态完全由内存中的栈管理                         |
| **无前进/后退**    | 浏览器的前进后退按钮无效（但可以通过 `router.go()` 等方法手动控制）  |
| **无服务器依赖**   | 不需要配置服务器 fallback，因为不依赖真实路径                        |
| **初始状态可配置** | 可以传入初始的 URL 条目，方便测试或预渲染                            |

### 2. 适用场景

- **服务端渲染（SSR）**：在 Node.js 环境中没有 `window.location` 和 `history` API，必须使用内存模式。Nuxt、Next (Vue) 等框架在服务端默认使用内存历史模式。
- **单元/集成测试**：在 Jest、Vitest 等测试框架中，避免真实的浏览器环境干扰。
- **非浏览器环境**：如 Electron 主进程、Web Worker、移动端 WebView（不依赖 URL 时）。
- **嵌套路由的独立组件测试**：当需要测试依赖路由的组件，但又不想引入完整路由环境时。

### 3. 基本用法

```javascript
import { createRouter, createMemoryHistory } from 'vue-router'

const routes = [
  { path: '/', component: Home },
  { path: '/about', component: About }
]

const router = createRouter({
  history: createMemoryHistory(),        // 使用内存历史模式
  routes
})

// 可以设置初始 URL（可选，默认 '/'）
// 例如：createMemoryHistory('/initial')
```

#### 初始位置
```javascript
const router = createRouter({
  history: createMemoryHistory('/start'),
  routes
})
console.log(router.currentRoute.value.path) // '/start'
```

#### 在测试中的典型使用（Vitest）
```javascript
import { describe, it, expect } from 'vitest'
import { mount } from '@vue/test-utils'
import { createRouter, createMemoryHistory } from 'vue-router'
import App from './App.vue'

describe('routing test', () => {
  it('renders home page', async () => {
    const router = createRouter({
      history: createMemoryHistory(),
      routes: [{ path: '/', component: Home }]
    })
    router.push('/')
    await router.isReady()
    const wrapper = mount(App, { global: { plugins: [router] } })
    expect(wrapper.html()).toContain('Home')
  })
})
```

### 4. 与其他历史模式的对比

| 模式                   | URL 表现                        | 适用环境                 | 服务器配置 |
| ---------------------- | ------------------------------- | ------------------------ | ---------- |
| `createWebHistory`     | 干净的路径（如 `/about`）       | 浏览器，需要配置 fallback | 需要       |
| `createWebHashHistory` | 带 `#` 的路径（如 `/#/about`）  | 浏览器，无需额外配置     | 不需要     |
| `createMemoryHistory`  | 不改变地址栏                    | Node.js / 测试 / 非浏览器 | 不需要     |

### 5. 在 SSR 中的工作原理（以 Nuxt 为例）

在 Nuxt 或自研 SSR 方案中：

- **服务端**：使用 `createMemoryHistory()`，根据请求的 URL 初始化路由，渲染出 HTML 字符串。
- **客户端**：在 `mount` 前，将内存模式替换为 `createWebHistory()`，并同步服务端传递的初始路由状态，实现 hydration。

手动实现简单 SSR 时：
```javascript
// server.js
import { createRouter, createMemoryHistory } from 'vue-router'
import { renderToString } from 'vue/server-renderer'

const router = createRouter({
  history: createMemoryHistory(req.url),   // 根据请求 URL 设置初始位置
  routes
})
await router.push(req.url)
await router.isReady()
const appHtml = await renderToString( ... )
```

### 6. 注意事项

- 使用内存模式时，**不要尝试通过浏览器的刷新或直接输入 URL 来访问深层路径**，因为地址栏不会改变，刷新总会从初始路径开始。
- 在测试中，务必在每次测试前重新创建路由器实例，避免状态污染。
- 内存模式不适用于需要 SEO 的纯前端项目，因为搜索引擎爬虫无法获取真实的路由内容（除非配合 SSR）。

### 总结

`createMemoryHistory()` 是 Vue Router 为**非浏览器环境**和**测试场景**专门设计的轻量级历史模式。它让你可以在 Node.js、测试框架等环境中完全使用路由功能，而不依赖真实的 DOM 和浏览器 API。在 SSR 中，它是连接服务端请求和客户端渲染的关键桥梁。
