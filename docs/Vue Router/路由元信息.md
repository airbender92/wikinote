## 路由元信息与数据获取

`meta` 字段是 Vue Router 路由配置中的一个**自由存储区域**，用于挂载与路由相关的自定义数据（如页面标题、权限角色、布局配置、缓存标记等）。结合数据获取时，通过 `meta` 可以灵活切换**导航前获取数据**和**导航后获取数据**两种策略。

---

### 1. 路由元信息：`meta` 的定义与使用

在路由配置中添加 `meta` 对象：

```javascript
const routes = [
  {
    path: '/dashboard',
    name: 'dashboard',
    component: () => import('@/views/Dashboard.vue'),
    meta: {
      title: '控制台',
      requiresAuth: true,
      roles: ['admin', 'editor'],
      keepAlive: true,
      preloadData: true   // 自定义标记：导航前预加载数据
    }
  },
  {
    path: '/user/:id',
    name: 'user',
    component: () => import('@/views/UserProfile.vue'),
    meta: { title: '个人资料' }
  }
]
```

#### 在守卫或组件中读取
```javascript
// 全局守卫中读取 meta
router.beforeEach((to, from, next) => {
  document.title = to.meta.title || '默认标题'
  
  if (to.meta.requiresAuth && !isLoggedIn()) {
    next('/login')
  } else {
    next()
  }
})
```

```vue
<!-- 组件内组合式 API -->
<script setup>
import { useRoute } from 'vue-router'
const route = useRoute()
console.log(route.meta.title)
</script>
```

> **注意**：`meta` 字段中的属性可以是任意类型，但建议保持扁平化，避免过深的对象嵌套。

---

### 2. 数据获取的两种策略

根据数据获取的时机，分为**导航前获取**（在路由守卫中执行）和**导航后获取**（在组件内执行）。两者没有绝对优劣，取决于场景需求。

| 策略               | 执行时机                 | 用户体验                         | 适用场景                                 |
| ------------------ | ------------------------ | -------------------------------- | ---------------------------------------- |
| **导航前获取**     | 路由守卫中，跳转完成前   | 页面切换有短暂等待（可加 loading） | 数据必须就绪才能渲染页面（如详情页）     |
| **导航后获取**     | 组件已渲染后，在 `setup` 或 `onMounted` 中 | 先显示空白/骨架屏，数据到达后填充 | 数据不影响首屏结构，或可接受异步加载     |

---

### 2.1 导航前获取数据：在守卫中预加载

使用 `beforeEnter` 或全局 `beforeEach`，配合 `meta` 标记来决定哪些路由需要预加载。

```javascript
// 为需要预加载的路由定义标记
const routes = [
  {
    path: '/product/:id',
    name: 'product',
    component: ProductDetail,
    meta: { preload: true }
  }
]

// 路由独享守卫
beforeEnter: async (to, from, next) => {
  try {
    const data = await fetchProduct(to.params.id)
    // 将数据暂存到 store 或路由的 props 中
    store.commit('setProduct', data)
    next()
  } catch (error) {
    next('/error')
  }
}
```

**优点**：数据在页面切换前已准备完毕，进入组件即可直接渲染，无额外加载态。  
**缺点**：用户必须等待全部数据加载完成才能看到新页面，适合关键数据。

**全局实现示例（结合 meta）**：
```javascript
router.beforeEach(async (to, from, next) => {
  if (to.meta.preloadData) {
    const loading = showGlobalLoading()   // 开启全局加载动画
    try {
      await fetchDataForRoute(to)
      next()
    } finally {
      loading.close()
    }
  } else {
    next()
  }
})
```

### 2.2 导航后获取数据：在组件内获取

组件渲染后，在生命周期钩子中发起请求，先显示占位内容。

```vue
<script setup>
import { ref, onMounted } from 'vue'
import { useRoute } from 'vue-router'
import { fetchUser } from '@/api'

const route = useRoute()
const user = ref(null)
const loading = ref(false)

onMounted(async () => {
  loading.value = true
  try {
    user.value = await fetchUser(route.params.id)
  } finally {
    loading.value = false
  }
})
</script>

<template>
  <div v-if="loading">加载中...</div>
  <div v-else-if="user">{{ user.name }}</div>
  <div v-else>未找到用户</div>
</template>
```

**优点**：页面切换快，可配合骨架屏；不阻塞路由动画。  
**缺点**：组件可能因数据未到而显示空白或闪烁。

---

### 2.3 根据 `meta` 标记动态选择策略

在路由守卫中通过 `meta` 字段决定是否等待数据，在组件内通过相同标记决定是否再次请求。

**全局守卫策略**：
```javascript
router.beforeEach(async (to, from, next) => {
  // 标记为 preload 的路由，导航前获取数据并存入 store
  if (to.meta.preload) {
    await store.dispatch('fetchDataForRoute', to)
  }
  next()
})
```

**组件内策略**（避免重复加载）：
```vue
<script setup>
import { onMounted } from 'vue'
import { useRoute, onBeforeRouteUpdate } from 'vue-router'
import { useStore } from 'vuex'

const route = useRoute()
const store = useStore()

const loadData = async () => {
  // 如果路由标记 preload，数据已在 store 中，可考虑不再请求
  if (!route.meta.preload) {
    await store.dispatch('fetchDataForRoute', route)
  }
}

onMounted(loadData)
onBeforeRouteUpdate(loadData)  // 参数变化时重新获取
</script>
```

### 3. 结合 `meta` 的其他实践

- **缓存控制**：`meta.keepAlive: true` 配合 `<keep-alive>` 缓存组件。
- **面包屑**：`meta.breadcrumb: '用户管理'` 自动生成面包屑导航。
- **布局切换**：`meta.layout: 'admin'` 动态渲染不同布局组件。
- **滚动行为定制**：`meta.scrollToTop: false` 控制路由切换时是否滚动到顶部。

```javascript
// 滚动行为与 meta 结合
const router = createRouter({
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) return savedPosition
    if (to.meta.scrollToTop === false) return {}
    return { top: 0 }
  }
})
```

---

### 4. 总结与选型建议

| 场景                               | 推荐策略               | 利用 `meta` 标记                    |
| ---------------------------------- | ---------------------- | ----------------------------------- |
| 核心详情页（依赖完整数据渲染）     | 导航前获取             | `meta: { preload: true }`           |
| 列表页 + 次要数据                  | 导航后获取             | 默认行为，或 `meta: { lazy: true }` |
| 需要缓存但数据变化不频繁的页面     | 导航后 + keep-alive    | `meta: { keepAlive: true }`         |
| 需严格权限校验后再拉取敏感数据     | 守卫中获取（结合权限） | `meta: { requiresAuth: true }`      |

通过合理使用 `meta` 字段，你可以将路由的元数据（标题、权限、布局、缓存、数据获取策略）集中管理，避免在组件或守卫中写死条件，使路由配置成为应用的**单一事实来源**。
