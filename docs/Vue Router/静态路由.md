## 后台返回菜单权限，前端写全路由并匹配渲染

在你的场景中，前端**预先定义好全部路由**（包括所有权限页面），而后台只返回当前用户的**菜单权限标识**（例如路由名称或路径的列表），前端根据这些标识**动态控制菜单显示和路由访问**，但**不添加/删除路由规则**。这是与“全动态添加路由”并列的一种常见实现方案。

---

### 1. 方案核心思路

- **静态路由**：所有可能的路由在项目初始化时就已经配置完整（使用静态 `routes` 数组）。
- **权限控制点**：
  - **左侧菜单**：根据后台返回的菜单权限列表，过滤出用户有权看到的菜单项。
  - **路由守卫**：在 `beforeEach` 中判断目标路由是否需要权限，如果需要，检查当前用户是否拥有该权限，无权限则拦截跳转到 403 或登录页。
  - **路由表**：并不会通过 `addRoute` 增减路由，所有路由一直存在于路由表中，只是通过守卫控制访问。

---

### 2. 与动态添加路由方案的对比

| 特性                 | 静态写全 + 权限匹配                               | 动态添加路由（`addRoute`）                      |
| -------------------- | ------------------------------------------------- | ----------------------------------------------- |
| **路由表初始化**     | 启动时加载全部路由                                | 只加载静态基础路由，动态路由按需添加             |
| **权限控制点**       | 菜单过滤 + 路由守卫（beforeEach 中判断权限）      | 路由本身不存在的页面，用户无法通过 URL 访问     |
| **可访问路由数量**   | 全部路由常驻内存，但通过守卫拦截                  | 仅用户有权限的路由存在                          |
| **首屏加载体积**     | 所有路由组件可能被提前加载？<br>（可以用懒加载改进） | 只有基础路由组件被加载，权限路由可能按需加载    |
| **错误路由拦截**     | 未授权页面跳转首页或 403                          | 未授权页面直接 404（因为路由未添加）            |
| **实现复杂度**       | 简单，无需动态操作路由实例                        | 需要确保添加时机、顺序、刷新重定向等            |
| **典型适用场景**     | 中小型项目，权限层级简单，菜单基本固定            | 大型项目，权限复杂，希望最小化未授权代码暴露     |

---

### 3. 实现步骤（静态路由 + 权限匹配）

#### 3.1 定义全部路由（支持懒加载）

```javascript
// router/index.js
import { createRouter, createWebHistory } from 'vue-router'

const routes = [
  { path: '/login', name: 'Login', component: () => import('@/views/Login.vue') },
  {
    path: '/dashboard',
    name: 'Dashboard',
    component: () => import('@/views/Dashboard.vue'),
    meta: { permission: 'dashboard' }   // 自定义权限标识
  },
  {
    path: '/system/user',
    name: 'UserManage',
    component: () => import('@/views/system/User.vue'),
    meta: { permission: 'system:user' }
  },
  {
    path: '/system/role',
    name: 'RoleManage',
    component: () => import('@/views/system/Role.vue'),
    meta: { permission: 'system:role' }
  },
  { path: '/403', name: 'Forbidden', component: () => import('@/views/403.vue') },
  { path: '/:pathMatch(.*)*', name: 'NotFound', component: () => import('@/views/404.vue') }
]

const router = createRouter({
  history: createWebHistory(),
  routes
})

export default router
```

#### 3.2 权限数据存储（登录后获取）

```javascript
// store/modules/user.js
export default {
  state: {
    permissions: []   // 后端返回的权限标识数组，如 ['dashboard', 'system:user']
  },
  mutations: {
    SET_PERMISSIONS(state, perms) {
      state.permissions = perms
    }
  },
  actions: {
    async getUserPermissions() {
      const res = await api.getUserPermissions()
      commit('SET_PERMISSIONS', res.data)
    }
  }
}
```

#### 3.3 全局守卫：拦截无权限访问

```javascript
// router/index.js
import router from './index'
import store from '@/store'

router.beforeEach((to, from, next) => {
  const token = localStorage.getItem('token')
  const permissions = store.state.user.permissions

  // 未登录处理
  if (!token && to.name !== 'Login') {
    return next({ name: 'Login', query: { redirect: to.fullPath } })
  }
  if (token && to.name === 'Login') {
    return next({ name: 'Dashboard' })
  }

  // 权限校验：如果路由需要权限，检查用户是否拥有
  const requiredPermission = to.meta.permission
  if (requiredPermission && !permissions.includes(requiredPermission)) {
    // 无权限，跳转 403
    return next({ name: 'Forbidden' })
  }

  next()
})
```

#### 3.4 动态生成菜单（侧边栏）

```vue
<!-- Sidebar.vue -->
<template>
  <el-menu>
    <template v-for="item in menuList" :key="item.name">
      <el-menu-item v-if="hasPermission(item.permission)" @click="$router.push(item.path)">
        {{ item.title }}
      </el-menu-item>
    </template>
  </el-menu>
</template>

<script setup>
import { computed } from 'vue'
import { useStore } from 'vuex'

const store = useStore()
const permissions = computed(() => store.state.user.permissions)

// 前端预定义完整菜单树（也可以从路由表里自动生成）
const fullMenu = [
  { title: '仪表盘', path: '/dashboard', permission: 'dashboard' },
  { title: '用户管理', path: '/system/user', permission: 'system:user' },
  { title: '角色管理', path: '/system/role', permission: 'system:role' }
]

const menuList = computed(() => {
  return fullMenu.filter(item => 
    !item.permission || permissions.value.includes(item.permission)
  )
})

const hasPermission = (perm) => !perm || permissions.value.includes(perm)
</script>
```

### 4. 方案优缺点分析

#### 优点

- **实现简单**：不需要动态操作路由实例，避免 `addRoute`/`removeRoute` 带来的复杂性和坑点（如刷新重定向、重复添加）。
- **路由地址可预测**：前端完全掌握所有路由路径，可以直接使用 `router.push` 或 `<RouterLink>` 指向任何已定义路径，只要守卫会拦截。
- **懒加载依然有效**：虽然路由表全量定义，但使用动态 `import()` 的组件依然是按需加载，不会因为定义多而增加首屏体积。
- **便于调试和文档**：所有路由集中在一个文件，新开发人员容易理解系统全貌。

#### 缺点

- **路由表暴露**：所有路由规则都存在于前端代码中，查看 JS 文件可能看到未授权页面的路径和组件名称，安全性略低（但组件内容仍受后端 API 保护）。
- **内存占用**：路由实例中保留所有路由对象，但影响极小（路由配置只是一些 JS 对象）。
- **路由顺序问题**：必须注意通配路由 `/:pathMatch(.*)*` 放在最后，否则会覆盖权限拦截。
- **需要维护权限标识与路由的对应关系**：`meta.permission` 需要与后端返回的权限码一致。

---

### 5. 何时选择这种方案？

- **中小型管理系统**，权限粒度不细，菜单项不超过 50 个。
- **团队对动态路由的复杂性感到头疼**，希望用更直观的方式控制访问。
- **后端只提供简单的权限标识列表**（如 `['dashboard', 'user:list', 'user:edit']`），不提供完整路由树 JSON。
- **希望保留前端路由的明确性和可测试性**。

---

### 6. 进阶优化：结合 `addRoute` 的混合模式

如果你的项目很大，既想保留静态路由的简单性，又希望未授权路由完全不暴露，可以采用混合模式：

- **基础静态路由**：登录、404、公开页面。
- **动态添加的模块**：根据权限动态添加“系统管理”、“报表”等大模块，每个模块的路由定义放在单独文件中，在用户登录后按需 `addRoute`。

这样既享受了动态路由的安全性，又避免了手动处理海量细粒度路由的麻烦。

---

### 总结

“后台仅返回菜单权限，前端写全路由并匹配渲染”是一种**成熟、可靠且易于理解**的权限控制方案。它避免了动态路由的一系列细节问题，适合绝大多数后台管理系统。你只需要：
1. 在静态路由的 `meta` 中定义权限标识。
2. 在 `beforeEach` 中做权限拦截。
3. 根据权限列表过滤菜单。

如果你的项目对代码暴露和首屏加载速度有极致的追求，再考虑全动态路由方案。根据你的描述，静态写全 + 权限匹配的方式完全能够胜任，且维护成本更低。
