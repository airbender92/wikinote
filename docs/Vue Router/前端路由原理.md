## 前端路由原理：Hash 与 History 模式及导航工作流程

前端路由是现代单页应用（SPA）的基石，它的核心目标是：**在浏览器 URL 发生变化时，不向服务器发送请求，而是由前端 JavaScript 动态渲染对应的页面组件**。Vue Router 支持两种主要的底层实现方式：**Hash 模式** 和 **History 模式**。

---

### 1. Hash 模式原理

#### 1.1 URL 中的 Hash
Hash 指的是 URL 中 `#` 符号及其后面的部分，例如 `https://example.com/#/user/123`。Hash 有以下特性：

- **不会发送到服务器**：浏览器请求服务器时会忽略 `#` 之后的内容，服务器只会收到 `https://example.com/`。
- **改变 Hash 不会刷新页面**：通过 JavaScript 修改 `window.location.hash` 或点击带有 hash 的锚点链接，页面不会重新加载。
- **Hash 变化可被监听**：浏览器提供 `hashchange` 事件，可以监听 hash 的变化。

#### 1.2 核心实现机制
```javascript
// 监听 hash 变化
window.addEventListener('hashchange', () => {
  const hash = window.location.hash.slice(1) // 去掉 # 号
  // 根据 hash 匹配路由规则，渲染对应组件
  renderComponent(hash)
})

// 修改 hash（跳转）
function pushHash(path) {
  window.location.hash = path
}
```

#### 1.3 工作流程
1. 用户点击 `<a href="#/about">` 或调用 `router.push('/about')`（内部修改 `location.hash`）。
2. 浏览器地址栏 URL 的 hash 部分改变，但**不发送请求**，页面不刷新。
3. `hashchange` 事件被触发，Vue Router 监听到变化，获取当前 hash 值。
4. 路由匹配器根据 hash 找出对应的组件。
5. 动态替换 `<router-view>` 中的组件，实现视图更新。
6. 用户点击后退/前进按钮时，同样会触发 `hashchange`，路由根据历史栈中的 hash 进行反向匹配。

#### 1.4 优缺点
- **优点**：兼容性好（支持所有浏览器，包括 IE），无需服务器配置。
- **缺点**：URL 带有 `#` 不够美观；hash 部分不会被搜索引擎收录（对 SEO 不友好）。

---

### 2. History 模式原理

#### 2.1 HTML5 History API
History API 提供了对浏览器会话历史记录进行编程控制的能力，关键方法包括：

- `history.pushState(state, title, url)`：在历史栈中添加一条新记录，**不刷新页面**，但会改变浏览器地址栏 URL。
- `history.replaceState(state, title, url)`：替换当前历史记录，同样不刷新页面。
- `window.onpopstate` 事件：当用户点击浏览器的前进/后退按钮时触发，可以获取到当前历史记录关联的 state 对象。

#### 2.2 核心实现机制
```javascript
// 监听前进/后退
window.addEventListener('popstate', (event) => {
  const path = window.location.pathname
  // 根据 path 渲染组件
  renderComponent(path)
})

// 编程式跳转（push）
function pushState(path) {
  history.pushState(null, '', path)   // 改变 URL，不刷新
  renderComponent(path)               // 手动渲染目标组件
}

// replace 类似
function replaceState(path) {
  history.replaceState(null, '', path)
  renderComponent(path)
}
```

#### 2.3 工作流程
1. 用户点击 `<RouterLink to="/about">` 或调用 `router.push('/about')`。
2. Vue Router 内部调用 `history.pushState(null, '', '/about')`，浏览器地址栏变为 `/about`，**但不会向服务器发送请求**。
3. 路由匹配器根据当前 `pathname` 找到对应的组件。
4. 动态替换 `<router-view>` 中的组件。
5. 当用户点击浏览器的后退按钮时，`popstate` 事件触发，Vue Router 获取当前 `location.pathname`，重新匹配组件并渲染。

#### 2.4 服务器配置要求
使用 History 模式时，如果用户直接访问（或刷新）`https://example.com/about`，浏览器会向服务器发送请求。由于服务器上并没有 `/about` 对应的静态文件，需要配置 **fallback**：所有未匹配到静态文件的请求都返回 `index.html`，然后由前端路由接管。

**Nginx 示例**：
```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

**Node.js (Express) 示例**：
```javascript
app.use(express.static('dist'))
app.get('*', (req, res) => {
  res.sendFile(path.resolve(__dirname, 'dist', 'index.html'))
})
```

#### 2.5 优缺点
- **优点**：URL 干净，无 `#`，美观且对 SEO 友好（配合预渲染或 SSR）。
- **缺点**：需要服务器配置 fallback；在 IE9 及以下不兼容（但现代项目基本无需考虑）。

### 3. 导航跳转的核心工作流程（通用）

无论是 Hash 模式还是 History 模式，路由跳转的内部流程都遵循以下步骤：

1. **导航触发**：用户点击 `<RouterLink>`、调用 `router.push` / `replace` 或浏览器的前进/后退。
2. **调用底层 API**：
   - Hash 模式：修改 `window.location.hash` 或调用 `history.pushState` 并同时触发 hash 变化。
   - History 模式：调用 `history.pushState` / `replaceState`，并手动执行后续步骤。
3. **更新当前路由记录**：Vue Router 内部维护一个响应式的 `currentRoute` 对象。
4. **执行导航守卫**（按顺序）：
   - 组件内 `beforeRouteLeave`
   - 全局 `beforeEach`
   - 路由独享 `beforeEnter`
   - 组件内 `beforeRouteUpdate`（复用组件时）或 `beforeRouteEnter`
5. **解析异步组件**：如果目标组件使用了懒加载，则加载组件代码。
6. **确认导航**：所有守卫都 `next()` 或没有拒绝后，导航被确认。
7. **更新 URL**（实际已经在第2步完成，但此时 URL 与路由状态最终一致）。
8. **触发 `afterEach` 全局守卫**。
9. **DOM 更新**：Vue 渲染新组件，替换 `<router-view>`。
10. **调用 `beforeRouteEnter` 的 `next` 回调**（传入组件实例）。

#### 关键区别
- **Hash 模式下**：URL 变化会自动触发 `hashchange`，进而驱动路由更新。`push` 操作修改 hash 后，`hashchange` 事件会再次调用渲染逻辑，但 Vue Router 内部会去重，避免重复渲染。
- **History 模式下**：`pushState` 不会自动触发任何事件，所以需要在调用 `pushState` 后**手动执行路由匹配和组件渲染**。而 `popstate` 事件则用于处理前进/后退。

---

### 4. 总结对比表

| 特性                 | Hash 模式                                     | History 模式                                       |
| -------------------- | --------------------------------------------- | -------------------------------------------------- |
| **底层 API**         | `hashchange` 事件 + `location.hash`           | `history.pushState` + `popstate` 事件              |
| **URL 格式**         | `/#/path`                                     | `/path`                                            |
| **是否发送请求**     | 改变 hash 不发送请求，刷新时 hash 被忽略      | 改变路径不发送请求，但刷新时会请求服务器真实路径   |
| **服务器配置**       | 不需要                                        | 需要 fallback 到 index.html                        |
| **SEO**              | 差（搜索引擎忽略 hash）                       | 好（需配合 SSR 或预渲染获得更好效果）              |
| **兼容性**           | 所有浏览器                                    | IE10+，现代浏览器                                  |
| **导航跳转实现**     | 修改 `location.hash` + 监听 `hashchange`      | 调用 `pushState` + 手动渲染 + 监听 `popstate`      |

理解这两种模式的底层机制，有助于你在不同场景下正确选择路由模式，也能在出现路由相关 bug（如刷新后 404、hash 模式下锚点问题）时快速定位原因。Vue Router 的 `createWebHistory` 和 `createWebHashHistory` 正是对上述原理的封装，让开发者无需直接操作这些底层 API。
