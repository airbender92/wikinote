## 导航故障处理：精确控制路由跳转失败逻辑

在 Vue Router 中，`router.push`、`router.replace` 等导航方法返回的是一个 **Promise**。通常情况下，当导航成功完成时，Promise 会 resolve（但不会返回任何值）；而当导航被**中断**或**失败**时，Promise 会 reject（旧版本）或 resolve 一个 **`NavigationFailure`** 对象（Vue Router 4 及以后）。正确处理这些故障，可以避免控制台报错，并根据失败原因执行自定义逻辑（如提示用户、重试或记录日志）。

---

### 1. 导航失败场景

- **被守卫拦截**：`beforeEach`、`beforeEnter` 等守卫中调用了 `next(false)` 或 `next('/somewhere')`。
- **重复导航**：尝试跳转到当前已激活的相同路由（例如路径和参数完全一致）。
- **路由不存在**：目标路由没有匹配的静态或动态路由。
- **异步组件加载失败**：路由组件的动态 `import()` 语法加载超时或网络错误。
- **未知错误**：守卫中抛出异常。

---

### 2. `push` / `replace` 的 Promise 行为

```javascript
// Vue Router 4 (Vue 3)
import { useRouter } from 'vue-router'

const router = useRouter()

// 方式1：使用 catch 捕获错误（旧行为）
router.push('/some-path').catch(err => {
  console.error(err)
})

// 方式2（推荐）：检查返回值是否是 NavigationFailure
router.push('/admin').then(res => {
  if (res) {
    // 导航失败，res 是 NavigationFailure 对象
    console.log('导航失败', res)
  } else {
    // 导航成功（没有返回值）
    console.log('导航成功')
  }
})
```

> **注意**：在 Vue Router 4 中，除非导航失败是由**未捕获的错误**（如守卫中抛出异常、组件加载失败）引起的，否则 Promise 不会进入 `catch`，而是 resolve 一个 `NavigationFailure` 对象。因此推荐使用 `.then()` 接收结果并判断。

---

### 3. 识别故障类型：`isNavigationFailure` 和 `NavigationFailureType`

Vue Router 提供了工具函数和枚举，方便区分故障原因。

```javascript
import { isNavigationFailure, NavigationFailureType } from 'vue-router'

router.push('/target').then(failure => {
  if (isNavigationFailure(failure, NavigationFailureType.aborted)) {
    // 被守卫调用 next(false) 中止
    console.log('导航被守卫中止')
  } else if (isNavigationFailure(failure, NavigationFailureType.cancelled)) {
    // 重复导航或当前导航被新导航取代
    console.log('导航被取消（如重复点击或新导航）')
  } else if (isNavigationFailure(failure, NavigationFailureType.duplicated)) {
    // 尝试跳转到完全相同的路由
    console.log('重复导航，路径未变化')
  } else if (isNavigationFailure(failure)) {
    // 其他类型的 NavigationFailure
    console.log('导航失败', failure)
  } else {
    // 导航成功，failure 为 undefined 或 null
    console.log('导航成功')
  }
})
```

**导航故障类型含义**：

| 类型                       | 触发条件                                                       |
| -------------------------- | -------------------------------------------------------------- |
| `aborted`                  | 守卫中调用 `next(false)` 显式中止导航。                        |
| `cancelled`                | 在导航完成前，又发生了新的导航，导致当前导航被取消。           |
| `duplicated`               | 目标路由与当前路由完全相同（包括参数、哈希等），不会触发导航。 |

> 如果导航是因为路由不存在（`No match found`）或守卫中重定向（`next('/login')`），则会返回一个携带 `to` 和 `from` 的 `NavigationFailure`，其 `type` 通常是 `aborted`。

### 4. 实际使用场景

#### 4.1 处理登录跳转中的被拦截

```vue
<script setup>
import { useRouter } from 'vue-router'
import { isNavigationFailure, NavigationFailureType } from 'vue-router'

const router = useRouter()

async function handleLogin() {
  const success = await api.login()
  if (success) {
    const failure = await router.push('/dashboard')
    if (isNavigationFailure(failure, NavigationFailureType.aborted)) {
      // 可能是因为 token 失效跳回了登录页，或者是权限不足
      ElMessage.warning('登录状态异常，请重新登录')
    } else if (isNavigationFailure(failure)) {
      ElMessage.error('导航失败，请稍后重试')
    } else {
      ElMessage.success('登录成功')
    }
  }
}
</script>
```

#### 4.2 防止重复导航导致的错误提示

用户快速点击同一个菜单时，可能会产生重复导航，默认控制台会有一条 `Redirected when going from "/dashboard" to "/dashboard"` 的错误。我们可以忽略这种失败。

```javascript
async function navigateTo(path) {
  const failure = await router.push(path)
  if (isNavigationFailure(failure, NavigationFailureType.duplicated)) {
    // 重复导航，不做任何处理，也不提示用户
    return
  }
  if (failure) {
    // 其他失败，可以提示或记录
    console.warn('导航失败', failure)
    ElMessage.warning('页面跳转失败')
  }
}
```

#### 4.3 守卫中重定向导致的失败处理

假设全局守卫检测到未登录会自动跳转到 `/login`，此时 `router.push('/dashboard')` 会返回一个 `failure`，我们可以识别并显示提示。

```javascript
// 在某个组件中
const failure = await router.push('/dashboard')
if (isNavigationFailure(failure)) {
  // 被重定向到登录页了，可以不管（因为已经自动跳转）
  console.log('请先登录')
}
```

#### 4.4 路由不存在时跳转 404

如果目标路由没有定义，`router.push` 会 resolve 一个失败对象，其 `to` 属性指向不存在的路由。我们可以手动跳转到 404 页面。

```javascript
const failure = await router.push('/unknown-page')
if (failure && failure.to.matched.length === 0) {
  // 没有匹配到任何路由
  router.replace('/404')
}
```

### 5. 全局统一处理导航故障

可以在创建路由器后，监听全局的导航故障（例如使用 `router.afterEach` 无法获得失败信息，但可通过扩展或封装 `push` 方法实现）。

```javascript
// 对 router.push 进行全局包装
const originalPush = router.push
router.push = function(to) {
  return originalPush.call(this, to).catch(err => {
    if (!isNavigationFailure(err)) {
      // 非导航故障错误（如组件加载失败），上报或提示
      console.error('路由跳转异常', err)
    }
    return err
  })
}
```

> 注意：Vue Router 4 中，导航故障不再进入 `catch`，而是 resolve 一个 `failure`，所以上面的 `catch` 可能只捕获真正的错误。更好的封装方式是在每个调用点判断，或使用全局 mixin。

### 6. 最佳实践总结

| 场景                               | 处理方式                                                     |
| ---------------------------------- | ------------------------------------------------------------ |
| **用户重复点击菜单**               | 忽略 `duplicated` 类型的失败，不显示任何错误提示             |
| **守卫拦截未登录访问**             | 不额外提示（因为已跳转登录页），但可记录或静默处理           |
| **动态添加路由后立即跳转**          | 跳转前确保路由已添加，若失败可尝试重试或提示页面不存在       |
| **权限不足被守卫重定向到 403**      | 识别 `aborted` 类型并提示“无权限访问”                        |
| **异步组件加载超时**               | 捕获真正的异常（通过 `try/catch` 或 `.catch`），显示错误 UI  |

**推荐写法**：

```typescript
import { isNavigationFailure, NavigationFailureType } from 'vue-router'

async function safePush(to: string) {
  const result = await router.push(to)
  if (isNavigationFailure(result)) {
    if (result.type === NavigationFailureType.duplicated) {
      // 重复导航，静默返回
      return true
    }
    // 其他失败：可以弹窗或记录
    console.warn('导航失败', result)
    return false
  }
  return true
}
```

### 7. 与选项式 API 的结合

在组件中使用 `this.$router.push` 同样返回 Promise，处理方式相同：

```javascript
this.$router.push('/admin').then(failure => {
  if (this.$router.isNavigationFailure(failure)) {
    // 处理失败
  }
})
```

---

### 总结

- Vue Router 4 中，导航方法 resolve 的值可能是 `undefined`（成功）或 `NavigationFailure` 对象（失败）。
- 使用 `isNavigationFailure` 和 `NavigationFailureType` 精确判断失败原因。
- 处理失败可以避免控制台报错，并根据不同原因（重复、拦截、取消）给出恰当的用户反馈。
- 推荐封装一个 `safePush` 函数，在项目中统一使用。

精确的导航故障处理是现代前端应用提升健壮性和用户体验的重要环节。
