## 模块化路由配置：拆分大型路由表提升可维护性

随着项目规模增长，`routes` 数组会迅速膨胀，包含数十甚至上百条路由规则。将所有路由写在同一个文件中会导致：
- 文件过长，难以导航和协作。
- 合并冲突频繁。
- 特定业务逻辑（如权限、嵌套）分散，不易理解。

**模块化路由配置** 的核心思想是：**按业务功能、模块或领域将路由定义拆分为多个小文件，然后统一导入并组合成最终的路由表**。

---

### 1. 基础拆分方式

假设项目结构如下：
```
src/
├── router/
│   ├── index.js          // 路由器主入口
│   ├── modules/          // 各模块路由
│   │   ├── user.js       // 用户管理相关路由
│   │   ├── product.js    // 商品管理相关路由
│   │   ├── order.js      // 订单相关路由
│   │   └── static.js     // 静态页面（关于、帮助等）
│   └── guards.js         // 全局守卫（可单独管理）
```

#### 示例：`modules/user.js`

```javascript
// modules/user.js
const userRoutes = [
  {
    path: '/user',
    name: 'UserLayout',
    component: () => import('@/layouts/UserLayout.vue'),
    meta: { requiresAuth: true },
    children: [
      {
        path: 'profile',
        name: 'UserProfile',
        component: () => import('@/views/user/Profile.vue'),
        meta: { title: '个人资料' }
      },
      {
        path: 'settings',
        name: 'UserSettings',
        component: () => import('@/views/user/Settings.vue'),
        meta: { title: '账号设置' }
      }
    ]
  },
  {
    path: '/users',
    name: 'UserList',
    component: () => import('@/views/user/List.vue'),
    meta: { requiresAuth: true, roles: ['admin'] }
  }
]

export default userRoutes
```

#### 主入口 `index.js`

```javascript
// router/index.js
import { createRouter, createWebHistory } from 'vue-router'
import userRoutes from './modules/user'
import productRoutes from './modules/product'
import orderRoutes from './modules/order'
import staticRoutes from './modules/static'

// 静态基础路由（无需登录）
const constantRoutes = [
  { path: '/login', name: 'Login', component: () => import('@/views/Login.vue') },
  { path: '/', redirect: '/dashboard' }
]

// 合并所有路由
const routes = [
  ...constantRoutes,
  ...userRoutes,
  ...productRoutes,
  ...orderRoutes,
  ...staticRoutes,
  { path: '/:pathMatch(.*)*', name: 'NotFound', component: () => import('@/views/NotFound.vue') }
]

const router = createRouter({
  history: createWebHistory(),
  routes
})

export default router
```

### 2. 命名空间与路由名称冲突

不同模块可能使用相同的路由名称（name），导致在 `router.push({ name: ... })` 时产生歧义。**推荐命名规范**：使用模块前缀，如 `user-profile`、`product-list`。

```javascript
// user.js
{
  path: 'profile',
  name: 'user-profile',   // 前缀 user-
  component: () => import('@/views/user/Profile.vue')
}
```

---

### 3. 处理嵌套路由拆分

当一个模块包含复杂的嵌套结构时，可以将子路由也拆分到独立文件。例如 `user.js` 中引用子模块：

```javascript
// modules/user/children/settings.js
const settingsRoutes = {
  path: 'settings',
  name: 'user-settings',
  component: () => import('@/views/user/Settings.vue'),
  children: [
    { path: 'security', name: 'user-security', component: ... }
  ]
}
export default settingsRoutes
```

然后在 `user.js` 中导入并合并到 children 数组。

---

### 4. 利用动态导入实现按需加载路由模块

在某些超大型应用中，你甚至可以根据用户权限动态加载某些模块的路由定义（结合 `router.addRoute` 和 `import()`）。但一般而言，静态模块化已经足够清晰。

---

### 5. 统一管理路由元信息类型（TypeScript 增强）

如果你使用 TypeScript，可以定义全局 `RouteMeta` 接口，并在每个模块中共享类型。

```typescript
// router/types.ts
declare module 'vue-router' {
  interface RouteMeta {
    title?: string
    requiresAuth?: boolean
    roles?: string[]
  }
}
```

每个模块中的路由配置会自动获得类型提示。

---

### 6. 自动导入模块（进阶玩法）

为了避免每次新增模块都要手动 `import`，可以使用 Vite 或 Webpack 的 `import.meta.glob` 自动收集模块。

**Vite 示例**：

```javascript
// router/index.js
const modules = import.meta.glob('./modules/**/*.js', { eager: true })
let asyncRoutes = []

Object.values(modules).forEach(module => {
  asyncRoutes = asyncRoutes.concat(module.default || module)
})

const routes = [...constantRoutes, ...asyncRoutes, ...catchAllRoute]
```

这样只需在 `modules/` 目录下创建新文件，并确保导出路由数组，就会自动被合并。需要注意：**自动导入可能导致顺序不可控**（通配路由必须最后），可能需要手动排序或约定文件名。

---

### 7. 优缺点总结

| 优点                                         | 缺点                                   |
| -------------------------------------------- | -------------------------------------- |
| 按业务拆分，代码职责清晰，易于团队协作       | 模块间可能存在路由顺序依赖（如通配路由） |
| 合并冲突减少，每个模块独立演进               | 需要建立统一的命名规范和拆分粒度约定   |
| 便于进行路由层面的懒加载（整模块）           | 过多的模块文件可能导致目录深层次增加   |
| 可以结合权限动态加载特定模块（进一步增强性能） | 初学者需要理解模块化概念               |

---

### 8. 最佳实践建议

- **按功能模块拆分**，每个模块内部包含该模块的所有路由（包括嵌套路由）。
- **统一命名规范**：模块前缀 + 路由名称（如 `user-profile`）。
- **将全局守卫单独放到 `guards.js`**，不要在 `index.js` 中混杂守卫逻辑。
- **使用 `meta` 字段集中管理权限、标题、布局等元数据**。
- **通配路由（404）始终放在最后导入**，或者在主入口合并时确保它在数组末尾。
- **对于特别大的子模块，可以再拆分二级目录**，如 `modules/user/routes.js` 和 `modules/user/children.js`。
- **利用 TypeScript** 为路由配置提供强类型校验。

通过模块化路由配置，大型项目的路由表将变得像文件系统一样井井有条，开发人员可以快速定位并修改特定业务的路由规则，显著提升长期可维护性。
