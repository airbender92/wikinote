## 动态路由：运行时增删路由（`router.addRoute`）

在传统的前后端不分离项目中，路由表通常是静态的、由后端模板控制。而在单页应用中，路由表往往需要**根据用户身份、权限或业务模块动态调整**。Vue Router 提供了 `addRoute`、`removeRoute` 等 API，允许在应用运行时**动态添加或删除路由规则**，为实现基于权限的路由、微前端子应用注入等场景提供了基础能力。

---

### 1. 为什么需要动态路由？

- **权限控制**：不同角色用户看到的菜单和页面不同。例如普通用户无法访问“管理员面板”。
- **模块懒加载**：超级大的应用可以拆分成多个独立路由模块，在用户访问某个功能时再动态注入，进一步减少首屏体积。
- **插件化 / 微前端**：主应用需要动态挂载子应用提供的路由。

如果没有动态路由，常见的做法是在路由守卫中判断权限后简单拦截并跳转 `403`，但菜单和路由表依然是全量的，用户即使无法访问某个页面，路由规则仍然存在（不过通过守卫拦截）。动态路由可以实现真正的“不可见”，并且可以按需加载组件。

---

### 2. 核心 API

| 方法                                      | 作用                                                                 |
| ----------------------------------------- | -------------------------------------------------------------------- |
| `router.addRoute(route: RouteRecordRaw)`  | 添加一条新路由规则。可以添加在根级别，也可以指定父路由名称添加到嵌套路由中。 |
| `router.addRoute(parentName, route)`      | 将新路由作为指定父路由的 `children` 插入。                           |
| `router.removeRoute(name: string)`        | 删除一条已添加的路由（仅删除通过 `addRoute` 添加的路由）。           |
| `router.hasRoute(name: string): boolean`  | 检查路由是否存在。                                                   |
| `router.getRoutes(): RouteRecord[]`       | 获取当前所有路由记录的数组（包括静态和动态添加的）。                 |

> **注意**：`removeRoute` 只能删除通过 `addRoute` 添加的路由，不能删除初始化时静态配置的路由。

---

### 3. 动态路由的典型场景：权限动态加载

#### 3.1 设计思路

1. 用户在登录时，后端返回该用户的**权限标识列表** 或 **可直接访问的路由配置**（通常是一棵嵌套路由树）。
2. 前端根据这些信息，使用 `router.addRoute` **动态构建**出用户专属的路由表。
3. 同时，将路由表同步给侧边栏菜单组件，让其据此渲染菜单项。
4. 用户退出登录时，调用 `router.removeRoute` 清除动态添加的路由，并重置为仅公开路由。

#### 3.2 静态路由 + 动态路由的划分

通常我们会将路由分为两部分：

- **静态路由**：无需登录即可访问的页面，如登录页、注册页、404页、首页（公开部分）。
- **动态路由**：需要登录且根据权限动态生成的路由，如后台管理页面、个人中心等。

```javascript
// router/index.js
import { createRouter, createWebHistory } from 'vue-router'

// 公开路由
const constantRoutes = [
  { path: '/login', name: 'Login', component: () => import('@/views/Login.vue') },
  { path: '/404', name: 'NotFound', component: () => import('@/views/404.vue') },
  { path: '/', redirect: '/dashboard' }  // 占位，后面会被动态路由覆盖或重定向
]

const router = createRouter({
  history: createWebHistory(),
  routes: constantRoutes
})

export default router
```

#### 3.3 动态添加路由的函数

```javascript
// router/dynamic.js 或直接在 store 中
import router from './index'

/**
 * 根据后端返回的权限路由配置动态添加路由
 * @param {Array} asyncRoutes 后端返回的动态路由配置（需符合 RouteRecordRaw 格式）
 */
export function addDynamicRoutes(asyncRoutes) {
  asyncRoutes.forEach(route => {
    // 如果已经添加过，避免重复添加
    if (!router.hasRoute(route.name)) {
      router.addRoute(route)
    }
  })
}

/**
 * 清除所有动态添加的路由（通常用于登出）
 */
export function resetDynamicRoutes() {
  // 获取所有路由记录
  const routes = router.getRoutes()
  routes.forEach(route => {
    // 如果路由有叫 dynamic 的标记，或者路由不是静态路由列表中的，则 remove
    if (route.name && !constantRouteNames.includes(route.name)) {
      router.removeRoute(route.name)
    }
  })
}
```

#### 3.4 在全局前置守卫中完成动态注入

核心逻辑：进入任何需要登录的页面时，如果用户已登录但尚未添加动态路由，则先向后端请求权限数据，然后动态添加路由，最后**替换当前导航**以确保路由成功匹配。

```javascript
// router/index.js
import router from './router'
import store from '@/store'

// 白名单：不需要登录即可访问的页面名称
const whiteList = ['Login', 'NotFound']

router.beforeEach(async (to, from, next) => {
  const token = localStorage.getItem('token')
  
  // 情况1：已登录
  if (token) {
    if (to.name === 'Login') {
      // 已登录时访问登录页，重定向到首页
      next({ name: 'Dashboard' })
    } else {
      // 检查是否已经添加了动态路由（通过 store 标识）
      if (!store.state.user.routesLoaded) {
        try {
          // 请求后端获取用户权限路由配置
          const asyncRoutes = await store.dispatch('user/getAsyncRoutes')
          // 动态添加路由
          asyncRoutes.forEach(route => {
            router.addRoute(route)
          })
          // 标记已加载
          store.commit('user/setRoutesLoaded', true)
          
          // 关键：动态添加路由后，需要重新触发当前导航
          // 使用 next({ ...to, replace: true }) 保证不会丢失
          next({ ...to, replace: true })
        } catch (error) {
          // 请求失败，可能是 token 无效，清除并跳转登录
          await store.dispatch('user/logout')
          next({ name: 'Login' })
        }
      } else {
        // 动态路由已加载，直接放行
        next()
      }
    }
  } 
  // 情况2：未登录
  else {
    if (whiteList.includes(to.name)) {
      next()
    } else {
      next({ name: 'Login', query: { redirect: to.fullPath } })
    }
  }
})
```

#### 3.5 后端返回的路由配置格式

后端通常返回一个类似前端 `routes` 配置的 JSON 树，需要注意组件必须通过 `component` 字段指定异步加载函数（字符串写法需要前端提前注册组件映射）。

**后端返回示例：**
```json
[
  {
    "path": "/dashboard",
    "name": "Dashboard",
    "component": "@/views/Dashboard.vue",
    "meta": { "title": "控制台", "icon": "dashboard" }
  },
  {
    "path": "/system",
    "name": "System",
    "component": "@/layouts/SystemLayout.vue",
    "children": [
      {
        "path": "user",
        "name": "UserManage",
        "component": "@/views/system/User.vue"
      }
    ]
  }
]
```

**前端处理函数映射：**
```javascript
// 将后端返回的 component 字符串转换为真正的异步组件
function mapComponent(componentPath) {
  return () => import(`@/${componentPath}`)
}
```

动态添加前需要做转换：
```javascript
const normalizedRoutes = asyncRoutes.map(route => ({
  ...route,
  component: mapComponent(route.component)
}))
```

### 4. 动态删除路由与登出处理

用户点击退出登录时，需要清除动态路由，避免下个用户看到上一个用户的路由。

```javascript
// store/user.js
logout() {
  // 清除动态添加的路由
  const routes = router.getRoutes()
  routes.forEach(route => {
    if (route.name && !constantRouteNames.includes(route.name)) {
      router.removeRoute(route.name)
    }
  })
  // 清除 token 和状态
  localStorage.removeItem('token')
  this.token = null
  this.routesLoaded = false
  router.push('/login')
}
```

> 由于 `router.removeRoute` 只能删除通过 `addRoute` 添加的路由，所以我们需要维护两个列表：静态路由名称列表和动态添加的路由名称列表，或者通过路由的 `meta` 标记来识别。

---

### 5. 注意事项与最佳实践

| 问题         | 说明与解决方案                                                                                                    |
| ------------ | ----------------------------------------------------------------------------------------------------------------- |
| **导航挂起** | 动态添加路由后，必须使用 `next({ ...to, replace: true })` 重新触发一次导航，因为当前 `to` 原本无法匹配成功。      |
| **重复添加** | 在守卫中需要判断是否已添加（通过 `store` 标记或 `router.hasRoute`），避免每次刷新都重复添加。                     |
| **404 路由** | 动态路由通常要放在最后添加，且需要确保 `/:pathMatch(.*)*` 通配路由在最后。建议在动态添加完后再添加 404 路由。       |
| **路由顺序** | `addRoute` 添加的路由会追加到现有路由列表末尾。如果存在通配路由，需注意顺序，或先在静态路由中移除 404，最后动态添加。 |
| **权限更新** | 如果用户权限在会话期间变更（如管理员修改角色），可以重新调用动态添加逻辑，但必须先 `removeRoute` 旧路由再添加新路由。 |
| **内存管理** | 登出时务必调用 `removeRoute` 清除路由，否则路由表会不断累积。                                                     |

### 6. 完整示例：基于菜单树的权限路由

```javascript
// 假设后端返回的权限树如下：
const permissionTree = [
  { name: 'Dashboard', path: '/dashboard', component: 'Dashboard' },
  { name: 'UserManage', path: '/user', component: 'UserManage' }
]

// 动态构建路由
function generateRoutes(permissions) {
  return permissions.map(perm => ({
    path: perm.path,
    name: perm.name,
    component: () => import(`@/views/${perm.component}.vue`),
    meta: { title: perm.name }
  }))
}

// 在守卫中调用
const asyncRoutes = generateRoutes(permissionTree)
asyncRoutes.forEach(route => router.addRoute(route))
// 最后添加 404 路由（如果还没有）
router.addRoute({ path: '/:pathMatch(.*)*', name: 'NotFound', component: NotFound })
```

---

### 总结

- **`router.addRoute`** 是实现权限动态加载、模块化按需注入的核心 API。
- **最佳实践**：静态路由 + 动态路由分离，在登录后请求权限，在全局守卫中动态添加，注意添加后重新触发导航。
- **登出时**必须使用 `router.removeRoute` 清除动态路由，避免路由污染。
- **动态路由的顺序和 404 处理**需要特别留心，避免匹配失效。

合理使用动态路由，可以让你的应用像插件一样灵活扩展权限，同时显著减少首屏加载体积。
