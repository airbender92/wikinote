在 TypeScript 中，**交叉类型（`&`）** 和 **接口继承（`extends`）** 都可以组合多个类型，但它们的机制和适用场景有明显区别。

---

## 1. 核心概念

| 特性 | 交叉类型 `&` | 接口继承 `extends` |
|------|--------------|---------------------|
| **适用对象** | 任意类型（原始类型、联合、对象、函数等） | 主要用于对象类型（接口/类） |
| **语法位置** | 类型别名（`type`）中 | 接口（`interface`）中 |
| **组合方式** | 取所有成员（求交集） | 继承父接口的成员，可覆盖/扩展 |
| **同名属性处理** | 合并类型，可能导致 `never` 若类型不兼容 | 可以覆盖（子接口同名属性类型必须是父接口的子类型） |
| **方法合并** | 生成函数重载 | 简单覆盖（除非使用函数属性） |
| **适用场景** | 混合任意类型、高阶类型工具、组合独立类型 | 构建清晰的继承层次、扩展第三方接口、面向对象设计 |

---

## 2. 机制详解

### 交叉类型 `&`
- 将多个类型合并成一个新类型，该类型**同时拥有所有类型的成员**。
- 对于相同名称的属性，如果类型不兼容，结果会变成 `never`（不可赋值）。
- 示例：
  ```ts
  type A = { name: string; age: number };
  type B = { name: string; gender: string };
  type C = A & B;  // { name: string; age: number; gender: string }
  
  type D = { name: string } & { name: number }; // name: never
  ```

### 接口继承 `extends`
- 子接口继承父接口的成员，可以**添加新成员**，也可以**覆盖父接口中同名成员的类型**（但必须兼容，即子类型）。
- 继承支持多继承（用逗号分隔）。
- 示例：
  ```ts
  interface Animal {
    name: string;
    eat(): void;
  }
  interface Dog extends Animal {
    bark(): void;
    // 可以覆盖，但类型必须兼容（string 仍为 string，不能改为 number）
  }
  ```

---

## 3. 关键区别示例

### 同名属性冲突
```ts
interface IA { x: string; }
interface IB { x: number; }

// 交叉：x 变成 never
type Intersection = IA & IB; // { x: never }

// 继承：不允许（错误，因为 string 和 number 不兼容）
interface Wrong extends IA, IB { } // ❌
```

### 方法合并
```ts
interface A { log(): void; }
interface B { log(s: string): void; }

type Combined = A & B;
// Combined 的 log 是一个交叉函数类型，相当于重载：
// log(): void;
// log(s: string): void;

interface C extends A, B { }  // 同样可以（多个父接口相同方法名会合并为重载）
```

### 对象字面量赋值
```ts
type T = { a: number } & { b: number };
const obj: T = { a: 1, b: 2 }; // 必须同时提供

interface I { a: number; }
interface J extends I { b: number; }
const obj2: J = { a: 1, b: 2 };
```

## 4. 语义和设计倾向

- **继承（`extends`）**：表达 **“是一种”** 关系（is-a）。子接口是父接口的特化，适合建立层次结构，代码更易读、更符合 OOP。
- **交叉（`&`）**：表达 **“合并”** 关系（mixin / combination）。更多用于组合独立的类型片段，如在工具类型中动态混合属性。交叉类型**不需要预先声明**，灵活但可能产生难以理解的 `never` 属性。

## 5. 实际使用建议

| 场景 | 推荐方式 |
|------|----------|
| 扩展第三方接口 | `interface MyInterface extends ThirdPartyInterface {}` |
| 组合多个独立的类型片段（如 Props 合并） | `type Props = OwnProps & InjectedProps` |
| 需要覆盖父接口的同名属性并收窄类型 | 继承（必须兼容） |
| 创建高阶类型（如 `Required<T> & Partial<T>`） | 交叉 |
| 清晰描述类的继承关系 | `extends` |

---

## 总结

- **`extends`** 用于**接口继承**，强调层次化和可覆盖，适合 OOP 风格。
- **`&`** 用于**交叉类型**，强调机械合并，适合组合任意类型，更灵活但粗粒度。

在你的代码例子中：
```ts
type iFlowEditorConfig = Omit<...> & iFlowEditorDefaultConfig;
```
这里使用 `&` 是因为左侧是 `Omit` 产生的类型（不能作为接口去继承），且需要在类型别名中组合两部分，无法用 `extends` 实现。这正体现了交叉类型在组合任意类型时的优势。
