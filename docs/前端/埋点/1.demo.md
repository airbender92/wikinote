## 1. 埋点类型定义（types/analytics.ts）
```ts
// 埋点事件类型
export enum TrackEventType {
  PAGE_VIEW = 'page_view',
  BUTTON_CLICK = 'button_click',
  FLOW_SAVE = 'flow_save',
  DRILL_START = 'drill_start',
  NODE_EXECUTE = 'node_execute',
  API_ERROR = 'api_error',
  EXCEPTION = 'exception',
}

// 埋点基础字段
export interface TrackBaseParams {
  event: TrackEventType
  page?: string
  module?: string
  operator?: string // 操作人（银行必备）
  timestamp?: number
  [key: string]: any
}

// 完整埋点数据（自动补充公共参数）
export interface TrackData extends TrackBaseParams {
  timestamp: number
  uid: string
  page: string
  browser: string
  os: string
  screen: string
}
```

## 2. 埋点核心工具类（utils/analytics.ts）
```ts
import { TrackBaseParams, TrackData, TrackEventType } from '@/types/analytics'

// 全局缓存队列（批量上报）
let trackQueue: TrackData[] = []
let timer: NodeJS.Timeout | null = null

// 公共参数
const getCommonParams = () => {
  return {
    uid: localStorage.getItem('user_id') || 'unknown',
    page: location.pathname,
    browser: navigator.userAgent,
    os: navigator.platform,
    screen: `${window.screen.width}x${window.screen.height}`,
  }
}

// 真实上报接口
const reportTrack = async (data: TrackData[]) => {
  try {
    // 生产环境替换为真实接口
    await fetch('/api/v1/track', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(data),
      keepalive: true, // 页面关闭也能发
    })
  } catch (err) {
    console.warn('埋点上报失败', err)
    // 失败可做重试策略
  }
}

// 批量上报（节流 3s）
const flush = () => {
  if (trackQueue.length === 0) return
  reportTrack([...trackQueue])
  trackQueue = []
  timer = null
}

// 核心埋点方法（唯一入口）
export const track = (params: TrackBaseParams) => {
  // 测试环境可关闭
  if (import.meta.env.MODE === 'development') return

  const data: TrackData = {
    ...getCommonParams(),
    ...params,
    timestamp: Date.now(),
  }

  trackQueue.push(data)

  // 3s 批量上报
  if (!timer) {
    timer = setTimeout(flush, 3000)
  }
}

// 页面曝光埋点
export const trackPageView = (page?: string) => {
  track({
    event: TrackEventType.PAGE_VIEW,
    page: page || location.pathname,
  })
}

// 立即上报（如关闭页面、重要操作）
export const trackImmediately = (params: TrackBaseParams) => {
  track(params)
  flush()
}
```

# 一、fetch 的 keepalive 到底是什么？
## 1. 核心作用（埋点场景刚需）
普通 `fetch` / axios 请求有个致命问题：
当页面**跳转、关闭、刷新**时，浏览器会立刻销毁页面JS上下文，**直接中断还在传输的请求**，埋点日志丢失。

`keepalive: true` 是 fetch 的专属参数，作用：
> 告诉浏览器：**哪怕页面卸载销毁，也要在后台独立完成这条HTTP请求，不被强制取消**。

## 2. 关键特性
1. **不阻塞页面关闭**：不会像同步XHR那样卡住页面等待请求完成，用户无感知；
2. **支持完整请求能力**：自定义Header、Token鉴权、POST/GET/PUT、JSON请求体，比 `sendBeacon` 灵活（sendBeacon不能自定义请求头）；
3. **容量限制**：单次请求body总大小不能超过64KB，埋点日志完全够用；
4. 适用场景：页面退出埋点、会话结束日志、关闭前审计上报（你的银行灾备系统埋点完美适配）。

### 标准示例（埋点上报）
```js
fetch('/api/v1/track', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    Authorization: `Bearer ${localStorage.getItem('token')}`
  },
  body: JSON.stringify(trackData),
  keepalive: true, // 核心，页面关了也能发出去
});
```

## 3. 和 HTTP 协议层 Keep-Alive 区分（极易混淆）
- fetch `keepalive`：**浏览器页面卸载保活请求**（前端埋点用）；
- HTTP `Connection: Keep-Alive`：**TCP连接复用**，减少多次握手耗时（Node.js服务端/axios node端用），两者完全不是一回事。

# 二、Axios 有没有等价的 keepalive？
## 结论分两种环境：浏览器端 / Node.js 端
### 1. 浏览器环境（你写React前端项目，重点看这个）
**Axios 原生不支持 fetch 的 `keepalive` 能力**。
底层Axios浏览器端基于 `XMLHttpRequest(XHR)` 实现，XHR没有页面卸载后台保活的API，页面关闭请求一定会被中断，没有任何配置能模拟 `keepalive: true`。

### 2. Node.js 环境（后端）
Axios 有 `httpAgent/httpsAgent` 的 `keepAlive` 配置，但**仅用于TCP连接复用**，和页面卸载无关，完全不能解决埋点丢失问题：
```js
// 仅Node.js可用，浏览器无效
import axios from 'axios';
import https from 'https';
const instance = axios.create({
  httpsAgent: new https.Agent({ keepAlive: true })
})
```

## 3. Axios 浏览器端替代方案（埋点上报最优解）
### 方案A：埋点逻辑单独用原生 fetch + keepalive（推荐，我之前给你的埋点demo就是这套）
业务接口正常用axios，**埋点上报统一封装fetch**，兼顾鉴权、保活，不会丢失日志。

### 方案B：页面卸载兜底用 navigator.sendBeacon
无自定义Header需求时可用，缺点是不能携带Token、自定义请求头，银行系统鉴权场景不推荐。
```js
// sendBeacon 无法设置Authorization头，不适合带登录态埋点
navigator.sendBeacon('/api/track', JSON.stringify(data));
```

### 方案C：同步XHR（不推荐）
页面卸载时同步发送，会卡住页面加载，用户体验差，银行系统禁止使用。

# 三、结合你的灾备埋点项目最佳实践
1. 普通实时埋点（点击、节点执行）：axios / fetch 均可；
2. 页面退出、会话结束埋点：**必须用 fetch + keepalive: true**，防止审计日志丢失；
3. 封装埋点工具分离两套逻辑：
   - 常规埋点：异步无阻塞；
   - 退出兜底埋点：强制开启 keepalive。
