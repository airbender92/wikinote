# 持久Cookie vs 会话Cookie（Session Cookie）
核心区别只有一条：**生命周期、存储位置**

## 1. 会话 Cookie（Session Cookie）
### 特征
- **不设置 Expires / Max‑Age**
- 保存在**浏览器内存**，不写入本地硬盘
### 失效规则
1. 标签页关掉**不一定失效**（现代浏览器多进程，全部浏览器窗口彻底关闭才销毁）
2. 浏览器进程退出 → Cookie直接消失
3. 重新打开浏览器访问，登录态丢失，需要重新登录

> 场景：**不勾选「记住我」**，关闭浏览器下次要重新登录。

## 2. 持久 Cookie（Persistent Cookie）
### 特征
- 设置了 `Expires`（绝对过期时间）或者 `Max‑Age`（存活秒数）
- 浏览器把它保存到**本地磁盘文件**
### 失效规则
1. 关闭浏览器、关机都不会删掉
2. 直到**时间到期 / 用户手动清除缓存 / 服务端主动删除**才失效
> 场景：勾选**记住我，7天免登录**，关掉浏览器再打开依然登录。

# 对比表格
| 对比项 | 会话Cookie | 持久Cookie |
|---|---|---|
| 过期字段 | 无 Expires / Max‑Age | 配置 Expires / Max‑Age |
| 存储位置 | 浏览器内存 | 本地硬盘 |
| 关闭浏览器 | 全部关闭后自动销毁 | 保留，不会消失 |
| 有效期 | 本次浏览器会话 | 自定义时长（1天/7天/30天） |
| 适用场景 | 临时登录，关闭浏览器下线 | 记住登录，免重复输入密码 |

# 共同点（非常重要）
1. 都遵循**域名隔离规则**：哪个域名下发，哪个域名才能读到
2. 请求后端时，浏览器都会自动带上
3. 都可以配置 HttpOnly、Secure、SameSite 安全属性（防XSS、CSRF）

# 结合SSO举例子
1. SSO下发**会话Cookie**：关掉浏览器 → sso凭证消失，访问a.com要重新输密码
2. SSO下发**持久Cookie（7天）**：关闭浏览器重启，sso Cookie还在，访问a自动免登

# 一句话口诀
**无过期=会话cookie，关浏览器就没；
有过期=持久cookie，存硬盘，到期才失效。**

## 补充小坑
1. 就算是持久Cookie，**业务系统a.com自己的cookie也可以单独设置短时效**
表现：页面打开看似掉线，后台悄悄跳转SSO校验，刷新业务cookie，无感自动登录
2. 浏览器「恢复上次会话」功能：部分浏览器保留内存cookie，**就算会话cookie，重启浏览器依然在线，属于浏览器特殊行为，不是标准机制**

# 一、持久Cookie 写入本地完整流程（浏览器自动处理，后端只下发指令）
## 1. 后端响应头下发 Set‑Cookie
HTTP 返回头告诉浏览器：**这个Cookie叫什么、值多少、存活多久**
示例：
```http
Set‑Cookie: token=abc123; Max‑Age=604800; Domain=sso.com; Path=/; HttpOnly
```
`Max‑Age=604800` = 7天，**只要写了 Max‑Age / Expires → 标记为持久Cookie**

## 2. 浏览器接收后的动作
1. 解析响应头里的 `Set‑Cookie`
2. 判断：**存在过期时间 → 持久Cookie**
3. 浏览器**内核自动序列化保存到本地磁盘文件/数据库**，不是我们能直接编辑的txt：
    - Chrome：SQLite数据库文件，存放在用户目录下的 `Cookies`
    - Edge / Firefox 同理，都是加密数据库
> ✨ 关键点：**写入磁盘是浏览器内部行为，后端不能直接操作电脑文件！后端只是下发规则，浏览器自己落地存储。**

会话Cookie对比：没有Max‑Age，**只放到内存，不写硬盘**。

## 持久Cookie存储特点
- 浏览器关闭、电脑重启，文件保留
- 浏览器发起同域名请求时，自动从磁盘读取这个Cookie放到请求头 `Cookie:` 带给服务器

# 二、持久Cookie 的4种删除方式
## 方式1：服务端主动删除（最常用，退出登录）
原理：**下发同样名称、域名的Cookie，把过期时间设置成过去**
HTTP头示例：
```http
Set‑Cookie: token=; Max‑Age=0; Domain=sso.com; Path=/
```
`Max‑Age=0` → 告诉浏览器立刻删除这条Cookie
> 后端不能直接删掉你电脑上的文件！只能**发指令让浏览器自己删除本地记录**

## 方式2：时间自动到期（被动删除）
`Max‑Age` 倒计时走完 / `Expires` 时间一过
浏览器下次启动/访问站点时，自动清理过期Cookie记录。

## 方式3：用户在浏览器手动清除
1. 清除缓存与Cookie
2. 删除指定网站的数据
浏览器直接操作本地Cookie数据库文件删掉这条记录。**完全绕过后端控制**
> 就算登录态没到期，用户清缓存直接下线。

## 方式4：JS删除（有限制）
```js
document.cookie = "token=;max‑age=0;path=/;domain=sso.com"
```
⚠️ 如果Cookie加了 `HttpOnly` 属性，**JS读不到、也删不掉**，只能后端接口删除（SSO登录凭证一般都会开启HttpOnly）

# 三、一句话总结整个逻辑
1. **后端只发规则（Set‑Cookie带过期时间），浏览器自己把持久Cookie写到本地数据库文件**
2. **后端没有直接读写你硬盘的权限**，增删改全部依靠浏览器执行指令
3. 删除分三类：
    - 服务端指令过期删除（登出接口）
    - 时间到期浏览器自动清理
    - 用户手动清空浏览器缓存暴力删除

# 对比会话Cookie的删除逻辑
会话Cookie：**存在内存，浏览器进程关闭 → 内存释放自动销毁；硬盘从头到尾没有文件**
