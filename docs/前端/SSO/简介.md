## SSO 单点登录 (Single Sign-On)

**核心概念**：用户只需登录一次，就可以访问多个相互信任的系统。

### 生活中的例子

就像你登录微信后，可以直接打开微信小程序、微信支付、腾讯视频等，这些腾讯系产品不需要你再次输入账号密码。

### 没有 SSO 的情况

```
系统A: 账号 + 密码
系统B: 账号 + 密码  (又要输入一次)
系统C: 账号 + 密码  (还要输入)
```

### 有 SSO 的情况

```
┌──────────────────────────────────────┐
│           SSO 统一认证中心            │
│         (只需登录一次)                │
└──────────────────────────────────────┘
         │
    ┌────┴────┬────────┐
    ▼         ▼        ▼
  系统A     系统B     系统C
```

### 在你项目中的体现

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│   vue-demo   │      │   鉴权系统    │      │   其它系统   │
│   当前项目   │      │   (SSO)      │      │   (如CRM)    │
└──────────────┘      └──────────────┘      └──────────────┘
```

1. 用户在 vue-demo 点击 "SSO 登录"
2. 跳转到公司统一的鉴权系统登录页
3. 登录成功后，鉴权系统生成一个 `sso_token`
4. 鉴权系统 redirect 回 vue-demo，带上 `sso_token`
5. vue-demo 用 `sso_token` 换取自己的访问 token
6. 之后用户再访问公司其它系统（如 CRM），如果也接入了同一个 SSO，用户就**无需再次登录**

### 为什么企业需要 SSO

- **安全性**：员工只需管理一个密码，减少密码泄露风险
- **便捷性**：一个账号访问所有系统
- **统一管理**：员工离职时，只需停用一个账号即可撤销所有系统权限



## SSO "一次登录，多系统访问" 的实现原理

核心在于 **Cookie/Session 共享**或 **Token 验证机制**。

### 方案一：基于 Cookie + Session 共享（最常见）

```
┌─────────────────────────────────────────────────────────────┐
│                      用户浏览器                              │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  .sso-company.com  (SSO 域名的 Cookie)               │   │
│  │  session_id = abc123                                 │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

**原理**：

1. **统一域名下共享 Cookie**
   - SSO 系统的域名设置为 `sso.company.com`
   - 各子系统域名设置为 `crm.company.com`、`oa.company.com`
   - SSO 的 Cookie 设置在 `.company.com` 域名下（注意前面有点），这样 `crm.company.com` 和 `oa.company.com` 都能访问这个 Cookie

2. **Session 存储在共享缓存中**
   - SSO 系统、各子系统都连接同一个 Redis 或数据库存储 Session
   - 任何子系统验证时，只需拿着 Cookie 里的 session_id 去查，就能知道用户是否已登录

**访问流程**：

```
用户访问 CRM 系统
       │
       ▼
CRM 系统检查 Cookie 中的 session_id
       │
       ├─► 有 session_id → 查 Redis 确认有效 → 允许访问
       │
       └─► 没有/无效 → 跳转到 SSO 登录页
                      │
                      ▼
               用户在 SSO 登录（已在同域的其它系统登录过，Cookie 存在 → 直接通过）
                      │
                      ▼
               返回 CRM，带上 session_id Cookie
```

### 方案二：基于 Token 验证

各子系统不共享 Cookie，而是信任 SSO 颁发的 Token。

```
┌──────────────┐      ┌──────────────┐      ┌──────────────┐
│   vue-demo   │      │   SSO 系统    │      │   CRM 系统   │
│              │      │              │      │              │
│  存 localStorage │      │              │      │  存 localStorage │
│  token: xxx  │      │              │      │  token: xxx │
└──────────────┘      └──────────────┘      └──────────────┘
```

1. 用户在 SSO 登录后，SSO 系统生成一个**全局 Token**（或直接用项目 Token）
2. Token 存在各子系统的 localStorage 中
3. 各子系统请求后端时，后端拿着 Token 去 SSO 系统验证（或者 SSO 和各系统共享签名密钥）

### 你项目中体现的原理

你项目的 SSO 流程：

```
1. 点击 SSO 登录 → 跳 SSO 系统
2. SSO 系统登录成功 → redirect 回来 ?sso_token=xxx
3. 后端用 sso_token 换取项目自己的 token
4. 之后请求带上这个项目 token 即可
```

如果要让**其它系统也免登录**，只需要：
- 其它系统也接入同一个 SSO 鉴权服务
- 用户在任何一个系统完成 SSO 登录后，Cookie/Token 已经存在
- 用户访问下一个系统时，系统检查到有效凭证，就直接放行

### 关键技术点总结

| 技术 | 作用 |
|------|------|
| 统一域名 Cookie | 让多系统共享 session_id |
| 共享 Session 存储 | 让多系统能验证同一个 session_id |
| 重定向 (redirect) | SSO 验证完成后带用户回到原系统 |
| sso_token | SSO 给的一次性凭证，用于换取正式 token |



你问到了 SSO 的核心理解点。

## 每个项目都有 token ≠ 每个项目都要登录

**关键区别**：
- **登录** = 输入用户名 + 密码（繁琐）
- **获取 token** = 自动交换（用户无感知）

### SSO 的用户体验

```
┌────────────────────────────────────────────────────────────┐
│  用户视角                                                 │
├────────────────────────────────────────────────────────────┤
│  1. 打开 vue-demo，点 SSO 登录                            │
│     → 跳转到 SSO 登录页                                   │
│     → 输入用户名 + 密码  ← 只有这一次需要输入密码！         │
│     → 自动跳回 vue-demo，完成                             │
│                                                            │
│  2. 打开 CRM（同一浏览器）                                 │
│     → 直接进入，无需输入任何东西  ← 因为 SSO 的 session    │
│     → 内部自动完成 token 交换                             │
│                                                            │
│  3. 打开 OA（同一浏览器）                                  │
│     → 直接进入，无需输入任何东西                          │
└────────────────────────────────────────────────────────────┘
```

### 技术原理

```
用户首次登录 (vue-demo)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. 跳 SSO → 输入密码 → SSO 设置 Cookie（全局有效）
2. SSO 返回 vue-demo?sso_token=xxx
3. vue-demo 后端用 sso_token 换 token，存到 vue-demo 的 localStorage


用户访问 CRM（同一浏览器）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
1. CRM 检查 localStorage → 没有 token
2. 跳 SSO → SSO 检查 Cookie → 用户已登录！
3. SSO 直接返回 CRM?sso_token=yyy（无需再输密码）
4. CRM 后端用 sso_token 换 token，存到 CRM 的 localStorage
```

### 所以

| 动作 | 是否需要用户操作 |
|------|----------------|
| 登录（输入密码） | **只一次** |
| 获取各系统 token | 自动完成，用户无感知 |

**用户感受** = 一次登录，处处访问
**实际技术** = 每个系统都有自己的 token，但登录状态由 SSO 统一管理

SSO 的价值在于：**你只需要输一次密码**，而不是每个系统都输一遍。
