用最直白、好记的方式给你讲清楚**进程 vs 线程**，前端/后端/Node.js 都通用。

# 一、进程（Process）
可以理解成：**操作系统里独立运行的一个“程序实例”**。

- 每开一个程序，系统就给它划一块**独立内存**
- 进程之间**内存完全隔离**，互不干扰
- 一个进程挂了，通常不会影响别的进程
- 开销大，创建/销毁成本高

**例子：**
- 打开一个 Chrome 浏览器 → 一个进程
- 打开 VS Code → 一个进程
- 运行一个 Node 服务 → 一个进程

# 二、线程（Thread）
线程是**进程内部的“执行单元”**，一个进程至少有一个线程（主线程）。

- 共享所属进程的内存空间
- 一个线程崩溃，**整个进程可能一起崩**
- 轻量级，创建/切换成本低
- 用来实现**并发**：同时干多件事

**例子：**
- Chrome 每个标签页可能是一个进程，里面又有多个线程（渲染线程、网络线程、JS 引擎线程）
- Node.js 主线程跑 JS，底层 libuv 用线程池处理异步 I/O

# 三、一句话区别
- **进程**：独立车间，有自己完整厂房、设备，互不打扰。
- **线程**：车间里的工人，共用厂房资源，一个出事可能连累所有人。

# 四、经典类比（最好记）
- **进程 = 工厂**
- **线程 = 工人**

1. 工厂之间相互独立，互不干扰
2. 一个工厂里可以有多个工人一起干活
3. 工人共享工厂的资源（原料、机器）
4. 工厂贵，工人便宜

# 五、和你前面问的内存关系
- 每个**进程**有自己独立的：
  - 堆内存（Heap）
  - 调用栈（Call Stack）
- 同一进程内的**多个线程**：
  - **共享堆内存**
  - **每个线程有自己独立的调用栈**

# 六、常见考点总结
- 进程拥有独立资源，线程共享资源
- 进程切换开销大，线程切换开销小
- 进程是资源分配单位，线程是CPU调度单位
- 进程间通信麻烦（IPC），线程间通信简单（直接读写共享内存）
