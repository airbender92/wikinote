# ESLint 核心作用

一句话：**静态代码检查工具，在代码运行前找出代码问题、统一编码规范**，不负责格式化（格式化交给Prettier）。

## 一、ESLint 主要检查这4大类

### 1. 语法错误（防止代码直接报错）

解析 JS/TS/Vue 模板语法，提前揪出低级错误：

- 少写分号、括号不匹配
- 变量未声明、重复声明
- 非法关键字、语法书写错误

> 这类问题不修复，代码运行直接抛异常。

### 2. 潜在逻辑缺陷（容易产生bug）

最有价值的部分，**运行时才会暴露的隐患提前拦截**

- 使用未定义变量
- `==` 松散相等、空判断错误
- `return`、`break` 逻辑异常
- 死循环、无法执行的代码块
- 异步代码忘记 await
- 禁止修改 const 变量

### 3. 代码质量规范（不好的写法）

约束坏习惯，提升可维护性：

- 禁止 `eval`、`with`
- 不允许无用变量、未使用函数参数
- 禁止全局变量污染
- 复杂嵌套、过多回调

### 4. 编码风格规范（团队统一写法）

> ⚠️ 重点区分：风格规则很多可以交给 Prettier，ESLint 负责逻辑规范

- 变量命名规范（驼峰、常量大写）
- 函数写法、箭头函数约束
- 导入顺序、禁止默认导出等

## 二、在 Vue 项目额外检查（eslint-plugin-vue）

专门解析 `.vue` 文件 template + script：

1. Template 模板语法错误
2. 组件规范：组件命名、props 校验
3. Vue 语法陷阱：禁止直接修改 props、错误使用生命周期
4. v-if / v-for 混用风险、key缺失等

## 三、ESLint vs Prettier 极简区分（很多人混淆）

| 工具     | 定位             | 管什么                                |
| -------- | ---------------- | ------------------------------------- |
| ESLint   | **代码质量校验** | 有没有bug、写法是否合理、语法是否合法 |
| Prettier | **代码格式化**   | 空格、引号、换行、逗号、排版美观      |

> 为什么要搭配 `eslint-config-prettier`：
> 关闭 ESLint 里所有排版相关规则，避免两者互相冲突。

## 四、两条脚本作用回顾

```json
"lint": "eslint . --ext .vue,.js,.ts",
"lint:fix": "eslint . --ext .vue,.js,.ts --fix"
```

- `npm run lint`：扫描项目，列出所有错误/警告
- `--fix`：**自动修复一部分可修复规则**（变量声明、简单语法规范），逻辑bug无法自动修复，必须手动改

## 五、补充一个实操建议

开发中开启 VSCode ESLint 插件：
保存文件实时提示红线，不用等到运行命令才发现问题。
