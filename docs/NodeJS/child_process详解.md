在 Node.js 里，`child_process` 的这四个方法核心区别是：**是否创建 shell、是否缓冲输出、是否新开 Node 进程、是否流式输出**。

# 一句话速记
- **spawn**：通用流式执行命令，适合大数据、长时间运行
- **exec**：带 shell，结果一次性缓存返回，简单命令用
- **execFile**：直接执行可执行文件，**更安全、性能更好**，无 shell
- **fork**：专门开**新 Node 子进程**，自带 IPC 通道，可发消息

---

# 详细用途

## 1. spawn
```js
const child = spawn('ls', ['-l']);
```
- **用途**：执行**任意系统命令**
- **特点**：
  - 不使用 shell，直接启动进程
  - **流式返回 stdout/stderr**，不会爆内存
  - 适合：大量输出、长时间运行（ffmpeg、git、npm 安装、服务进程）
- **不适合**：简单小命令（代码稍繁琐）

## 2. exec
```js
exec('ls -l', (err, stdout, stderr) => {});
```
- **用途**：执行**简单 shell 命令**，方便写管道、重定向
- **特点**：
  - **会创建 shell**，支持 `ls | grep`、`&&`、`>` 等语法
  - 把输出**全部缓存到内存**，统一返回
  - 默认最大缓存 200KB，超了会爆内存
- **适合**：短命令、结果少、需要 shell 语法

## 3. execFile
```js
execFile('node', ['--version'], (err, stdout, stderr) => {});
```
- **用途**：**直接执行可执行文件**，比 exec 更安全高效
- **特点**：
  - **不启动 shell**，直接调用程序
  - 避免命令注入，性能更好
  - 同样缓存输出，但更轻量
- **适合**：执行文件（node、python、脚本）、生产环境推荐

## 4. fork
```js
const child = fork('./child.js');
```
- **用途**：**专门创建 Node.js 子进程**
- **特点**：
  - 是 `spawn` 的特殊版本
  - 自动建立 **IPC 通信通道**
  - 父子进程可用 `child.send()` / `process.on('message')` 通信
- **适合**：
  - 拆分 CPU 密集任务（不阻塞主线程）
  - 多进程服务、任务队列

---

# 最简单选择指南
- 要跑 shell 管道、复杂命令 → **exec**
- 执行文件、要安全高效 → **execFile**
- 输出大、长时间运行 → **spawn**
- 开子 Node 进程、发消息通信 → **fork**
