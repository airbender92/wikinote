```javascript
Buffer.alloc(20 * 1024 * 1024, 0)
```

这句话的意思是：

### 1. 大小
- `20 * 1024 * 1024` = **20,971,520 字节**
- 也就是 **20 MB** 的 Buffer

### 2. 含义
- `Buffer.alloc(size, fill)`
- 创建一个**长度固定**的 Node.js 二进制缓冲区
- 并用 `0`（二进制 `0x00`）**全部填充初始化**

### 3. 特点
- 安全：会**清零内存**，不会残留旧数据
- 同步、阻塞：创建 20MB 很快，基本无感
- 常用于：
  - 大文件读写缓存
  - 二进制协议打包
  - 内存池、预分配缓冲区

### 等价简写
```javascript
Buffer.alloc(20 * 1024 * 1024)
```
因为 `fill` 默认就是 `0`，可以不写。

如果你是要配合前面的 `tmp-io-demo` 做文件流读写，我可以给你一段完整示例。
这句就是：
**创建一个 100MB 大小、全部填 0 的 Buffer**

## 拆开看
```js
Buffer.alloc(
  100 * 1024 * 1024,  // 大小：104857600 字节 = 100MB
  0                     // 用 0 填充每一个字节
)
```

## 关键点
1. **`Buffer.alloc` 是安全的**
   会**强制清零**，不会读到旧内存垃圾。

2. **内存不在 V8 堆上**
   只在 JS 里有一个小对象，真实 100MB 内存是 C++ 分配的。
   → 对应你前面看到的：
   - `heapUsed` 几乎不变
   - `external` 直接 +100MB

3. 和 `Buffer.allocUnsafe` 的区别
   - `alloc`: 清零 → 安全、稍慢
   - `allocUnsafe`: 不清旧内存 → 快、可能有敏感数据残留

你这段代码用 `alloc(..., 0)` 就是为了**明确分配一块干净的 100MB 内存**，用来演示 external 内存增长。


`buf.fill(0)`  
就是：**把整个 Buffer 里的每一个字节，都设置成 `0`**

---

### 1. 作用
```js
buf.fill(0);
```

- 从头到位**逐字节覆盖**
- 全部变成二进制 `0x00`
- 和你一开始写的 `Buffer.alloc(100*1024*1024, 0)` 效果**几乎一样**

---

### 2. 为什么这里还要再 fill 一次？
在你这段测试代码里，其实**有点多余**，因为：
- `Buffer.alloc(size, 0)` 本身就**已经自动填 0** 了

但这么写通常是为了：
1. 模拟**真正使用这块内存**，而不是只分配不访问
2. 确保内存确实被 touched，让操作系统真正分配物理页
3. 让 `rss` 内存表现更明显、更符合真实使用场景

---

### 3. 简单对比
```js
const buf = Buffer.alloc(100);  // 内部已经 fill(0)
buf.fill(0);                    // 再填一遍 0，效果一样
```

---

### 一句话总结
`buf.fill(0)` = 手动把整块 Buffer 擦成 0，确保内存被真实使用。
