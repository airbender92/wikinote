用最简单、最前端也能听懂的话讲：

# 服务句柄 = 服务器的“钥匙”

在 Node.js 集群里：
**服务句柄（server handle）**
就是一个**代表“监听在某个端口上的服务器”的内部对象**。

你可以把它理解成：
- 不是代码
- 不是文件
- 而是**系统内核认的一个“标识”**
谁拿到它，谁就能处理这个端口的请求。

---

# 为什么要传这个“句柄”？

正常情况：
2 个进程同时 `listen(3000)` → 报错端口被占用。

用集群：
1. **主进程先创建服务器，拿到句柄**
2. **主进程把这个句柄通过 IPC 发给子进程**
3. 子进程**不自己 listen**，而是直接用这个句柄
4. 内核知道：这几个进程共用同一个服务

结果：
**多个进程，共享同一个端口，不会冲突。**

---

# 超级通俗比喻

- 端口 = 一扇门
- 服务句柄 = **门的总钥匙**
- 主进程 = 配钥匙的人
- 子进程 = 多个员工

主进程配好一把总钥匙，复制给所有员工。
大家都能用这把钥匙开门接待客人，不会抢门、不会打架。

---

# 对应到代码里长啥样？

```javascript
// 主进程
const server = net.createServer();
server.listen(3000);

// 这个 server 本身，就是服务句柄
worker.send('server', server);
```

子进程收到后，直接用它处理连接：
```javascript
process.on('message', (type, server) => {
  server.on('connection', socket => {
    socket.end('hello');
  });
});
```

# 最终一句话总结
**服务句柄，就是内核级的服务器标识。
主进程把它发给子进程，让多个进程能共享同一个端口，实现集群。**
