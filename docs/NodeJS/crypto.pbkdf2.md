`crypto.pbkdf2` 是 Node.js 里专门用来**给用户密码做安全哈希加密**的函数，几乎所有登录系统都会用到它。

# 一句话作用
**把用户密码 → 变成一串无法反向还原的安全字符串，存进数据库**
防止密码明文泄露。

# 完整解释
## 1. 全称
**PBKDF2**
= Password-Based Key Derivation Function 2
= **基于密码的密钥派生函数**

简单理解：
它不是简单加密，而是**故意把密码算得很慢、很难破解**，专门防暴力破解。

## 2. 为什么不用 md5 / sha256？
- md5、sha256 计算**太快**，黑客可以每秒试几亿个密码
- pbkdf2 可以设置**迭代次数**，故意变慢，让破解成本极高

## 3. 核心参数（必须看懂）
```javascript
crypto.pbkdf2(
  password,    // 用户密码原文
  salt,        // 随机盐（每个用户必须不一样）
  iterations,  // 迭代次数（越大越慢越安全）
  keylen,      // 输出长度
  digest,      // 哈希算法（如 sha256）
  callback
)
```

- **salt（盐）**
  每个用户随机生成一串字符串，和密码混在一起算
  → 即使两个用户密码一样，存库结果也完全不同

- **iterations（迭代次数）**
  比如 100000 次
  电脑要重复计算 10w 次才出结果
  → 暴力破解速度直接被拖慢 10w 倍

## 4. 典型流程（登录系统标准做法）
1. **注册时**
   - 生成随机 salt
   - 用 pbkdf2(password, salt, ...) 得到 hash
   - 把 **salt + hash** 存数据库
   - **绝不存明文密码**

2. **登录时**
   - 取出该用户的 salt 和 hash
   - 用用户输入的密码 + salt 再跑一次 pbkdf2
   - 对比结果是否和存的 hash 一致
   - 一致则登录成功

## 5. 为什么它会阻塞/占线程池？
因为它是 **CPU 密集型计算**，而且故意算得慢。

- 同步版 `pbkdf2Sync`：**直接阻塞主线程**
- 异步版 `pbkdf2`：**丢进 libuv 线程池**

这就是你前面问的：
**高并发登录 → pbkdf2 占满 libuv 4 个线程 → fs、dns 全部排队卡住**

## 6. 安全建议（生产环境）
- 每个用户必须用**独立随机 salt**
- 迭代次数至少 **100000+**
- 算法用 `sha256`
- 高并发场景建议放到 **worker_threads**，避免占 libuv 线程池
