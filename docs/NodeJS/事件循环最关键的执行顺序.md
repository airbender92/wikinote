# 为什么 setTimeout 里的同步代码还能阻塞前面的定时器？
因为：

## **Node.js 只有一个主线程**
不管是：
- 最外层代码
- setTimeout 回调
- setInterval 回调
- fs 回调
- http 回调

**全部都跑在同一个主线程上**

只要其中任何一个位置出现**同步死循环 /  heavy 计算 / fs.readFileSync**

→ **整个主线程卡住**
→ **所有定时器全部暂停**
→ **漂移直接爆炸**

# 最直白的比喻
- 主线程 = **一条单行道**
- setInterval / setTimeout = **路上的车**
- while 循环 = **一辆车在路上停着不动，堵死整条路**

不管这辆“堵路车”是从哪里开进来的（外层 / setTimeout / 回调）
**只要它停在主线程上，所有车都动不了。**
