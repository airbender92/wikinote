这两句合起来就是：

**拿到服务器随机分配的端口 → 让客户端去连接这个本地服务器**

---

## 1. `const port = server.address().port;`
- `server.address()` 获取当前监听的地址信息
- 因为你写的是 `listen(0)`，系统会**随机给一个可用端口**
- 所以这里要把这个**真实端口**取出来，客户端才能连上

## 2. `net.connect(port, '127.0.0.1', callback)`
创建一个**TCP客户端**，去连接刚才启动的服务端：

- `port`：刚才随机分配的端口
- `127.0.0.1`：本机地址
- 连接成功后，回调执行 `connected++`

---

## 整体逻辑
```
服务器 listen(0)
  ↓
系统分配随机端口
  ↓
server.address().port 拿到这个端口
  ↓
客户端 net.connect 连过去
```

就是**自己启动服务端 → 自己批量连接自己**，用来做并发连接测试。

```js
client.on('data', () => {});
```

就一句话：**注册一个接收数据的事件，内容为空，只占个坑**

### 作用
- 客户端收到服务器发过来的 `hello from single-thread server` 数据时触发
- 你这里是空函数，**什么都不做**，只是必须监听 `data` 事件

### 为什么要写这句？
Node.js 有个机制：
- **如果不监听 `data` 事件，收到的数据会一直留在缓冲区里**
- 写个空回调，就是告诉系统：数据我收到了，你可以丢掉

### 对你这段测试的意义
不影响连接、关闭、计时逻辑，
只是**让 TCP 流正常结束**，避免奇怪的内存/状态问题。

极简理解：
**占位用，防止数据堆积，无实际业务逻辑。**
