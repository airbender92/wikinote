# 调用栈（Call Stack）
用最简单、最直观的方式讲清楚：

## 1. 一句话定义
**调用栈 = JS 引擎用来记录“当前正在执行哪个函数、执行到哪一步”的栈结构。**
它遵循 **后进先出（LIFO）** 原则：
- 最后调用的函数，最先执行完、最先弹出。

---

## 2. 超通俗类比
你可以把它理解成：
**一叠盘子**
- 调用一个函数 = 往上面**放一个盘子**
- 函数执行完 return = 把最上面的盘子**拿走**
- 盘子堆太高放不下了 = **栈溢出（Maximum call stack size exceeded）**

---

## 3. 执行过程举例
```js
function a() {
  b();
}
function b() {
  c();
}
function c() {
  console.log('hi');
}

a();
```

调用栈变化顺序：
1. 全局代码开始执行
2. 调用 `a()` → 压入栈
3. `a()` 里调用 `b()` → 压入栈
4. `b()` 里调用 `c()` → 压入栈
5. `c()` 执行 `console.log`
6. `c()` 执行完 → 弹出栈
7. `b()` 执行完 → 弹出栈
8. `a()` 执行完 → 弹出栈
9. 回到全局

栈里的样子大概是：
```
[全局]
[全局, a]
[全局, a, b]
[全局, a, b, c]
[全局, a, b]
[全局, a]
[全局]
```

---

## 4. 你刚才那段递归为什么会爆栈？
```js
function probeStack(depth) {
  try {
    return probeStack(depth + 1);
  } catch (e) {
    return depth;
  }
}
probeStack(0);
```

- 每递归一次，**往调用栈里多压一个函数**
- 栈空间有限，不能无限堆
- 堆到一定层数，引擎直接报错：
  `RangeError: Maximum call stack size exceeded`

这就是**调用栈溢出**。

---

## 5. 调用栈的核心作用
1. **记住当前执行位置**：函数执行完该回到哪里
2. **管理执行顺序**：保证同步代码按顺序、不混乱
3. **抛出错误堆栈**：报错时告诉你 `at xxx (xxx.js:1:1)`，就是从调用栈里读的

---

## 6. 极简总结
- **调用栈**：JS 同步代码的执行轨迹记录器
- **规则**：后进先出
- **满了**：栈溢出
- **你那代码**：故意把栈堆满，测最大深度
