你这句问到**最核心的设计区别**了，我用最直白、最落地的话讲清楚：

# 一句话结论
- 这里用 `http`，是为了**模拟真实 HTTP 接口业务**（接口里有异步、有耗时）
- 用 `net` 只能发裸数据流，**没有 req/res、没有路由、没有接口语义**
- 这个 demo 目的是演示：**HTTP 接口异步时，不阻塞主线程、不影响其他请求**，所以必须用 `http`

---

# 1. 为什么这里要用 http，而不是 net？
你这段代码：
```js
const httpServer = http.createServer((req, res) => {
  setTimeout(() => res.end('ok'), 20);
});
```

目的是：
**模拟一个真实后端接口：收到请求 → 等待20ms异步操作 → 返回结果**

只有 `http` 模块才提供：
- `req` 请求对象（路径、方法、参数）
- `res` 响应对象（`res.end()` 返回数据）
- 完整 HTTP 协议解析（浏览器/Postman可访问）

而 `net` 是**裸 TCP**，没有这些东西，不能叫“接口”。

---

# 2. http 和 net 在这个场景下的真实区别
## 用 http（适合这个 demo）
- 面向**业务接口**
- 有请求、响应、状态码、Header
- 能直接用浏览器/ab/curl压测
- 异步 `setTimeout` 不会阻塞主线程
→ **完美模拟真实 Web 服务**

## 用 net（不适合这个 demo）
- 只传**二进制流**，没有“请求/响应”概念
- 没有路由，没有 GET/POST
- 你要自己定义数据格式、分包、解析
- 不能直接当 HTTP 接口用
→ **只适合底层长连接、游戏、自定义协议**

---

# 3. 这个 demo 想证明什么？（非常关键）
它想证明：

## **Node.js 做 HTTP 接口时，异步操作（setTimeout/数据库/文件/网络请求）不会阻塞主线程**

即使一个接口等 20ms，
**主线程依然可以同时处理成千上万其他 HTTP 请求**。

这就是 Node 适合做 **API 网关、Web 服务、高并发接口** 的原因。

而这一切，**必须基于 HTTP 协议演示**，所以用 `http` 模块。

---

# 4. 超级精简总结
- **http = 写 Web 接口**（你这个 demo 场景）
- **net = 写底层 TCP 长连接**

你这里要模拟**接口异步非阻塞**，
所以必须用 `http`，用 `net` 就不是业务接口了。
