简单说：**常驻物理内存（RSS，Resident Set Size）**，就是你的 Node.js 程序**当前真正占用在电脑物理内存里、实实在在占着硬件资源的那部分内存大小**。

---

### 一、RSS 到底是什么？

- 物理内存 = 你电脑的内存条（8G/16G/32G）
- RSS 就是：**操作系统给这个进程分配、并且正在使用的物理内存**
- 不包含：
  - 被交换到硬盘虚拟内存的部分
  - 只申请了但还没真正用到的内存

你可以理解成：
> **RSS ≈ 任务管理器 / 活动监视器里看到的“内存占用”**

---

### 二、和堆内存（heapUsed）有什么区别？

- `heapUsed`：只算 **V8 堆里 JS 对象用掉的内存**
- `RSS`：**整个进程所有内存**
  - V8 堆内存
  - 栈内存
  - 系统库、C++ 扩展、外部内存
  - 缓冲区、文件缓存等

所以一般：
**RSS > heapUsed**，而且 RSS 更能反映**真实硬件占用压力**。

---

### 三、举个直观例子

```javascript
const mem = process.memoryUsage();

console.log('常驻物理内存(RSS):', (mem.rss / 1024 / 1024).toFixed(2) + 'MB');
```

比如输出：
> 常驻物理内存(RSS): 31.25 MB

意思就是：
**这个 Node 进程现在实打实占了 31MB 左右的内存条空间。**

---

### 四、什么时候要看 RSS？

- 看程序**会不会越跑越占内存**（内存泄漏）
- 服务器资源紧张，看哪个进程吃物理内存最多
- 对比 heapUsed，如果 RSS 涨得特别快、但 heapUsed 没怎么涨，多半是：
  - 大量文件流、Buffer
  - C++ 模块内存没释放
  - 外部内存（external）暴涨

是的，**RSS 一定包含 heapUsed**，而且范围比它大得多。

可以用一句话记：
**RSS = heapUsed + 堆外内存 + 共享库等其他物理内存**

### 包含关系（从大到小）

- **RSS**：整个进程占用的**所有物理内存**
  - 包含 V8 堆（heapTotal、heapUsed）
  - 包含栈内存
  - 包含 Buffer、C++ 扩展、外部内存
  - 包含系统共享库占用的内存
- **heapUsed**：只是 V8 堆里**JS 对象实际使用**的那一小块

所以它们不是并列关系，而是**完全包含**关系：
**heapUsed ⊂ heapTotal ⊂ RSS**

### 简单比喻
- RSS = 你整个房子的面积
- heapTotal = 你家客厅的总面积
- heapUsed = 客厅里已经放了家具的面积

整个客厅当然在房子里面，所以 **RSS 必然包含 heapUsed**。
