这份就是**按钮权限判断的核心逻辑**，和上面的指令搭配使用，我给你讲得清清楚楚。

# 完整注释版
```typescript
import { useUserStoreWithOut } from '@/store/modules/user'
import { useI18n } from '@/hooks/web/useI18n'

const { t } = useI18n()

export const hasPermission = (value: string | Array<string>): boolean => {
  // 获取用户仓库
  const userStore = useUserStoreWithOut()
  // 当前用户拥有的权限码数组
  const permission = userStore.getPermissions
  // 是否超级管理员
  const isAdmin = userStore.getIsAdmin

  // 没传权限值直接报错
  if (!value) {
    throw new Error(t('permission.hasPermission'))
  }

  // 1. 环境未开启权限控制 或 2. 是管理员 → 直接放行
  if (import.meta.env.VITE_USE_PERMISSION !== 'true' || isAdmin) {
    return true
  }

  // 传入数组：满足任意一个权限即可
  if (Array.isArray(value)) {
    return value.some((v) => permission.includes(v))
  }

  // 传入单个字符串：精确匹配
  if (permission.includes(value)) {
    return true
  }

  // 都不满足 → 无权限
  return false
}
```

---

# 核心逻辑一句话总结
1. **管理员一律放行**
2. **环境关闭权限控制也一律放行**
3. 普通用户：
   - 单个权限：必须完全匹配
   - 多个权限：满足一个就行
4. 没权限 → 按钮被删掉

---

# 使用示例
```vue
<!-- 单个权限 -->
<button v-hasPermi="'system:user:add'">新增</button>

<!-- 多个权限满足一个即可 -->
<button v-hasPermi="['system:user:edit', 'system:user:delete']">操作</button>
```

# 到这里，你整个项目的**完整权限体系**就全部闭环了
1. **路由级别**
   `permission.ts` 路由守卫 → 控制能不能进页面
2. **接口级别**
   Axios 拦截器 + Token + 401 自动跳转 → 控制接口能不能调
3. **按钮/元素级别**
   `v-hasPermi` 指令 + `hasPermission` → 控制按钮显不显示（直接删 DOM）
4. **超级管理员豁免**
   管理员不受任何权限控制

这是**非常标准、企业级的中后台权限方案**，非常稳。
