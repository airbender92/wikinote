# 配置含义
```js
server: {
  port: 4000,            // 开发服务端口 4000
  proxy: {
    // 1. 非 mock 的接口 → 代理到后端测试环境
    [`^${apiProxyPath}(?!/mock)`]: {
      changeOrigin: true,        // 跨域：修改请求源
      target: 'http://10.1.130.93:8080/', // 后端地址
      rewrite: apiProxyRewrite,  // 路径重写函数
      ws: true                   // 支持 websocket 代理
    },

    // 2. websocket 专用代理
    '^/ws': {
      changeOrigin: true,
      target: 'http://10.1.130.93:8080/',
      ws: true
    }
  },

  hmr: { overlay: false }, // 热更新出错时不弹出全屏错误遮罩
  host: '0.0.0.0'          // 允许局域网 IP 访问（手机/同事可打开）
},
```

---

# 核心逻辑：正则代理规则
```
[^${apiProxyPath}(?!/mock)]
```
这是一个**零宽负向先行断言**正则，意思是：

- 以 `apiProxyPath`（比如 `/api`）开头
- **并且后面不是 `/mock`**
- 满足 → 转发到真实测试环境

也就是说：
- `/api/xxx` → 代理到后端
- `/api/mock/xxx` → **不走这个代理**，留给 mock 插件处理

这是非常标准的 **真实接口 + mock 共存** 代理方案，逻辑完全正确。

---

# 关键点说明

## 1. port: 4000
- 本地开发启动端口：`http://localhost:4000`

## 2. host: '0.0.0.0'
- 允许本机 IP、局域网 IP 访问
- 手机连同一 Wi-Fi 可访问

## 3. hmr.overlay: false
- 代码语法错误时，**不会弹出全屏白色错误页**
- 只在控制台提示，不遮挡页面，适合开发调试

## 4. proxy 里的 ws: true
- 同时代理 http 和 websocket
- 后端如果用 websocket 实时推送，必须开

## 5. changeOrigin: true
- 解决本地开发跨域
- 几乎所有代理都要加，否则后端可能拒绝

## 6. apiProxyRewrite
一般是类似这样的函数，作用是去掉前缀：
```js
const apiProxyRewrite = (path) => path.replace(/^\/api/, '')
```
你这里直接引用变量，写法规范。

# 小优化建议（可选）
## 1. /ws 可以合并（更简洁）
因为目标地址一样，可以不用单独写：
```js
proxy: {
  [`^${apiProxyPath}(?!/mock)`]: {
    changeOrigin: true,
    target: 'http://10.1.130.93:8080/',
    rewrite: apiProxyRewrite,
    ws: true
  },
  '^/ws': { target: 'http://10.1.130.93:8080/', ws: true }
}
```
你现在这样写**完全没问题**，更清晰。

## 2. 如果你想支持 https
可以加：
```js
server: {
  https: false, // 默认就是 false，可不写
  // ...
}
```
