## Vite 配置完整解读

### 一、开发服务器配置（端口 & 代理）

```ts
server: {
  port: 4000,                      // 本地开发端口
  host: '0.0.0.0',                 // 监听所有网卡，支持局域网访问
  hmr: { overlay: false },         // HMR 热更新，关闭错误弹窗覆盖层
  proxy: {
    // 代理1：API 接口代理（动态路径匹配）
    [`^${apiProxyPath}(?!/mock)`]: {
      changeOrigin: true,          // 改变请求 Origin 到目标域名
      target: 'http://10.1.130.93:8080/',  // → 后端测试地址
      rewrite: apiProxyRewrite,    // 当 apiBasePath 以 /dr 开头时，去掉 /dr 前缀
      ws: true                     // 支持 WebSocket
    },
    // 代理2：专门 WebSocket 代理
    '^/ws': {
      changeOrigin: true,
      target: 'http://10.1.130.93:8080/',
      ws: true
    }
  }
}
```

**工作流程：**
- 浏览器请求 `http://localhost:4000/front/api/user/list` → 匹配 `^/front/api(?!/mock)` → 转发到 `http://10.1.130.93:8080/front/api/user/list`
- 如果 `VITE_API_BASE_PATH=/dr`，则请求 `/dr/user/list` → 代理带到 `/dr` 前缀后重写为 `/user/list`（去掉 `/dr`）
- mock 接口由 `viteMockServe` 插件直接拦截，不经过代理

### 二、环境变量加载规则

```ts
if (!isBuild) {
  // 开发模式：从命令行 argv 取 mode
  env = loadEnv(process.argv[3] === '--mode' ? process.argv[4] : process.argv[3], root)
} else {
  // 构建模式：从 command 参数取 mode
  env = loadEnv(mode, root)
}
```

- `loadEnv(mode, root)` 会加载根目录下的 `.env.[mode]` 文件
- 支持 `.env.development`、`.env.production`、`.env.staging` 等
- 最关键的几个环境变量：
  | 变量名 | 用途 |
  |---|---|
  | `VITE_API_BASE_PATH` | API 基础路径（默认 `/front/api`） |
  | `VITE_BASE_PATH` | 应用根路径（对应 `base` 配置） |
  | `VITE_OUT_DIR` | 构建输出目录（默认 `dist`） |
  | `VITE_DROP_CONSOLE` | 是否移除 `console.log` |
  | `VITE_DROP_DEBUGGER` | 是否移除 `debugger` |
  | `VITE_SOURCEMAP` | 是否生成 sourcemap |
  | `VITE_USE_MOCK` | 是否启用 mock |
  | `VITE_USE_LEGACY` | 是否启用 legacy 兼容 |
  | `VITE_APP_TITLE` | HTML 标题（通过 ejs 注入） |

### 三、静态资源 & 别名 alias

```ts
resolve: {
  extensions: ['.mjs', '.js', '.ts', '.jsx', '.tsx', '.json', '.less', '.css'],
  alias: [
    { find: 'vue-i18n', replacement: 'vue-i18n/dist/vue-i18n.cjs.js' },  // 强制使用 CJS 版本
    { find: /\@\//, replacement: `${pathResolve('src')}/` }              // @ → src/
  ]
}
```

- **`@` 别名**：`@/components/xxx` → `src/components/xxx`
- **`vue-i18n` 别名**：强制指向 CJS 版本，避免 ESM 兼容问题
- **自动解析扩展名**：import 时可以省略 `.ts`、`.vue` 等后缀
- SVG 图标通过 `createSvgIconsPlugin` 统一管理，放在 `src/assets/svgs/` 目录，使用 `icon-[dir]-[name]` 格式的 symbolId

### 四、构建打包配置

```ts
build: {
  target: 'es2015',                       // 编译目标（兼容 ES2015）
  outDir: env.VITE_OUT_DIR || 'dist',     // 输出目录（默认 dist）
  sourcemap: env.VITE_SOURCEMAP === 'true',
  reportCompressedSize: false,            // 关闭 gzip 大小报告（加快构建）
  cssCodeSplit: true,                     // CSS 按需分割（默认开启）
  cssTarget: ['chrome31'],                // CSS 兼容目标
  
  rollupOptions: {
    // 分包策略（manualChunks）
    output: {
      manualChunks: {
        'vue-chunks': ['vue', 'vue-router', 'pinia', 'vue-i18n'],     // Vue 全家桶
        'element-plus': ['element-plus'],                              // UI 库单独打包
        'wang-editor': ['@wangeditor/editor', '@wangeditor/editor-for-vue'], // 编辑器
        'echarts': ['echarts', 'echarts-wordcloud']                    // 图表库
      }
    }
  }
}
```

**分包策略说明**：将大型依赖拆成独立 chunk，利用浏览器并行加载 + 长期缓存，避免因改动业务代码导致第三方库缓存失效。

**esbuild 优化**：
```ts
esbuild: {
  pure: env.VITE_DROP_CONSOLE === 'true' ? ['console.log'] : undefined,
  drop: env.VITE_DROP_DEBUGGER === 'true' ? ['debugger'] : undefined
}
```

### 六、Nginx 部署 & Hash 路由配置

#### 1. `base` 路径配置
```ts
base: env.VITE_BASE_PATH
```
- 通过环境变量 `VITE_BASE_PATH` 控制应用的根路径
- 如果是 **hash 模式**（`vue-router` 使用 `createWebHashHistory`），路由的 `#` 之后部分由前端控制，服务端无需特殊处理

#### 2. Nginx 部署示例（hash 路由 + `/front/` 子路径）

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # 静态资源托管（对应构建产物 dist）
    location /front/ {
        alias /path/to/dist/;
        try_files $uri $uri/ /front/index.html;  # 兼容刷新（hash 路由也建议配）
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 静态资源（js/css/img）长期缓存
    location /front/assets/ {
        alias /path/to/dist/assets/;
        expires 365d;
        add_header Cache-Control "public, immutable";
    }

    # API 反向代理到后端
    location /front/api/ {
        proxy_pass http://backend-server:8080/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /ws {
        proxy_pass http://backend-server:8080/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

#### 3. 关键注意点

- **hash 路由 vs history 路由**：此配置使用 hash 路由（代码中用了 `createWebHashHistory`），所以 Nginx 不需要像 history 模式那样用 `try_files` 兜底，但保留 `try_files` 仍是最佳实践
- **`base` 路径一致性**：`VITE_BASE_PATH` 需与 Nginx `location` 路径一致（如 `/front/`），否则资源加载 404
- **静态资源缓存**：对 `assets/` 子目录设置 `immutable` 强缓存 —— 因为 Vite 构建产物文件名带 hash，可以永久缓存
- **分包策略的价值**：分包后的 `vue-chunks.js`、`element-plus.js` 等文件 hash 极少变化，浏览器长期缓存，仅首页加载一次后绝大部分走缓存
