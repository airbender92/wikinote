### 五、Nginx Hash 路由相关处理代码

Nginx 配置文件位于 `nginx/conf.d/` 下，三个环境配置结构基本一致：

**关键点（Hash路由不需要特殊try_files处理，但这里用的是 History 回退模式）：**

实际上，项目用 Hash 路由 (`createWebHashHistory`)，但 Nginx 却配置了 `try_files $uri $uri/ /index.html` 这种 History 模式的回退。这是因为：

> **Nginx 的配置是"通用兜底"** — 无论是 Hash 路由还是 History 路由，`location / { try_files $uri $uri/ /index.html; }` 都能工作。对 Hash 路由来说，`#` 后的路径不会发送到服务端，所以此配置实际不影响 Hash 路由的正常运行。

**三个环境的 Nginx 配置对比**：

| 配置项 | dev.conf (8081) | test.conf (8082) | prod.conf (8083) |
|--------|----------------|-----------------|-----------------|
| 监听端口 | 8081 | 8082 | 8083 |
| 静态资源根目录 | `/var/www/html/dev` | `/var/www/html/test` | `/var/www/html/prod` |
| API代理路径 | `/dr/front/api/` | `/front/api/` | `/dr/front/api/` |
| 后端目标 | `10.1.130.93:8080` | `10.1.130.93:8080` | `10.1.130.93:8080` |
| WS代理路径 | `/ws` | `/ws` | `/ws` |

**Nginx 核心功能点**：

1. **`location /`** — 静态资源回退到 `index.html`，保障Hash路由的入口加载
2. **`location ~* \.(js|css|...)`** — 静态资源长缓存（1年），`public, immutable`
3. **`location ^~ /dr/front/api/`** — API 代理，含 `/mock` 路径跳过代理逻辑
4. **`location ^~ /ws`** — WebSocket 代理，带 `Upgrade` 头 + 24h超时

**关于 `base` 路径**：`vite.config.ts` 中 `base: env.VITE_BASE_PATH`，通过环境变量控制部署子路径。

**Dockerfile 相关**：`Dockerfile.dev` 仅用于开发环境容器化启动，生产部署需参考 Nginx 配置文件。
