这是一份**基于 commitlint + 约定式提交**的配置文件，用于规范项目 Git 提交信息格式。我给你整理成**清晰注释 + 可直接使用**的版本，并简单说明用法。

# commitlint.config.js
```javascript
module.exports = {
  extends: ['@commitlint/config-conventional'],
  rules: {
    // 提交类型枚举
    'type-enum': [
      2,
      'always',
      [
        'feat',      // 新功能（feature）
        'fix',       // 修复 bug
        'docs',      // 仅文档修改
        'style',     // 代码格式/样式（不影响代码逻辑）
        'refactor',  // 重构（既不是新功能，也不是改 bug）
        'perf',      // 性能/体验优化
        'test',      // 测试用例新增、修改
        'ci',        // CI/CD 配置文件与脚本修改
        'chore',     // 构建过程、辅助工具变动
        'revert',    // 回滚上一次提交
        'workflow',  // 工作流改进
        'mod',       // 不确定分类的修改
        'wip',       // 开发中（Work In Progress）
        'types',     // TS 类型定义修改
        'release'    // 版本发布
      ]
    ],
    // 主题结尾不使用句号
    'subject-full-stop': [0, 'never'],
    // 主题大小写不做强制校验
    'subject-case': [0, 'never']
  }
}
```

---

## 配套依赖安装
```bash
npm install -D @commitlint/cli @commitlint/config-conventional husky
```

## 配合 husky 启用 Git 提交校验
```bash
npx husky install
npx husky add .husky/commit-msg 'npx --no -- commitlint --edit $1'
```

---

## 合法提交示例
```bash
git commit -m "feat: 新增用户登录接口"
git commit -m "fix: 修复表单验证失效问题"
git commit -m "docs: 更新 README 部署说明"
git commit -m "refactor: 优化 axios 封装逻辑"
git commit -m "types: 完善全局 TS 类型"
```
