# 时间复杂度 & 空间复杂度（IT/算法基础，通俗版）

> 
> 一句话总结：**时间复杂度看运行耗时增长有多快；空间复杂度看占用内存增长有多快。**
> 它们不是精确的运行秒数、内存字节数，描述的是**数据量变大的时候，开销怎么增长**，用大O符号 `O(...)` 表示。

## 一、时间复杂度 Time Complexity

衡量：**算法执行需要多少操作次数，随输入数据规模 n 的变化趋势**

> 
> n = 输入数据的数量，比如数组有多少个元素

### 常见复杂度（从快到慢，优先选前面的）

1. **O(1) 常数级**
不管数据多少，永远只做固定次数操作。
例子：取数组第3个元素、变量赋值。

```
const a = arr[2]; // 只取一次，和数组长短无关
```
2. **O(log n) 对数级**
数据翻倍，操作只多一点点。每次直接砍掉一半数据。
例子：二分查找。1000个数据只要最多10次判断。
3. **O(n) 线性级**
数据增加一倍，操作次数增加一倍。从头到尾遍历一遍。
例子：循环遍历整个数组求和。

```
let sum = 0;
for(let i=0;i<arr.length;i++) sum += arr[i];
```
4. **O(n log n) 线性对数**
大部分优秀排序算法：归并排序、快速排序（平均）。大数据常用。
5. **O(n²) 平方级**
两层嵌套循环，n翻倍，耗时变成4倍。数据量大的时候会巨慢。
例子：双重for循环，冒泡排序最坏情况。

```
// 两层循环 n*n 次
for(let i=0;i<n;i++){
    for(let j=0;j<n;j++){}
}
```
6. **O(2ⁿ) 指数级、O(n!)阶乘级**
数据稍微变大，计算量爆炸。只适合极小数据，一般要避免。

> 
> 重点：我们一般看**最坏情况**的复杂度，忽略常数和低次项。
> 比如 `O(2n + 100)` 简化成 `O(n)`；`O(n²+100n)` 简化成 `O(n²)`。因为n很大时，常数项影响可以忽略。

## 二、空间复杂度 Space Complexity

衡量：**算法运行额外需要开辟多少内存空间，随输入规模n变化**

> 
> 注意：**输入本身占用的空间不算，只算算法额外新开的变量、数组、递归栈**

例子：

- O(1)：只用几个临时变量，没有新开数组。原地排序。
- O(n)：函数内新建一个长度为n的数组，额外空间随n线性增长。
- O(log n)：递归二分，递归栈深度logn。

举个对比：

```
// 空间 O(1)，原地反转数组，没有新建大数组
function reverse(arr){
    let l=0,r=arr.length-1;
    while(l<r){
        [arr[l],arr[r]] = [arr[r],arr[l]];
        l++;r--;
    }
}

// 空间 O(n)，新建了一个新数组存储结果
function reverse2(arr){
    const res = []; // 额外数组，大小n
    for(let i=arr.length-1;i>=0;i--){
        res.push(arr[i]);
    }
    return res;
}
```

## 三、简单对比记忆

| 指标 | 关注点 | 核心 |
| --- | --- | --- |
| 时间复杂度 | CPU运算次数 | 跑得多快 |
| 空间复杂度 | 内存占用 | 占多少内存 |

## 四、面试常考一句话

> 
> 时间复杂度：输入规模增大时，算法执行时间的增长量级；
> 空间复杂度：输入规模增大时，算法额外占用存储空间的增长量级；
> 采用大O表示法，只保留最高阶项，忽略常数。

## 五、取舍思路

很多时候是**时空权衡**：

- 拿空间换时间：缓存、哈希表，多占内存，减少计算
- 拿时间换空间：原地算法，不开新数组，但是循环变多
